Memory's graph status cache now asks `sdd repo path <repo-id>` where each connected repository's copy lives, built in commit `d00e4e4` and released in agentic-helpers v2.29.1.

On each refresh memory runs `sdd repo path` once per connected repository and stores the answers under `clones` in `graph-status.json`; a cached read builds its key from the stored paths and starts no process. Where `sdd repo path` fails or prints nothing, the stored path is `<XDG_CACHE_HOME>/sdd/<repo-id>`. A repository with no stored path adds a key part that never matches, so a cache written before the change refreshes once. `docs/memory/architecture.md` and `docs/plugin/usage.md` describe the lookup and the fallback; commit `1c4b465`, after the release, corrected the fallback path in `docs/plugin/usage.md`.

Every acceptance criterion has its test in `source/hooks/internal/memory/crossrepo_test.go`, with `sdd` faked:
- a change in the copy sdd names re-runs `sdd export`, while a change at the old path does not (the test counts export calls; it asserts no changed flag);
- a cached read with no graph changed starts no process;
- with `sdd repo path` failing, and with it printing nothing, the key reads the old cache path;
- a cache without `clones` refreshes exactly once.

The fallback on a failed call is masked by the fallback on an empty answer, since both implementations of the call return an empty path with their error: breaking the failed-call check alone leaves the tests green, while breaking the empty-answer check fails the printing-nothing case.
