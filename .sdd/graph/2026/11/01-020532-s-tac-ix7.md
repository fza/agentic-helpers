Trap and note notices mark the calling agent's own shown set, and the memory MCP server's call-id fallback for `full` subagents is removed, in agentic-helpers commits bb2335a and f1bacbd on `main`, not yet released. It closes the notice directive (20261101-013521-d-tac-meo) and settles the three points the done 20261101-010124-s-tac-ng6 left open.

**Notices.** `trapNotices` picks the shown set by the payload's `agent_id`, and a subagent first adopts a fork's copied set. Tests show a `rules` subagent told once and its parent told afterwards, a fresh subagent told of a trap its parent saw, and a fork not told again, for a trap and an `--about` note alike. A fork's copy is now kept at every level, not only from `silent` up, since notices reach a fork at `rules` or `none`.

**Probe**, a headless `claude -p` loading the built plugin with logged MCP input and hook payloads under a throwaway home: the memory MCP server received `"agent":"<id>"` in the arguments of both a fresh subagent's and a fork's `show` call, so Claude Code applies the PreToolUse input rewrite to MCP tools; `SubagentStop` fired for both, `agent_type` `general-purpose` and `fork`, and the slot file held no subagent set or spawn slot afterwards.

**Fallback removed.** With the `agent` key reaching the server, the join by `_meta` call id (`subagentOfCall`, `mcpserver.CallID`, the per-subagent `Calls` records) had nothing left to do and is gone; a call without the key now stays on the session's seat whatever its call id. The fork set the live run of 20261101-010124-s-tac-ng6 found left behind did not recur; the slot file keeps a deleted key's bytes in its twin slot, which a raw byte read shows as present, the likely misreading.

Every new guard was broken, caught by its own test and restored byte-identically; the inverted call-id assertion was reasoned to fail on the old code, not run against it. `docs/memory/usage.md`, `docs/memory/architecture.md` and the agent-memory skill's `subagents.md` describe it.
