The rename of the agentic-memory option `entry_max_words` to `entry_target_words` is built in agentic-helpers commits 1fe85fb and fff5cfc on `main`, not yet released, closing 20261101-190826-d-tac-vf3: `plugin/.claude-plugin/plugin.json`, the Go option `EntryTargetWords` and the note `new` prints for a body past the target (`internal/memory/entries.go`) carry the new name, the `Renamed` table reads `entry_max_words` from every layer for one release with the new name winning and `agentic-helpers check` naming the old one, and `MigrateAgentAnswers` copies an old user-settings answer into `config.yaml` under the new name, never overwriting a value there.

**Deviations.** The `Renamed` mechanism held only keys `config.yaml` alone sets; it now also handles a key Claude Code's settings and the `CLAUDE_PLUGIN_OPTION_<KEY>` environment carry, with its comments corrected. fff5cfc fixes a defect found on the way: `MigrateAgentAnswers` panicked on assignment to a nil map wherever `config.yaml` was missing, empty or held only comments and an answer needed copying, which a session start hit; its test was red against the unfixed code first.

**Proof.** Tests cover the old name read from every layer, the new name winning where a layer sets both, the copy into `config.yaml`, no overwrite where the file names either key, and the new note wording; each guard was broken and its test turned red. The full suite passes, and README, `docs/memory/usage.md` and agentic-helpers:agent-memory name the new key. Not checked live: a machine with an old answer in its settings.
