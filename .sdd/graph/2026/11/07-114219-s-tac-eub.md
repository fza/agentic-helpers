agentic-helpers v2.29.0 (release commit `346b0aa`) ships both decisions it closes: the grounding gate and `agentic-capture` leave for the sdd-helpers plugin (20261107-100211-d-tac-d1x, commit `dccf21e`), and the `agentic-helpers export` and `uninstall` verbs land (20261107-100353-d-tac-01g, commit `6eccafc`). One record covers both because one release carries them and one round of proof verified them.

## Proof

- **Release:** the release workflow's tests passed on Ubuntu and macOS and its plugin check passed; the published `darwin_arm64` archive holds `agentic-helpers`, `agentic-memory`, `agentic-scratch`, `agentic-tools` and `agentic-shell-guard`, and no `agentic-grounding-gate` or `agentic-capture`. Its `agentic-helpers` answers `export` and `uninstall` with their usage lines.
- **Order:** sdd-helpers v1.0.0 was published before v2.29.0, so the line `agentic-helpers check` prints at session start in graph projects lacking sdd-helpers never named a plugin users could not install.
- **Guards:** every new guard of the notice, export and uninstall was broken and seen failing on its own test, then restored byte-identically. Two refusals of an existing export target hide each other and are caught only broken together.
- **Real data, scratch home:** an export of a copy of a full store backup from 2026-11-04 wrote one archive holding every store, reading memory stores of formats 3 to 11 through migrated copies; the copied home was byte-identical afterwards. `uninstall --dry-run` and a real run on that copy exported first, removed the data and cache roots, and listed every checkout's `.tmp/` and `autoMemoryEnabled` key without touching them.

## Deviations

- The removal shipped as a minor release with the new verbs instead of a patch of its own.
- Decisions taken after d-tac-01g and built into v2.29.0: an older-format store is exported through a migrated copy in the cache, recorded as `migrated_from` in the manifest, the original untouched; `uninstall` refuses while another Claude Code session is live (`--ignore-sessions` overrides a stale record, `--dry-run` lists them instead), removes the plugin before any folder, and ends with a line asking for a restart.
- A home whose `format.json` is the moved-away stub `{"format":999}` is refused as a newer format, so `uninstall` there needs `--discard-data`.
- Not reachable by a test, named and not counted: re-verifying an archive the writer already verified, removing a temporary file after an attachment vanishes mid-write, and races with another writer while made cache folders are removed.
