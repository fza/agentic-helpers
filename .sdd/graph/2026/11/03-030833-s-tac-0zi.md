Entry names, hidden memory lines, the reminder's answer rule and cadence, and the session id shape check are built on `main` and proven end to end with binaries built from `d2290e7`, run against a throwaway store and home: commits `724a20b` (names, store format 9), `21b94c3` (hidden lines), `126779f` (answer rule), `c93b07a` (cadence) and `daf8d27` (session id shape). Both Go suites, darwin with `-race` and Linux through `scripts/linux-test`, pass on the merged tree.

- **Entry names (20261102-232808-d-tac-fvh):** filing printed `filed m-hp9rwh (apfs-span)`, a second entry of the same title `apfs-span-2`; `show apfs-span-2` worked from the CLI and over MCP stdio, and `show gate-reads` still worked after `retitle`. A store written at format 8 by release 2.25.1 moved to format 9 on the first command of the new build, naming every entry, and 2.25.1 then refused it as newer. The kill-safety part of criterion 3 rests on `TestEveryStepCarriesOnFromAnyOperation` and the release-fixture test.
- **Hidden lines (20261102-225941-d-tac-em1):** every non-empty memory hook output was one JSON object carrying `additionalContext`; Stop printed nothing; a do-now line owed at Stop arrived once at the next UserPromptSubmit. Delivery at PreToolUse, PostToolUse and SessionStart rests on `TestALineOwedAtStopArrivesOnceWithTheNextHook`.
- **Answer rule (20261102-232355-d-tac-9pq):** after a commit landed past a reminder, a throwaway state line left the reminder owed, ending `Answered once each hook line since is cited in a line of yours, ticked or dropped: state#8ga`; ticking `state#8ga` answered it.
- **Cadence (20261102-232434-d-tac-oqu):** at 70% context, each prompt carried the reminder once; of 25 tool calls, calls 10 and 20 carried it; after the answer, prompts and 20 further calls carried none, and Stop stayed empty.
- **Session id shape (20261103-001416-d-tac-0ts):** ids `a/b`, one of 129 characters and an empty one went through every hook with exit 0 and left the slot file's key list unchanged; a UUID wrote its `ladder`, `instructions` and `graph-seen` keys as before.

**Skill and docs** change in the same commits as the code: `docs/memory/usage.md` gains a Names section with numbered listings and quotes the hidden-line, reminder and answer wording; `docs/memory/architecture.md` describes the name index, format 9 and the session id check; `plugin/skills/agent-memory/SKILL.md` and its `triggers.md` and `reference.md` tell agents to show names and numbered lists, never ids, say where an owed line arrives, and quote `Context near compaction. Add or tick state lines where work moved: ...` and the answer rule's `Answered once each hook line since is cited in a line of yours, ticked or dropped` (`docs/memory/usage.md:1475`, `SKILL.md:265`). The skill's size budget test passes at 20403 of 20500 characters, and `TestAReminderNamesTheHookLinesItWaitsFor` checks the skill against the hook's wording.

Side finding: in one of five runs, the prompt hook printed 423 bytes for each malformed session id; the text was not kept and four reruns printed nothing. No criterion depends on it.
