Shell-guard asks about a script an earlier command in the call names, follows a `cd` later in an `&&` chain and a `cd <dir> || exit` or `|| return`, and reads fish scripts, in agentic-helpers commits f4cd6a9, 3447d13 and e09979d on `main`, not yet released. It closes the script-write directive (20261031-225613-d-tac-4rz), the `cd` directive (20261031-225716-d-tac-ob0) and the fish directive (20261031-235440-d-tac-5qj).

**Proof on the installed binary**, Bash payloads fed to `agentic-shell-guard` from a tree under `.tmp/`:
- `cp new.sh x.sh && bash x.sh`, `sed -i '' 's/a/b/' x.sh && ./x.sh` and `mytool x.sh && bash x.sh` ask `cannot read the script x.sh (the command writes it before running it)`; `chmod +x x.sh && ./x.sh` and `cat x.sh && bash x.sh` pass.
- `cd sub || exit 1; ./build.sh` and `make && cd sub && ./build.sh` read `sub/build.sh` and judge its removal outside the project; `cd sub || echo no; ./build.sh` asks `the directory it runs in is not known`.
- `fish clean.fish` (holding `rm -rf build`) asks, `fish list.fish` passes, `fish missing.fish` asks `cannot read the script missing.fish (no such file)`.

The tests cover every acceptance criterion, including `curl -o`, `dd of=`, `sudo` and `env -C` forms, the here-document case, `cd sub || return` and a path-run file with a fish `#!` line. Every new guard was broken, caught by its own test and restored byte-identically.

**Deviations.** A fish script's reason is the one other interpreters' code already gets, `in the script <name>: inline code for fish names a removal or mktemp; refusing` (an ask), not the shorter `code for fish names a removal` the fish directive names. A fixed argument the walk cannot place (a relative word under `env -C`) also makes later scripts unknown, so `env -C .. cp new.sh scripts/x.sh; bash x.sh` asks; `docs/shell-guard/architecture.md` states it. Non-literal arguments (`cp a "$dst"`) mark nothing, as the directive limits the rule to a named path.
