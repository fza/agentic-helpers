An agentic-memory seat claim made where no Claude Code process is among the caller's ancestors succeeds without a word, and every later call that needs a seat refuses with `claim a seat first`, a refusal that points at the claim rather than at the owner recognition that failed.

`seat.Holder` (`source/hooks/internal/seat/seat.go`) falls back to the caller's immediate parent with no process name when `seat.OwnerAncestor` finds no Claude Code process within its ancestor walk, and the claim in `source/hooks/internal/memory/seats.go` records that parent as the holder. `seat.Alive` then compares the parent's name with the owner name, finds them different, and reads the seat as not held, so `seat.Of` returns no seat for the session. The same fallback is recorded on two paths that answer no claim call: a reservation the session's first hook takes over (`adopt` in `source/hooks/internal/memory/claimfor.go`) and a seat held for a subagent (`holdForSubagent` in `source/hooks/internal/memory/subagents.go`).

The cost: an unrecognised Claude Code install shows as a broken claim instead of as an unknown owner process, and the agent repeats the claim without learning why it fails. The npm package's native `claude.exe` did exactly this (20261111-164834-s-tac-lei): every claim succeeded and the next call refused, and finding the cause took a diagnosis on the affected machine. Its recognition is fixed (20261111-175654-s-tac-9mf, which names this silence as left open), but the next Claude Code install that runs under an unknown name meets the same silence.

Closing it means the claim reports, at claim time, that no Claude Code process was found above it, naming what it found instead, and that a reservation taken over or a subagent seat held under the same fallback does not turn free unnoticed either. The claim's output wording is part of agentic-memory's contract, quoted by its skill, so the wording is its own decision.
