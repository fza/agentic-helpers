A commit also matches a live todo, todo item or trap in the landed-commit scan of 20261101-110914-d-tac-pu1 when its full commit message names an sdd graph entry the todo, item or trap links to. This adds a fourth test beside branch, path and subject similarity; scan, storage, delivery and every other part of that directive stand unchanged, and both retire together.

**What names an entry.** The message holds the entry's full id (`20261101-110914-d-tac-pu1`), its qualified form for another repository's graph (`<repo-id>:<entry-id>`), or its short id (`d-tac-pu1`) where that short id resolves to exactly one linked entry. The link is the memory link set by `--link`, `link`, or a linked todo item (`--item <graph id>`). A matched item is mapped as `<todo>#<item>`; a matched todo or trap as its own id.

**Why.** Work tied to a graph entry often lands in a commit that cites that entry, as done entries and their commits do, while the commit's branch and subject share no words with the todo. The id is the most precise evidence the scan can find: an exact reference rather than a similarity.

**Rejected.** Matching any graph id in a message, linked or not: it would map commits to todos that never pointed at that entry. Reading only the subject line: ids usually sit in the body.

**Accepted cost.** The scan reads full commit messages instead of subjects alone.

**Acceptance.**
- A commit whose message names a full, qualified, or uniquely resolving short id of an entry a todo links to yields a stored mapping for that todo; one naming an item's linked entry yields a `<todo>#<item>` mapping.
- A commit naming an unlinked entry, or a short id matching several linked entries, yields none from this test.
