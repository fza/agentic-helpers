`agentic-memory`, `agentic-tools`, `agentic-capture` and `agentic-scratch` now run as names of the one `agentic-helpers` program, built on `main` in commits `ae3eaf2` and `a4f260d`; `agentic-shell-guard` and `agentic-grounding-gate` stay programs of their own. Built from `main` into a throwaway folder with the four names linked to `agentic-helpers` as the release archive carries them, each name ran its own command: `usage: agentic-memory <subcommand>`, `usage: agentic-tools <subcommand>`, `usage: agentic-capture <draft.md> ...`, `usage: agentic-scratch end|start`, and `agentic-helpers` its own `check | config | sweep | end | prune | dump | bound`.

- **Archive (criterion 1 of both decisions):** a goreleaser snapshot on all four platforms holds `agentic-helpers`, `agentic-shell-guard` and `agentic-grounding-gate` as programs and the four names as links to `agentic-helpers`; `tar -x` keeps them as links. `TestTheReleaseCarriesTheCommandNamesAsLinksToAgenticHelpers` fails if a folded name gets a program of its own again.
- **Each name runs its command (criterion 2):** `TestEachNameRunsItsOwnCommand` and `TestScratchSweepsTheProjectUnderItsName` run the test binary through a link under each name.
- **Development builds (criterion 3):** `go install` builds `agentic-helpers` alone, since it cannot create links; the launcher (`plugin/hooks/run`) with `AGENTIC_HELPERS_BIN_DIR` set links each missing name to it on first use, and replaces a program an earlier build left once `agentic-helpers` is newer, proven by `TestTheOverrideLinksEachCommandNameToAgenticHelpers` and its neighbours, which run the launcher against a fake folder. The launcher was not run by hand: the shell guard on this machine refuses it.
- **Size (criterion 4):** with three names folded, amd64 stayed over the 30 MB budget (darwin 32.4 MiB, linux 31.8 MiB), which led to the scratch fold. With all four folded and `-trimpath` on every build, an unpacked release is 27.64 MB on darwin amd64, 25.40 MB on darwin arm64, 27.15 MB on linux amd64 and 24.91 MB on linux arm64 (50 MiB for 2.25.1), and the archives 10.2 to 11.5 MB (21 to 23 MB before).
- **Startup:** the three hook programs keep their package-init time (shell-guard 0.43 ms, gate 0.68 ms); `agentic-helpers bound` went from about 0.75 to 1.28 ms and `agentic-scratch start` from 0.51 to 1.28 ms, within the 2 ms and 0.8 ms the decisions accepted.

Deviation: memory's detached `landed-round` starts through the `agentic-memory` link beside the program (`namedPath`), because Linux resolves a program's own path through the link and would start it as `agentic-helpers`.
