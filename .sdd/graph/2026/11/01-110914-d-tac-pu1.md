agentic-memory detects commits that may settle a seat's live todos, todo items and traps, keeps each match until it has been delivered, and delivers it hidden at the next occasion, never through a Stop hold. This answers 20261101-110128-s-tac-f8f: a seat must always know when its work has already landed.

**Git scan.** The `agentic-memory` hooks scan the checkout's history regularly: at `UserPromptSubmit` and `PostToolUse`, at most once per interval set by a new plugin option `landed_scan_interval`, and at once after a Bash call that ran `git merge`, `git commit`, `git pull`, `git rebase` or `git cherry-pick`. Each scan reads commits reachable from `HEAD` since the checkout's last scan mark; the first scan reaches back to the oldest live todo's or trap's filing time. A commit matches a live todo, item or trap of a seat on this checkout's store when any one holds:
- its subject or a merge's branch names the branch of a `merged:` end, or the branch the entry's text names;
- it changes a path the entry is anchored to or names with `--about`;
- its subject is similar to the entry's or item's title and body above a threshold, through the store's embedder (an embedder outage skips this test, never the scan).

**Memorized until delivered.** Every match is stored in the store as a mapping (entry or `<todo>#<item>`, commit sha, subject, which test matched), several per entry allowed, and kept across sessions and claims. A mapping is dropped once delivered, or when its entry or item is ticked, retired or superseded.

**Delivery.** Pending mappings reach the seat's agent as hidden context: the claim brief and the post-compaction brief end the entry's line with `retire? landed: <sha> <subject>`, and a running session gets one line at its next `UserPromptSubmit` or `PostToolUse` naming each match with its `ack` or `retire` command. Delivered once per mapping, then dropped. Never Stop: Stop feedback always shows in the user's terminal (20261101-105300-s-tac-n5b), and hidden messages stay one per cause (20261027-222117-d-tac-yjy).

**`merged:` survives branch deletion.** Each probe of a `merged:<branch>` end records the branch tip while the branch exists; once the branch is gone, the end is met when the recorded tip is an ancestor of the target, and a branch never seen keeps the end armed as before.

**Filing hint.** `agentic-memory new --kind todo` with neither `--until` nor `--item` adds one reply line suggesting `--until merged:<branch>` or items splitting the work, such as build and capture.

**Skill rule.** The agent-memory skill states: a todo or trap is a lead; before presenting open work to the user, check it against the repository, and tick or retire a todo in the turn its work lands. `docs/memory/usage.md` describes scan, matches, delivery and the option.

**Rejected.** A merge-time PostToolUse line alone: todos with no branch or anchor stay stale, and the line is lost if the session ends before it is read. A brief-only check: a running session learns nothing until its next claim or compaction. A Stop hold for matches: visible to the user. Retiring matched entries automatically: a similar subject is evidence, not proof, so the agent decides.

**Accepted costs.** A git read per scan interval and after git calls; one embedder call per new commit subject; a store slot holding pending mappings; false matches on loosely worded todos, each delivered once.

**Acceptance.**
- A commit matching a live todo by branch, path or subject yields a stored mapping, kept across a session end and a new claim, until delivered.
- Several mappings for one entry, and for several entries, are kept and delivered together.
- The brief line ends `retire? landed: <sha> <subject>`; a running session gets the match once at its next prompt or tool call; no Stop output carries it.
- A delivered, ticked, retired or superseded mapping is gone from store and brief.
- `merged:<branch>` ends after the branch is deleted, when its recorded tip reached the target.
- `new --kind todo` without `--until` or `--item` prints the filing hint; with either, it does not.
- Skill and `docs/memory/usage.md` state the rule and the mechanism in the same change.
