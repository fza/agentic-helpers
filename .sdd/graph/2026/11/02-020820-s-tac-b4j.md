Shell-guard leaves unread a script a shell only parses, so `bash -n x.sh` passes whatever the script holds, in agentic-helpers commit d448f7d on `main`, not released. The script-reading work (20261031-220638-s-tac-7zg) judged the operand of every shell call as code the command runs; under `-n` nothing runs, so a script holding `eval` was refused as `cannot read the code handed to eval` for a syntax check, and an acceptance criterion naming `bash -n` could not be measured.

**Surface.** `parsesOnly` in `internal/shellwalk/scripts.go`: for `sh`, `bash`, `zsh`, `dash`, `ksh` and `mksh`, `-n` alone or grouped (`-en`, `-x -n`, `-n --`) with a literal operand skips the read. The operand still counts as run rather than written, so `bash -n x.sh && bash x.sh` reads the script for the second call instead of asking that the command wrote it.

**What keeps the read.** `+n`, which ran the script on every shell measured; `-i`, since bash's manual has an interactive shell ignore `-n`, though `bash -n -i` ran nothing when measured; the value of `-o` or `-O`; any long option; an operand built at run time, which may itself be an option; and `fish -n`, whose options differ. The rule accepts only what is known to parse and leaves the rest judged: listing the harmful options across six shells was rejected as the list that misses one. Accepted cost: `bash -n "$f"` in a loop and `bash -n -o pipefail x.sh` still ask or refuse. `bash -n -c` and `-n` on piped input are unchanged.

**Evidence.** Marker-script probes: bash, sh, zsh, dash and ksh on macOS, and bash, sh, dash and mksh in a Linux container, ran nothing under `-n` and `-en`, and ran the script under `-n +n`. `go test -race ./...` and `go vet ./...` pass. Each kept condition was broken and caught by its own case in `TestAScriptAShellOnlyParsesIsNotJudged`, and restored byte-identically; separate `-o`, `-O` checks could not fail, since the value word already ends the rule, so they were removed. On the installed binary `bash -n` of a script holding `eval` passes. `docs/shell-guard/usage.md`, `docs/shell-guard/architecture.md` and the agent-shell-guard skill state the rule.

**Left open.** An unknown long option takes the next word as its value in `scriptOperand`, so `zsh --exec x.sh` names no script and goes unread, with or without `-n`.
