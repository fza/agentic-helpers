Shell-guard now reads the script behind a shell's long option, so `zsh --exec x.sh` is judged, in agentic-helpers commit f8e91d1 on `main`, pushed, not released. It takes up the item 20261102-020820-s-tac-b4j left open: `scriptOperand` and `namesScript` took the word after any long option outside a list of flags as that option's value, so the script went unread whenever the option was missing from the list. zsh sets every option it has by name, which no list of flags keeps up with.

**Surface.** `longValues` in `internal/shellwalk/shellwalk.go` holds, per shell, the long options taking the next word: `--rcfile` and `--init-file` on `bash` and `sh`, `--emulate` on `zsh`, and fish's `--debug`, `--debug-output`, `--features`, `--profile` and `--profile-startup`. Any other long option takes none, and `longFlags` is gone. The table is per shell because `bash --debug` is a flag where `fish --debug` takes a value. `longOption` also reads zsh's `+-name` spelling, which the short-option branch took for flags, so `zsh +-sh-word-split x.sh` read an `s` as `-s` and left the script unread.

**Behaviour change.** `echo 'rm x' | bash --dump-po-strings x` now asks about the missing script instead of being denied as piped code: bash's manual gives that option no value, so `x` is the script and the pipe is not what runs. The test case pinning the old verdict was changed to match. A long option a shell rejects runs nothing, so the word after it is read for no gain.

**Evidence.** The value lists come from the bash and zsh manuals and fish's documentation; marker-script probes of long options were not run here. dash's, ksh's and mksh's long options were not established, so those shells list none. The ten long-option cases that failed against the unchanged code pass, every entry of `longValues` and each branch was broken and caught, and the installed binary asks about `zsh --exec` of a script naming a path outside the project. `docs/shell-guard/architecture.md` and `docs/shell-guard/usage.md` state the rule.

**Left open.** bash's and zsh's manuals have a lone `-` end the options, so `zsh - x.sh` runs `x.sh`, while `scriptOperand` reads `-` as standard input and leaves the script unread. This reading comes from the manuals and was not measured.
