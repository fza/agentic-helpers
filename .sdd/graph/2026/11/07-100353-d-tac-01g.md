agentic-helpers gains two verbs of its own binary, `agentic-helpers export <file>` and `agentic-helpers uninstall`, so the user owns their data: everything agentic-helpers keeps can be read, kept and moved as one documented archive, and a machine can be left with nothing agentic-helpers wrote except traces it cannot prove its own.

## Export

- **One archive for the machine:** a single `tar.gz` holding every store of the home, not a file per store or shelf.
- **Format:** `agent-memory-export`, version 1, a neutral id tied to no product, so any tool may produce or import it; `manifest.json` carries `format`, `version`, `exported` and `producer`. Its spec, `docs/export/format.md`, is public and the single source of truth; a change to the format is a new version.
- **Entries as records:** each memory entry of any status (live, retired, superseded), carrying every field the store keeps, plus an `events` array with the times of its later changes (item ticks, supersedes, confirms), so an importer rebuilds it as close to the original as the log allows.
- **Reach:** memory entries, seats with their last claim, shelves, state ledger lines, seat slices (`slices/<seat id>.txt`), attachments once each by sha256, the tool library with every version, its files, history, takes and merges, each store's identity, purged entry names and topic merges, and unclaimed stores flagged as such. Not the cache (vectors, heat, the folded log, session slots), which is rebuilt at will, nor machine state (update check, prune marks, session records), which matters to this install only.
- **Safety:** read only under the readers' locks; a store whose format the release cannot read refuses the whole export rather than writing a partial archive; the archive is written atomically and read back whole before the command reports success.

## Uninstall

- **Export first, always:** to `~/agentic-helpers-export-<UTC stamp>.tar.gz` or `--export-to <file>`, verified as it reads back; any failure stops the uninstall before anything is deleted. `--discard-data` skips the export after a warning that memory, tools and attachments are deleted with none kept.
- **Removes only what it can prove its own:** the cache root, the data root (`AGENTIC_HELPERS_HOME`, else `$XDG_DATA_HOME/agentic-helpers`, else `~/.local/share/agentic-helpers`), the old `~/.claude/agentic-helpers` layout, and the plugin data folder; then `claude plugin uninstall` and `claude plugin marketplace remove`, printing either command for the user where it cannot run.
- **Lists, never removes, shared traces:** the global git excludes lines `.tmp/` and `**/.claude/settings.local.json`, each known checkout's `.tmp/`, and `autoMemoryEnabled: false` in its `.claude/settings.local.json`, each with the command to remove it by hand. None carries a mark of who wrote it, and other tools write the same.
- `--dry-run` changes nothing; there is no interactive prompt, since agents run the command and the flags are the consent.

## Rejected

- **Uninstall without export:** a user would lose memory and tools, the opposite of data ownership. **Export only:** leftovers keep the machine from ending clean. **Uninstall now, export later:** anyone uninstalling first loses their data.
- **A shell script or a docs page instead of verbs:** a script is hard to test and asks users to pipe a download into a shell; a page gets steps missed.
- **The raw event log as the archive:** an importer would have to replay this release's event meanings. **A copy of the store folders:** binary files a person cannot read and a layout an importer must know.
- **Memory only:** tools and slices would be lost on uninstall. **The cache too:** a far larger archive, and vectors useless under any other embedding model.
- **A format named after agentic-helpers:** any other producer's archives would carry this product's name. **The spec kept elsewhere and restated here:** two copies drift.
- **Refusing to uninstall without a recent export:** a marker goes stale between check and delete. **A warning only:** a hurried confirmation loses everything.
- **Removing the shared traces, or asking per trace:** the first may delete a line or scratch files the user or another tool wrote; the second asks many questions an agent then answers itself.

## Accepted costs

- New code and tests in a repository otherwise taking fixes.
- The memory log folds an entry's changes older than 14 days into the entry's first record, so the archive carries the separate events of the last 14 days only.
- An uninstall takes as long as an export and leaves an archive the user may not want.
- Shared traces stay unless the user removes them.

## Acceptance

1. An export of a home holding every kind of record reads back with every entry, event, seat, shelf, state line, slice, attachment and tool version the spec names; an empty home exports a valid archive.
2. An unreadable store, a missing attachment or an existing target without `--force` produces no archive and exit 1.
3. An uninstall whose export fails deletes nothing; a full run leaves no data root, cache root, old layout or plugin data folder, and changes no shared trace.
4. `--dry-run` changes nothing; no removal follows a link planted inside a root.
5. Every new guard is covered by a test that fails when the guard is broken.
