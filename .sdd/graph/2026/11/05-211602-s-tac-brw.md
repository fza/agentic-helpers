`agentic-memory`'s capture notice now counts a graph entry arriving in any year or month folder as a capture, whether the session wrote it or a `git pull`, `merge` or `checkout` brought it in, built in commit 71a689bf on branch `v2` (`feat: count graph entries arriving in any month folder as captures, folding a burst`), not yet released. It closes the decision 20261104-211234-d-tac-gq6, every acceptance criterion holding.

Each call stats the graph root and every year and month folder and lists a folder only when its stamp moved, keeping per session the slots `graph-mark/<session>` and `graph-folders/<session>` and sharing the append-only table `graph-table/<yyyy>/<mm>`. Each arriving entry counts once, and a checkout of an older ref and back gains nothing. Past three gains the notice names three ids, decisions first and newest first, and folds the rest into a `+<n> more gained` line naming `agentic-memory show state --with-history`, a fold the decision did not ask for that keeps a pull of many entries to one line.

Acceptance: tests drive an entry arriving in the current month, an earlier month, a month folder new to its year and a year folder new to the graph, a pull renaming one entry and adding another, and a checkout of an older ref and back; `BenchmarkCaptureNoticeOnGraphs` measures the per-call check on the repository's graph and on a synthetic graph spanning many months, an unchanged graph listing no folder; `docs/memory/` and the agent-memory skill describe the widened notice. The decision's accepted cost holds: another person's pulled capture ends this seat's `--until captured` lines and prompts links.
