Shell-guard's unattended-session marker is built in agentic-helpers commit f14c199 on `main`, not yet released, closing 20261101-175128-d-tac-u9l: with `AGENTIC_HELPERS_UNATTENDED=1` in its environment, `agentic-shell-guard` answers every ask as a deny carrying the guard's reason, whatever the permission mode. A table-driven test covers the value `1`, another value and none in `auto`, `default` and `bypassPermissions`; breaking the mode check and the value check each turned it red. A headless `claude --permission-mode auto` run of the `~/go/bin` build with the variable set got `PreToolUse:Bash hook error: agentic-shell-guard: find -delete`, the hook's own deny, while a run without it got the ask's reason through Claude Code's handling of the ask, confirming the variable reaches the hook from the session's process. `docs/shell-guard/usage.md`, `docs/shell-guard/architecture.md` and the agent-shell-guard skill name the variable and the deny it causes.
