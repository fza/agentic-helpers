agentic-memory refuses to hold a seat when no Claude Code process is among the caller's ancestors, instead of recording a holder that already reads as gone: a direct claim refuses and names what it found, and a reservation takeover or a subagent hold writes nothing.

- **Claim** (`claim` in `source/hooks/internal/memory/seats.go`): with no Claude Code ancestor, it refuses before writing any seat file, with the text `no Claude Code process above this call (nearest: <name> <pid>, ...); a seat needs one to hold it`. The list names the nearest three processes the ancestor walk passed, nearest first, each by its kernel name and pid, so an unrecognised install shows under the name it runs as. A launcher's `claim <seat> --session <id>` (`claimFor`), which runs outside Claude Code and records no process of its own, is unchanged.
- **Takeover** (`adopt` in `source/hooks/internal/memory/claimfor.go`): with no Claude Code ancestor, the session's first hook leaves the reservation untouched and prints nothing, since a hidden hook message fires only when it changes what the agent does next (20261027-222117-d-tac-yjy), and the direct claim that follows names the failure itself. The reservation frees on its own timeout, and a direct claim in that session meets the refusal above.
- **Subagent hold** (`holdForSubagent` in `source/hooks/internal/memory/subagents.go`): with no Claude Code ancestor, no subagent seat is minted.
- **`seat.Holder`** no longer falls back to the caller's parent: it reports that no owner was found, and each of the three callers above acts on that. `seat.Owner`, which callers use only to compare or key on a pid (`seat.Of`, release, session end, agentic-tools' seen slot), keeps its parent fallback, so none of them changes.
- The refusal text joins the 'Seats, in detail' list in `plugin/skills/agent-memory/reference.md`, and `docs/memory/architecture.md` and `docs/memory/usage.md` say a claim needs a Claude Code process above it.

This answers 20261111-203204-s-tac-3uu, which stays open until the refusal is built: no path records a holder that cannot hold, and the one path that answers the agent names the recognition failure at claim time, instead of leaving the agent to meet the `claim a seat first` refusal on its next call.

Rejected: a claim that succeeds with a warning line (the seat file is written already free, so `who` and the next call contradict the claim's own answer); recording the nearest process under its own name as the holder (through the `memory` MCP server that process is Claude Code and the seat would hold, but through the `agentic-memory` command it is the Bash tool's shell, which exits at once, and either way the recognition failure stays hidden).

Accepted cost: under a Claude Code install the owner recognition does not know, memory refuses every claim until that install is recognised. Such a session could hold no seat before either, only without being told.

Acceptance:
- A claim with no Claude Code ancestor refuses with the text above, naming up to three ancestor processes, and writes no seat file; `who` is unchanged.
- A reservation taken over with no Claude Code ancestor stays a reservation.
- A subagent hold with no Claude Code ancestor mints no seat.
- A claim under each recognised install (`claude`, a version-named binary, `node` running the npm package, the npm package's `claude.exe`) holds as before.
- The refusal text appears in `plugin/skills/agent-memory/reference.md`.
