Subagents keep later `agentic-helpers: <level>` lines for their own spawns, each subagent gets its own shown set with a fork's copied from its spawner, and `agentic-memory pre-tool` answers a Bash call without a memory call before locating the store, in agentic-helpers commits 6cea28f, d4e474f and 3a70dd4 on `main`, not yet released. It closes the marker directive (20261031-235507-d-tac-jr4), the shown-set directive (20261031-235540-d-tac-wxh) and the early-exit directive (20261031-235624-d-tac-clm).

**Live proof** in a headless `claude -p` loading the built plugin with an isolated data home: the parent showed an entry, then spawned a fork and a fresh subagent at `silent`, each running `show` once; the fork got `(seen)`, the fresh one the full body. Before the early exit, 10 runs of `agentic-memory pre-tool` on an `ls -la` payload took a median of about 21 ms against `agentic-shell-guard`'s 7 ms; after it, 7 ms against 7 ms.

Every new guard was broken, caught by its own test and restored byte-identically. `docs/memory/usage.md`, `docs/memory/architecture.md`, the agent-memory skill and its `subagents.md` describe it.

**How a fork is told.** The hook payload carries no spawn id, so the `Agent` call with `subagent_type` `fork` stores the spawner's shown set and level in a slot keyed by its tool call id, and the fork's first hook finds that id in `agent-<id>.meta.json`, which Claude Code writes beside the subagent's transcript. That file is observed, not documented; `docs/memory/usage.md` names the cost.

**Found and fixed in the work.** A foreground fork never got its level: its transcript opens with a fork-context record rather than its prompt, so every memory call from a fork was refused at `none`.

**Beyond the directive.** A subagent's memory call nested in `bash -c` or similar is refused at `silent` and up, reads included, since only a direct call carries the agent id. Three refusals were reworded for every subagent reading memory, and the docs, skill, plugin README and `hooks.json` description quote the new wording.

**Left open.** A subagent's trap and note notices from the PostToolUse hook still mark the session's set. The MCP call-id join for `full` stays as a fallback beside the `agent` key. In the live run the fork's set remained after it ended, so whether `SubagentStop` fires for a fork is unconfirmed; session end removes it. The `agent` key, which the hook sets on a subagent's memory MCP tool calls, adds about 70 bytes to each listed memory tool schema.
