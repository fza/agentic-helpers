agentic-memory's slot file, `sessions.slots`, grew to gigabytes in stores that run many sessions or seats, holding keys nothing reads again.

Expected: the binary-formats decision (20261029-024635-d-tac-i5f) has a slot reclaimed by clearing its key and reused, so the file holds the state of live sessions and seats and no more.

Actual: the file cleared a session's keys only where its SessionEnd ran, or once a week had passed without a write, and never cleared the keys of a seat once the seat registry dropped it, as the purge of a closed temporary shelf does. A store running a temporary seat per job kept every job's seat keys. The file doubled its pairs whenever it ran out of free ones and never shrank, so the bound of its header's count times the width held while the count only grew. One store measured 16,216 keys in an 8 GiB file at 128 KiB per slot.

Cost: on APFS a written slot spends about its whole span on disk, so the dead keys cost real space, and every reclaim pass walks pairs that hold nothing live.
