A new plugin option `shell_guard_extra_roots` names, per project, the directories outside it that shell-guard treats like the project itself: a removal, an `mv` or `git mv` source, or a removal inside a script that targets a path under such a root gets the verdict a path inside the project gets, instead of the `outside project: <path>` ask. Agents in one project write and clean up files in another (an agent working in the `format-d-fdbox` project removing its spent draft `~/Codepot/sources/sdd-autopilot-python/.tmp/drafts/row-pass-reads.md`), and each such removal costs a confirmation today.

**Shape.** Comma-separated entries `<project>=<root>[;<root>]`: `<project>` is the checkout root shell-guard already resolves for the session, `<root>` a directory; both absolute or starting with `~`. A path is under a root when it is the root or lies below it, after the same cleaning and link resolution a project path gets. Only the session whose project matches an entry gains its roots; every other project keeps asking. An entry that does not parse, or names a relative path, is ignored and named by `agentic-helpers check` at session start.

**Where it is set.** The `/plugin` dialog, `pluginConfigs` in the user settings, or managed settings. `config.yaml` may only tighten a guard (20261029-145943-d-tac-gp7), and this option only loosens, so a `config.yaml` value for it is ignored and named by `agentic-helpers check`, and, like `shell_guard_secret_output_skip`, it is never read from the `CLAUDE_PLUGIN_OPTION_<KEY>` environment, which an agent could set by prefixing its own command.

**Rejected.** One machine-wide list of roots: a root opened for one project would be open from every project, including ones whose agents have no business there. Accepting both a machine-wide and a per-project form in one field: two syntaxes in one value to document and test, for a case the per-project form already covers with one entry per project. Patterns in roots: a pattern opens more than the owner wrote down; a directory is what the case needs.

**Accepted costs.** Each project pair is its own entry to keep. The option is machine-wide state naming project paths, so moving a checkout means editing it.

**Acceptance.**
- With `~/Codepot/devops/format-d-fdbox=~/Codepot/sources/sdd-autopilot-python/.tmp` set, `rm ~/Codepot/sources/sdd-autopilot-python/.tmp/drafts/x.md` from the fdbox project passes; the same command from another project asks `outside project`.
- A path outside every root, or reached through a link out of the root, still asks.
- A `config.yaml` value or a `CLAUDE_PLUGIN_OPTION_SHELL_GUARD_EXTRA_ROOTS` prefix on a command changes nothing, the former named at session start; a malformed entry is ignored and named.
- `docs/shell-guard/usage.md`, `docs/plugin/usage.md` (the option table) and the agent-shell-guard skill state it.
