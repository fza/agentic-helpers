The grounding gate's collapse of repeated sdd output runs for a session only where `sdd config get sessions.token_saving` prints exactly `off` at that session's start, compaction, `/clear` or resume, so sdd's own served-once stubbing under `on` and the gate's `PostToolUse` collapse hook never rewrite one answer twice; it is built in agentic-helpers commit 8728000 on `main`, not yet released.

Why: the collapse built under 20261101-175343-s-tac-n4e left sdd output alone only because an answer under `on` carries none of the structured fields it reads, an inference rather than a rule; the owner (Felix) set the rule that the collapse stays inactive unless the key is `off`, and that an sdd without the key (`no value for "sessions.token_saving"`, exit 1) counts as unsupported.

How: the `start` mode asks sdd in the graph's repository and writes `.sdd/tmp/grounding-gate/<session>.collapse-on.json` where the answer is `off`, removing it otherwise; `collapse` and `spawn` do nothing without it, since each runs on every sdd call and starts no process of its own. A key changed mid-session takes effect at the next start, compaction, `/clear` or resume. That `collapse-on.json` marker and the emptying of a session's shown set now run before the `.sdd/grounding.yaml` check, which fixes a project lifting the gate keeping its shown set across a compaction, and `Forget` no longer creates the folder merely to take its lock.

Rejected: asking sdd on every sdd call (a process per tool call); inferring the setting from the answer's shape (the inference the owner's rule replaces). Accepted cost: a mid-session change of the key waits for the next session start or compaction.

Proof: functional tests through the gate's `Main` cover `off`, `on`, an empty answer, `Off`, no sdd reader, a spawn under `on`, `on` taking effect at a resume, and the compaction reset in a project lifting the gate; each of the five new guards was broken and its test turned red, the `Forget` placement checked alone since the marker masks it. The full suite passes.
