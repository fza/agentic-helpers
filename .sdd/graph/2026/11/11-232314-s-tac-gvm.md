Shell-guard refuses a read of a file holding a credential before it runs, in agentic-helpers commit `65af258`, not yet released, and its output hook (20261027-091326-d-tac-we7) withholds such a file's lines from searches. It closes 20261111-224630-d-tac-5cl, whose every bullet it builds, with one widening named below.

**What landed.** `internal/credfile` finds credential spans in a file: a secret-named config key with a real value (the directive's extensions, env files and names; key words split at `_ - .` and camelCase; the last word or last two on its lists; references, placeholders and masks no value; a YAML block scalar spanned whole), the shared scanner's `private-key` and `age-secret-key` findings, a PuTTY key to its `Private-MAC:` line, and a credential store by name; `.p12 .pfx .jks .keystore` and `~/.gnupg/private-keys-v1.d/` by path. `agentic-shell-guard read`, wired as a `PreToolUse` hook on `Read|NotebookRead` in `plugin/hooks/hooks.json`, refuses a read whose range overlaps a span, handing back that range numbered as Read numbers it, each covered line `[withheld]`; a binary key store is refused with no copy. The Bash guard refuses a plain reader of such a file by literal path the same way, judging the whole file, refusing a config file over 8 MiB as `file too large to check`, and handing back at most 2000 lines. `agentic-shell-guard output` withholds each Grep line, and each line of a Bash command naming `grep`, `egrep` or `fgrep` in any literal word, whose `<file>:` prefix names a file whose span holds that line's text, inside the project too. `shell_guard_secret_read` (`deny`|`off`, tighten-only in `config.yaml`) and `shell_guard_secret_read_skip` (`<project>=<glob>[;<glob>]`, never from `config.yaml` or `CLAUDE_PLUGIN_OPTION_*`, ignored entries named by `agentic-helpers check`) are declared in `plugin.json` and read by `pluginconfig`.

**Widening.** A file over 8 MiB read by range is scanned over the range and 1 MiB before and after it, not only before: the private-key rule finds a key only with its end line, so a range starting inside a key whose end lies past the range found nothing with the lookback alone.

**Docs.** `docs/shell-guard/usage.md` (Credential files), `docs/shell-guard/architecture.md`, `docs/plugin/usage.md`, the README's options, the `agent-shell-guard` skill and its `output.md`.

**Verified.** Functional tests drive the read hook, the Bash guard and the output hook for every acceptance line of the directive: a `password: hunter2` YAML refused with its copy and `${DB_PASSWORD}` read as is; `token_url`, `max_tokens` and a bare `key` read as is and `client_secret`, `apiKey`, an env token and a TOML password refused; a range inside a PEM block in a YAML block scalar refused with only its own lines, clear ranges read as is; `~/.ssh/id_ed25519`, a `.pem` bundle, a `.p12` and a `.netrc` refused, a certificate-only `.crt` read as is; `cat .env` refused with its copy, `cat "$CONFIG"` (a path known only at run time) run, a reader after `cd` judged in its directory; a config file over 8 MiB refused, `tail -n 50` on a 20 MiB log run; a range of a 9 MiB file starting inside a key refused; the Grep tool, `grep -rn` and `xargs grep -n` withholding lines from a project config, `id_rsa` and `.netrc` and keeping clean lines; a skip entry passing reads and search lines as a plugin option and changing nothing in `config.yaml`; `off` passing reads, Bash readers and search lines, and `off` in `config.yaml` changing nothing. Unit tests cover the key and value rules, config types, stores, spans and the skip parser. Every new check was broken and caught by its own test, then restored byte-identically; the search pass's number stripping masks the skip and `off` checks of the search tests, so those were also broken alone. `go vet`, `go test -race ./...` on macOS, `scripts/linux-test`, `claude plugin validate` and `claude plugin test plugin` pass.
