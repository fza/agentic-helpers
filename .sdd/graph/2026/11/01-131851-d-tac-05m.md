Decides that agentic-helpers deletes a vector store nothing has read or written for `cache_retention` (90 days by default) automatically, in a once-a-day detached `agentic-helpers prune` run, so the stores an embedding-model change leaves behind stop accumulating. It adopts sdd's automatic background cache pruning decision (`github.com/networkteam/sdd` entry `20261101-131514-d-cpt-9ci`) for the one cache kind both tools share: vector data kept per embedder fingerprint, today `<cache>/tools/vectors/<fp>/` for tools and `<cache>/stores/<id>/memory/<fp12>/` for memory, laid out by the segment directives 20261027-130307-d-tac-wd3 and 20261027-132915-d-tac-cer. Neither ever deletes a store: a model change starts a new directory and the old one stays forever.

The rules taken over from sdd:

- **Use, not writes.** Every snapshot and every write of a store refreshes `used.json` in the store directory, at most once a day. A store whose newest stamp is older than the retention period is deleted. A store an older release wrote carries no stamp, and the newest modification time of its files stands in. Writes alone cannot judge use: a quiet store is read and never written.
- **Stamp per store format.** `used.json` maps the store format of the binary that used it (`vectorseg/1`) to the time; a store goes only once every format's stamp is past the retention period. The derivation rule is the directory itself, since the fingerprint names it. No process scanning: it cannot see a binary in a container or under another user, and a development build beside the installed release would block deletion for good.
- **One retention, `config.yaml` only.** `cache_retention`, a span defaulting to 90 days with a 14-day floor, joins the keys only `config.yaml` and managed settings set, because the cache is machine-wide and the lowest value of two agents would decide for both. Replaced rows inside a store need no age rule here: the segment merge already drops rows no entry or tool names. `tools_version_lifetime` stays apart, since tool versions are data, not a cache.
- **Unnoticeable.** agentic-memory's SessionStart pass and the `memory` and `tools` MCP servers' idle work only read the machine-wide stamp in `<data>/cache-prune.json`; at most once a day the first of them claims it under a lock taken without waiting and starts `agentic-helpers prune` detached. The run takes each store's `segments.lock` and `fill.lock` without waiting, skips a store another process holds, and deletes one store per lock session.
- **Fail loud, once.** Each run records its time, the stores it deleted and any error in `<data>/cache-prune.json`. After a failed run the next SessionStart prints one line naming the error and the file; no hook or command fails because of pruning.

Rejected: deleting a store at the moment its fingerprint stops matching the configured embedder, because a project may set its own embedder and another project's session still reads that store; leaving cleanup to a manual command, which nobody runs; a size cap, which deletes stores still inside the retention period and forces early re-embeds.

Accepted costs: a store nothing reads for the retention period is deleted, and its next search embeds everything again; one small write per store a day on the read path; a process that can write the cache can plant a stamp, keeping a store alive or letting it go early, which costs disk or one re-embed and never a wrong result (as the sandboxed-writer acceptance of 20261027-130307-d-tac-wd3 already holds for planted rows).

Done when tests cover the stamp refreshed at most once a day, a stale store deleted and a used one kept, a store kept while any format's stamp is fresh, the fallback to file times, a locked store skipped, the daily claim starting one run, and a failed run warned once, each guard broken and watched failing; `docs/memory/architecture.md`, `docs/tools/architecture.md` and the options listing name `cache_retention`, `used.json` and `<data>/cache-prune.json`.
