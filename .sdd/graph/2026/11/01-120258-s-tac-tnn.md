Shell-guard now resolves variables the text fixes and follows a `cd` into the script's own folder, built on `main` in commit 3e8ab1c (merged as 4b9e3469, pushed, not released) and proven on the installed binary: a script in `.tmp/proof-sg/scripts/` shaped like fdbox's `scripts/dev-setup.sh` (`cd "$(dirname "$0")/.."`, `OPENGREP_HOME=.tools/opengrep/$OPENGREP_TAG`, `rm -f` and `mv` of `$OPENGREP_HOME/...`) passed with no ask, and a variant whose fixed path leads outside the project asked. It closes the resolution directive 20261101-111421-d-tac-4ts and the gap it answered, 20261101-110215-s-tac-e89, whose removals the script's own text fixes now pass as if written out.

Every acceptance bullet has its test (`TestPathsTheTextFixesAreJudgedAsWrittenOut`, `TestTheWalkWritesOutTheVariablesTheTextFixes`, `TestACdIntoTheScriptsFolderIsFollowed`); no reason string changed; `docs/shell-guard/usage.md`, `architecture.md`, the agent-shell-guard skill, its `reference.md` and `scripts.md` describe the rules. Every new guard was broken and caught by its own test; masked pairs were broken together and alone; four guards no test could fail were removed.

Deviations:
- Stricter than the directive: every assignment of a variable anywhere in the text must qualify, not only those before the use; a use inside a function never resolves; `eval`, `source`, `trap`, `read`, `unset` and arithmetic leave every variable unresolved. A loop or function could otherwise reassign a value after the point the walk read it and let an outside removal pass.
- Wider: resolution lives in the shared `shellwalk` walk, so the grounding gate also sees resolved words; its tests pass.
- Narrower: the script-folder forms resolve only as `cd` operands.

Noticed in the doing: a literal `cd file/..` is still followed by joining the path text, which predates this change.
