The layout migration no longer leaves failure markers or the pre-home memory folder behind, fixed in agentic-helpers commits 5abbbd0 and 4ea80e6 on `main`, not yet released, closing the migration leftovers gap (20261102-225231-s-tac-g02).

In `internal/migration/migration.go`, `Run` returns before the lock once the home is settled, since `format.json` is written last and the journal removed after it, so a sandboxed call no longer fails on every run. A marker now stores the failure message the hook printed to stderr, so its cause can be read later. `ExpireMarkers`, run by `Prepare`, removes every marker in a settled home and, in an unsettled one, each marker a week old. In `sweep.go` and `fence.go`, a folder whose only entries are `.DS_Store` counts as empty: the sweep removes it, and a stub beside a `.DS_Store` is still a stub. `docs/plugin/architecture.md` says all of it.

Tests: `TestASettledHomeNeverOpensTheMigrationLock`, `TestAFailureMarkerKeepsTheLineItSaid`, `TestFailureMarkersOfAnUnsettledHomeExpireAfterAWeek`, `TestASettledHomeDropsEveryFailureMarker` in `markers_test.go` and `TestTheSweepTakesAFolderHoldingOnlyFinderFilesForEmpty` in `migration_test.go`; each new check was disabled once to see its test fail, then restored, and checks no test could fail were removed.

Live, with the built binaries, the markers on this machine are gone. `~/.claude/agentic-memory` still stands, because the sweep waits while a process of another release (2.25.0 or 2.25.1) runs; its removal is proven by the test only until those sessions end.
