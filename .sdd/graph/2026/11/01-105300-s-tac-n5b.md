Claude Code has no hidden way to keep a turn going after Stop: whatever a Stop hook sends the model, the user's terminal shows it. A Stop hook's `hookSpecificOutput.additionalContext` renders as `Stop hook feedback: <text>` under `Ran N stop hooks`, and neither the classic hook output nor a plugin's hooks module (`plugin/hooks/register.ts`) can hide that row. 20261029-024121-d-tac-wbu rests on the same premise, that Stop context always shows, when it keeps a visible Stop fallback only for the near-compaction case; this re-checks that premise with the hooks module included.

Source: Claude Code's hooks documentation and mods pages (events, api, reference) at code.claude.com, read 2026-11-01:
- Stop's only `hookSpecificOutput` field is `additionalContext`, "for non-error feedback that continues the conversation"; `suppressOutput` "has no effect"; no `isMeta`, verbose-only or hide flag is documented for Stop.
- `session.append` rewrites a row before it is stored, so the model reads the rewrite too; no display-only field exists on it.
- `MessageDisplay` replaces rendered assistant message text only; hook feedback rows are not assistant text, and hiding is not offered.
- No mods render site covers hook feedback rows.
- `prompt.submit` context is model-only but fires on a user prompt, not after Stop; `$.prompt.submit` from `turn.complete` starts a new turn rather than continuing one.

Confidence is medium because the rule that renders Stop feedback is itself not documented: the claim rests on observed rendering plus the absence of any documented hiding route, and the mods type definition for `SessionAppendMessage` (where `isMeta` and `type` are pinned) was read only in part. A Claude Code release adding a hidden Stop channel retires this fact.
