agentic-helpers' slot files move from one fixed 128 KiB width to a 512 B-twin directory with four size-class files (2, 8, 32 and 128 KiB), replacing the narrowing to 4 KiB slots, and every kind of value gets a byte cap with a trim step that guarantees it fits.

## Layout

- **Directory.** Each slot file but shell-guard's (a 4 KiB file whose values are bounded by construction, so it stays as it is) becomes one directory file of 512 B A/B twins with today's codec (generation, CRC32C, written time). A value up to about 430 B lives inline in its twin, about 93% of the keys in the largest live store.
- **Size classes.** A larger value goes to the smallest class file that holds it (2, 8, 32 or 128 KiB twins) under the same key, data written before the directory twin points at it, so a torn write leaves the older value readable.
- **Lookup by hash.** The directory places a key by its hash with linear probing, so a lookup reads one or two pairs instead of scanning every used pair (32,738 reads per missing key in the largest store today).
- **Kept from the slot file design** (20261029-024635-d-tac-i5f): a fixed handful of files per store, `pwrite` touching only its key's twin, lockless readers, the writer lock, reclaim by write age and the shrink once mostly empty, and the unchanged-write skip of commit 4db8ae3 (a value equal to the one held writes nothing while the held copy is under a day old).

## Bounds

No value passes the largest class's room, 130,785 B. Each kind of value declares a ceiling in encoded JSON bytes, never in words or runes, and a `fit` step that shrinks a value down to a minimal form that always fits. One test per kind builds its worst case and asserts it fits. A refused write is reported, never discarded with `_ =`.

- **Text is cut in bytes.** `ladder.last_prompt` is cut to the words of the `asked:` line, then to 3,500 B at a rune boundary; `ladder.Wrote` to 20 paths and 3,500 B.
- **Data growing without end is split across keys.** The graph-name month tables go into parts of 6,000 names (about 120 KB), a new part added when one fills.
- **Leftover work waits for the next round.** A landed-commit scan meeting its cap leaves the scan mark at the last commit whose mappings were stored.
- **A cache that overflows falls back to its source.** The trap index past its cap leaves a marker, and the tool hook matches against the log directly.
- **Recent-only lists drop their oldest items:** shown sets, seen, ledger-ended.

The ceiling of every kind is in the attached record, section 4.

## Why

The slot files hold 2.4 GiB on one machine, 2,307.6 MiB of it in one store holding about 45 MB of values. APFS fills any hole shorter than 16 MiB behind a write, so a sparse file costs as much as a dense one up to its highest written twin, and every key pays the full 128 KiB width. Narrowing the width to 4 KiB (20261102-225800-d-tac-nw1, superseded here) rested on every value but two staying under 1 KB, which does not hold: shown sets reach 5.8 KB, the asked line is cut by words, not bytes, `Wrote` reaches 3.6 KB, and landed mappings, subagent records, instruction records, the trap index, do-now and skipped lists have no cap at all. Today a value past its slot is refused and the refusal discarded, so a long prompt freezes the ladder and the context nudge repeats, more than about 500 pending landed mappings are lost for good, and new traps stop firing. Estimated disk for the largest store under the new layout: 60 to 80 MiB.

The [research record](./03-000615-d-tac-m0d/slot-research.md) carries the inventory of every key, the APFS probes, the exceed scenarios and the estimates.

## Rejected

- **`go.etcd.io/bbolt`:** its file lock couples readers and writers across processes, each commit needs an `fsync` or an unsafe no-sync mode, and the file never shrinks without compaction.
- **`modernc.org/sqlite`:** megabytes added to every hook binary and a slower open in hooks that live milliseconds, plus `-wal` and `-shm` side files.
- **A fixed width per kind of value:** 110 to 270 MiB, each key paying its kind's worst case, and every cap change a migration.
- **One file per session or seat:** 33 to 75 MiB, but it brings back the thousands of small files the slot file design removed.
- **Punching holes into today's layout:** about 510 MiB, macOS only, and it bounds nothing.
- **An append log:** a lookup needs an index or a full scan.

## Accepted costs

One format step per slot file through the shared runner (20261101-193020-d-tac-lh5), which locks 2.25.x sessions out of memory until their plugin reloads; owned code and tests for the directory, the class files and every `fit`.

## Acceptance

1. Every slot file but shell-guard's is a 512 B-twin directory plus 2, 8, 32 and 128 KiB class files; a value moves between inline and a class as it grows or shrinks, and a torn write at any point leaves the older value readable.
2. A lookup of a missing key reads at most the pairs of its probe run, not every used pair.
3. Every kind of value declares a byte ceiling and a `fit`; one test per kind builds its worst case and asserts it is stored; no slot write discards its error.
4. An existing store migrates through the format step keeping every key's value, proven on the release fixtures and by the kill-safety test.
5. On APFS the largest live store's slot files take under 100 MiB after migration and reclaim.
