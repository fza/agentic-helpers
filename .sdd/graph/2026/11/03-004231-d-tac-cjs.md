The daily `agentic-helpers prune` deletes release folders from the plugin's data directory (`<data>/<version>/`, where `plugin/hooks/run` unpacks each release) except those a session may still run.

- **Kept:** the version `plugin/.claude-plugin/plugin.json` names; every version a running process executes a program from (the process table, already read through sysctl on darwin and `/proc` on Linux); every version a SessionStart used within 14 days.
- **Use mark:** the launcher touches `<data>/<version>/used` at each SessionStart it runs a binary for, once per start.
- **How:** part of the existing daily detached run (20261101-134851-s-tac-zd6), under the same rules: no lock a hook waits on, a failure told once at the next SessionStart through `<data>/cache-prune.json`. Removal goes through `internal/safefs` and only touches folders named as a version (`^[0-9]+\.[0-9]+\.[0-9]+$`).

Why: the launcher unpacks every release into its own folder and never removes one, so the data directory holds 34 versions, 1.1 GB, recent releases about 50 MB each. A session still running an older plugin version runs that version's programs; without them its grounding gate and shell-guard refuse every call, so a folder is removed only once no session can need it.

Rejected:
- **Keeping the newest three:** a fixed bound of about 150 MB, but a session left running on an older version loses its programs and its guards then refuse every call.
- **Leaving them:** about 50 MB more per release, without end.

Accepted costs: up to two weeks of releases stay; one small file written per SessionStart.

Acceptance:

1. After a prune run, the data directory holds only the named version, versions a running process executes from, and versions used within 14 days, shown by a test over a tree in `t.TempDir()` with a faked process table.
2. A folder not named as a version, and any file beside the version folders, stays.
3. A SessionStart through the launcher leaves `<data>/<version>/used` with a fresh modification time.
