Shell-guard refuses a read of a file that holds a credential before the read runs, inside the project and outside it: a config file with a secret-named key holding a real value, a file whose name marks it as a credential store, or a file holding a private key. The refusal hands the agent the lines the read would have returned, each one that falls inside a credential withheld.

**Why a refusal before the read.** The output check (20261027-091326-d-tac-we7) withholds a line only where the line itself looks like a credential, and only from outside the project. A secret-named key's value carries no provider shape for the shared scanner (20261026-223236-d-tac-vr7) to know it by, the later lines of a multi-line key, read without its first line, carry neither a key name nor a marker, and a project's own `.env` is never scanned. The file, unlike a glob or a script, is known before the read, so it is judged then. This reverses three rejections the output check's directive (20261027-091326-d-tac-we7) made: refusing before the read, there rejected because a refusal sees no glob or script, now covers exactly the reads that name their file, while the output check keeps the rest; refusing beside redacting, there rejected as two mechanisms to keep consistent and a refusal where redaction lets the rest through, now holds because the refusal hands back the rest of the file withheld line by line, and the two judge different things, a file named before the read and a value in the output; and the project is no longer left out, since the withheld copy still shows the agent every line around a project credential it is asked to work on.

**What is refused.**

- **Read and NotebookRead**, through a new PreToolUse hook `agentic-shell-guard read` on `Read|NotebookRead` in `plugin/hooks/hooks.json`.
- **A plain Bash reader of a matched file through a literal path**, in the existing Bash guard (`agentic-shell-guard`, 20261025-235046-d-tac-n48): the readers and option lists the output check already trusts (`cat`, `head`, `tail`, `grep`, `sed` and the rest in `docs/shell-guard/usage.md`). A glob, a script or a variable path is not judged before the call; the value-based output check catches what it can there.
- **Grep**, which searches a tree and cannot be judged before it runs: `agentic-shell-guard output` withholds each Grep output line that comes from a config file and holds a secret-named key with a real value, as `[agentic-shell-guard: credential withheld (secret-key-name)]`, and, inside the project and outside it, each line that falls inside a private-key span of its file or comes from a credential store by name, as the refusal judges them.
- **Bash `grep` over a tree** (`-r`, `-H`, or several files), which names no file before it runs: the same per-line withholding applies to its output, inside the project and outside it, each line judged by the file its `<file>:` prefix names. Output with no file prefix (`grep -h`) cannot be judged by file and passes to the value-based output check.

**What matches.** Matching is case-insensitive; a key name is split into words at `_`, `-`, `.` and camelCase, so `apiKey`, `api-key` and `API_KEY` all read as `api key`.

- **Config files checked by key**: the extensions `.yaml`, `.yml`, `.json`, `.jsonc`, `.json5`, `.toml`, `.ini`, `.cfg`, `.conf`, `.properties`, `.tfvars`, `.xml`; `.env`, `.env.*` and `*.env`; the names `.npmrc`, `.pypirc`, `.yarnrc`, `credentials` and `.s3cfg`.
- **A secret-named key**: its last word is `password`, `passwd`, `pwd`, `pass`, `passphrase`, `secret`, `token`, `apikey`, `credential`, `credentials`, `creds`, `authorization` or `cookie`; or its last two words are `api key`, `access key`, `secret key`, `private key`, `signing key`, `encryption key`, `master key`, `auth key`, `client secret` or `session key`. A plural or a later word passes (`max_tokens`, `token_url`, `password_min_length`), and so does a bare `key`.
- **A real value**: anything but an empty value, `null`, `~`, a reference to a value kept elsewhere (`${…}`, `$NAME`, `{{…}}`, `%(…)s`, `<…>`) or a run of only `*` or `x`. So `password: ${DB_PASSWORD}` in a `docker-compose.yml` stays readable and editable.
- **Credential stores by name**, refused whole: `.netrc`, `.pgpass`, `.git-credentials`, `.htpasswd`.
- **Private keys by content**, in any file: the scanner's `private-key` rule, `-----BEGIN … PRIVATE KEY-----` through its end line (RSA, EC, DSA, OpenSSH, PKCS#8, encrypted keys, a PGP private key block, and a `.pem` or `.crt` bundling a certificate with its key), its `age-secret-key` rule (`AGE-SECRET-KEY-1`), and a PuTTY key file from its `PuTTY-User-Key-File-` line to its end.
- **Private keys by path**, refused whole with no copy, since their content is binary: `.p12`, `.pfx`, `.jks`, `.keystore`, and anything under `~/.gnupg/private-keys-v1.d/`.

**How much is read.** A credential is a span of lines, and a multi-line one, a PEM block in a YAML block scalar among them, carries its key name or marker only on its first line. So the spans are found from more than the slice a read returns:

- A file up to 8 MiB is scanned whole for spans. A Read is refused only when the range it returns overlaps a span, and its withheld copy is that range; a range clear of every span reads as it is.
- A file over 8 MiB read through a Read range is scanned over that range and the 1 MiB before it, so a span starting before the range is found from its first line.
- A Bash reader returns the whole file, so the whole file up to 8 MiB is judged. A config-type file over 8 MiB is refused, `file too large to check`, since its keys can sit anywhere. Any other file over 8 MiB is judged for private keys on its first 8 MiB and the rest passes unjudged, so `tail` or `grep` on a large log stays possible.

A path is judged once its symlinks are resolved, as the output check judges one.

**The refusal.** It names the path and what it found, then the returned lines:

    agentic-shell-guard: <path> holds a credential (<what>); reading it is refused. Its lines, those inside a credential withheld:
    <line>
    [withheld]
    ...

`<what>` names the secret-named keys found, `a private key`, or `a credential store by name`. A file refused by path carries no copy. The wording is part of shell-guard's contract, quoted by the `agent-shell-guard` skill.

**Options.**

- `shell_guard_secret_read`: `deny` or `off`, default `deny`. The shared `config.yaml` may only tighten it, as for every guard (20261029-145943-d-tac-gp7).
- `shell_guard_secret_read_skip`: paths that are never refused, as `<project>=<glob>[;<glob>]` with each glob relative to that project, the shape of `shell_guard_extra_roots` (20261101-020134-d-tac-c60). It only loosens, so it is a plugin option alone, never read from `config.yaml` or the `CLAUDE_PLUGIN_OPTION_<KEY>` environment (20261029-153231-d-tac-hor), which any agent can write or set and would unblock itself through. A skipped path's Grep lines are not withheld either. This repository's credential fixtures under `source/hooks/test/fixtures/secrets/` are stored base64-encoded as `*.b64` and decoded only in memory by `test.SecretFixtures`, so they match no pattern and need no skip entry; the list is for checkouts whose credential fixtures are kept plain.

`docs/shell-guard/usage.md` and `docs/shell-guard/architecture.md` describe the refusal, its patterns and its options; the `agent-shell-guard` skill names the refusal and what to do on it: tell the user the path, read nothing around it.

**Rejected.**

- **A bare refusal with no copy**: the agent loses the file's shape and the keys around each secret, which it needs to work on the file at all.
- **Letting the read run and withholding lines in the output only**: the file is not refused, and the line-wise check sees no key name on a multi-line secret's later lines.
- **The project left out**, as the output check leaves it: a project's own `.env` is the commonest place for a real key.
- **A pre-read check of Grep**: Grep names a tree, not a file, so its lines are judged in the output, where each names its file.
- **No skip list**: a checkout keeping plain credential fixtures, or a config file it must read whose keys look secret, could never read it.
- **Refusing every Bash reader of any file over 8 MiB**: `tail -n 50` on a large log would be refused though it returns a few lines.
- **Read alone, or Read and Bash without Grep**: `cat .env` or `grep -rn password .` shows what the Read refusal hides.
- **Every value counting, placeholders included**: most config files holding no secret turn unreadable and, through Edit, uneditable.
- **gitleaks' wide word list** (`key`, `auth`, `access`, `api` anywhere in a name): `access_log`, Kubernetes' `key:` and `author` all match.
- **Judging only the returned slice**: a slice starting inside a multi-line secret shows its body. **Refusing every read of a file holding a secret anywhere**: a clean slice of such a file is refused for nothing.
- **No size cap**: a large file runs the hook past its timeout, and a timed-out hook lets the call through unjudged.

**Accepted costs.** Claude Code's Edit needs a successful Read first, so a file whose Read is refused cannot be edited through Edit. A secret under a key the list does not name (`dsn`, `database_url`) passes, as does one read through a glob, a script or a variable path, where only the value-based output check applies. A Bash reader cannot read a config-type file over 8 MiB, and a private key past the first 8 MiB of a larger non-config file passes a Bash reader unjudged; inside the project nothing withholds it. `grep -h` output passes unjudged by file. A multi-line secret starting over 1 MiB before the range read from a file over 8 MiB is not found from its start. A path swapped by a link between the check and the read is read unjudged, a race no hook closes.

**Acceptance.**

- A Read of a `.yaml` with `password: hunter2` is refused with the wording above and the copy shows every other line; `password: ${DB_PASSWORD}` reads as is.
- `token_url:`, `max_tokens:` and a bare `key:` read as is; `client_secret:` and `apiKey:` with real values are refused.
- A Read whose range starts inside a PEM block held in a YAML block scalar is refused with every key line in the range withheld; a range clear of it reads as is.
- `~/.ssh/id_ed25519`, a `.pem` bundling a certificate with its key, and a `.p12` are refused; a `.crt` holding only a certificate reads as is.
- `cat .env` holding a real secret is refused before it runs; `cat $F` runs.
- `grep -rn password .` returns each matching config line withheld and every other line as is.
- A Bash reader of a config-type file over 8 MiB is refused as too large to check; `tail -n 50` on a 20 MiB log runs.
- A Grep tool search and a Bash `grep -rn` over the project withhold a line inside a project `id_rsa` or from a project `.netrc`.
- A path under `shell_guard_secret_read_skip` reads as is; the same entry in `config.yaml` changes nothing.
- `shell_guard_secret_read: off` lets every read through; `off` in `config.yaml` over a plugin `deny` changes nothing.
