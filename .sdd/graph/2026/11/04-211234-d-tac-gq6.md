agentic-memory's capture notice, the PostToolUse check that names graph entries a tool call added while the seat holds open `--until captured` entries, counts a graph entry that arrives by `git pull`, `merge` or `checkout` as a capture, exactly as one the session wrote, and watches every month folder of the graph instead of the current month's alone. Such an entry ends the seat's open `captured` lines and prompts the link that settles a waiting todo, as the end-conditions decision (20261026-215617-d-tac-45q) and the seat ledger's `captured` hook lines (20261101-190255-d-tac-6hl) describe for a session's own capture.

Why: the notice finds new entries by the graph directory's state, never by a capture's output, and today it stats and reads only the current month's folder (`graphMark` in `internal/memory/captures.go`). An entry captured in an earlier month, which a pull, merge or checkout brings in, lands in that month's folder and is never seen, so a todo waiting for exactly that capture stays open. Whoever wrote the entry, it is in the graph the seat works against, and that is what a `captured` end waits for.

The build is held to the owner's constraints: low token cost, accuracy, performance, CPU and disk. Watching every month must not turn the per-call stat of one folder into a read of the whole graph on every tool call, nor grow the per-session mark without bound; and the notice still fires once per cause, per the token-cost criteria (20261029-021515-d-tac-00q).

Rejected:

- Telling pulled entries apart from the session's own captures: it needs a fuller stamp of how the graph changed (which commit or ref move brought each entry) and a new hint wording agents must learn, for a distinction the `captured` end does not need.
- Leaving git-delivered entries to the grounding gate: the gate voids read credit when the graph changes, but settles no memory entry and names no todo to link.

Accepted cost: someone else's capture arriving by pull ends this seat's `--until captured` lines and prompts links, though this session captured nothing.

Acceptance:

1. An entry added to any month folder, by the session or by `git pull`, `merge` or `checkout`, triggers the notice once while the seat holds open `captured` entries, and adds a `captured` hook line; shown by tests driving each arrival.
2. A tool call that changes no month folder reads no folder's listing, and the cost of the per-call check is measured by a benchmark over a graph spanning several months.
3. `docs/memory/` and agentic-helpers:agent-memory describe the widened notice in the same change.
