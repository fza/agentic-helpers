`agentic-memory`'s `changed:<path>` end and its anchors no longer read a file they cannot open as changed or gone, fixed in commit 73a03955 on branch `v2` (`fix: changed: end fired on a file it could not read and never on a folder; anchors called it gone`), not yet released. It closes the gap 20261104-211535-s-tac-qcy, that an unreadable file retired a `changed:` entry and a folder never fired one, restoring the end as the end-conditions decision 20261026-215617-d-tac-45q defines it.

A path's content hash now gives three answers: its hash; gone, for a missing path, a folder or a file that is not regular; or no verdict, for a path that exists but cannot be read. A `changed:` end fires only on a verdict, so an unreadable file leaves the entry alone until it reads again, while a removed file, or one replaced by a folder, fires it. At filing, `--until changed:` refuses a folder (`names a folder, whose content no hash covers; take gone:<path>, or changed: on a file inside it`) and a file that cannot be read; a path that does not exist yet is still accepted. Anchors are fixed alike: an unreadable anchor raises no `gone:` flag and no `retire? every anchor gone`, the JSON reads report the anchor state `unreadable`, and `confirm` keeps the anchor and its earlier hash. An instruction file that cannot be read sends no "changed since loaded" line.
