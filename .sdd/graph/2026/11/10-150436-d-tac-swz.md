Only agentic-memory and agentic-tools serve MCP tools, as the `memory` and `tools` servers in the plugin's `.mcp.json`; every other agentic-helpers program stays a hook or a command run through Bash, and gains no MCP server.

- `agentic-scratch` (`start`, `end`) and `agentic-shell-guard` (its Bash and Monitor check, `permission`, `output`) are hooks only: nothing in them is for an agent to call. The session record, `agentic-helpers record`, and the session-end sweep, `agentic-helpers end`, are hooks too.
- `agentic-helpers` keeps `check` and the `config` commands of 20261028-212647-d-tac-cld as Bash commands; `export`, `uninstall`, `sessions --json`, `bound`, `dump`, `sweep` and `prune` are Bash commands as well. An MCP server for them would run one more idle process in every open session for commands an agent seldom calls, and would be one more server held in step with its command line. Folding its tools into the `memory` server instead would put configuration under memory's name and switch it off whenever `memory_enabled` is off, as 20261026-000502-d-tac-yrx has an off piece's MCP server list no tools.

This replaces 20261028-214433-d-tac-rw7, which still named `agentic-grounding-gate` as a hook here and kept `agentic-capture` as a command: both left agentic-helpers in v2.29.0 (20261107-114219-s-tac-eub), and the `fza/sdd` fork runs the grounding gate and capture itself. It also took its list of pieces from an overview fact that 20261110-145421-d-cpt-cvx closed; the pieces are those `docs/` describes.

This is settled: it adds nothing to build and records why the programs outside memory and tools have no MCP server, so the question is not reopened without a new reason, such as an agent that runs no Bash.

**Rejected.** An `agentic-helpers` MCP server with `check` and `config` tools; those tools inside the `memory` server.

**Accepted costs.** An agent changing a setting for the user runs `agentic-helpers config set` through Bash.
