Prompt vectors, the tool library's per-store session file and its shared seen file drop a key no write touched for a week, and shrink once mostly empty, as memory's slot file and shell-guard's permission-countdown file (`internal/shellguard/permission.go`, `staleState` of 7 days) already do.

- **Files:** `prompt-vectors/sessions.slots` (`internal/promptvector`), `stores/<id>/tools/sessions.slots` (`internal/tools/session.go`) and the shared `tools/sessions.slots` (`internal/tools/seen.go`).
- **Rule:** the reclaim memory runs (20261102-225603-s-tac-inq): `slots.Reclaim` drops every key whose newest twin was written 7 days ago or more, and writes the file anew at the size its kept keys need once a quarter of its pairs or fewer stay in use. Each file runs it at its first SessionStart of the day, under its writer lock.
- **Kept:** the removal at a clean session end (`promptvector.Remove`, `forgetSession`, `forgetSeen`) stays.

Why: those three files clear a key only when its session ends cleanly. A session that crashes or is killed leaves its key for good, so the files grow without bound. Under the size-class layout (20261103-000615-d-tac-m0d) a leftover prompt vector holds a 128 KiB-class box.

Rejected:
- **One day for prompt vectors, a week for the rest:** frees the largest boxes sooner, but adds a second constant, and a resumed session re-embeds its last prompt.
- **Leaving them:** every crashed session's keys stay forever.

Accepted cost: a session idle for over a week loses its tools seen set and cached prompt vector, both rebuilt at the next call.

Acceptance:

1. In each of the three files, a key last written over 7 days ago is gone after the next reclaim, and a key written within 7 days stays, shown by one test per file.
2. A file left a quarter full or less after a reclaim shrinks to the size its kept keys need.
3. A clean session end still clears its keys at once.
