The grounding gate and `agentic-capture` leave agentic-helpers for the public sdd-helpers plugin (`fza/sdd-helpers`), where they ship as `sdd-grounding-gate` and `sdd-capture`; agentic-helpers removes both and names the new plugin at session start in projects keeping an sdd graph. Both programs work around gaps of stock sdd that upstream sdd is expected to absorb, and a repository of their own keeps those fixes apart from the hooks for memory, tools, scratch and shell-guard, ready to hand upstream.

## What changes in agentic-helpers

- **Removed:** `source/hooks/cmd/agentic-grounding-gate`, `internal/grounding`, `internal/capture`, and `internal/collapse` and `internal/draftlint`, which only they used; the `agentic-capture` name of the `agentic-helpers` binary and `plugin/bin/agentic-capture`; their entries in `plugin/hooks/hooks.json`; the plugin options `grounding_gate_enabled`, `capture_enabled` and `capture_remove_draft`; the skills `agent-capture` and `agent-grounding`; `docs/grounding-gate/` and `docs/capture/`. `internal/sddcaps` and `internal/graphconfig` keep only what memory reads.
- **Kept:** neutralizing a filed text that opens with `GROUNDING GATE:` in hook context (`internal/hookio`), since sdd-helpers' gate runs in the same sessions and a filed line can still impersonate it.
- **Notice:** `agentic-helpers check` at SessionStart prints `agentic-helpers: the grounding gate and agentic-capture moved to the sdd-helpers plugin: claude plugin marketplace add fza/sdd-helpers, then claude plugin install sdd-helpers@sdd-helpers`, only where the project directory carries `.sdd/` and `~/.claude/plugins/installed_plugins.json` (under `CLAUDE_CONFIG_DIR` where set) holds no key starting `sdd-helpers@`; a missing or unparsable file counts as not installed. `README.md`, `plugin/README.md` and `docs/plugin/usage.md` carry a "Moved to sdd-helpers" section with the same steps.
- **Graph:** this graph declares `github.com/fza/sdd-helpers` as a dependency, and sdd-helpers' graph declares this one, so each cites the other's entries. The entries on the gate and capture stay here and keep explaining why both work as they do.
- **Order:** the agentic-helpers release carrying the removal is cut only once sdd-helpers v1.0.0 is published, so the notice never names a plugin users cannot install.

## Rejected

- **README and release notes only:** the plugin updates itself, so most users never read either and find the gate gone without a word.
- **A session-start line in every project with a graph:** users who already installed sdd-helpers would read it at every session start, with no way to turn it off.
- **Keeping both programs here until upstream sdd absorbs them:** the sdd fixes would stay tangled with hooks that have nothing to do with sdd.

## Accepted costs

- The check reads Claude Code's `installed_plugins.json`, which is no stable API; a change to its shape shows the line to users who have the plugin.
- Any `sdd-helpers@<marketplace>` key suppresses the line, whatever its install scope, so a project-scope install made in another project hides it too.
- A plugin `config.yaml` still setting one of the dropped options gets the generic line that the key is no option.
- Users install and update a second plugin.

## Acceptance

1. agentic-helpers' tree holds no program, skill, hook or plugin option of the grounding gate or `agentic-capture`; `go vet ./...` and `go test -race ./...` pass.
2. The notice shows in a project with `.sdd/` while no `sdd-helpers@` key is installed, and nowhere else; each of its conditions is covered by a test that fails when the condition is broken.
3. The release carrying the removal is published after sdd-helpers v1.0.0.
