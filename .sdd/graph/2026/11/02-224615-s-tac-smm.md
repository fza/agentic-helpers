The `memory` and `tools` MCP servers now take one value or an array for every list key, built in agentic-helpers commit 1ed8405 on `main`, not yet released, closing the one-or-array directive (20261102-224531-d-tac-8lh).

`internal/mcpserver/lists.go` rewrites each top-level array property of a tool's input schema to `anyOf` its item and the array when the server starts, records which keys it widened, and wraps a lone value for one of them into a one-item array before the tool runs. A schema carrying array keywords it cannot carry over to the `anyOf` refuses the server's start. The key descriptions in `internal/memory/commands.go` and `internal/tools/commands.go`, the agent-memory skill and its reference, and `docs/memory/usage.md` drop "array even for one" and say a list key takes one quoted string or an array.

Acceptance: items 1 and 2 hold, by `TestAListKeyIsListedAsOneValueOrAnArray`, `TestOneValueForAListKeyReachesTheToolAsAOneItemArray` and `TestAToolWithAnUnreadableSchemaShapeIsRefused` in `internal/mcpserver/lists_test.go`, and each check in the new code was disabled once to see its test fail, then restored. Item 3, the rescan of transcripts written after the release, stays open until a release carries the change.
