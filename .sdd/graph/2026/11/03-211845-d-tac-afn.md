An agentic-memory todo filed without items becomes a note plus an open line on the filing seat's state ledger: `new --kind todo` with no `--item` (MCP `new` with `kind` `todo` and no `item`), and no item that `--items carry` moves onto it, files a `note` keeping the title, body, topics, links and anchors, and adds the line `<title> (<id>)` carrying the todo's `--until` ends (`until`, `until_hashes`, `until_hold`), its session and its `--due` time, which the note no longer holds. A todo is a todolist (20261028-223759-d-tac-jkj); a single open task is where the seat's work stands, which is what the ledger (20261101-190255-d-tac-6hl) holds, so it belongs there rather than in the todos section.

Surfaces:

- **Filing.** `new` writes the `note` row and, in the same append, an `item` row on the seat's ledger built by `todoLine` (`internal/memory/todolines.go`). The line cites the note, so it also ends once the note is retired or superseded. The reply says so in its opening line: `filed <id> (<name>) as a note and added state#<item>: a todo without items is a state line`, with the line's ends and due time.
- **A due time on a state line.** `ack state --add '<line>' --due <time>` (MCP `ack` key `due`) takes the forms `new --due` takes (20261029-200931-d-tac-8h5) and is refused anywhere else: `--due sets when the lines ack state --add adds come due; a todo's items and rules take none`. The row payload gains `due`. A line due more than a day ahead is held back in the brief's state section into one count, `(<n> due later, next <time>: agentic-memory show state)`; within a day or past it the line stands whole with `due in 3h` or `due 2h ago`, is told once in the `due for <seat>` notice as `state#<item>: <text>  due <age> ago`, and is keyed in the seen mark as `state#<id>@<RFC 3339 due>`. No command moves a line's due time: remove the line and add it again.
- **Store format 11.** The step from format 10 (`lineSteps`, run from `formatSteps` in `internal/memory/migrate.go`) folds the store and, for every live todo whose items are none or all removed, appends an `item` row adding its line, then a `rekind` row to `note` whose `line` names that line, which clears the entry's ends and due time; both rows go in one write. A run cut between the two finds the line by its text and appends the rekind alone, and a run after it finds no todo left. No backup is taken, since no row is rewritten; a rekind back restores the kind, the line keeping the ends. The format keeps a format-10 binary off the store, which would file item-less todos again and drop a line's `due` unread.
- The `no end declared` reply line for a todo filed with neither `--until` nor `--item` goes, with the hints that named `--until merged:<branch>` and `--item build --item capture`.

Rejected:

- Rewriting the log with the todo's `new` row changed to a note: it loses the entry's history of being a todo and needs a backup of the whole log.
- A new event kind for the change: the existing `item` and `rekind` rows already say it, and a new kind is one more row every reader and binary must learn.
- Refusing a todo without items: a retry for the filer for a choice the tool can make itself.
- Keeping it a todo: it leaves a single task in the todos section while the ledger is where the seat's work stands.
- Leaving the ends on the note as well: the note and the line would end separately.

Accepted costs: a store format step that a format-10 binary cannot follow; filing `--kind todo` now answers with a different kind than asked, named in the reply; a state line gains a due field, and its due time cannot be moved in place.

Settled: built on `main` (commits e21655b9 and d4240925), described in `docs/memory/usage.md` and `docs/memory/architecture.md` and the agentic-helpers:agent-memory skill; nothing follows from this entry.
