A checkout moved on a volume without a UUID now replaces the paths its store recorded instead of being added beside them, fixed in agentic-helpers commit bccf9b2 on `main`, not yet released, closing the gap on duplicate checkout entries (20261102-230119-s-tac-lyy).

`admit` in `internal/home/resolve.go` replaces every admitted checkout with the moved one when no entry matches by git common directory or by volume and inode, the checkout's pointer names the store, and no admitted checkout still exists on disk. `noneOnDisk`, shared with `confirms`, makes that last check. `docs/plugin/architecture.md` says so.

Rejected: making `scripts/linux-test` put the test's temp folder on a disk with a UUID (dead paths would keep piling up on such disks, and the container would stop testing the case); accepting the one failing test (a local Linux run that is never green hides a new failure). Accepted cost: a checkout on an unplugged external drive loses its recorded path once a moved copy of it is seen elsewhere; its pointer still finds the store.

Tests: `TestACheckoutMovedWithoutAVolumeIdentityReplacesThePathsItLeft` in `internal/home/admit_internal_test.go` covers all paths gone, one path still on disk, and a pointer naming another store. `scripts/linux-test` and the macOS suite both pass in full, `TestAWorktreeAndAMovedCheckoutKeepTheStore` included.
