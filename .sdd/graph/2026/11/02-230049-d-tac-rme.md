agentic-helpers is developed on macOS, and Linux support is tested locally before a push with `scripts/linux-test`, which runs `go vet` and `go test -race` for every Go suite in a Linux container of Apple's `container` tool, beside the ubuntu job CI runs on every push.

The script mounts the whole checkout, since tests read the plugin, the skills and the docs beside `source/hooks`; runs the suites as the calling user, since as root every test of a permission refusal passes through it; keeps Go's module and build caches in `.tmp/linux-test/`; and checks the service with `container list`, since `container system status` can report a running service as down. Its arguments go to `go test` (`./...` when it gets none). The README's Testing section shows how to start the service; AGENTS.md lists the command beside the other suites.

Why: Linux and macOS differ where the hooks care, as in what a sparse file costs on disk (a small write into agentic-memory's sparse slot file costs one 4 KiB block on Linux, about 242 KiB on APFS), and CI alone reports a Linux defect only after a push.

Settled: built in commit c35fed0, so nothing follows from this decision.

Rejected: Docker or OrbStack (a second container runtime beside the one Apple ships, and the script's checks would need both); CI only (a Linux failure surfaces after the push, never before).
