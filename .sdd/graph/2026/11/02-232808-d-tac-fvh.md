title: Human-readable entry names in `agentic-memory`
summary: 'agentic-memory entries get short title-derived names (like `apfs-span`) that users and agents use instead of random ids such as `m-6fxex1`; ids stay the stored identity and names are aliases in a new name index built by a format step. Agents show numbered lists and names to users, never ids, per the agent-memory skill and `docs/memory/usage.md`. Rejected alternatives: random two-word names and list numbers alone, which do not survive across listings.'
---

Users never see agentic-memory's entry ids (`m-6fxex1`). Agents show entries as numbered lists, and every entry gets a short name built from words of its title, such as `apfs-span`, which memory accepts wherever it takes an id: CLI arguments, MCP keys, links and `--until` ends.

- **Name:** two or three lowercase content words of the title, joined by dashes, stop words left out; where the name is taken in the store, a short suffix keeps it unique (`apfs-span-2`). The name stays when the title changes, so a name a user once said keeps working.
- **Numbers:** a listing an agent shows a user is numbered; a number refers to that listing only, so an agent maps it back before acting.
- **Ids stay the stored identity**; the name is an alias kept in a name index in the store, which a format step through the shared migration runner builds for existing entries.
- **The agent-memory skill** tells agents to show names and numbers to users and never ids, and every reply that names an entry gives its name beside the id.

Why: ids are random letters nobody can read, say or remember, so a user cannot point at an entry without copying one. A name from the title is easy to say, stays tied to what the entry is about, and survives across listings, unlike a list number.

Accepted cost: a name index in the store, a format step with its fixtures, and a suffix where two names would clash.

Rejected: a random two-word name per entry, such as `amber-otter` (same index and step, but the name says nothing about the entry and is easy to mix up); numbers alone (no index, but a number changes from one listing to the next, so it works only within one reply).

Acceptance:

1. Every live and newly filed entry has a unique name, and every command and MCP key taking an id takes the name too.
2. A retitled entry keeps its name.
3. The format step names every existing entry, proven on the release fixtures and by the kill-safety test.
4. The agent-memory skill and `docs/memory/usage.md` describe names and numbered listings.
