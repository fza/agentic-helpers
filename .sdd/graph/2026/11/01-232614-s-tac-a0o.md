Parallel sdd MCP calls collapse correctly with commit ef62c33: of three `mcp__sdd__view` calls sent in one batch for an entry not yet shown, one printed in full and two answered as pointers. This settles the case 20261101-231520-s-tac-vz5 left unchecked. Both calls of the earlier batch printing in full was that record's defect, not a concurrency fault.

**Test.** Commit e7b8813 adds `TestParallelCallsPrintAnEntryOnce`, which runs concurrent `Store.Collapse` calls and expects only the first to print in full. The file lock serializing each call's read and write of the shown set had no test before. Removing the lock turned it red on its own assertion, with several calls of a batch printing in full. No production code changed.
