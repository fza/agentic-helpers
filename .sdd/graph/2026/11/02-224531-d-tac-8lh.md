Every list key of the `memory` and `tools` MCP servers takes one value or an array of them. The shared server (`internal/mcpserver`) lists each top-level array property of a tool's input schema as `anyOf` its item and the array, and hands a call sending one value to the tool as a one-item array, so every tool still reads a list. The key descriptions, the agent-memory skill and `docs/memory/usage.md` drop the "array even for one" wording in the same change and say that a list key takes one value or an array.

Why: every JSON parse failure on an agentic-helpers tool found across the machine's transcripts (14 distinct calls) hit an array key given one value, written bare and unquoted (`"term": Tom`, `"topic": release`, `"link": m-fe7ijg`). Claude Code refuses such a call before it reaches the server, so only the schema can prevent it. String keys (`title`, `query`, `body`) showed no such failure.

This refines the exact-values rule (20261026-222355-d-tac-kbi) without loosening it: the one-value form is declared in the listed schema, so a client checks it before sending, and an enum value stays exact inside either form. A malformed value is still refused, never repaired.

Acceptance:

1. A list key's listed schema accepts its item or an array of items, and a tool given one value receives a one-item array.
2. A tool schema whose list keys the shared server cannot rewrite to the one-or-many form refuses the server's start rather than listing a wrong schema.
3. A rescan of transcripts written after the release finds no parse failure on a list key of either server.

Accepted cost: the listed schemas change for every MCP reader, additively: every call valid before stays valid.

Rejected: keeping arrays and adding a JSON example to each description (it pushes harder on the form that fails, for tokens in every listing); a PostToolUseFailure hook adding the right shape after a failure (Claude Code does not document that the event fires for input that never parses, its own error already asks for a retry, and nothing is prevented).
