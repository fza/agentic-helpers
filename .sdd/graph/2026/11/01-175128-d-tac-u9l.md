Shell-guard denies every ask at once, with the guard's own reason as `dontAsk` mode does, in a session whose environment carries `AGENTIC_HELPERS_UNATTENDED=1`, whatever its permission mode; any other value, or none, leaves the permission-mode rules of 20261026-223555-d-tac-1ny deciding. fdbox's job board starts its jobs as `claude --permission-mode auto`, so a shell-guard ask there waits out the `shell_guard_ask_timeout` countdown (2m by default) with nobody at the window, and the board counts the job neither working nor quiet meanwhile; a deny at once lets the agent rewrite the call right away. The board sets the variable in every job it starts.

**Surface.** The environment variable `AGENTIC_HELPERS_UNATTENDED` (`shellguard.UnattendedVar`), read by `agentic-shell-guard` from its own environment, which the hook inherits from the session's process. The `PermissionRequest` countdown never runs for such a session, since no prompt is put.

**Revisits a rejected alternative.** 20261026-223555-d-tac-1ny rejected marking unattended sessions with an environment variable the launcher sets, because the launcher must remember to set it while the permission mode already sits in every hook input. That holds for launchers that do not know the marker; fdbox's board does, and for it the countdown costs two minutes per ask on every unattended job, which the permission mode alone cannot avoid without losing auto mode's approvals.

**Rejected.** Setting the existing option through `CLAUDE_PLUGIN_OPTION_SHELL_GUARD_ASK_TIMEOUT=1` per job: a one-second wait per ask, the countdown's wording instead of the guard's reason, and reliance on Claude Code passing that variable to hooks. Starting the jobs in `dontAsk`: it refuses every Claude Code permission prompt too, so jobs lose auto mode's approvals of tools not pre-allowed.

**Accepted costs.** A new way to change guard behaviour, documented in `docs/shell-guard/` and the agent-shell-guard skill. A session a person works in that inherits the variable loses every ask, each becoming a deny.

**Acceptance.**
- With the variable at `1`, an ask in `auto`, `default` and `bypassPermissions` comes back as a deny carrying the guard's reason; with another value or none, as before.
- Proven live: in a headless `claude --permission-mode auto` run with the variable set, a `find -delete` is denied by the `PreToolUse` hook itself (`PreToolUse:Bash hook error: agentic-shell-guard: ...`), where a run without it reaches Claude Code's own handling of the ask; a headless run denies an unanswered ask either way, so only the wording tells them apart.
- `docs/shell-guard/usage.md`, `docs/shell-guard/architecture.md` and the agent-shell-guard skill name the variable.
