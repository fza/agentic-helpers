Slot files are now a 512 B directory of twins with 2, 8, 32 and 128 KiB class files, every kind of value has a byte ceiling and a `fit` step, and no slot write discards its error, built on `main` in commits `191c300` and `23893c8` with three fixes from the live proof (`9ac9f33`, `d498051`, `1bdcae7`). The proof ran binaries built from `main` against stores that release 2.25.1 and the `d2290e7` build wrote under a throwaway home.

- **Directory and classes (criterion 1):** after migration every store holds `sessions.slots` (format 2, width 512) and `sessions-2k`, `-8k`, `-32k`, `-128k.slots`. Prompts of 1,500 and 15,000 B and short ones moved one seat's ladder value from inline to the 2 KiB class, the 8 KiB class and back, its generation counting up. A torn write keeping the older value rests on `TestATornWriteLeavesTheOlderValueReadable` and the kill-safety tests: killing a process mid-write cannot be timed from outside.
- **Missing-key lookups (criterion 2):** rest on `TestALookupOfAMissingKeyReadsItsProbeRunAlone`; no command performs a single lookup, and timing whole hook runs measured process start, not probe length. The probe bound is 64 pairs, not 16: at 16 a half-full directory of the largest store overflowed by chance and doubled, so directories are written half full and a key placed more than 16 pairs from its home grows the directory instead.
- **Ceilings and reported writes (criterion 3):** a 15,000-byte one-word prompt was stored fitted to 3,659 B. Read-only class files and directories made memory, tools and shell-guard print `<cmd>: keeping|clearing|reclaiming <key>: <err>` on stderr and exit 0; shell-guard discarded its reclaim and write errors until `9ac9f33`, which keeps its answer byte-identical. Each kind's worst case is stored by `TestEveryKindStoresItsWorstCase`.
- **Migration (criterion 4):** memory stores moved from format 8 and 9 to 10, the tool library from 2 to 3, prompt vectors and the seen file from 2 to 3, keeping every key's value, generation and time, except values past their ceiling, which were fitted (ladders of 15 to 20 KB to about 3,660 B, a 3,000-id shown set to its newer 1,500), and a value of no known kind over `slots.MaxValue`, which the step leaves out as `docs/memory/architecture.md` now says.
- **Disk (criterion 5):** an APFS clone of the largest live store, 8,590,065,664 B apparent and 2.45 GiB on disk with 17,150 keys, took 77.6 MiB after the format step, no key lost; seeded test stores fell from 138,360 KiB to 13,436 KiB in all.

As the decision accepts, and as release 2.25.1 showed in the proof by refusing a migrated store, a 2.25.x session refuses a format-10 memory store until its plugin moves to the release carrying this layout.
