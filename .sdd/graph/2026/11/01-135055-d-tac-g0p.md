Decides that the tool library's machine-wide version pruning, `tools.Prune`, leaves agentic-memory's SessionStart pass and runs inside the daily detached `agentic-helpers prune` instead, so a session start no longer reads every tool store or waits up to 200 ms on another process's store lock. It extends the pruning run of 20261101-131851-d-tac-05m to the tool library, under the owner's requirement that pruning never be noticeable to a user or an agent, and moves the SessionStart half of the pruning that 20261029-024444-d-tac-x9j placed there; the age rule (`tools_version_lifetime`) and the size rule (`tools_total_mb`) stay as they are.

The pass moves whole, with its other work: bringing a store of an earlier format to the current one and writing a size ledger for a store that has none. Its lock wait stays short (200 ms) in the detached run, where nobody waits for it.

The pruning inside a write that needs room (`makeRoom`) stays in the foreground: it decides whether `agentic-tools add` or `update` fits under `tools_total_mb`, so it cannot be deferred, and its wait on another store's lock (up to 2 s) happens only when two writers collide.

Rejected: also making the write-time pruning skip a locked store instead of waiting, which would refuse a rare write that a short wait lets through; leaving the pass in SessionStart, which costs every session start a read of every tool store.

Accepted costs: a version past its lifetime or over the size limit lingers up to a day longer; a store of an earlier format or without a ledger gets them up to a day later, and until then the space figure reads that store's recorded sizes as missing.

Done when SessionStart no longer runs `tools.Prune`, `agentic-helpers prune` runs it with the configured `tools_total_mb` and `tools_version_lifetime`, a test shows each, every guard broken and watched failing, and `docs/tools/architecture.md`, `docs/tools/usage.md` and `docs/plugin/usage.md` say where the pass runs.
