agentic-helpers is tested locally before every push, on macOS with `go vet` and `go test -race` and on Linux with `scripts/linux-test`, and its CI suites run only as the release workflow's gate: `.github/workflows/test.yml` keeps `workflow_call` as its sole trigger, so pushes and pull requests run no CI, and `release.yml` runs every Go suite on ubuntu and macOS, plus the plugin checks, before it cuts a release (a run finishing an existing tag's release skips them, since that tag was tested before its release commit).

`scripts/linux-test` runs `go vet` and `go test -race` for every Go suite in a Linux container of Apple's `container` tool. It mounts the whole checkout, since tests read the plugin, the skills and the docs beside `source/hooks`; runs the suites as the calling user, since as root every test of a permission refusal passes through it; keeps Go's module and build caches in `.tmp/linux-test/`; and checks the service with `container list`, since `container system status` can report a running service as down. Its arguments go to `go test` (`./...` when it gets none). The README's Testing section shows how to start the service; AGENTS.md lists the command beside the other suites.

Why local runs: Linux and macOS differ where the hooks care, as in what a sparse file costs on disk (a small write into agentic-memory's sparse slot file costs one 4 KiB block on Linux, about 242 KiB on APFS), and CI alone reports a Linux defect only after a push.

Why no CI per push: the local runs already precede every push, so a CI run per push repeats them. The release run stays the last gate, since it is the only point where code reaches other machines.

This replaces 20261102-230049-d-tac-rme, which set up the local Linux runs beside a CI ubuntu job on every push. That job no longer runs on push, so the local runs are now the only Linux check before a push; everything else that entry decided holds and is restated here.

Rejected: Docker or OrbStack for the Linux runs (a second container runtime beside the one Apple ships, and the script's checks would need both); CI only (a Linux failure surfaces after the push, never before); deleting `test.yml` and the release's test job (a release could ship code no CI ran).

Accepted cost: a push made without the local runs goes unchecked until the next release.

Guiding: every push and every later change to the workflows or the test scripts must keep this split, local runs before a push and CI only at a release; a push without the local runs breaks it. `scripts/linux-test` was built in commit `c35fed0` and the CI triggers changed in `e3e8af4`, with `README.md`, `docs/plugin/architecture.md` and the `scripts/linux-test` header saying so.
