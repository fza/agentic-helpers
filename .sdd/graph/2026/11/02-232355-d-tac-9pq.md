A memory reminder counts as answered only once every hook-written state line newer than the reminder is settled: cited by a line the agent wrote, ticked, or dropped. Hook lines are the ones memory adds for free for work that happened (`landed`, `captured`); the `dirty` and `asked` lines do not count. With no such line newer than the reminder, an own state line or entry written after it answers, as today.

Why: `answer` in `internal/memory/hooks.go` clears the reminder on any own write newer than it (`newestOwn`), so one throwaway state line silences it while the work it should record stays unrecorded. The hook lines are events the hook itself saw, so settling them proves the agent looked at each piece of finished work, with no text matching. This settles the proof the hidden-delivery decision (20261102-225941-d-tac-em1) left open.

Accepted cost: an agent pays one `ack` call per batch of landed or captured work, and a reminder stays owed while such lines remain.

Rejected: requiring a new line to name a path, commit or id from the turns since the reminder (a text match that pasting a path games, and misses work described in words); keeping any write as the answer and reminding more often (a throwaway line still silences every reminder).

Acceptance:

1. After a reminder, a throwaway state line does not answer it while a `landed` or `captured` line newer than the reminder is unsettled.
2. Citing, ticking or dropping every such line answers it.
3. With no such line, any own state line or entry newer than the reminder answers it.
4. The agent-memory skill says what answers a reminder, in the wording the hook uses.
