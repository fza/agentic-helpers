`agentic-capture` removes a captured draft lying in the work tree of the repository whose graph it wrote to, in agentic-helpers commit 84977fd on `main`, not yet released, closing the draft-removal directive (20261101-021320-d-tac-el4).

`removeDraft` counts the work tree around the graph's folder beside the working directory's and the temp root, with every existing check; `git ls-files` already ran beside the draft, so it asks the index of whichever tree holds it. Tests run the capture from another working directory against a fake git answering per repository: an untracked draft in the graph's tree is removed with `draft removed:`, a tracked one is kept `tracked by git`, a draft in a third tree is kept. Each new guard was broken, caught by its own test and restored byte-identically.

**Live proof**, headless `claude -p` in a throwaway repository A capturing into a throwaway repository B's graph: `sdd new` wrote `20261101-023358-s-tac-ssa` and the run printed `draft removed: <B>/.tmp/drafts/proof.md`; the file is gone. The third-tree case rests on its test.

The same commit updates `docs/capture/usage.md`, `docs/capture/architecture.md`, the `capture_remove_draft` description in the plugin manifest and README, and the agent-capture skill to name which trees count.
