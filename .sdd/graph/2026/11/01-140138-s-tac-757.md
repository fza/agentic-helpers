The tool library's version pruning, `tools.Prune`, now runs in the daily detached `agentic-helpers prune` and no longer in agentic-memory's SessionStart pass, shipped on `main` in commit 9202361 (merge 470d14e), pushed, not yet released, closing 20261101-135055-d-tac-g0p. `cmd/agentic-helpers` hands `tools.Prune` to the command through `pieces.Env.ToolPrune`, since `internal/tools` imports `internal/pieces` and the reverse import would cycle.

Criteria: a memory test shows a session start leaving an over-limit tool version in place, and a pieces test shows `prune` calling the tool pruning once with the configured `tools_total_mb` and `tools_version_lifetime` while agentic-tools is on and never while it is off; both guards were broken and watched failing. `docs/tools/architecture.md`, `docs/tools/usage.md`, `docs/plugin/usage.md` and the `tools_total_mb` row of `docs/memory/usage.md` say where the pass runs. Run live on the installed build: the prune exited cleanly.

`TestAnEarlierStoreMovesToTheBinaryFormats` in `internal/memory/binaryformats_test.go` now runs the daily pass after the session start before checking the tool library, since the format move and the ledger for another project's library arrive with that run, the cost the directive accepted.
