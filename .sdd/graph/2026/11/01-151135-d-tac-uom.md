agentic-helpers will collapse sdd output an agent's context already holds through a `PostToolUse` hook on every sdd MCP surface (`show`, `search`, `view`, `start_session`, `start_procedure`, `next`, `resume_session`), replacing a repeated piece with `<id> <title> (shown earlier)` or a one-line stub through `updatedMCPToolOutput`, while sdd's own served-once memory yields to it behind a config key. Over three days sdd returned 13.8M characters to agents, 42% of them repeats of text the same agent had already received (`show` 44%, `next` 49%, `search` 47%), and the token-cost criteria (20261029-021515-d-tac-00q) rank this the largest saving left, provided nothing an agent acts on is hidden.

**What a repeat is.** A piece repeats only while its text is still in the calling agent's context. The hook keeps a shown set per agent, as agentic-memory does (20261031-235540-d-tac-wxh): the main thread's per session, a subagent's its own, a fork's starting from its parent's copy; a compaction, `/clear` or resume empties it. A piece is keyed by its id plus a hash of its printed bytes, so a changed status, summary or body prints in full. Anything the hook cannot read passes through unchanged, and agentic-helpers' grounding gate, which refuses a question or capture until the graph was searched and listed, credits each sdd read exactly as before.

**Asked ids always print in full.** An entry a call names in `ids` is never collapsed; only the entries listed upstream and downstream of it, repeated `search` hits, and repeated pieces of a serve collapse. Showing a collapsed id by itself brings its full text back, with no new parameter. Rejected: an sdd `again` flag on `show` that skips the collapse, which needs a schema change and lets an agent that misreads the collapsed line work without content it asked for; printing an id in full when it is asked again within one turn, an escape invisible unless the collapsed line explains it, costing an extra call each time. Accepted cost: re-showing the same id still prints it in full, so part of `show`'s repeat share stays.

**sdd's served-once memory yields.** sdd stubs instruction lanes, framing blocks, report schemas and hints it already served, per sdd session, resetting only on `resume_session`; after a compaction its stubs point at text the agent no longer holds. sdd gains a key in its global config layer (named by sdd, for example `serve.served_once: off`), set once per machine with `sdd config set`, that turns its filter off, so one per-agent filter covers every surface. `agentic-helpers check` prints one SessionStart line while the hook is on and the key is unset, the one cause that line names (20261027-222117-d-tac-yjy). Both mismatches fail safe: the key set without the hook serves full text, and the hook without the key leaves sdd's own stubs in place, as today. Rejected: both filters side by side, keeping sdd's stale stubs after a compaction; the hook on reads only, leaving about 0.5M repeated serve characters over three days on `next`; a flag on every sdd call added by a `PreToolUse` rewrite, a parameter on every sdd tool schema resting on an unverified rewrite of MCP tool input; an environment variable in each project's `.mcp.json`, a checked-in file per project inherited by collaborators without the plugin. Accepted costs: one manual setting per machine, and the key outliving a removed plugin, which costs tokens only.

**sdd returns structure the hook keys on.** `show` answers one object per entry and `search` one per hit, and a serve carries its instruction lanes, framing blocks and report schema as separate named fields, so the hook never parses text layouts. The hook changes output only when it carries that structure: output from an older sdd passes through untouched. README and the `docs/` pages name the minimum sdd (fork) version the hook needs. Rejected: splitting today's text blobs on entry headers and paragraphs, where a layout change in sdd silently turns collapsing off, caught only by a fixture of real output. Accepted cost: a larger sdd change, and the hook build waits for an sdd release carrying it.

This builds on the lesson that savings hold when they remove repetition and leave a runnable way back (20261031-122251-s-tac-jgs): every collapsed line passes the empty-context test because it exists only while the full text sits in the same agent's context.

**Acceptance.**
- A second `show` of an entry whose chain lists an entry shown earlier prints that chain entry as `<id> <title> (shown earlier)`; the asked id prints in full.
- After a compaction, `/clear` or resume, the same call prints everything in full.
- A fork's first read collapses what the parent showed before the spawn; a fresh subagent's prints in full; a subagent's read never collapses anything for its parent.
- A piece whose bytes changed prints in full.
- Output from an sdd without the structured fields passes through byte-identical.
- With the hook on and sdd's key unset, SessionStart prints one `agentic-helpers check` line naming the key; with the key set, none.
- `docs/` and README name the surfaces, the reset rules, sdd's key and the minimum sdd version.
