Trap and note notices read and mark the calling agent's own shown set, as memory reads do: the parent's set for the main thread, a subagent's own set for a subagent, a fork's starting from its parent's copy at the spawn. Today `trapNotices` in `source/hooks/internal/memory/triggers.go` reads and marks the session's set (`mem.shownKey(session)`) whatever agent made the call, so a subagent touching a trapped file uses the notice up and its parent is never told, and a fresh subagent is never told of a trap its parent already saw. The done 20261101-010124-s-tac-ng6 names this as left open; the per-subagent sets of 20261031-235540-d-tac-wxh carry it.

**Rule.** The PostToolUse hook picks the set by the payload's `agent_id`: none means the session's set, an id means that subagent's set (`shown/<session>/agent/<id>`), created from the fork's copied set where the subagent is a fork. Each agent hears each trap and note once per context.

**Rejected.** Giving subagents below level `silent` no notices at all: a builder at `rules` would walk into a known trap untold, and traps are exactly what a builder needs. Leaving it: the parent keeps missing notices a subagent used up.

**Accepted cost.** A trap can be told several times in a session, once to the parent and once to each subagent touching it.

**Acceptance.**
- A subagent touching a trapped file gets the notice, and the parent touching it afterwards gets it too.
- A fresh subagent touching a trap its parent already saw gets the notice; a fork spawned after the parent saw it does not.
- `docs/memory/usage.md` and the agent-memory skill's `subagents.md` state it.
