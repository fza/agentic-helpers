agentic-memory now recognises Claude Code run as the npm package's native `claude.exe`, so a seat claimed under such an install stays held, in agentic-helpers commit `eea971f`, not yet released. It closes 20261111-164834-s-tac-lei, whose cause it removes.

`seat.OwnerAncestor` (`internal/seat/seat.go`) now takes a process named `claude.exe` for Claude Code when its executable, its links resolved, lies inside `node_modules/@anthropic-ai/claude-code/`, as it already did for `node` running that package's script. A `claude.exe` elsewhere, or one whose command does not read, is never taken for it. A claim under the binary records `claude.exe` as its holder's name, and `seat.Alive` reads it alive while that process runs. `docs/memory/architecture.md` names the case.

**Verified.** Table tests of `seat.OwnerAncestor` for the package's binary, a `claude.exe` outside the package, one whose command does not read, and one started through a link; a test that a claim under the binary names it and reads alive. The name filter and the package-path check were each broken alone, each failing its own cases, and restored byte-identically. A check on the executable's file name was removed instead of kept: the kernel names the process after that file, so no test could fail it. Not run: `scripts/linux-test`, and a live session under an npm install, which waits for the release on the affected machine.

**Left open.** A claim that finds no Claude Code ancestor still succeeds without a word, recording a holder already read as gone. The other callers of the same owner recognition that 20261111-164834-s-tac-lei names as a candidate, the bind and merge guardrail (`seat.UnderOwner`) and the session-end close (`seat.Owner`), share the fix but have no test under `claude.exe`.
