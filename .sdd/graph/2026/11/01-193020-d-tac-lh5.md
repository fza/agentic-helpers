Persisted agentic-helpers data migrates through one shared runner over an ordered table of steps, one per format, each a list of rerun-safe operations, proven on committed fixtures of every release and cut after every operation.

## Shape

Every persisted component migrates through one shared runner over an ordered step table:
`[]Step{{From: 7, To: 8, Run: ...}}`, exactly one step per format, each doing one job. The runner
takes the component's lock, re-reads the version, refuses a version newer than its table knows,
runs the steps from the version found to the newest in order, and writes `format.json` after each
step, so a kill resumes at the next step. A step is safe to rerun from any point it can be killed
at. The memory store moves first (today's `migrateFormat1` to `migrateFormat6` in `internal/memory/migrate.go`, one function per starting format, split into one step each, the 3-to-5 jump into 3-to-4
and 4-to-5), then the tools library, slot-file adoption and the home layout. Steps that only fence
older binaries away from new event kinds (4 to 5, 6 to 7) stay as steps that bump the version alone.

Why: the memory chain (`internal/memory/migrate.go`) runs steps under mixed conditions (`==1`,
`<=2`, a switch on `<=3`/`==4`, `<=5`, then unconditional), one step writes format 5 skipping 4,
steps bundle jobs (`migrateFormat3` assigns kinds and also scans every body for credentials; `migrateFormat5` seals the legacy tail, imports per-session cache files into the slot file and rebuilds the size ledger), and two defects follow:
the re-check under the lock tests only `== storeFormat` (migrate.go:60), so a store a newer binary
moved past 7 is written back to 7; a kill between `swapLog` and `writeFormat` leaves
`log.format-N` set aside and blocks the next run. Each other component carries a mechanism of its
own (the [survey of every mechanism](./01-193020-d-tac-lh5/migration-survey.md)).

Rejected: rebuilding every derived file from the log (the registry and shelves hold ids minted
outside the log, unproven, a large refactor, and the log still needs steps); copying forward into a
sibling folder per format (older binaries keep writing the old folder and lose their writes, disk
doubles until a sweep, every path changes).

## Hop tests

Every release proves it migrates what earlier releases wrote, on real data. A script downloads a
released binary (the network is allowed in the script, never in a test), drives it through a
scripted session into a temporary home (claims, every entry kind, items, state, due times,
attachments, tool takes, slots), and commits the tree under
`source/hooks/test/fixtures/releases/<version>/` with a canonical dump of what it held
(`dump.json`: `brief --json`, `show --json` per seat, the tools list). One table-driven test copies
every committed release into `t.TempDir()`, runs every component's runner, and compares the dump;
the oldest fixture runs the whole chain, home layout included. A test fails where no fixture exists
for the release `plugin/.claude-plugin/plugin.json` names, so a release cannot ship without one.
The first fixture comes from v2.24.0. Each step also keeps a unit test from format N to N+1.

Rejected: hand-built fixtures per format (they show what format N was thought to be, not what a
release wrote); a CI job running the old release (breaks the no-network rule for tests, proves
nothing locally, and covers nothing the committed fixture does not, the guard on the named release
answering a forgotten fixture). Accepted costs: the script, a fixture of some hundred KB per
release, and its step before each release.

## Kill safety

A step returns an ordered list of operations (copy, rename, write a file, rewrite the log, remove),
each safe to rerun, and the runner applies them in order. One test, over every step and every k,
applies the first k operations to a fresh copy of a release fixture, then runs the runner in full
and compares the dump with an uninterrupted run. A new step is covered by declaring its operations;
no production code exists for the test. An operation too large to split, the log rewrite, is one
operation and relies on `log.RewriteAfter` being crash-safe as it is.

Rejected: reusing `internal/migration`'s write-ahead journal (an undo for every change, a journal
format to keep stable, and the `halt` hook, production code only tests use); rerun-safe steps with
no kill test (safety only claimed, as when the set-aside folder defect got in). Accepted costs: a
new runner, and every large operation carrying its own crash safety.

## Acceptance criteria

1. One runner in a shared package applies a component's step table under its lock, refuses a format newer than the table knows, runs every step from the format found in order, and writes `format.json` after each step; a table-driven test covers each starting format and the refusal.
2. The memory store's steps 1 to 7 live in the table, one job each, the 3-to-5 jump split; a store moved past the newest format by a newer binary is refused, never written back, and a kill between a log swap and the format write no longer blocks the next run, each shown by a test red against the old chain first.
3. The tools library, slot-file adoption and the home layout move onto the runner, each with its steps in a table.
4. `scripts/release-fixture <version>` writes a release's tree and `dump.json` under `source/hooks/test/fixtures/releases/<version>/`; the fixture for v2.24.0 is committed; one test migrates every committed release and matches its dump; a test fails while no fixture exists for the release `plugin/.claude-plugin/plugin.json` names.
5. One test applies the first k operations of every step for every k, reruns the runner, and matches an uninterrupted run.
6. Each new guard is broken once and its test watched failing; `docs/` describe the runner, the fixtures and the release step, and the release workflow docs name the fixture step, in the same change.
