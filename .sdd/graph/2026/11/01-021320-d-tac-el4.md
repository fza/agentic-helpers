`agentic-capture` deletes a captured draft that lies inside the work tree of the repository holding the graph it just wrote to, as well as one inside the work tree of its working directory or under the temporary root. It extends the draft removal of 20261029-023740-d-tac-yl8, which keeps a draft outside both the work tree and `/tmp` and took the work tree to be the working directory's alone. Today `removeDraft` in `source/hooks/internal/capture/capture.go` judges the work tree only from the working directory (`git rev-parse --show-toplevel` in `env.WorkingDir`), so an agent capturing into another repository's graph from its own checkout gets `draft kept: <path> is outside the work tree` for a draft under that repository's `.tmp/drafts/`, and the agent's follow-up `rm` meets shell-guard's outside-project ask, which in auto mode expires unanswered.

**Rule.** The graph's repository is the work tree `git rev-parse --show-toplevel` names from the folder holding the governing graph (`run.root`). A draft inside it gets every check a draft in the working directory's tree gets: a regular file, not a link, untracked by git, unchanged while checked. A draft in neither tree nor the temporary root stays, with the existing line.

**Why.** The capture has just written to that repository's graph, so a draft in its tree belongs to this run as much as a draft in the working directory's tree does; running the capture from that repository's root already deletes it.

**Rejected.** Judging from the draft's own repository, whatever it is: capture would remove untracked files in repositories it never wrote to. Leaving it to shell-guard's `shell_guard_extra_roots` (20261101-020134-d-tac-c60) and running captures from the graph's root: every cross-repository capture leaves its draft until an agent removes it, and the option needs setting per project pair.

**Accepted cost.** An untracked file in the graph's repository that an agent passes as the draft is deleted after a successful capture, as it already is from that repository's root.

**Acceptance.**
- Capturing from one repository into a second repository's graph deletes an untracked draft under the second's tree and prints `draft removed: <path>`.
- A tracked draft there, or a draft in a third repository, stays with its `draft kept:` line.
- `docs/capture/usage.md` and the agent-capture skill state which trees count.
