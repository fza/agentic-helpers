Shell-guard now reads a shell's arguments the way each shell was measured to read them, in `shellwalk.readShellArguments` (`internal/shellwalk/shellargs.go`), agentic-helpers commit 5a218f6 on `main`, pushed, not released. Marker scripts ran on macOS's bash, sh, zsh, dash and ksh93, on mksh 59c and on fish 4.9.3. Its tables replace the manual-based rules of 20261102-135923-s-tac-s1m, and `docs/shell-guard/architecture.md` holds them by shell.

The runs corrected that entry in two places. fish takes an operand `-` for a file named `-`, never for standard input, and so does every other shell when `-` follows the end of the options (`bash - -`, `bash -- -`). dash, ksh and mksh do not read their options like bash.

They also found defects in released code, each leaving something unjudged or unread:

- `bash x.sh -c 'code'` runs `x.sh` with those arguments, while the guard took the code and left the script unread.
- zsh, ksh and mksh attach a value to its letter. `zsh -oerrexit x.sh` left the script unread as the value, `zsh -osh_word_split x.sh` read as -s, `zsh -ocorrect` read as -c and let piped code through, and `zsh -ono_rcs x.sh` read as -n, so the script passed as parse-only.
- fish's code options went unjudged in `fish -c'code'`, `fish -C'code'`, `fish --command='code'` and the unique prefixes `--comm`, `--c` and `--init`; only the first of several `-c` or `-C` was judged; and `fish -C 'code' x.fish` left the script unread.
- fish's value options `-d`, `-D`, `-f`, `-p` and `--debug-stack-frames` took the value for the script.
- `dash -c -s 'code'` runs standard input after the code, which the guard treated as replaced. `sh` counts the same for where it is dash.
- `+c` hands code on bash, sh, zsh and dash, which the guard read as a script name, and `+s` reads the input only on bash and sh, while the guard left the script unread on every shell.
- zsh's `+`, `+-` and any group holding `b` end the options, as a lone `+` does on ksh and mksh. On bash, sh and dash `+` ends nothing.

`namesScript`, `shellCode` and `replacesInput` are gone: one reader serves the script, the piped-input check and the code. A word built at run time counts as the operand, since it has no literal value.

Proof: 66 cases failed before the reader and pass after it, `go vet` and `go test -race` pass, and the installed guard gives the verdicts on the new forms. Every guard was broken and caught, the sources restored byte-identically; what no break could fail was removed rather than kept: the `debug` and `profile` table rows, covered by prefix matching, `O` in the parse-only check, and two non-literal branches the default covers.

Accepted costs: a call `bash "$opt" -c 'code'` now asks about an unreadable script instead of denying the code, and `echo x | bash -- x.sh` allows as `echo x | bash x.sh` does. `ksh -R` and `mksh -T` run nothing here without a real database or terminal, so their value letters stand on usage text and a failing run, and reading past them can only add a read.

Left open: the tables hold what these versions do. bash here is macOS's old one, so a newer bash, a Linux dash or an older fish may differ, and none of those ran.
