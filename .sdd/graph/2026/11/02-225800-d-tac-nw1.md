agentic-memory's `sessions.slots` narrows from 128 KiB slots to 4 KiB, and a slot write putting back the value a key already holds writes nothing.

- **The last prompt is stored cut.** `ladder.last_prompt` holds only the first words of the prompt that the seat's state ledger shows as its `asked:` line (cut by `cutWords`), not the whole prompt.
- **The month tables of graph entry names move to a slot file of their own** with wide slots, since a month's table (41 KB measured) is the one value past 4 KiB.
- **A slot-file format step** in the shared runner (`internal/formatsteps`, 20261101-193020-d-tac-lh5) rewrites an existing file at the new width, moving the table keys out; the release fixtures prove it, and the kill-safety test covers its operations.
- **An unchanged value writes nothing** while the held copy is under a day old (`slots.Update`). Readers drop a key by its write time, a week on at the shortest, so a key in use is still written once a day. This part is built, in commit 4db8ae3.

Why: APFS charges each written slot nearly its whole span on disk, about 242 KiB per write of 300 bytes at a 256 KiB stride (measured), so a store costs about 256 KiB per live key whatever the key holds; Linux charges one 4 KiB block (measured in a container). Every value but two is under 1 KB: the last prompt (median 14 KB, up to 126 KB, kept only for a line cut to a few words) and the month table. Writes are frequent: `ladder` 3,827 writes over 14 sessions of one store, `seen` 35,004 and `traps` 21,010 in a store running a job per seat, each a twin rewrite even for an unchanged value. The growth fix (20261102-225503-s-tac-zbd) bounds how many keys a file holds; the width bounds what each one costs.

Acceptance:

1. A new `sessions.slots` has 4 KiB slots, and no value written to it is refused as too large.
2. A store of the newest release migrates to the narrow file through the format step, keeping every key's value, proven on the release fixtures and by the kill-safety test.
3. The graph-name month tables live in their own slot file and still collapse repeated sdd output.
4. On APFS, a store's slot file spends about 4 KiB per live key on disk.

Accepted cost: one format step with its fixture coverage, and a second slot file.

Rejected: cutting only the last prompt at 128 KiB width (APFS still charges the span per key, so nothing is saved on macOS); leaving the file as the reclaim and shrink bound it (about 256 KiB per live key on macOS); skipping unchanged writes for good (a key in use would age out of a reader's week).
