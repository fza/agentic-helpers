agentic-tools gains no MCP call that takes a script's content inline and registers it and takes it into `.tmp/` in one step; a tool stays written to a file, run, then registered with `add` from its path.

Why: the script's body is sent once either way, since `add` reads the file it names and the server's existing `take` call, which copies a stored tool into `.tmp/`, is redundant for a file already there, so the call would save about 100 to 200 tokens per registered script. Against that, it asks for a judgment of library-worthiness before the script ever ran: over 14 days, 205 scratch scripts met 27 `add` calls, most of them one-offs, so registering up front would file untested tools and churn updates, with summaries and usage written blind. The larger sink, about 8,000 inline interpreter heredocs that never reach a file, stays untouched by it.

Settled: nothing changes; the `tools` server (20261028-214433-d-tac-rw7) keeps its calls. Revisit only with a measurement showing registered scripts are mostly written once and kept unchanged.
