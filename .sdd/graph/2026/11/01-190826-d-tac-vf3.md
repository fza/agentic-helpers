The agentic-memory plugin option `entry_max_words` is renamed `entry_target_words`, since it is the word count an entry body aims at, told to agents, and no storage limit: a longer body lands whole, its filing note saying no rewrite is needed.

The old name stays readable for one release through the `Renamed` table in `internal/pluginconfig`, as `retired_body_days` did; the new name wins where both are set, and `agentic-helpers check` names the old one while a layer still sets it. `MigrateAgentAnswers` copies a user settings answer under `entry_max_words` into `config.yaml` as `entry_target_words` where the file names neither key, and writes no settings file, since Claude Code's settings sit behind its permission prompts. Surfaces: the userConfig key `entry_target_words` in `plugin/.claude-plugin/plugin.json` (title "Entry word target"), the Go option `EntryTargetWords` and default `DefaultEntryTargetWords` (500), and the filing note `note: the body has <n> words, past the <limit> an entry aims at (entry_target_words); it landed whole, no rewrite needed`.

Rejected: `entry_suggested_words` (longer, and reads weaker than a guide agents mostly follow); `entry_words_hint` ("hint" already names the similar-entry hint); keeping the name ("max" tells agents a body past it is wrong, inviting a costly rewrite). Accepted cost: a breaking key rename.

Acceptance criteria: `entry_target_words` sets the note's limit; `entry_max_words` is still read for one release, the new name winning where both are set, and `check` names it; the migration copies an old settings answer into `config.yaml` and never overwrites a value there; README, `docs/memory/usage.md` and agentic-helpers:agent-memory name the new key; each new guard is broken once and its test watched failing.
