Text that `agentic-memory` and `agentic-tools` file and print back into hook context can no longer pass for a line of the hooks or for a harness tag, built in commit 3306f184 on branch `v2` (`fix: filed text in hook context could forge our hook lines and harness tags`), not yet released. Filed text needs this because any writer of a store chooses what it holds (20261025-185324-s-tac-k4o), and a body copied from tool output could otherwise read as a hook's verdict or a harness reminder.

`hookio.Neutralize` puts `> ` before a filed line whose first visible text opens like a line of the hooks (`agentic-<name>:` and `agentic-<name> <word>:`, `scratch:`, `tool library:`, `GROUNDING GATE:` and shell-guard's `[agentic-shell-guard:` withheld-credential mark, case folded, blanks and invisible format characters before it skipped), and turns the `<` of a tag-shaped token into `‹` (U+2039), so `</system-reminder>` reads `‹/system-reminder>`. The look-alike is chosen over `&lt;`: no tag parser reads it as `<` and no decoding turns it back into one. It runs wherever a hook prints filed text, `agentic-tools`' script nudge naming scratch files included. Direct reads (`show`, `search`, `--json`, MCP structured reads) print filed text as filed, since the agent asked for them and the hooks never print them.
