agentic-helpers keeps its command tables and does not adopt sdd's command/finder (CQRS) split.

Why: sdd split commands, queries, handlers and finders so its CLI and its MCP server share one code path. agentic-helpers has that already: memory serves both from one table of `command{name, flags, schema, run, cliOnly}` (`source/hooks/internal/memory/commands.go`), and the tool library from its own (`internal/tools/tools.go`). Of the 130 fix commits from 2026-10-20 to 2026-11-02, none came from CLI and MCP drifting apart; the MCP fixes concern schemas, key descriptions and a long-lived server rereading registries, none of which a command/finder split prevents.

Rejected:
- **Finders for reads only:** clearer read-only tests, but a refactor across about 45k lines of memory for no defect class it removes.
- **Full CQRS as in sdd:** command structs, handlers with narrow ports, finders and a wiring root. Boilerplate per command and a wiring file the size of sdd's `cliapp/app.go` (2,588 lines), for the same sharing the tables give.

Accepted cost: run functions keep mixing reads and writes, so a read-only test still builds a whole memory value.

Nothing follows: the structure stays as it is unless a defect class appears that the split would prevent.
