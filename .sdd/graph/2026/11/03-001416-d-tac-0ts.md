agentic-memory refuses a hook payload's session id outside `^[A-Za-z0-9_-]{1,128}$` before building any per-session slot key, as the tool library and prompt vectors already do.

- **Where:** one check where memory reads the payload's session id. An id outside the shape gets no per-session state: no `ladder`, `shown`, `spawn`, `agents`, `fork`, `waiter` or `instructions` key is read or written. The brief and the seat's own state still work.
- **Pattern:** the `sessionShape` memory already holds for its scratch line (`internal/memory/subagents.go:484`), identical to `internal/tools/session.go` and `internal/promptvector/promptvector.go`.

Why: memory builds keys as `"ladder/" + session` (`internal/memory/sessionslots.go`, `internal/memory/subagents.go`) from an id nothing checks. An id over about 230 B makes every such key exceed the slot files' 255 B key limit (`slots.MaxKey`), and since slot write errors are discarded, the session's state is lost silently. An id holding `/` can land on another session's key (`spawn/<a>/<call>` against a session named `<a>/<call>`). Claude Code sends UUIDs, so neither happens today; a forged payload or another host could.

Rejected:
- **Hex-encoding ids outside the shape:** every host keeps its state, but it is a second rule unlike tools and prompt vectors, and a long id still needs hashing to fit 255 B.
- **Leaving it:** a payload of another shape loses its state silently or overwrites another session's keys.

Accepted cost: a host sending ids of another shape gets no per-session memory state.

Acceptance:

1. A hook payload with a session id outside the shape writes no per-session key and exits as it would without memory state, shown by a table test with an id holding `/`, one of 129 characters and an empty one.
2. A UUID session id keeps every per-session key, unchanged.
