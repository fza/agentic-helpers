A seat's agentic-memory state becomes a ledger of lines the agent adds, ticks and pins through `ack state`, never retyping the rest, with lines ending on their own when the ids they cite end and hooks adding what shipped; the free-text slot overwritten whole by `agentic-memory state < body` goes.

**Why.** Over 3 days to 2026-11-01, machine-wide, agents wrote the state slot 1679 times in 148 transcripts, about 1.07M characters of output, the costliest token kind. 89% of those writes were overwritten before any brief, claim or compaction read them; 6% were read. The shipped-work request (20261027-222420-d-tac-ac7) drove 492 writes, 469 never read. A rewrite restated 35% of the previous one. 85% of writes cite commit shas, 61% memory ids, 38% graph ids: the agent retypes what git and the store hold. About 10% of state text is derivable from commits or entry titles; 34% is intent and 57% reasoning only the agent holds, so state stays agent-written, only cheaper to change. Of state clauses citing a memory id that left the next write, 51% cite an entry now ended, so half of all dropping is mechanical. The measurements ran with [statevalue.py](./01-190255-d-tac-6hl/statevalue.py) and [derivable.py](./01-190255-d-tac-6hl/derivable.py). Agents writing only when a nudge asks (20261030-125612-d-tac-hz8, superseded here) did not reach the cost: each write still rewrote the whole slot.

**Write surface.** `ack` writes the ledger through the reserved id `state`, routed to the calling seat's ledger, never to an entry: `ack state --add '<line>'` adds a line, `ack state --add <memory id>|<todo>#<item>|<graph id>` pins one, `ack state#<item> --done`, `--remove` and `--undo` change one. MCP `ack` takes `{"ids":["state"],...}`; its id pattern widens to `^(m-[a-z0-9]{4,16}|state)(#[a-z0-9]+)?$`, and `itemAddress` in `internal/memory/todolist.go` with it. No memory id can collide, every one starting `m-`. Lines reuse todolist items (20261028-223759-d-tac-jkj): a stable three-character id each, so dropping one renumbers nothing, and a pinned line follows jkj's linked-item rules. `show state` prints the whole ledger. The ledger is created on first use, never by the agent; a seat with none reads as empty at claim and in the brief. It belongs to the seat, keyed as the slot is (`folded.states[seatName]`), so a temporary seat on its parent's shelf keeps its own and two live agents never edit one list. The CLI `state` command refuses, naming the `ack state` form; the MCP `state` tool goes. Item events gain the ledger as a target, a store format bump migrated under lock as earlier ones were.

**Line ends.** A line citing ids ends once every id it cites has ended: a graph entry closed or superseded, a memory entry retired or superseded, a todo item ticked or dropped. `ack state --add '<line>' --until <condition>` (MCP `ack` key `until`, an array) declares ends for the lines that call adds, in every form `new --until` takes; any one reached ends the line. `until` is refused on a todo's items. An ended line shows once under the brief's `ended since last brief`, and `--undo` brings it back. A line with neither ids nor `--until` lives until the agent drops it.

**Hook lines.** Hooks add lines marked `hook`, at no agent cost, replacing the hook-written draft (20261027-222635-d-tac-fki): `landed <sha> <subject>` at the `PostToolUse` of a Bash `git commit`, `merge` or `cherry-pick` and at `Stop` for commits made elsewhere; `captured <graph id> <title>` when the graph gains an entry; one `dirty <paths>` line at `Stop`, the files the session's Edit, Write and NotebookEdit calls named that no commit holds, ended once every path is committed or reverted; one `asked <last prompt>` line at `Stop`, withheld where the prompt looks like it holds a credential. The brief prints the newest 12 `landed` and `captured` lines and folds the rest into `(<n> more: agentic-memory show state)`; they carry across sessions until they leave the newest 12. A landed round matching a commit to an agent line nests the commit under that line as evidence, ending with it. The agent may cite or drop a hook line and never has to.

**Nudges.** The shipped-work request goes: `internal/memory/shipped.go`, its prompt and Stop holds, and the plugin option `state_stale_after_writes`; hook lines record what shipped. The near-compaction nudge, its `Memory overdue` Stop backstop and the replay-overflow nudge stay, worded for the ledger (`Add or tick state lines where work moved: agentic-memory ack state --add '<line>' | ack state#<item> --done`), and any agent change to its ledger answers them. The replay starts after the seat's newest entry or agent ledger change (`newestOwn`); hook lines move nothing, holding no reasoning.

**Limits.** Nothing refuses a line for its length or the ledger for its count, a refusal costing a rewrite. The brief prints every open agent line whole, never cut as a todo item's text is. Past 12 open agent lines, the `ack` reply adds `ledger holds <n> lines; drop the settled ones`.

**Migration.** A seat whose newest state is a free-text body the agent wrote (a `state` event, not a draft, newer than any ledger event) shows it as item `state#old` in its brief at claim, compaction and resume, with `state is a ledger now: split this into lines (agentic-memory ack state --add '<line>' ...), then agentic-memory ack state#old --done`. `--done` or `--remove` on `state#old` confirms; until then each claim, compaction and resume asks again. A hook-written draft is discarded unasked. Old `state` events stay readable in the log.

**Rejected.**
- A free-text slot with fewer write moments: every write still retypes the slot, 35% repeated.
- A state computed at read with a 30-word intent line: about 90% of state text is not derivable, so plans and reasoning would be lost.
- Flags on `state` (`--add`, `--drop`, `--pin`): three more MCP schema keys and a second item grammar beside `ack`'s. The ledger as a real todo entry per seat: an id to look up, heat and retirement exceptions, visible to search and recall. Subcommands: a second subcommand level no other memory command has.
- A ledger per shelf: concurrent edits to one list, and the key would migrate.
- Ends by inference alone: a branch, path or time end has no id to cite. Declared ends only: agents would write ends the cited ids already give.
- One unnumbered hook block rewritten at every Stop: no fact can be cited, dropped or nested under the line it settles, and each session's block erases the last. No hook lines: a fresh claim loses the last prompt and the files written, and agents rebuild them through git.
- Dropping the replay-overflow nudge too: a long stretch with no entry and no ledger change would lose its oldest turns with only a cut count pointing at them. Keeping the shipped-work request reworded: brings back most writes, nearly all unread.
- A 40-word line cap with refusal, or a hard 12-line cap: each refusal costs a rewrite or a drop mid-task. Todo item display (60-character cut, 3 open shown): `show state` after every compaction.
- Folding the old body into a line silently: the agent never splits it. Starting every ledger empty: every live seat loses where its work stands mid-task. The first `ack state --add` confirming the migration: one new line would silently drop the rest of the body.

**Accepted costs.** `ack` gains the `until` key and a reserved id, and carries a third meaning beside do-now rules and todo items. A line citing an id only for context ends with it. Up to about 250 tokens of hook lines per brief; hook lines from earlier sessions sit beside today's, each showing its age; a landed match is evidence, so a commit can nest under a line it does not settle; the `asked` line keeps the last prompt after the owner moved on. Fewer ledger changes grow replay windows, so the overflow nudge fires more often, and a `next` line can go stale between compactions. A careless agent can grow the brief with no hard bound. One rewrite per seat at migration, about 600 output tokens, and a seat that never ticks `state#old` keeps it and the request in every brief. A store format bump.

**Acceptance criteria.**
1. `ack state --add`, a pin, `--done`, `--remove`, `--undo` and `--until` change the calling seat's ledger, table-tested; `state` on another seat's ledger is impossible by construction; MCP `ack` accepts `state` ids and `until`; `until` on a todo's items is refused.
2. A line ends when every id it cites ends and when a declared condition is reached, appears once under `ended since last brief`, and `--undo` restores it.
3. Hooks add `landed` lines at a commit call and at Stop, `captured` lines on a graph gain, and one `dirty` and one `asked` line at Stop, a credential-shaped prompt withheld; the brief shows the newest 12 and the fold line; `show state` prints the rest; a matched commit nests under its line.
4. The shipped-work request and `state_stale_after_writes` are gone; the remaining nudges carry the ledger wording and are answered by an agent ledger change, not by a hook line; the replay starts after the newest entry or agent ledger change.
5. No line or count is refused; the reply names `ledger holds <n> lines` past 12 open agent lines; the brief prints agent lines whole.
6. A seat with an agent-written slot sees `state#old` and the request at claim, compaction and resume until ticked or removed; a draft-only slot migrates silently; `agentic-memory state` refuses naming the `ack state` form; the store migrates under lock with a backup.
7. Each new guard is broken once and its test watched failing; agentic-helpers:agent-memory, `docs/memory/usage.md` and `docs/memory/architecture.md` describe the ledger, every reply and nudge wording, in the same change.
8. Three days after release, the same measurement over transcripts shows agent output into state well below the 1.07M characters per 3 days measured before.
