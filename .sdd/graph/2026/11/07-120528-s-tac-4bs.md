A memory seat now sees landed work both in its claim brief and when the work lands: the landed scan maps commits to the seat's live todos, todo items, traps and state lines, and delivers each match in every brief and at the next prompt or tool call, so both conditions of 20261101-110128-s-tac-f8f hold. The detection directive 20261101-110914-d-tac-pu1 addressed the gap and is closed by 20261101-120217-s-tac-r56, which did not close the gap itself.

**At the brief.** The claim brief, the post-compaction brief and every narrowed brief (recorded fixed in 20261101-223616-s-tac-cvq) end the line of a live todo or trap with `retire? landed: <sha> <subject>`, and a todo item's with `ack #<item>? landed: <sha> <subject>` (`landedFlag` in `source/hooks/internal/memory/landed.go`, read in `brief.go`). A match stays stored until its entry or item is ticked, retired or superseded, or the agent runs `agentic-memory landed dismiss <id>` (20261101-120342-d-tac-69v, recorded built in 20261101-221210-s-tac-c2w), so a new claim, a compaction and a `/clear` each see it again. A commit matched to an open state line nests under that line as `landed <sha> <subject>` (`stateSection` in `ledger.go`). Tests: `TestALandedMappingWaitsForTheBrief`, `TestADeliveredMappingSurvivesAFreshContextAndAClaim`, `TestANarrowedBriefCarriesTheLandedFlag`, `TestALandedMatchNestsUnderItsLine`.

**When work lands.** The `PostToolUse` hook starts a landed round at once after a Bash call running `git merge`, `commit`, `pull`, `rebase` or `cherry-pick` (`landingCall` in `landed.go`), and the prompt and tool hooks start one whenever `landed_scan_interval` has passed. The round runs in a process of its own, and the seat's main thread gets one hidden line at its next prompt or tool call, `agentic-memory: landed commits may settle live work; check each against the repository, then: ...`, naming each match with the `retire` or `ack` call that settles it; no Stop output carries it. Tests: `TestALandedMappingReachesTheToolHookOfTheMainThread`, `TestLandedMappingsArriveTogetherOnce`, `TestTheHookOnlyStartsARound`.

**The causes the gap names.**
- No tie between entries and commits: a commit matches by a `merged:` branch or a branch the entry names, a path it is anchored to or names with `--about`, an sdd entry id it links to, or a subject similar to the entry's title and body. Test: `TestALandedCommitMatchesByEachTest`, `TestALandedCommitMatchesByALinkedEntryID`.
- `merged:<branch>` failing once the branch is deleted: each probe records the branch tip while the branch exists, and once it is gone the end is met where that tip reached the target (`branch` in `ends.go`). Test: `TestAMergedBranchEndsAfterItsDeletion`.
- Missing ends at filing: an item-less todo files as a note plus a state line carrying its ends (20261103-211845-d-tac-afn), and every state line added needs `--until` or an explicit `--until none` (20261104-130942-d-tac-c7y); this replaces the filing hint the gap proposed.
- The agent-memory skill states that a todo or trap is a lead, to be checked against the repository before it is presented as open work and ticked or retired in the turn its work lands.

The commit ids 984ba7d, 7774da5 and 6de8fc8 that 20261101-120217-s-tac-r56, 20261101-221210-s-tac-c2w and 20261101-223616-s-tac-cvq cite no longer exist in the repository; the commits above carry the same changes on `main`.
