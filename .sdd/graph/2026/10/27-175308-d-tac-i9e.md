`agentic-capture` decides whether a draft's `title` may go to `sdd new` by `sdd info --format json` once a release of the fza fork ships that flag: where `sdd info --help` lists `--format`, a titled draft is refused before anything runs when `capabilities.titles` is false, and when `capabilities` is null, which marks a graph newer than the binary. Where `--format` is missing, the `.sdd/meta.json` check of 20261027-115753-d-tac-swc runs unchanged. The probe joins the `--help` reads that already detect `--title`.

Why: the fork's `capabilities.titles` states what writes actually use, the graph's own schema or the binary's where no `meta.json` exists, so `agentic-capture` stops mirroring sdd's rule that schema 1 holds no titles; the fork also refuses a `meta.json` whose `graph_schema_version` is missing or below 1, which `agentic-capture`'s own `meta.json` read takes for a graph naming no schema. Older fork releases keep working under the older-release rule (20261027-174929-d-tac-3q0), so the `meta.json` read stays as their path.

Rejected:

- Building before the fork releases the flag: built against an unreleased shape, redone if it changes.
- Requiring the new release for titled drafts: a titled capture fails on every machine still on an older fork release.

Accepted costs: one more `sdd info` run per titled capture where the flag exists; two paths to keep tested.

Done when tests cover `capabilities.titles` false refused, true captured, null refused, and help without `--format` taking the `meta.json` path unchanged, each guard broken and watched failing; `docs/capture/*` and `agentic-helpers:agent-capture` name both paths.
