`agentic-capture` maps the draft header keys `actor_kind` and `index` to `sdd new`, and refuses a draft carrying any header key it does not map.

- `actor_kind` becomes `--actor-kind` with one value (`human` or `machine`, kind actor only).
- `index` becomes `--index` with one JSON object `{"title": ..., "topic": ...}` (kind fact only).
- The accepted keys are exactly those mapped to a flag, plus `type`, `layer` and `attach`. A draft carrying another key exits 1 before the lint and the pre-flight, naming the key and listing the accepted ones. Nothing reaches `sdd new`.
- `skills/agent-capture/SKILL.md` lists both keys and the refusal.

Why: an unmapped key was dropped without a word, so an actor drafted with `actor_kind: human` was captured with the field absent, which sdd reads as unknown, never human, and a fact drafted with an `index` was never enrolled in the retrieval index. The entry is immutable once written, so a dropped key cannot be repaired afterwards. Refusing the unknown key turns the next `sdd new` flag the mapping misses into a loud failure at the draft rather than a silent gap in the graph.

Rejected:
- Warning on an unknown key and capturing anyway. The entry is written without the field all the same, and a warning scrolls past an agent's tool output.
- Passing every unknown key through as `--<key>`. Header keys use underscores where flags use hyphens, list and JSON values need their own encoding, and a misspelled key would reach `sdd new` as a flag it rejects only by luck.

Accepted cost: a draft carrying a key outside the mapping, including one a caller added for its own bookkeeping, now fails until the key is removed or mapped.

Done when `go test -race ./...` in `source/hooks` covers a draft with `actor_kind` reaching the argument vector as `--actor-kind`, a draft with `index` reaching it as `--index` with the JSON object, and a draft with an unknown key refused with exit 1 naming it and nothing run; each guard was broken and watched failing; the agent-capture skill names both keys.
