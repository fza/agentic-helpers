Refines the agentic-memory directive with surfaces and mechanics it left open.

**Seat lookup for tools outside Claude Code.** A process with no owning `claude` process (a Python orchestrator reading which seat a session holds) asks the command:

- `agentic-memory holder <seat> --json` prints `{"seat","session_id","pid","started","claimed","transcript_path","alive"}`; exit 0 where a live session holds the seat, 1 otherwise, the JSON printed either way.
- `agentic-memory holder --session <id> --json` prints the same for the seat that session holds; exit 1 with `{"seat":"","session_id":"<id>"}` where it holds none.

The claim file layout stays private: the command is the contract. Why: an orchestrator that read `.memory/roles/<seat>.json` directly loses that file, and the owning-process lookup answers only for the calling process.

**A command from the plugin's `bin/` fails loudly without its binary.** `hooks/run --command <binary>` exits 1 with `agentic-helpers: no <binary> binary is installed for v<version>; ...` on stderr, where a hook stays silent with exit 0; `bin/agentic-memory` and `bin/agentic-capture` both run it. Why: a silent exit 0 from `agentic-memory new` reads as an entry filed that was never written.

**Mechanics settled:**

- A claim made from the Bash tool knows neither its transcript nor, through MCP, a fresh session id; every hook a seated session runs writes both into the claim (`transcript_path`, and the session id `/clear` changes).
- A claim removed by `release`, a sweep or `--force` survives as `seats/<seat>.last.json`, so the next claim still finds the previous session's transcript.
- A slice opens with `session <id>`; the next claim prints it only where that id is the previous holder's, else it reads the previous holder's recorded transcript, so a killed session's turns are never replaced by an older session's slice.
- The vector cache is `~/.cache/agentic-memory/<project>/<sha256(fingerprint)[:12]>/vectors.gob`, every entry's chunk vectors in one file rewritten whole: at a few thousand entries a whole-file rewrite costs less than the segment machinery the log carries.
- Every write needs a claimed seat, `confirm` and `supersede` of another seat's entry included; a search without one must name `--seat` or `--all-seats`.
- `release` of a seat whose holder still runs is refused: only its holder releases it.
- Topic nearness in the filing aids is by spelling distance and containment; the embedder ranks similar entries, as embedding every topic name on each filing would cost a call per topic.
- Every entry line carries its source in the bracket: `[main, normal, from agent, 2026-10-25 10:00, 15af1a8c]`.
- The `UserPromptSubmit` hook's timeout is 30 seconds, room for one bounded embedding call.

Rejected: exposing the claim files as the contract for outside tools, since their fields follow the hooks' needs and change with them; making `hooks/run` fail loudly for hooks too, which would turn a missing binary into an error on every prompt.

Accepted costs: an outside tool spawns a process per lookup; a status line must write the context reading at the new path for the ladder to read context fill.
