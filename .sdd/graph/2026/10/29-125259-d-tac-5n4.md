---

Shell-guard gains command alternatives: a built-in table of commands agents reach for that are missing on the machine, or present in another platform's flavour, each with what to run instead, so a Bash call that would fail or silently do the wrong thing is refused with the working command, and the `agentic-helpers` SessionStart check names the substitutions the machine needs.

Why: agents write GNU habits on macOS. `timeout` is not installed, so a bounded command fails; the fallback `perl -e 'alarm N; exec @ARGV' cmd` makes shell-guard refuse every removal behind it, even `rm -rf ./build` inside the project, with `inline code for perl names a removal or mktemp; refusing`. BSD `sed` is worse: verified on macOS 27.0.1 (`sw_vers -productVersion`) with its system `sed`, `\+`, `\|`, `\s`, `\w` and `\b` in a basic expression and a `0,/re/` address match nothing without an error, `sed -i 's/a/A/' f` fails, and `sed -i -e ...` leaves a stray `f-e` backup.

**Entry.** Each entry is one record in Go: the command name, its kind, an ordered list of alternatives, and where the inner command starts for a launcher. An alternative is a program looked up with `exec.LookPath` at the call plus an argument template with named slots (`{dur}`, `{cmd...}`), built from the parsed command so quoting and pipelines survive. The launcher field drives both the suggested rewrite and shell-guard's walk, so every alternative that launches a command is walked by construction.

**Missing kind.** The name is not on PATH. The first installed alternative wins. `timeout`: `timeout` itself wherever it is on PATH (Linux, or macOS with GNU's gnubin or uutils' uubin), then `gtimeout` (GNU coreutils), then `uu-timeout` (uutils), then `perl -e 'alarm {dur}; exec @ARGV' {cmd...}`. `gtimeout`, `uu-timeout` and that perl form become launchers in `internal/shellwalk`, so the command behind each is judged as behind `timeout` today. Refusal: `agentic-shell-guard: timeout is not installed here; use: <rewritten command>`.

**Dialect kind.** The name is present but its flavour differs, detected once per resolved binary (GNU `sed` answers `--version`, BSD refuses it) and cached under the cache root. A pattern on the parsed arguments matches only a usage verified to fail or mislead on that flavour; the refusal names a GNU alternative where one is installed (`gsed`, `gdate`), else the flavour's own form, with no automatic rewrite where none is exact. First entries, BSD `sed`: `-i` without a suffix argument (use `-i ''`); a long option (use the short one); `-z`; GNU escapes `\+ \? \| \s \w \b \< \>` in a literal basic expression (use `-E` with `+ ? |`, `[[:space:]]`, `[[:alnum:]_]`, `[[:<:]]` `[[:>:]]`); a `0,/re/` address; one-line `a`, `i`, `c` text (use `a\` and a newline). BSD `date`: `-d` (use `gdate -d`, or `date -j -f <format> <value>`). `readlink -f` and `grep -P` work on the macOS checked and get no entry: an entry exists only for a verified failure.

**SessionStart line.** `agentic-helpers check` prints one line naming the substitutions the machine needs, such as `agentic-helpers: this machine: timeout -> gtimeout; sed and date are BSD`, and nothing where none is needed, as on Linux with GNU tools.

**Switch.** A boolean option `shell_guard_alternatives`, default on, switches the refusals and the line together, beside the other shell-guard options of d-tac-n48.

**Rejected.**
- Entries in `config.yaml`: the file is agent-writable (s-tac-wux), and a wrong launcher declaration there, such as `rm` declared a launcher, would make shell-guard judge the wrong word.
- A `timeout` shim of its own in the plugin's `bin/`: GNU and uutils already answer it, and a bare-name binary breaks the `agentic-` prefix rule.
- Rewriting raw command text: breaks on quotes, heredocs and pipelines.
- Entries learned from what agents retry: nothing can check them.
- Only a SessionStart line, or only the refusal: the line alone is missed by an agent that types `timeout` anyway, the refusal alone costs a failed call before the agent knows.

**Accepted costs.** A narrow pattern per dialect usage, each one a test case. A `PATH` lookup on every call naming an entry's command. The SessionStart line on every macOS session, about 15 tokens. The perl form ends a timed-out command by `SIGALRM`, exit 142 rather than GNU's 124; the skill says so.

**Acceptance.**
1. With `timeout` on PATH no call is refused and the line names no `timeout` substitution; without it, each alternative in the chain is named in turn as the earlier ones are removed from a fake PATH.
2. `gtimeout 9 rm -rf ~/x`, `uu-timeout 9 rm -rf ~/x` and `perl -e 'alarm 9; exec @ARGV' rm -rf ~/x` get the outside-project verdict, and the same three with `rm -rf ./build` run.
3. Each `sed` and `date` pattern above is refused against a BSD flavour and allowed against a GNU flavour, with a test per pattern, and the refusal names `gsed` or `gdate` when on PATH.
4. `sed -E 's/a+/X/' f`, `sed -i '' 's/a/b/' f` and a `\+` inside a quoted replacement text that is not an expression are allowed.
5. The SessionStart line appears only when a substitution is needed, and with `shell_guard_alternatives` off neither the line nor a refusal appears.
6. The `agentic-helpers:agent-shell-guard` skill quotes every new refusal, and `docs/shell-guard/` describes the table, the chain and the option.
