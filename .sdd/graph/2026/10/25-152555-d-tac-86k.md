Every time agentic-memory writes into a JSON file is an RFC 3339 string in UTC, ending in `Z`, with the precision the value carries: nanoseconds where Go's clock supplies them, seconds for a process start time. It covers:

- `log/tail.jsonl` `time`: `"2026-10-25T14:03:47.829928123Z"`, in place of Unix nanoseconds.
- `seats/<seat>.json` and `seats/<seat>.last.json` `claimed`: `"2026-10-25T14:03:47.829928123Z"`, in place of RFC 3339 with the local offset.
- the same files' `started`: `"2026-10-25T14:03:30Z"`, in place of the raw `ps -o lstart=` text. `process.StartTime` runs `ps` under `LC_ALL=C`, parses `Mon Jan _2 15:04:05 2006` in the local zone, and the liveness check in `internal/seat/seat.go` compares the two instants, not two strings.
- the cache's `heat.json` `at`, `briefs/<seat>.json` `at` and `ladder/<session>.json` `nudged_at`, converted to UTC before they are written.
- `sessions/<id>.ctx` `at`, which `plugin/hooks/register.ts` writes as an ISO string from `toISOString()` in place of Unix seconds.

The binary segments under `log/` keep their little-endian Unix nanoseconds: they are not read by people, and `agentic-memory dump` renders them. Printed stamps keep the local zone with its abbreviation, as 20261025-021923-d-tac-n7f settles.

Readers accept the previous form beside the new one: an integer `time` in a `tail.jsonl` row, a `started` in `ps` text, a numeric `at` in a `.ctx` file. Without that, a seat held across the upgrade would read as dead because its `started` no longer matches, and a session on an older plugin release would lose its context reading.

Why: one store holding raw `ps` text, Unix nanoseconds, Unix seconds and two offset styles cannot be read or compared at a glance. RFC 3339 reads as a date; UTC keeps every string in time order when sorted as text and never repeats an hour when the clocks go back.

Rejected: RFC 3339 with the local offset (reads like the wall clock, but one store mixes `+02:00` and `+01:00` across a change of clocks, so sorted text leaves time order); Unix numbers everywhere (sort and compare well, read by nobody); millisecond precision (rounds stored nanosecond times, so a value written and read back differs from the one held).

Accepted costs: a stored time reads an hour or two off the wall clock; `tail.jsonl` rows grow by about ten bytes each; the readers carry the previous forms until no store holds them, which for `started` and `.ctx` is the next claim and the next turn, and for `tail.jsonl` the next seal.

Acceptance criteria:

1. A row appended to `tail.jsonl` carries `time` as an RFC 3339 UTC string with nanoseconds; a test reads back a tail holding an integer row and a string row, both at their original instants.
2. A claim writes `claimed` and `started` as RFC 3339 UTC; a test shows the liveness check holding for a seat whose `started` is in `ps` text and for one in RFC 3339, and failing for a different start instant in either form.
3. `process.StartTime` runs `ps` with `LC_ALL=C` and returns a `time.Time`; a unit test parses a fixture `lstart` line in a fixed zone.
4. `heat.json`, `briefs/<seat>.json` and `ladder/<session>.json` hold UTC times; a test fails on any written time carrying an offset other than `Z`.
5. `register.ts` writes `at` as an ISO string ending in `Z`; `claude plugin test plugin` covers it, and a Go test reads a `.ctx` holding an ISO `at` and one holding a numeric `at`.
6. `README.md` names the stored format.
