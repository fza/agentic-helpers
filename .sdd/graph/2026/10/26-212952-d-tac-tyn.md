A seat claim turns Claude Code's own auto memory off for the project it is claimed in, so agentic-memory is the only memory an agent there files into and reads back. Claiming writes `"autoMemoryEnabled": false` into the project's `.claude/settings.local.json`; it takes effect from the next session. The plugin option `memory_turns_off_auto` (boolean, default true) switches the write off.

**Where and when.**

- The file is the one Claude Code itself reads: `.claude/settings.local.json` at the root of the main checkout, which a worktree shares (`project.Root`, as agentic-memory already resolves it).
- Every claim, the MCP `claim` included, checks the file. Where `autoMemoryEnabled` is absent, it is added and every other key and the file's formatting are kept; where the key carries any value, the owner set it, and the file is left alone. A file that does not parse as a JSON object is left alone too, and the claim says so in one line.
- A file created this way is kept out of git: where `git check-ignore` does not already ignore it, `/.claude/settings.local.json` is appended to the repository's `info/exclude`, which stays local. Claude Code gitignores the file only when it creates it itself.
- The claim says once what it wrote: `agentic-memory: Claude Code's own auto memory is off for this project from the next session (.claude/settings.local.json); plugin option memory_turns_off_auto: false leaves it on`.

The option joins the plugin's `userConfig` beside `memory_language` and `memory_require_git` (20261026-000502-d-tac-yrx lists every option in `README.md`'s Options section). It builds on the seat claim of 20261025-014326-d-tac-mvn.

Why: Claude Code's auto memory files notes into `~/.claude/projects/<project>/memory/` and loads its index into every session, beside agentic-memory's seats; an agent then keeps two memories that drift apart, and the project rule that no parallel memory store exists is broken by default. Nothing turns it off from inside a session: a plugin's `settings.json` applies only `agent` and `subagentStatusLine`, and `autoMemoryEnabled` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY` apply as a session starts. The project's local settings are the narrowest place that holds from the next session on, and a claim is the moment a project starts using agentic-memory.

Rejected:

- The global switch in `~/.claude/settings.json`, set by hand: turns auto memory off in projects where no seat is ever claimed.
- Docs only: both memories keep running until someone acts.
- Option named `memory_auto_memory_off`: names memory twice and reads as a switch for auto memory everywhere. Default false: changes nothing until an owner opts in, the state that leaves both memories running.
- Overwriting an `autoMemoryEnabled: true` the file already carries: the owner's own setting for the project.

Accepted costs:

- agentic-memory writes a Claude Code settings file, the local one only, and the repository's `info/exclude`.
- The session that claims still runs with auto memory; the next one does not.
- Deleting the key undoes it only until the next claim; `autoMemoryEnabled: true` in the file, or the option set to false, keeps auto memory on.

Acceptance criteria:

1. A claim in a project without `.claude/settings.local.json` creates it holding `autoMemoryEnabled: false`, prints the line once, and adds `/.claude/settings.local.json` to `info/exclude` where git does not ignore the file.
2. A claim in a project whose file holds other keys adds the key and keeps every other key and the existing text around it.
3. A file already setting `autoMemoryEnabled` to true or false is left byte-identical, and no line is printed.
4. A file that does not parse is left byte-identical, and the claim says it was left alone.
5. With `memory_turns_off_auto: false`, no file is touched and no line printed.
6. A claim from a worktree writes the main checkout's file.
7. `memory_turns_off_auto` is declared in `plugin/.claude-plugin/plugin.json` `userConfig` and listed in `README.md`'s Options; `docs/memory/usage.md` and `agentic-helpers:agent-memory` describe it.
