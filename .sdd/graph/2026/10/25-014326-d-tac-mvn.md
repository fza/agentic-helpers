`agentic-memory` replaces `agentic-carryforward`, in one release. A session no longer rewrites a carry-forward file: it files entries (`agentic-memory new`), each with a 3-10 word title, a free-form body, one or more topics it chooses, a retention level and a source, and the tool stamps and indexes each one the moment it lands. Nothing is ever rewritten: entries are retired or superseded, and the tool, not the agent, chooses what returns to a fresh context. Every agent-facing operation is both a subcommand and a tool of the plugin's MCP server `memory`. The attached `design.md` carries every decision with its rejected alternatives, every surface, and the acceptance criteria.

The shape, in short:

- **Storage.** The log is the truth, under `~/.claude/agentic-memory/<project>/`, `<project>` keyed as sdd keys its search index (`repo_id`, else `local/<sha12 of the stable root>`). Events append to `log/tail.jsonl`, which seals past 64 KB into immutable, content-hashed binary segments (`<sha256[:8]>.seg`, row table first, mapped read-only), merged at eight. Vectors, heat and per-session state are a cache under `~/.cache/agentic-memory/<project>/`.
- **Seats.** A seat is a named job held by one session; claiming one (`agentic-memory claim <seat> [--force]`) is the only opt-in, and no `.memory/` directory exists. A call finds its seat through the owning `claude` process, so a Bash-run command, an MCP tool call and the grounding gate's `exempt_seats` all resolve alike. Every entry carries its seat; search defaults to the own seat and widens with `--seat` or `--all-seats`, so seats see each other's work and nothing is done twice.
- **Recall.** A brief at claim and after every compaction (at most 9,000 characters: `standing` entries, then heat-ranked live entries, then other seats' news and changes, then topic counts); prompt recall in `UserPromptSubmit` (top three hits standing out at `μ + 2σ`, another seat's at `μ + 3σ`); heat decaying by retention level (`standing`, `long` 90 days, `normal` 14, `short` 3, `scratch` 12 hours).
- **Stale truths.** Every entry is stamped with time, seat, session, branch and commit, and anchored to the files it names by content hash; every result shows `drifted`, `gone` or `other branch` as computed at read time, and `confirm` re-anchors.
- **Lifecycle.** `retire` keeps an entry in results, flagged; `supersede` takes exactly one of `--by <id>`, which shadows the entry for good, or `--because '<why>'`, which `--with-superseded` brings back; bodies are dropped 14 days after a supersede; `revive`, `retitle`, `tag`, `retain`, `merge` are events like every other.
- **No handoff.** Filing as work goes and a nudge ladder before compaction (answered by any filed entry) keep memory current. Claude Code's own transcript is read in place: after a compaction the turns since the seat's newest entry come back, and a session's last turns survive its end as a slice the next claim prints.
- **Embedder.** One per machine, set through the plugin's `userConfig` (`embedding_provider`, `embedding_model`, `embedding_endpoint`, `embedding_dimensions`, `embedding_api_key_env`, plus `entry_max_words`, default 500), read from `pluginConfigs` in user and managed settings. Semantic search fails closed without it; filing never waits on it.

Why: rewriting a carry-forward file by hand is the costly, often skipped work the carry-forward depends on, and a file curated by one agent holds only what that agent chose to keep. Filing an entry costs one call, keeps everything, and leaves the choice of what to replay to rules keyed on time, use and importance, which hold for a session that runs for days through many compactions as well as for one claimed and closed again often.

Rejected: keeping the carry-forward beside it for a trial (two seat stores and a gate checking both, for a design that replaces rather than extends); a forwarding shim under the old name; one JSONL replayed whole on every call; one file per entry; SQLite through `modernc.org/sqlite`; a refusal for long bodies or malformed titles, each costing a full resend.

Accepted costs: no fallback short of reverting the release; memory lives outside the repository, so a project declaring no `repo_id` loses it to a move or a fresh clone; `agentic-memory` parses settings and transcript files Claude Code owns; recall by meaning breaks while the model server is down; every caller of `agentic-carryforward` (hook texts, skills, fdbox's seat, instruction files, a status line writing the context reading) changes in the same release.
