agentic-helpers refuses sdd's embedder whenever `sdd config get embedding` reports the endpoint from the `project` layer, the repository's committed `.sdd/config.yaml`, so a cloned repository cannot choose where memory entries and prompts are sent.

Why: the sdd fallback of 20261030-083307-d-tac-q74 takes sdd's whole embedding block, and sdd layers a repository's committed `.sdd/config.yaml` (shown as `(project)`) over the user's global layer. Under `auto` with no own provider, the default on a fresh machine, any clone could set `embedding.endpoint` to a server of its choosing, and agentic-memory would send every entry it embeds and every prompt it recalls against there. Sending no API key, as q74 already rules, does not stop that: the text itself is what leaks. 20261029-145943-d-tac-gp7 kept the endpoint out of agent-writable files for the same reason; a file a stranger commits is weaker still.

**Rule.** `embed.Settle` reads the layer of each key sdd prints. An endpoint from the `project` layer refuses the whole block (`embed.ErrProjectEndpoint`) and leaves search by meaning off. Provider, model and templates from that layer still apply, since they send nothing anywhere new. The global and local (`.sdd/config.local.yaml`, uncommitted) layers apply as before. Under `auto` and `sdd` alike (20261030-084308-d-tac-pz4) the session start says so: `agentic-helpers: sdd's embedding endpoint is set in this repository's .sdd/config.yaml, which a clone brings along; search by meaning stays off until `sdd config set` sets it in sdd's own layer, or embedding_provider and embedding_endpoint set one here`.

**Rejected.** Making `own` the default source: safe, but every machine would lose semantic search until configured, which pz4 rejected for the same reason. Accepting only a loopback endpoint from the project layer: still lets a repository aim requests at local services, and leaves a rule to test per address form. Ignoring only the project layer's endpoint and keeping the global one: sdd prints only the effective value, so the global endpoint is not knowable without reading sdd's files, which q74 rejected.

**Accepted costs.** A team that commits its embedder endpoint to `.sdd/config.yaml` gets no search by meaning from the fallback until each member sets it in sdd's global or local layer. Under `auto`, the session-start check now runs `sdd config get embedding` once wherever no own provider is set.

**Acceptance.**
- An sdd block whose endpoint is `(project)` yields no embedder and `ErrProjectEndpoint`; the same block with the endpoint `(local)` or `(global)` applies.
- The session-start check prints the line above under `auto` without an own provider and under `sdd`, and nothing under `own`.
- README `Options` states the refusal.
