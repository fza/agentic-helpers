Four points `config.yaml`'s tighten-only rule (20261029-145943-d-tac-gp7) left open, settled as built:

- **`shell_guard_secret_output`** takes `all`, `files` or `off`, not a boolean. Its strictness is `off` < `files` < `all`, so `config.yaml` may only set `all`, its default.
- **Keys `config.yaml` never sets** (`embedding_endpoint`, `embedding_api_key_env`, `shell_guard_secret_output_skip`) get their own wording, since "may only tighten" does not fit them:
  - `agentic-helpers check`: `agentic-helpers: config.yaml never sets <key>; <value> ignored`
  - `agentic-helpers config set`: `refused: config.yaml never sets <key>; set it in Claude Code's settings`, for any value, an empty one included.
- **The `CLAUDE_PLUGIN_OPTION_<KEY>` environment layer is never read for those keys.** An agent can prefix its own Bash command with these variables; for the embedder that would name another secret's variable as the key and send it to an endpoint the agent chose, in a command holding no credential text for shell-guard to ask about. None of the three is a `sensitive` plugin option, so Claude Code keeps them in `settings.json` `pluginConfigs`, which the user and managed layers read; the environment added nothing legitimate. Every other key still takes the environment layer: hooks get it from Claude Code, and an agent's prefix never reaches a hook.
- **`agentic-helpers config` marks each key** `config.yaml only tightens` or `never config.yaml`.

**Accepted cost.** `CLAUDE_CONFIG_DIR` still chooses the user settings file, as it does for Claude Code itself. An agent can stage a settings file and point the variable at it. Any user-level path, `HOME` included, is one a shell running as the user can redirect, so no user-level read is tamper-proof; managed settings are the only lock, and they fold last for every key.

**Rejected.** Ignoring `CLAUDE_CONFIG_DIR` for these keys: breaks the embedder for every user who relocates Claude Code's config, and an agent sets `HOME` as easily. Comparing it with a value the SessionStart hook records: the record sits in a file the same agent can rewrite.

**Acceptance.** `TestConfigYAMLNeverSetsTheEmbedderOrTheSkipList`: an environment value alone sets none of the three keys, `settings.json` wins over it, and `embedding_model` from the environment still applies. `TestConfigYAMLMayOnlyTightenAGuard` and `TestSetRefusesALooserGuardAndEveryKeyConfigNeverSets` cover the ranking and both refusals.
