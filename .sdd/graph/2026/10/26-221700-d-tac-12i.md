`agentic-memory untag <id> <topic>...` (MCP `untag`, keys `id` and `topics`) removes topics from an entry. Removing the entry's last remaining topic is refused: `<id> keeps at least one topic; tag the right one first: agentic-memory tag <id> <topic>`. Any seat on the entry's shelf may untag, as with `tag`; a seat on another shelf is refused `<id> is on shelf <name>`.

Why: a topic could be added to an entry with the `tag` verb of the agentic-memory directive (20261025-014326-d-tac-mvn) but never taken off, so a wrong one stayed for the entry's life. One heavy seat had to file an entry again only to drop a stale topic. `merge <from> <into>` renames a topic across the store and cannot take one off a single entry.

Rejected alternatives:

- `retag <id> <topic>...` replacing the whole list: a second way to add topics beside `tag`, and a typo in the list drops topics the call meant to keep.
- Allowing an entry with no topic: every entry carries at least one, which `brief --topic` and the topic counts rely on.

Accepted costs:

- Replacing an entry's only topic takes two calls, `tag` then `untag`.

Acceptance criteria:

1. `untag` removes the named topics and the change shows in `show`, `search` and the topic counts; MCP the same.
2. Untagging the last topic is refused with the wording above; untagging a topic the entry does not carry is refused naming it.
3. A seat on another shelf is refused.
4. The event appears in the shelf mates' `changed on shelf` notice as `tag` changes do.
5. Skill and docs name `untag`, in the same change.
