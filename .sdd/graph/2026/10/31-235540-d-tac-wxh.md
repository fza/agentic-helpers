Each subagent gets its own set of shown entries, and every memory call it makes carries its agent id, so a `(seen)` pointer reaches an agent only for text its own context holds. A forked subagent's set starts as a copy of its parent's set at the moment of the spawn, since a fork inherits the parent's context; a fresh subagent's starts empty. The parent's set is never touched by a subagent's read. Today the set is kept per session (`source/hooks/internal/memory/presented.go`) and a subagent runs in its parent's session, so a subagent's `show` or `search` marks entries for the parent, which then gets bare pointers to text it never held; the done 20261031-214728-s-tac-msb names this as a cost of the subagent ladder 20261031-202547-d-tac-xmy.

**Tagging.** `agentic-memory pre-tool` already rewrites a `full` subagent's Bash call with the hidden `--agent <id>`; it does so for every subagent level that reads (`silent`, `shared`, `full`), and adds an `agent` key to each memory MCP tool call such a subagent makes. Every memory MCP tool's schema gains that `agent` key. The CLI and the MCP server refuse an agent id the session's subagent records do not name, as the CLI refuses `--agent` today, so a parent cannot read through a subagent's set. `agentic-memory pre-tool` on the `Agent` call that spawns the subagent tells a fork from a fresh one by that call's `tool_input.subagent_type` (`fork`), and copies the parent's set then.

**Consequence.** Fresh subagents no longer pass `--again`: their own set starts empty, so their first read of an entry prints it in full. The agent-memory skill drops that instruction.

**Rejected.** Saving the session's set before a subagent's call and restoring it after: simplest, but a fork gets pointers for entries the parent read after the fork started, and a fork's second read of an entry prints it in full again. Swapping the subagent's set in for the length of its call, with no schema change: a parent read landing while a subagent's call is in flight reads with the subagent's set and can get a bare pointer to text it never saw, the very error being fixed.

**Accepted costs.** One more key in every memory MCP tool's schema, visible to every agent that loads one. A set slot per subagent, removed at `SubagentStop` and at session end.

**Acceptance.**
- A fresh subagent's `show <id>` prints the body in full without `--again`; its second `show <id>` prints a pointer.
- A fork's `show` of an entry the parent read before the spawn prints a pointer; of one the parent read after the spawn, the body in full.
- After a subagent read an entry the parent never read, the parent's `show <id>` prints the body in full, by Bash and by MCP alike.
- A parent's call naming a subagent's id, by `--agent` or the `agent` key, is refused.
- Live proof that the hook tells a forked from a fresh subagent.
- `docs/memory/usage.md` (`## Subagents`), `docs/memory/architecture.md` and the agent-memory skill describe it.
