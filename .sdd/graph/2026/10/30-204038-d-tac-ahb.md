Every write tool of the memory MCP server answers `{"message": <the text the command prints>}` alone, as `new` does under 20261030-202708-d-tac-962, and each write's text stops echoing the ids, topics, title or seat the caller just sent; reads keep their JSON.

**Why.** Measured over the 907 replies of `state`, `link`, `supersede`, `retire`, `ack`, `confirm`, `retitle`, `tag`, `untag` and `due` in three days of transcripts: 68.6k characters as sent, 38.7k as `message` alone, 26.6k with the echo cut, a 61% saving. The typed fields beside each message (`seat`/`shelf`, `ids`, `id`/`target`, `by`/`because`, `title`, `topics`, `due`) repeat the message word for word, as `new`'s did, and the messages repeat the caller's own input (`state of main written`, `retired m-x, m-y`, `m-x linked to <target>`). Under 20261029-021515-d-tac-00q nothing an agent acts on leaves: every refusal names what failed, and a write either lands whole or not at all.

**The texts.**
- `state`: `state written`, plus the over-length note where it fires.
- `retire`: `retired`. `supersede`: `superseded`, plus the lines naming each todo item `--items carry` moved onto the successor.
- `link`: `linked`, plus the lines naming an entry the link ended; a tool link `linked` or `unlinked`.
- `tag`, `untag`, `retitle`: `tagged`, `untagged`, `retitled`, plus the title-length note.
- `ack`: the verb alone (`done`, `undone`, `dropped`, `removed`), plus the lines naming a todo the ack ended; `ack --add` keeps `added <todo>#<id>...`, since the item ids are new; `ack --order` answers `reordered`.
- `due`: `due <time>`, the time normalized, or `due cleared`.
- Unchanged, since they carry what the caller did not send: `confirm` (anchors re-hashed, against which commit), `claim` (the brief), `release`.

The command line prints the same texts, so a message still equals the CLI text. Fields leave every memory tool, the CLI-only ones included, since nothing reads them: `--json` covers reads alone. The tools server is out of scope: its writes are rare (5 replies in three days).

**Rejected.**
- Message alone with the echo kept: 38.7k, leaving the caller's own input in every reply.
- Verb-only texts for `ack --add` and `confirm` too: the new item ids and re-hash counts are outputs an agent acts on.
- Grouping `who --all` by project or answering reads as text lines: separate questions with their own trade-offs.

**Accepted costs.** A script reading a write tool's MCP fields breaks; none is known. Wording of every changed write text changes on the CLI as well, a contract change made on purpose; docs and skill lines quoting the old texts change with it. It ships as a minor release, as 20261030-202708-d-tac-962 does.

**Acceptance.**
1. Every write tool of the memory MCP server answers an object holding `message` alone, equal to the CLI text.
2. Each changed text reads as listed above; `confirm`, `claim` and `release` read as before.
3. A link or ack ending an entry, a supersede carrying items, an `ack --add`, and an over-length state or title still name what they name today.
4. `docs/memory/usage.md` drops its table of fields beside `message` under MCP answers and quotes the new texts; no skill or doc quotes an old one.
5. The tests asserting criteria 1 and 2 each fail when the field or echo they rule out is put back.
