Embedder input sizing and the `embedding_path` option of 20261031-113332-d-tac-l3a, as refined by 20261031-113450-d-tac-bmm and 20261031-114135-d-tac-3s1, are built on `main` in commits 8d6ecc6 and f9c5e3b, not yet pushed or released; projects running the 2.20.0 release still embed uncapped.

Built as decided, with sdd's constants and wording: probes of 1000 Latin, 1000 CJK and 20000 runes, bisect tolerance 64, plateau fraction 0.9, margin 0.9, cap rounded down to 64 runes; the calibration file `calibration-<16 hex of sha256(fingerprint, URL, path)>.json` under the cache home, written atomically; `max_runes` in each vector store's manifest; every row keyed by hash(content, cap); readers cut queries to the manifest's cap and never probe; no batch split.

**Migration rule.** The upgrade is silent: the first fill per store and endpoint calibrates, records the cap and re-embeds once, saving per request. Every path that writes rows (memory's fill, the tool library's fill and its add, update and merge) calibrates or fails, so no row is written without a cap. Failures are loud: `search --query`, `find --query` and `reindex` refuse naming the cause (`calibration latin probe: ...`, `calibration cjk probe: ...`, `reading calibration <path>: ...`, `calibration for <key> holds no usable rune cap (N)`, `calibrated limit of N tokens leaves no room for a 64-rune cap`); prompt recall prints its existing failure line once per outage.

Evidence: `go vet` and `go test -race ./...` pass; each new guard was broken and caught by its own named test, files restored byte-identically. Live, this checkout's store calibrated by plateau to a 2048-token limit, cap 1792 runes, recorded in its manifest; recall timed out once during that first re-embed and recovered on the next prompt. An isolated-home run against rapid-mlx at 127.0.0.1:1235 searched a 132,000-character query and an entry of about 40,000 characters with exit 0, the store recording the same cap. rapid-mlx's own log was not read, so the done-when's "no truncation line" rests on every input being cut below the measured limit.

Deviations:
- A path-less endpoint ending in `/v1` still gets `/embeddings`, so existing settings keep working.
- sdd's `path` from a repository layer refuses the whole block, as its endpoint does.
- The tool library fills its vectors before `find --query` and before the prompt hook that offers a matching library tool compares the prompt, which the silent upgrade needs.
- Legacy `vectors.gob` and the tools JSON cache are deleted and re-embedded, since their rows carry no cap.
- Entry chunks keep their existing 3200-rune size as an upper bound under the calibrated cap, so a model with a large input limit gets no larger chunks than before.
