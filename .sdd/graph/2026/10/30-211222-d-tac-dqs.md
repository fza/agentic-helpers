The memory MCP server's `search`, `brief`, `view` and `who` answer `{"message": <the text the command prints>}` instead of their `--json` object; `show` and `topics` keep answering JSON, and `--json` on the command line stays for scripts.

**Why.** Measured on one checkout, the JSON of a read costs 2 to 7 times its text: a 10-hit `search` 5.1k to 7.4k bytes against 1.9k to 3.7k, `brief` 20.9k against 3.0k, `view` as a list 20.3k against 6.5k, `who --all` 14.8k against 5.6k. Every entry repeats every key and stamp (`seat`, `shelf`, `kind`, `retention`, `from`, `filed` in full RFC 3339, `branch`, `commit`, `status`), and `brief`'s JSON lists every live entry where its text caps each section. Over three days of transcripts these four reads came to about 320k characters, half of it JSON syntax. Agents already act on the text form: every claim prints the brief as text, and every Bash call to `agentic-memory` answers text. Under 20261029-021515-d-tac-00q the text is no riskier, since it carries every line, flag, score and `more:` hint an agent acts on, and it costs far fewer tokens.

**What stays JSON.** `show`, whose JSON is no larger than its text (1.3k against 1.4k for one entry, the body dominating), and `topics`, a short count. `view`'s `explain` already answers a message.

**Rejected.**
- Keeping JSON and dropping stamps an agent never acts on, plus grouping `who --all` by project: about 30-40% saved, still costlier than text, and it reverses 20261029-130234-d-tac-s4c's only-empty-keys rule anyway.
- Grouping `who --all` by project alone: leaves the 2-7x overhead of `search`, `brief` and `view`.
- Leaving reads as they are: about 160k characters of overhead every three days.

20261029-130234-d-tac-s4c rejected text over MCP because the agent would lose the typed fields 20261027-180531-d-tac-04v gave it. An agent reads text lines as readily as keys and acts on the same values either way; scripts, which need the keys, call `--json`.

**Accepted costs.** A script reading these four MCP answers as JSON breaks; none is known. `docs/memory/usage.md`, `architecture.md` and the skill's `reference.md` stop describing their MCP keys. Ships as a minor release, as 20261030-204038-d-tac-ahb does.

**Acceptance.**
1. Over MCP, `search`, `brief`, `view` and `who` answer an object holding `message` alone, equal to the CLI text for the same arguments; `show` and `topics` answer their `--json` object as before.
2. The CLI's `--json` answers of all six are unchanged.
3. The `<id> <title> (seen)` pointers printed for an entry already shown in the context, scores and `more:` hints appear in the MCP answer as in the CLI text.
4. Docs and the skill describe the new MCP answers and no longer list keys for the four reads.
5. The test asserting criterion 1 fails when any of the four answers JSON again.
