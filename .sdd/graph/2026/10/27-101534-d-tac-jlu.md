Two changes to shell-guard's asks. A command name that can split into several words, an unquoted expansion (`$CMD`), a glob or a brace (`{rm,-rf,/}`), asks even with no arguments, where the dynamic-commands directive (20261027-090426-d-tac-gj8) let a name with no arguments run; a name wholly in double quotes with no arguments (`"$tool"`) still runs. And an ask an agent can fix by rewriting the command refuses with its reason the first two times in a session and prompts the user only on the third.

Why: `CMD='rm -rf /'; $CMD` runs a removal with no argument written, so "no arguments" was no proof of harmlessness. A shell-guard ask puts a permission prompt in front of the user for a command the agent could have written plainly; refusing with the reason first lets the agent rewrite it, and the user sees only a command the agent could not make judgeable.

Which asks refuse first: a command name that is not fixed text, a launcher option value that may split, and a command holding what looks like a credential (20261026-223236-d-tac-vr7: reference it as `"$NAME"` instead). An outside-project removal and `find -delete` prompt at once, since no rewording makes them judgeable.

Mechanics: the count is per session and per reason, kept in shell-guard's per-session state file (`$XDG_CACHE_HOME/agentic-helpers/shell-guard/<session>.json`), the file the auto-mode countdown of 20261026-223555-d-tac-1ny already writes; the refusal says `<reason>; rewrite the command (attempt <n> of 3)`; the third attempt answers `ask`, and that prompt follows the permission mode (20261026-223555-d-tac-1ny). A `deny` setting denies every time; `off` passes.

Rejected alternatives:

- Refusing first for every ask: an intended removal outside the project would take three tries before the user could approve it.
- Only the dynamic-commands verdicts: a command holding a credential would still prompt at once, though `"$NAME"` fixes it.
- Keeping no-argument names running: the split case runs a removal unjudged.

Accepted costs:

- A bare `$CMD` or `$EDITOR` is refused, then asks.
- Two refusals before a user can approve a deliberate command of these shapes.
- Per-session state for the count, and the refusal wording in the hook's contract, quoted by agentic-helpers:agent-shell-guard.

Acceptance criteria:

1. `$CMD` and `{rm,-rf,/}` alone get the verdict; `"$tool"` alone runs.
2. For each rephrasable reason: attempts one and two deny with the attempt count, the third asks; a new session starts at one; a different reason counts apart.
3. `rm ~/x` and `find / -delete` ask at once.
4. Skill and `docs/shell-guard/` name the rule and the wording.
