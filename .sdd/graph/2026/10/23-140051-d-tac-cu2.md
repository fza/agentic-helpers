summary: The plugin moves into its own `plugin/` directory so the repository's development MCP server (`.mcp.json`) no longer loads in every session running the plugin. It builds on the plugin layout at the repository root (20261023-115644-d-tac-4ni) and narrows the plugin distribution's shipped content (20261023-115501-d-cpt-sd6) to the plugin's own files, with the marketplace staying at the root and the fix shipping as a patch release.
---

The plugin lives in `plugin/`, and the marketplace at the repository root points at it with source `"./plugin"`. Only the plugin's own files ship; the repository root keeps what serves work on the repository.

- `plugin/.claude-plugin/plugin.json`, `plugin/hooks/hooks.json`, `plugin/hooks/run`, `plugin/bin/agentic-capture`, `plugin/bin/agentic-carryforward` and `plugin/skills/` hold what `.claude-plugin/plugin.json`, `hooks/`, `bin/` and `skills/` held. `.claude-plugin/marketplace.json` stays at the root.
- `.mcp.json`, `CLAUDE.md`, `AGENTS.md`, `README.md`, `source/`, `.sdd/` and `.github/` stay at the root and never reach a plugin install.
- `.releaserc.yml` writes and commits the version in `plugin/.claude-plugin/plugin.json`. The launcher, the release archives, the data directory and the install commands are unchanged.
- The fix ships as a patch release.

Why: Claude Code reads a plugin's root for every component it supports, `.mcp.json` included, so with the repository root as plugin root the repository's development MCP server (`sdd serve`, always loaded) became `plugin:agentic-helpers:sdd` in every session running the plugin, and fdbox hands installed plugins' MCP servers to its board jobs. An empty `mcpServers` in `plugin.json` does not stop it. A directory of its own also keeps the repository's `CLAUDE.md`, sources and graph out of every plugin install.

Rejected: deleting the repository's `.mcp.json`. Sessions in this repository would get the `sdd` server only from user-level configuration, which a fresh clone lacks, and the next root file Claude Code reads from a plugin (`.lsp.json`, `agents/`, `commands/`) would leak the same way.

Accepted cost: the skills' path in the checkout becomes `plugin/skills/`, and every path in the tests, the release configuration and the docs moves with it.

Done when a session loading the plugin from the checkout starts no `plugin:agentic-helpers:*` MCP server and still runs every hook through `plugin/hooks/run`; `claude plugin validate .` passes for the marketplace and for `plugin/`; `go test -race ./...` passes with the plugin suite reading `plugin/`; a release run writes the version into `plugin/.claude-plugin/plugin.json`; `README.md` and `AGENTS.md` name the new paths.
