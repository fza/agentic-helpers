The plugin launcher `plugin/hooks/run` takes its per-version fetch lock as a symlink, `.fetch-<version>`, whose target is the fetching process's pid, created with `ln -s "$$"`; the download and unpacking run in a work directory beside it, `.fetch-<version>.<pid>/`. A lock never exists without its owner: `ln -s` creates the name and its target in one `symlink(2)` call and fails if the name exists, on darwin and Linux alike, so a fetch killed at any moment leaves either no lock or a lock naming a dead pid, which a waiter takes over at once. Everything else the fetch-lock directive (20261025-165016-d-tac-9xz) set stays: one fetch per version, signal traps removing the lock and work directory, waiters checking the owner every second, a race-safe takeover through `.takeover`, and an earlier launcher's directory lock honoured by its `owner` file, or the five-minute rule where it has none.

Why: that directive took the lock with `mkdir` and wrote the owner as a second step, accepting that a lock caught between the two waits five minutes. Claude Code kills an MCP server that has not connected within 30 seconds, and a kill in that window stalls every hook and command up to their 100-second wait; a test killing a fetch under load hit it as a flaky 103-second failure.

Rejected alternatives:

- Building the lock directory with its owner under a temporary name and renaming it into place: macOS `mv` has no `-T` and moves a directory into an existing one instead of failing.
- A shorter age for an ownerless lock: a slow fetch could be taken over while alive, fetching twice into one lock.
- `flock`: not on macOS by default.

Accepted costs:

- `ln -s` onto an existing directory creates the link inside it and succeeds, so the launcher counts the lock taken only when `readlink` names its own pid, and otherwise removes the stray link and waits.
- Two names per fetch, the lock and its work directory.

Acceptance criteria:

1. A fetch killed without a trap at any point is taken over at once, nothing left behind, checked with the kill after the lock names the fetch.
2. A live owner's lock is waited on however old; an earlier launcher's ownerless directory lock is waited on while young and taken over once stale.
3. Parallel starts still fetch once; signals still clean up.
4. `docs/plugin/architecture.md` describes the symlink lock.
