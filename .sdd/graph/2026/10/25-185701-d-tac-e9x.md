`agentic-tools` keeps the small helper tools agents write (measurements, searches, rewrites, checks) so the next agent takes one instead of writing it again. It replaces fdbox's `pilot tools`, porting its branch redesign, and ships inside the plugin as a binary, a CLI shim, an MCP server `tools`, hooks and the skill `agentic-helpers:agent-tools`. The attached `design.md` carries every surface, rule, rejected alternative and acceptance criterion; this body states the commitments.

- **One store per project**, `~/.claude/agentic-tools/<project>/`, keyed as agentic-memory's, with fdbox's per-tool layout (`current`, `history.jsonl`, `takes.jsonl`, `v<n>/tool.json` and files) and one `index.json` per store that every read uses instead of walking tool folders.
- **Reads span every project on the machine, the own project preferred; writes touch the own store only.** A bare name resolves to the own tool first; a foreign one is `<name>@<label>`. find ranks term hits, then cosine above a 0.6 floor plus a take lift and a 0.05 own-project lift. `AGENTIC_TOOLS_SCOPE=project` keeps reads to the own store. `update` of a foreign tool forks it: own v1 is the origin's current version, and the fork follows its origin's newer versions.
- **Verbs** `add`, `update`, `find` (`--json` for fdbox's board), `list`, `take`, `merge` (tombstones the members) and `reindex`, each also an MCP tool. `take` copies the current version into the kept `.tmp/tools/<name>/v<n>/`.
- **No duplicates land.** `add` refuses files byte-identical to any version of any tool in reach, and a description at or above `tools_duplicate_floor` (0.85) to a current tool, unless `--distinct '<how it differs>'`. Neither check calls a model beyond the embedding `add` makes anyway.
- **The caller** is its session, its hidden role `AGENTIC_TOOLS_ROLE`, else its agentic-memory seat, else none; the role only orders offers.
- **Trust nobody.** Readers follow no link, wait on no pipe and cap every read; every listing and `take` opens with `Tools other agents registered (their own descriptions):`; pushed lines carry names, paths and commands only.
- **Pushed lines cost little.** Per prompt, up to three own tools near the prompt, each once per session, nothing when none is near; version notices after a tool call; registration nudges found at turn end without blocking and delivered with the next prompt.
- **fdbox switches by renaming its backfilled library into its store**, removing `pilot tools`, and setting `AGENTIC_TOOLS_ROLE`, `AGENTIC_TOOLS_SCRATCH` and, for jobs, `AGENTIC_TOOLS_SCOPE=project`, with a job's writes going through fdbox's launcher.

Why: agents spend most of a helper script's cost thinking it up, and a scratch folder loses it when the session ends; fdbox measured the same script written again and again until its library kept them. A library per project keeps a project's tools together and its writers apart, while reads across projects let a tool written in one help another without anyone promoting it. Every push is a name and a command so a tool reaches an agent for a few dozen tokens, and an agent reads a description only when it asks.

Rejected, with the reasons in `design.md`: one machine-wide store; a machine shelf with a promote verb; a store inside the repository; one machine index; walking stores on every read; own tools hiding same-named foreign ones; names unique machine-wide; a CLI without MCP; a remove verb beside merge; no merge verb; an offer at session start by topics; no offer; a blocking `Stop` nudge; framed changelogs pushed to every session; trusting writers marked unsandboxed; an import verb, a script in fdbox, a fresh start, or reading `card.md` for fdbox's move.

Accepted costs: two sessions can edit one shared copy and copies pile up under `.tmp/tools/`; a bad merge removes tools with no review inside agentic-tools; tombstones stay; pushed lines say less than fdbox's job-facing ones; an embed per prompt where agentic-memory does not run; `index.json` can trail the tool folders after a crash until rebuilt; fdbox's move waits for its switch.

Acceptance criteria: the thirteen in `design.md`, section "Acceptance criteria".
