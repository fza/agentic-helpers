agentic-helpers releases through Homebrew from semver git tags, built and published by GoReleaser in GitHub Actions.

- A release is a pushed tag `v<major>.<minor>.<patch>`. Nothing else cuts one.
- `.github/workflows/test.yml` runs `go vet ./...` and `go test -race ./...` in `source/hooks` on every push and pull request.
- `.github/workflows/release.yml` runs on a pushed `v*` tag: the same tests first, then GoReleaser through `goreleaser/goreleaser-action`. A failing test publishes nothing.
- `.goreleaser.yaml` at the repository root builds every binary under `source/hooks/cmd/` for darwin and linux, arm64 and amd64, with `CGO_ENABLED=0`, and packs each platform's binaries with `skills/`, `README.md` and `LICENSE` into one archive attached to the GitHub release.
- GoReleaser writes a cask through `homebrew_casks` to the tap repository `fza/homebrew-tap`, under `Casks/agentic-helpers.rb`. Users install with `brew install fza/tap/agentic-helpers`.
- The release workflow pushes to the tap with a repository secret `HOMEBREW_TAP_TOKEN`, a token allowed to write `fza/homebrew-tap` and nothing else.
- `go install -C source/hooks ./cmd/...` from a checkout stays a supported install path.

Why: a Homebrew install needs a fixed artifact and checksum per release, and a machine without Go or a checkout should still get the hooks. GoReleaser in Actions makes the tag the whole release step, and the test workflow puts the suite in front of every change and every release rather than on the developer's machine alone.

Rejected:
- A formula built from source in the tap, bumped by hand per tag. Every install needs Go 1.27, and each release owes a manual url and sha256 edit.
- A HEAD-only formula tracking main. A plain `brew upgrade` skips it, and no release can be pinned as known good.
- GoReleaser's `brews` section. GoReleaser deprecated it for `homebrew_casks`.
- Submitting to homebrew-core. Its notability bar and review cycle do not fit a tool with one maintainer's machines as its users.

Accepted costs: a version number now exists and somebody decides each bump; the release needs a token kept valid in the repository's secrets; the binaries are unsigned, so the cask strips the quarantine attribute on macOS after install; how `agentic-install` finds the skills and which binary path it wires under Homebrew is decided separately, and until then a Homebrew install wires nothing.

Done when a pushed `v*` tag runs the tests, publishes a GitHub release carrying the darwin and linux arm64 and amd64 archives each holding every binary and `skills/`, and commits `Casks/agentic-helpers.rb` to `fza/homebrew-tap`; a push and a pull request run `go vet` and `go test -race` in `source/hooks`; `README.md` describes the Homebrew install and how a release is cut.
