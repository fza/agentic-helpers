Agents write a seat's state slot when a nudge asks for it (the shipped-work request, the near-compaction nudge and its Stop backstop, the replay-overflow nudge), not whenever the picture changes. The `agentic-helpers:agent-memory` skill says so, and `docs/memory/usage.md` states it under the state slot.

**Why.** Writes into memory are the agent's output tokens, the costliest kind. In 36 hours of transcripts machine-wide (25 seated sessions), agents wrote the state slot 611 times: a median of 15 writes per session, up to 89, at a median 713 characters (p90 1174). 293 writes (48%) followed no nudge, 173 the shipped-work request, 112 the near-compaction nudge, 31 the overdue backstop. The skill's line "write it whenever the picture changes and whenever a nudge asks" invites the unprompted ones, yet the shipped-work request of 20261027-222420-d-tac-ac7 already fires on what changes the picture: a moved HEAD, a new graph entry, or `state_stale_after_writes` file writes (default 5). Each unprompted write rewrites the whole slot.

**Risk, judged low.** Between nudges the state lags at most one shipping period. A compaction is preceded by the near-compaction nudge; the post-compaction replay carries every turn since the newest write; a session ending without a write leaves the Stop and SessionEnd hook draft. The token-cost criteria of 20261029-021515-d-tac-00q rank least risk first, then fewest tokens.

**Rejected.**
- Raising `state_stale_after_writes`: fewer requests, but the slot lags further behind file work, and it leaves the unprompted writes untouched.
- A word cap on the state body: cuts the slot a resumed session reads first; the length is already terse at the median.
- Leaving the rule as is: about 210k characters of agent output per 36 hours that the nudges make redundant.

**Accepted cost.** A state written only on request can describe the work one shipping period old when a session is read mid-period, for instance by `who` from another seat.

**Acceptance.**
1. The skill's state rule names the nudges as the time to write and drops "whenever the picture changes"; `docs/memory/usage.md` says the same.
2. After a release, the share of state writes following no nudge is re-measured with the same method and drops well below 48%.
