A new option, `embedding_source`, decides where agentic-helpers takes its embedder from: `auto` (default), `sdd` or `own`, so the sdd fallback of 20261030-083307-d-tac-q74 can be forced either way instead of following only from whether `embedding_provider` is set.

- `auto`: as 20261030-083307-d-tac-q74 decided. An own `embedding_provider` means only own keys apply; without one, sdd's whole embedding block applies, read with one `sdd config get embedding` per process.
- `sdd`: sdd's whole embedding block applies whatever own `embedding_*` keys are set; `agentic-helpers check` names the ignored ones at session start: `agentic-helpers: embedding_source is sdd; <keys> ignored`. No sdd on the PATH, or no embedding block, leaves semantic search off and the check line says so.
- `own`: sdd is never run; without an own provider semantic search is off.

Under sdd's block no API key is sent, in `auto` and `sdd` alike, as 20261030-083307-d-tac-q74 set. The option is declared in `userConfig` as a picker under 20261030-083534-d-tac-ws7 and is overridable in every layer: it chooses which configuration applies, and sends no secret anywhere.

Why: with only the implicit fallback, a machine with its own provider set could not follow sdd's setup without clearing every own key, and a machine wanting no sdd call at all had no way to say so.

**Rejected.** A boolean `embedding_follow_sdd` replacing the implicit fallback: simpler, but a machine with nothing set would lose semantic search until someone switched it on.

**Accepted costs.** One more option. In `sdd` mode own embedding keys do nothing, which only the check line reveals.

**Acceptance.**
- Table-driven over the three values, with and without an own provider and with and without an sdd embedding block: the embedder resolves as listed above.
- `own` runs no `sdd` process.
- `sdd` with own keys set prints the check line naming them.
- No API key is sent under sdd's block in any mode.
- `plugin.json` declares `embedding_source` with `options` `auto`, `sdd`, `own` and no `default`; README `Options` lists it with default `auto`.
