agentic-memory now prints each entry once per context, a repeated read printing `<id> <title> (seen)` in its place, built in agentic-helpers commit 4a61b57 with a test in e4a3c3b proving a pointer hit still raises the entry's use score (heat), which closes 20261029-110631-d-tac-99b.

What was built against the decision's acceptance:
- A search, show, brief, view or recall marks what it printed in the per-session shown set; a later read of the same entry prints the pointer in rank order, the rest in full. A `show` after a search line prints the body; a second `show` prints the pointer.
- Over MCP and `--json` a seen entry is `{"id", "title", "seen": true}`, declared in the tools' output schema through a second accepted shape.
- `--again` (MCP `again: true`) on `search`, `show`, `brief` and `view` prints in full. A compaction, `/clear` and a resume empty the set.
- Recall names no entry a read printed. A pointer hit warms as a full hit does.
- `docs/memory/` and agentic-helpers:agent-memory describe the pointer and `again`, the skill telling a fresh subagent to pass it.

Two refinements beyond the decision's text. A mark records the entry's state (its line digest and event count), so an entry that changed since it was printed (a retire, a new link, a file the entry names changing on disk) prints in full again rather than hiding the change behind a pointer. A view section adding return reasons, expanded links or sizes prints in full, since it carries more than the line printed before.

Verified: functional tests for every acceptance item, each new guard broken alone and caught; and the installed build itself (`go install`, then `~/go/bin/agentic-memory`) in this repository: a repeated `search --term` printed `m-z130yt Only agentic-helpers sessions run ~/go/bin builds (seen)` for each earlier hit, `--again` printed the full line, and `--json` answered `{"id", "title", "seen": true}`. Not yet released: other projects run v2.15.0, which lacks it, until the next release.
