The embedding options that follow sdd (20261030-083307-d-tac-q74), the `embedding_source` option (20261030-084308-d-tac-pz4) and the allow-list of repository-free layers for sdd's endpoint (20261030-092612-d-tac-c24) are built in agentic-helpers commits 6d235b8, 8d49a8a, 65aecdb and 302e700, not yet released, closing all three directives.

The own embedding options take sdd's names, adding `embedding_timeout` (default `2m`) and the query and document templates. With `embedding_source` `auto` and no own provider, or `sdd`, the embedder is sdd's block as `sdd config get embedding` reports it; `own` never runs sdd. No API key is sent under sdd's block. The templated text is part of a vector space's fingerprint, so a template change starts a fresh space. sdd's endpoint is taken only from its `global` or `default` layer; any other layer refuses the whole block with `embed.ErrRepositoryEndpoint`. Output whose lines do not all have the expected shape, or that names a key twice, is refused. The session-start check names the refusal under `auto` and `sdd` alike, and under `sdd` names the own keys it ignores.

Proof: the `embed` and `pieces` tests cover each source, the layer allow-list, the duplicate-key and malformed-output refusals and the check lines. Live on the installed build, semantic search answered through the own embedder. In a checkout whose `.sdd/config.yaml` set the endpoint at sdd's project layer, with `embedding_source: sdd` in `config.yaml`, the session-start check printed `embedding_source is sdd; embedding_provider, embedding_model, embedding_endpoint ignored` and `sdd's embedding endpoint is set in this repository's .sdd/ (layer project), which a clone can bring along; search by meaning stays off until ...`.
