Shell-guard reads the shell scripts a command runs and judges the sources of `mv` and `git mv`, in agentic-helpers commit c6242b5 on local `main`, not pushed or released. It closes the script-reading directive (20261031-211859-d-tac-59g), its strictness refinement (20261031-215731-d-tac-tux) and the move directive (20261031-212214-d-tac-med).

**Surfaces.** `internal/shellwalk/scripts.go` reads a script named to `sh`, `bash`, `zsh`, `dash`, `ksh` or `mksh` without `-c`/`-s`, sourced with `source` or `.`, or run by its path; the walk's `Visitor` gains the code's directory and a `Script` event carrying the interpreter. New shell-guard reasons `cannot read the script <name> (<why>)` and the prefix `in the script <name>: `. The grounding gate reads script text through a new `Env.Files`.

**Live proof** on the installed binary, run from a project subfolder:
- `bash clean.sh` (`ls`, then `rm -rf ./build`) passes, while the same two commands typed are refused as a removal not alone.
- `bash outside.sh` asks `in the script outside.sh: outside project: ~/agentic-probe-none`; `source var.sh` (`rm -rf $DIR`) asks; `./tidy.py` with a python `#!` line asks through the rule matching removal names in an interpreter's code (`code for python3 names a removal`); `bash missing.sh` asks `cannot read the script missing.sh (no such file)`.
- `mv ~/agentic-probe-none/x ./x` and `mv -t ./dest ~/agentic-probe-none/y` ask `outside project`; `mv ./a ./b`, `git mv ./a ./b` and `cp ~/agentic-probe-none/x ./x` pass.

Evidence also: `go test -race -count=1 ./...` and `claude plugin validate .` pass; new test-table rows for each directive failed against the code before the change, including the gate seeing an `sdd new` in a sourced script; every new guard broken, caught by its own test and restored byte-identically. `docs/shell-guard/usage.md`, `docs/shell-guard/architecture.md`, `docs/grounding-gate/architecture.md` and the agent-shell-guard skill describe it.

**Left open.** A script replaced by `cp` or `sed -i` in the same command is judged as it stood before. A `cd` behind another command or after `|| exit` loses the directory, so a relative script after it asks. A missing script asks even where the command creates it first. fish scripts are not read.
