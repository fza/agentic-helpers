In a project carrying no `.sdd/` graph, the `agentic-helpers:agent-memory` skill sends to memory what it otherwise sends to the graph: a decision, and a defect, gap or blocker. Each is filed `--retention long`. A defect fixed is retired (`agentic-memory retire`); a decision overturned is superseded by the one replacing it (`agentic-memory supersede <old> --by <new>`). The other rows of the skill's routing table stand as they are: system shape to `docs/`, how work is done to `AGENTS.md`, code structure and git history nowhere. Where a graph exists, nothing changes, and memory still never holds a second copy of a decision.

Why: the skill's routing table sends decisions and defects to a graph, so in a project without one they had no place at all and were lost at the next compaction. Memory is the store every seated session already has.

Rejected: routing every row of the table to memory, system shape and working rules included. Those belong in the repository, where teammates and other tools read them; in memory they would sit outside the checkout and fade with retention. Rejected: `standing` for a decision the user took. Standing entries are capped at a third of the brief, so a project with many decisions would force demotions. Rejected: leaving retention to the agent. The default `normal` drops a decision out of the brief within weeks.

Accepted costs: a decision still in force but rarely used decays out of the brief after months, and an agent finds it only by searching; heat orders the brief alone (`internal/memory/brief.go`), so search still finds it. A project with no `docs/` or `AGENTS.md` still sees those rows name files it does not have.

Acceptance:

- `plugin/skills/agent-memory/SKILL.md` states that with no `.sdd/` graph a decision and a defect, gap or blocker go into memory with `--retention long`, a fixed one retired, an overturned decision superseded.
- The rows for `docs/`, `AGENTS.md` and code structure are unchanged.
- The rule "never a second copy of a decision" applies only where a graph holds it.
- `README.md`'s description of the skill names the case.
