The grounding gate keeps a session's credited reads across that session's own capture: when a successful capture leaves the graph changed by exactly the entry it wrote, the ledger moves to the new graph state with its query, term and listing credit intact. Any other change still voids the credit, as 20261025-182429-d-tac-fhx sets out.

**Recognising the session's own entry.**

- `agentic-capture` through `Bash`: the `PostToolUse` record reads the captured entry id from the command's output, the `<id>.md` line it prints on success.
- The MCP capture (20261025-020550-d-tac-ofh): `PostToolUse` gains `mcp__sdd__next`, and the record reads `produced.entryId` from the result that ends a `capture` procedure.
- Exactly the own entry: the graph state the ledger holds is count `n` with newest entry `X`; the state now is count `n + 1` with newest entry the captured id. Both hold → the ledger's graph moves to the new state and the reads stay. Anything else (two entries landed, another session's entry is newest, no id found) → the reads reset, as today.

The state compared is `graphState()` over the resolved graph project (20261026-195422-d-tac-g3w).

Why: every capture is a graph change, so a session's next question after its own capture carried the reads-owed note though the only new entry was the one it had just written. In a `gvb-mika-sdd` session 13 questions carried the note, most right after the agent's own capture and about subjects the graph did not touch (a Nuxt version, scaffold scope, actor aliases); all 13 were ignored. A note that is right only rarely trains agents to skip it, which disarms it for the change it exists to flag: another session's entry.

Rejected:

- Moving to the new state after any own capture, whatever else changed: an entry another session captured between this session's reads and its capture would go unnoticed.
- Keeping the reset: the note keeps following every capture, and agents keep learning to ignore it.

Accepted costs:

- The record parses `agentic-capture`'s output and sdd's `next` result; a change to either shape ends the credit silently, falling back to the reset, never to false credit.
- A capture whose summary step fails after the write prints no id, so its reads reset.
- `PostToolUse` runs the record on every `mcp__sdd__next`, most of which carry no capture result.

Acceptance criteria:

1. Three reads, then a successful `agentic-capture` printing `<id>.md`, then `AskUserQuestion`: no note.
2. The same with another entry file added before the capture: the note appears.
3. The same with a capture that prints no id: the note appears.
4. An `mcp__sdd__next` result carrying `produced.entryId` of the one new entry keeps the reads; one carrying an id that is not the newest entry resets them.
5. `plugin/hooks/hooks.json` runs `agentic-grounding-gate record` on `PostToolUse` `mcp__sdd__next`; `claude plugin validate .` passes.
6. `docs/grounding-gate/usage.md`, `docs/grounding-gate/architecture.md` and `agentic-helpers:agent-grounding` say an own capture keeps the reads.
