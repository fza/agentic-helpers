Shell-guard counts the input a piped shell inside a compound command reads as replaced only by here-documents and here-strings, in agentic-helpers commit 0fc499c, not yet released, building on the compound-pipe handling of 20261031-163018-s-tac-ptl. It replaces 20261031-163518-s-tac-csg (commit 4d2b759), whose rule still let two cases through: a file named by fixed text counted as replacing the pipe, yet any name may be a link to `/dev/stdin` (`echo 'rm x' | { ln -s /dev/stdin s; sh < s; }`), made in the same command or before it; and only the last redirection of descriptor 0 counted, yet zsh's MULTIOS feeds every one of them to the command (`{ sh < /dev/stdin <<< 'echo hi'; }`).

`internal/shellwalk`'s `redirectsInput` now answers true only when a statement redirects descriptor 0 and every such redirection is a here-document or here-string, whose code the walk judges itself; any file or duplicated descriptor (`0<&3`) keeps the shell reported as reading the pipe. Accepted cost: `echo x | { sh < script.sh; }` is refused, as `sh < file` at a pipe's end already was. Each check, broken in turn, made its own test fail, and restored, passes; `docs/shell-guard/architecture.md` states the rule.
