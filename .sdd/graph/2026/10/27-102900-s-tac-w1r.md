The plugin launcher takes its fetch lock as a symlink naming the owner's pid, in agentic-helpers commit 63ab1e2, not yet released, completing 20261027-102655-d-tac-5nv.

Each criterion with its test in `internal/plugin/plugin_test.go`:

1. A fetch killed without a trap is taken over at once with nothing left behind: TestAFetchKilledUncaughtIsTakenOver, which now fails unless the lock named the first fetch before the kill, and a table of dead-owner cases (killed the moment it took the lock, killed mid-download, an earlier launcher's directory lock naming a dead pid).
2. A live owner's symlink lock is waited on however old, an earlier launcher's ownerless directory lock while young, and taken over once stale: the waited-on table and TestAnEarlierLaunchersOwnerlessLockIsTakenOverOnceStale.
3. Parallel starts still fetch once and signals still clean up: the existing tests, now also asserting nothing is left behind.
4. `docs/plugin/architecture.md` describes the symlink lock.

TestAFetchKilledUncaughtIsTakenOver, which under load had failed after about 103 seconds when its 10-second wait expired with the first fetch inside the old ownerless window, did not fail over three rounds of `-count=5` with every other package running in parallel.
