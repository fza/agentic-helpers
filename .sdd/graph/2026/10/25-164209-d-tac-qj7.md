title: Claim force flag removal
summary: A seat held by a running session can no longer be seized. The --force flag of claim and the force key of the MCP tool are removed, and a seat frees only when its holder releases it or its process ends. Nothing takes a seat from a holder that is running. `agentic-memory claim <seat>` on a seat whose holder reads as alive is refused, always:

    agentic-memory: main is held by session 8109b4dc (pid 87518), still running; its holder releases it with `agentic-memory release`, or the seat frees when that session ends

- **Removed surfaces**: the `--force` flag of `claim`, and the `force` key of the `memory` MCP tool `claim`. `--force` is refused as an unknown flag, and `force` as a key the schema does not list, under the exact-keys rule.
- **How a seat frees**: its holder runs `release`, or its holder's process ends; a claim or `sweep` then takes it as from any dead holder, unchanged.
- **Claim files**: no claim writes `seized_from` any more; a claim file holding it from an earlier release still reads. `holder --json` keeps its field names and exit codes.
- **Skill and README**: every `--force` line goes; `agentic-helpers:agent-memory` says a seat held by a running session is the user's to free, by closing that session or asking its agent to release it.

Why: a running holder may be in the middle of its work, and seizing its seat makes every write it files next land as refused or under no seat, without it noticing. Nothing tells a stuck holder from a busy one: the process is alive in both cases. The cost of a stuck holder blocking its seat is a session to close, which the user can see and do; the cost of a busy holder losing its seat is silent. Since 20261025-162618-d-tac-hsx a running holder no longer reads as dead because of its locale, so `--force` is not needed to recover from that either. fdbox already forbids `--force` for every job.

Rejected: `--force` only for a holder whose transcript has not changed for a set time (a guess at stuck from transcript age, and a long turn or a session waiting on its user looks idle); keeping `--force` with the skill saying to use it only on a stuck holder (an agent can still take a busy session's seat).

Accepted costs: a session left open but stuck blocks its seat until someone closes it or its agent releases; removing a CLI flag and an MCP key is a breaking change, released as a major version.

Acceptance criteria:

1. A claim on a live holder's seat is refused with the text above; `claim <seat> --force` is refused as an unknown flag; the MCP `claim` with `force` is refused naming the key.
2. After the holder's process ends, a claim takes the seat without any flag, and `sweep` frees it.
3. A claim file carrying `seized_from` reads, and `holder --json` prints the same field names as before.
4. `README.md` and `agentic-helpers:agent-memory` carry no `--force`, and the skill states how a held seat frees.
5. The release carrying the change is a major version (`feat!:` commit).
