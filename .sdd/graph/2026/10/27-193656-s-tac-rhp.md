agentic-memory's `view` takes the four words of the memory view vocabulary additions (20261027-185652-d-tac-shv) from sdd's layout language, in agentic-helpers commit e37847a, not yet released.

- `topic(L)` opening a section ranks hottest first, later words overriding; elsewhere it filters only. `view --explain` spells `rank(heat)` out for it.
- `rank(in-degree)` orders by the links `← n` counts, superseded linkers aside, ties newest first (`internal/memory/rank.go`).
- `group(by(kind|seat|shelf|from))` with `as-grouped` blocks the page after `n` and `skip`, blocks in the order their first entry ranks; JSON answers `{"groups": {value: {"entries"}}, "more"}`. `as-grouped` without `group`, `group` with another render, and any field outside the four are refused with token, position and nearest word.
- `expand(refs)` lists each link under its entry in `as-list`, `as-grouped` and `as-bodies`: a memory target as its short line, a graph target as its id, either followed by its state where not ok; JSON entries carry `expanded`, the linked memory entries. With `as-counts` it is refused.

Beyond the directive: the refusals for a missing render word and an unknown rank now list `as-grouped` and `in-degree`; link states moved into one `linkStates` both `show`'s JSON and `expand` read.

Criteria: every word is table-tested over the golden fixture store (`internal/memory/view_test.go`), refusals on CLI and MCP alike; `TestViewExplainSpellsTheLayoutWhole` covers the macro; grouped and expanded MCP answers are checked against view's listed `outputSchema`, which `TestTheViewSchemaTypesGroupedSections` pins to type `groups` and `expanded`; `docs/memory/usage.md`, `docs/memory/architecture.md` and `agentic-helpers:agent-memory` name the words. Every new guard was broken and its test watched fail.
