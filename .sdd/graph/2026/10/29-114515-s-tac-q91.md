agentic-memory's near-compaction nudges now measure the context against the window Claude Code compacts at, read from `session.usage` by the plugin's hooks module `plugin/hooks/register.ts` (a Claude Code mod), built in agentic-helpers commit ffa8f63 and released in v2.15.0. This closes 20261029-104632-d-tac-qxo, and the gap 20261029-023926-s-tac-y8f with it: a window set in settings rather than the environment no longer leaves the first nudge rung past the point of compaction.

What was built against the decision's acceptance:
1. `plugin/hooks/register.ts` adds `compact_window` (the breakdown's `rawMaxTokens` from `$.session.usage({ breakdown: 'summary' })`) to the `.ctx` reading; a missing call, a throwing call and a breakdown-less answer leave the key out, since `JSON.stringify` drops an undefined value, and the event is always passed on. `plugin/hooks/register.test.ts` covers each case.
2. `contextPercent` in `source/hooks/internal/memory/hooks.go` rescales to `compact_window` where it is smaller than `size`, else to `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, else reads the full-window share, covered by a table-driven test with each guard broken once and caught.
3. Verified live: on this machine, whose window comes from `modelSettings["claude-opus-5-5"].autoCompactWindow` = 500000 in `~/.claude/settings.json` with the environment variable unset, the reading the v2.15.0 mod wrote for a running session is `{"used_percentage":13,"size":1000000,"compact_window":500000,...}`, so the nudge reads 13 % of a 1M window as 26 % of the window Claude Code compacts at.
4. `docs/memory/architecture.md` (the context reading) and agentic-helpers:agent-memory (the nudge measured against the window Claude Code compacts at, however set) describe the reading and its fallbacks.
