Every agentic-helpers piece gets a boolean plugin option that switches it on or off for the machine, on by default: `memory_enabled`, `tools_enabled`, `scratch_enabled`, `grounding_gate_enabled`, `capture_enabled` and `shell_guard_enabled`, declared in `plugin/.claude-plugin/plugin.json` `userConfig`. A feature leaning on a piece that is off goes off with it, and a session start names what is off and which option restores it.

Why: a user who wants agentic-memory without the grounding gate, or the scratch sweep without shell-guard, has no way to say so; the plugin is all or nothing. The switches change nothing about installing: one plugin, one marketplace, one release.

**An off piece.**
- Its hooks return at once with no output.
- Its commands under `plugin/bin/` refuse, exit 1: `<binary>: off on this machine (plugin option <key>)`.
- Its MCP server answers the handshake and lists no tools; its instructions read `<binary> is off on this machine; plugin option <key> turns it on`.
- Its skill stays listed, since Claude Code lists a plugin's skills whatever its options say.

Each binary checks its own switch. The launcher does not: `plugin/hooks/run` hands a call to `AGENTIC_HELPERS_BIN_DIR` before anything else, and a check there would miss every command the Bash tool runs.

**Ties between pieces.** No piece breaks when another is off; one of its features loses what it rests on. Exactly that feature goes off, and the rest of the piece runs:

| Off | Feature that goes off | Why |
|---|---|---|
| `scratch_enabled` | shell-guard's `mktemp` ban, whatever `shell_guard_mktemp` says | its refusal sends scratch files to a `.tmp/` nothing sweeps |
| `grounding_gate_enabled` | `agentic-capture` | its grounding check is the gate's hook; without it a draft lands ungrounded |
| `memory_enabled` | the grounding gate's `exempt_seats` | a seat is an agentic-memory claim; a claim left from before the switch must not exempt anything |
| `memory_enabled` | the seat name agentic-tools stamps on what it files | it reads the name from agentic-memory's seat registry |

The ties live in one Go package under `source/hooks/internal/` that every binary reads, so the feature that goes off and the line that reports it never disagree.

**`agentic-helpers`**, a new binary for the plugin as a whole (`source/hooks/cmd/agentic-helpers`, `plugin/bin/agentic-helpers`):
- `agentic-helpers check` runs once at `SessionStart` (`run --session-start agentic-helpers check` in `plugin/hooks/hooks.json`) and prints one line per broken tie, e.g. `agentic-helpers: scratch is off, so shell-guard's mktemp ban is off; turn scratch_enabled on to restore it`. Nothing broken, nothing printed.
- Run by an agent or the user, it lists every piece as on or off and, under each, the features off through a tie.

**Hooks and commands read the same switches.** Hooks get options as `CLAUDE_PLUGIN_OPTION_<KEY>`; commands and MCP servers read the settings files through `internal/pluginconfig`. `pluginconfig.Paths` learns `CLAUDE_CONFIG_DIR` in place of a fixed `~/.claude`, and the `managed-settings.d/` drop-ins beside `managed-settings.json`, merged after it in alphabetical order as Claude Code merges them, so a switch set in either place reaches both.

**`README.md` lists every option.** An `Options` section names every `userConfig` key with its default and a one-line explanation, the switches and every other piece's options alike, and a `Dependencies` section carries the tie table above. A user deciding what to run reads both on the page they install from.

**Surfaces:** the six `*_enabled` keys; binary `agentic-helpers` with subcommand `check`; its `SessionStart` entry; the ties package; `pluginconfig.Paths` reading `CLAUDE_CONFIG_DIR` and `managed-settings.d/`; the `Options` and `Dependencies` sections of `README.md`.

Rejected:
- **One plugin per piece, with Claude Code's own plugin `dependencies`.** Turning plugins on and off would come for free, but every skill (`agentic-helpers:agent-memory`), every MCP tool (`mcp__plugin_agentic-helpers_memory__*`) and `pluginconfig.PluginID` carry the plugin's name, so every skill and agent quoting them breaks, each plugin fetches the binaries into its own data directory, and every machine reinstalls.
- **Warn only, the dependent feature keeps running.** A degraded feature runs on as if whole: capture without its grounding check.
- **The whole dependent piece goes off.** Switching off the scratch sweep would take shell-guard's removal guards with it, and switching off memory would take the grounding gate, agentic-tools and, through the gate, capture.
- **A warning the user silences per tie.** One more option whose values name ties the user must spell right.
- **The line printed by `agentic-scratch start`.** The scratch sweep would report ties it has nothing to do with, and switching it off would silence every report.
- **The line printed by `plugin/hooks/run`.** The ties would live in shell beside the Go table, two copies to keep in step.
- **Keys named for the bare piece (`memory`) or `enable_<piece>`.** A bare name reads as a section beside `memory_language`; `enable_` sorts every switch away from its piece's options, and `.sdd/grounding.yaml` already spells a piece's switch `enabled`.
- **An off piece's MCP server listing refusing tools, or exiting.** Refusing tools stay in the agent's tool list inviting calls; an exit shows as a connection failure every session.

Accepted costs: an off piece's skill stays listed; its MCP server idles for the session; `agentic-helpers` is the first binary named for the plugin rather than a piece.

## Acceptance criteria

- With every `*_enabled` option unset, every piece runs as before.
- Each piece set off: its hooks print nothing and exit 0, each of its commands exits 1 with `<binary>: off on this machine (plugin option <key>)`, and its MCP server lists no tools and names the option in its instructions; a test per piece.
- Each tie in the table, broken, turns off exactly its feature and leaves the rest of the piece running; a test per tie, including `shell_guard_mktemp` true with `scratch_enabled` false.
- `agentic-helpers check` at `SessionStart` prints one line per broken tie and nothing when none is broken; run as a command, it lists every piece on or off with the features off through a tie.
- A switch set only in a `managed-settings.d/` drop-in, or in settings under `CLAUDE_CONFIG_DIR`, reaches a hook and a command alike.
- `README.md` has an `Options` section naming every `userConfig` key in `plugin/.claude-plugin/plugin.json` with its default and an explanation, and a `Dependencies` section with the tie table; a test fails when a key is missing from `Options`.
- `docs/` pages and skills describing a piece say what happens when it is off.
