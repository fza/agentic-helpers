`~/.config/agentic-helpers/config.yaml` and `agentic-helpers config set` let an agent switch agentic-helpers' guards off or redirect the embedder's API key in one Bash call, where Claude Code's own settings sit behind its settings protection; nothing guards the file.

**Observed.** An automated security review of agentic-helpers commit ed08e24, which builds the layering of 20261028-212647-d-tac-cld, flagged two paths, confirmed by reading the code. `agentic-helpers config set` writes any key the reader accepts, so `agentic-helpers config set shell_guard_enabled false` (or `grounding_gate_enabled`, any `shell_guard_*` mode) run through the agent's Bash tool turns a guard off for every session on the machine, and an agent can write the same lines into the file with Write or Edit. `embedding_endpoint` and `embedding_api_key_env` are read from `config.yaml` too, so an agent can name any environment variable, such as a GitHub token, as the key and point the endpoint at a server it chose; the embedder then sends that variable's value as a bearer token with each embed. Shell-guard judges neither the command nor writes to the file. The change is unreleased.

**Expected.** The guards exist to hold an agent in, so an agent should not be able to lift them, or send a credential off the machine, more easily than before the layering: before it, the same keys lived only in Claude Code's settings, which Claude Code's permission handling covers.

**Candidate remedies, unsettled:** keep guard switches and the embedder's endpoint and key variable out of `config.yaml`, readable only from Claude Code's settings and managed settings; have shell-guard ask on `agentic-helpers config set` and on writes to the `config.yaml` path; allow only key-variable names that look like an embedder's (`*_API_KEY`).
