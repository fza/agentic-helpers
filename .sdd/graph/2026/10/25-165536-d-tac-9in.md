The repository's documentation lives under `docs/`, one folder per piece, each holding the two tiers as two files:

- `docs/index.md`: what lives where, one line per folder.
- `docs/memory/`, `docs/scratch/`, `docs/grounding-gate/`, `docs/capture/`: `usage.md` (what an agent or a person does with the piece: commands, flags, outputs, what a refusal means, how a project opts in) and `architecture.md` (how it works inside: storage, formats, hooks it runs on, invariants, the reasons behind them).
- `docs/plugin/`: `usage.md` (the plugin's options, the skills it ships, `AGENTIC_HELPERS_BIN_DIR`) and `architecture.md` (the launcher `plugin/hooks/run`, its fetch and lock, the hooks module, the release workflow).

Every document states what the tree does in the present tense; what is unbuilt or undecided stays in the graph. `README.md` keeps only what the repository is, how to install the plugin, and a pointer to `docs/index.md`. The `Coming from agentic-install` section and the note on `.memory/carryforward/` files leave the README and are not carried into `docs/`.

`AGENTS.md` carries the standing rule: **a change that lands updates the `docs/` pages it makes untrue, in the same change**, replacing the rule that a change to a hook updates its skill and the README. A skill still changes with any wording it quotes.

Why: the README holds the install steps, every piece's behaviour and the internals in one 429-line file, so a reader wanting either the install or one piece's internals reads past everything else. One folder per piece keeps a change to one piece inside one folder.

Rejected: tier first, then piece (`docs/usage/`, `docs/architecture/`): a change to one piece touches two folders; two flat files (`docs/usage.md`, `docs/architecture.md`): memory alone fills a long file and every change collides in it.

Accepted costs: the two tiers are told apart only by filename; cross-cutting parts live under `docs/plugin/`, which is not one of the pieces the README lists.

Acceptance criteria:

1. `docs/index.md` and the five folders exist, each folder with `usage.md` and `architecture.md`, together holding everything the README's sections other than the introduction and installing held, rewritten to the tier each belongs to.
2. `README.md` holds the introduction, installing, and a link to `docs/index.md`, nothing else; it names neither `agentic-install` nor `.memory/carryforward`.
3. `AGENTS.md` states the docs rule in place of the README-and-skill rule, and its table names `docs/`.
4. No authored page states a count of what the tree holds.
