Every tool of the plugin's memory and tools MCP servers describes its call in the words of its keys: the tool description carries no command-line form, every input key carries its own description, and a rule between keys is stated in the tool description.

Why: each description used to end in `CLI form: agentic-memory <usage>`, and the usage line names positionals and flags, not keys. `supersede <id>... --by <id> | --because '<why>'` taught the key `id` where the schema takes `ids`, so agents sent `{"id":...}` and were refused; the `|` was the only statement that `by` and `because` excluded each other, so agents sent both and were refused again. Schema keys carried no descriptions, so nothing said that `ids` is an array even for one entry.

What changes:

- **No command-line form in a tool description** (`internal/memory/mcp.go`, `internal/tools/mcp.go`): the description is the command's own, worded without flags or placeholders. The CLI's `help` keeps the usage line beside it, and agentic-helpers:agent-memory keeps the CLI examples.
- **Every key described.** A key naming entries says its shape: `id` "the entry's id, one string", `ids` "entry ids, an array even for one", and the same for `topic`, `names` and `members`.
- **Rules between keys stated in the tool description**: `supersede` takes `by`, `because` or both, at least one; `ack` takes `done` or `decline`, not both; `search` needs `term`, `query` or `status`; `view` takes `layout` or `explain`.
- **`supersede` takes `by` and `because` together**: the entry is replaced and the reason kept, read back as `superseded <stamp> by <id>: <why>`. Only a call with neither is refused: `supersede needs --by <id>, --because '<why>' or both`. The stored event already carried both fields, so nothing migrates.

Rejected: accepting `id` as a second spelling of `ids`, which the exact-keys directive (20261025-034140-d-tac-9os) and the exact-values directive (20261026-222355-d-tac-kbi) reject; a refusal carrying a replay token, whose tool description would sit in every agent's context to save a copy-paste; a JSON example generated into each description, since a schema cannot express rules between keys and an example built from it can show a call the command refuses; renaming keys to one rule (`ids` everywhere, `topics` for `tag`), which breaks every caller for a shape the descriptions now state.

Accepted costs: an agent that never loads a tool's schema still guesses its keys; a client that reads the command-line form from the description loses it.

Acceptance criteria:

1. A test lists the tools of both servers and fails on a tool description holding `--` or `<`, and on an input key without a description.
2. `supersede` with `ids`, `by` and `because` lands and its entry reads both back; `supersede` with neither is refused.
3. Each guard is broken once and its test watched failing; `docs/memory/usage.md`, `docs/tools/usage.md` and agentic-helpers:agent-memory describe the rule in the same change.
