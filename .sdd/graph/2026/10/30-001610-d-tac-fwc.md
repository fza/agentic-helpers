The agentic-tools library refuses a tool smaller than 2 KiB: `add` and `update` refuse a version whose files, `tool.json` aside, hold fewer than 2,048 bytes together, and the next release removes once every tool already below that floor.

Why: a tool earns its place only when finding and taking it costs less than writing it again. Measured on this machine, `agentic-tools find --term replace` answered 5.3 KB, about 1,400 input tokens, before any take or file read; the tool it surfaced, `replace-exact`, is 362 bytes, about 100 output tokens to write fresh, which at output tokens' roughly fivefold price still undercuts the lookup by about three times. The break-even sits around 1 to 1.5 KB of script against one lookup, and an agent rarely finds the right tool with one. Tiny tools also crowd every search they do not answer: `exact-replace`, `exact-replace-spec`, `replace-exact` and `unique-replace-json` are four near-duplicates of one ten-line job, each lengthening every replace search. The floor follows the token-cost criteria of d-tac-00q.

**The floor.**
- Fixed at 2 KiB, like the 1 MiB cap of d-tac-x9j it sits beside; no setting.
- Counted over the files of the version being written, `tool.json` excluded, by the same measure as the cap.
- Refused below it, naming the size and the reason: `<path> holds <n> bytes; a tool below 2 KB costs more to find than to write again, so write it when needed`. The reason is in the refusal so an agent has no motive to pad the script past the floor.
- Applies to `add`, to `update` (a fork's update included), and to the survivor version a `merge` writes. No flag bypasses it.
- The `agentic-helpers:agent-tools` skill, the `add` and `update` MCP descriptions and `--help` state the floor beside the cap.

**The one-off prune.** The first SessionStart pass of the release carrying the floor removes every tool, in every store on the machine, whose current version is below 2 KiB: the whole tool folder, current version included, and its index row. Measured now that is 38 of 51 tools, 37 of them in the store of fdbox, the sibling project whose backfilled library seeded agentic-tools (d-tac-e9x). A removed tool leaves no tombstone and frees its name; a fork in another project keeps its own versions and simply stops following the removed origin. A copy a session took stays in its checkout's `.tmp/tools/`. The pass records that it ran in each store, so it runs once; later tools below the floor cannot exist, since writes refuse them.

**Rejected.**
- No floor, with skill guidance only: nothing refuses, so tiny tools keep landing and keep crowding searches.
- A bypass flag carrying a reason, like `--distinct`: agents reach for bypass flags routinely, which empties the floor. Knowledge that makes a short script hard to write (a BSD `sed` flag, an edge case) belongs in an agentic-memory trap entry (surfaced in the brief and when a matching tool is called) or a shell-guard alternatives row (named in the refusal of the failing command), where it reaches the agent without a lookup.
- A floor of 1 KiB or 512 B: tools between those and 2 KiB still cost about as much to find as to write, and a lookup often takes more than one search.
- A setting for the floor: one more key for a figure that follows from token prices, not from a machine's preferences.
- Keeping sub-floor tools that are already registered: they keep crowding every search for as long as they exist.

**Accepted costs.** Short but fiddly scripts are written again each time they are needed. fdbox loses most of its library at once, including tools its agents take. Updating an existing tool that is below the floor is refused; it is removed at the next release anyway.

**Acceptance.**
1. `add` and `update` of a version holding 2,047 bytes of files are refused with the reason; 2,048 bytes are accepted; `tool.json` does not count.
2. A `merge` whose survivor version falls below the floor is refused.
3. Against a fixture machine with tools above and below the floor in two stores, the release's first SessionStart pass removes exactly the tools whose current version is below it, in both stores, and a second pass removes nothing.
4. A fork whose origin was removed still lists and takes its own versions.
5. The skill, MCP descriptions, `--help`, `docs/tools/usage.md` and `docs/tools/architecture.md` state the floor and the one-off prune in the same change.
