An agentic-memory entry's body stays append-only: a changed finding is filed as a new entry that supersedes the old one (`new --absorbs <id>`, or `new` then `supersede`), and no command edits or patches a body in place. Only `retitle`, `tag`, `untag`, `rekind` and `retain` change an entry where it stands, as today. The choice applies the token-cost criteria (20261029-021515-d-tac-00q) to the append-only store the agentic-memory directive set out (20261025-014326-d-tac-mvn).

**Why.** A supersede is visible: every search line and link flag shows `superseded by <id>`, so an agent or another seat that read the old text learns it changed and reads the successor. An edit in place changes what an id says with no sign, under links and under other seats that already acted on the old text; that is the mistake the risk criterion rules out. The cost difference is small: the median entry body is 96 words, about 130 tokens, and across every store on one machine 37 superseded todos re-emitted 7264 words, about 9.5k output tokens in total, roughly 250 per rewrite. Reading costs the same either way, since a superseded entry never returns in search or the brief.

**Rejected alternatives.**
- *Replacing a body in place:* writes the same text again and saves only the second call (about 100 tokens; none with `new --absorbs`, 20261025-183015-d-tac-j5j), while hiding the change.
- *Patching a body with search-replace pairs:* writes only the changed lines, the one real saving, and only on long list-shaped todos; it hides the change all the same. The todolist directive (20261028-223759-d-tac-jkj) already takes that case out of the body: items change through `ack` at a few tokens each.

Accepted cost: a change to a long entry writes the whole text again. Settled: nothing is built; the store and the commands stay as they are.
