agentic-tools presents each tool version to a session once per context: after `find`, `list` or the per-prompt offer has printed a tool's line, a later `find` or `list` hit on the same version prints a pointer, `<name> v<n> (seen)`, in its place, until a compaction, `/clear` or resume starts the context afresh. It applies the once-per-context presentation agentic-memory adopts (20261029-110631-d-tac-99b) to the tool library of 20261025-185701-d-tac-e9x.

**What counts as presented.** A tool's line, `<name>  v<n>  <summary>`, from `find`, `list` or the offer. Tools print no body (`take` copies files and prints only where they lie), so one level suffices. A hit on a newer version than the one presented prints in full: its summary may have changed. The pointer keeps the hit's place in rank order; paging and counts stay. Over MCP and `--json` a seen tool is `{"name", "version", "seen": true}`.

**The offer.** The per-prompt offer of up to three own tools near the prompt already names each tool once per session. It now shares the seen set: it skips any tool version `find` or `list` already printed, since an unrequested pointer tells the agent nothing, and its own once-only memory resets with the seen set at a compaction, `/clear` and resume instead of lasting the whole session.

**Escape.** `--again` (MCP `again: true`) on `find` and `list` prints every hit in full and marks it presented. A freshly spawned subagent shares the session id and the tools server sees no agent identity, so agentic-helpers:agent-tools tells such an agent to pass `again`; a forked subagent inherits the context and needs none.

**Reset.** The seen set lives in each session's own file beside its holdings and is emptied at a compaction, `/clear` and a resumed session's SessionStart. A call no session owns prints everything in full.

**Why.** Several `find` calls in one task overlap, and the offer may name a tool a search printed a turn before; each repeat re-spends a line already in the agent's context.

**Pointer shape.** Name plus version, by least risk first, then fewest tokens (20261029-021515-d-tac-00q): the name is the tool's readable identifier, as a memory entry's title is, and the version tells the agent whether the line it saw is current; the summary is dropped.

**Rejected.** Leaving agentic-tools out: its find and offer overlap the same way. A bare name without version: a repeat could hide that the tool moved on. Keeping the offer's once-per-session memory past a compaction: the agent loses the tool from its context while the offer stays silent about it.

**Accepted costs.** A few tokens per repeated hit; a fresh subagent that omits `again` calls again; a breaking change to `find` and `list` output, with `docs/tools/` and the skill following in the same change.

**Acceptance.**
- Two overlapping `find` calls: the second prints a pointer for each version the first printed, in rank order.
- A newer version than the one presented prints in full.
- The offer skips a tool version `find` printed, and offers a tool again after a compaction, `/clear` or resume.
- `--again` and MCP `again: true` print in full.
- JSON carries `{"name", "version", "seen": true}` for a seen tool.
- `docs/tools/` and agentic-helpers:agent-tools describe the pointer and `again`.
