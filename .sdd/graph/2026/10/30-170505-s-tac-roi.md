The grounding gate lints a capture body given by `bodyHandle` as it lints one given as `body`, built in agentic-helpers commit dbb18f2, not yet released. This closes the directive 20261030-163932-d-tac-quq and the gap it addresses, 20261030-163356-s-tac-mre.

**Built.** A `PostToolUse` group on `mcp__sdd__stage_attachment` in `plugin/hooks/hooks.json` runs `agentic-grounding-gate record`, appended after every existing group. Where `.sdd/grounding.yaml` sets `draft_lint`, `recordStaged` (`internal/grounding/enginestaged.go`) keeps the text a staging left under the handle sdd answered with: the `content` given, the file a `path` names, or the held text with `patches` applied by sdd's edit rule. The text sits under a new optional `staged` key in the session ledger. A capture start or report naming `bodyHandle` has that text, after a leading `---` header block, linted with the existing `draft_lint` refusal. A handle with no text held is refused once (`refusals/engine-handle.txt`) and passes after.

**Compatibility.** The check turns on only when a report names `bodyHandle` and a staging answer carries a `handle`; nothing compares sdd versions. Reports by `body` and `bodyPatch` and stock sdd behave as before, the existing tests passing unchanged. A ledger written without `staged`, or carrying a key this build does not know, still reads and keeps every key. A staging answer naming no handle, a failed one, or one that does not decode records nothing and refuses nothing. The hook wiring and the skill and doc text only gained lines.

**Tests**, each guard broken and caught: every acceptance criterion of the directive has a case in `enginestaged_test.go`; `TestALedgerWrittenBeforeStagingStillReads` reads the fixture `ledgers/before-staging.json`; `TestStagingReadsEveryAnswerShape` covers each answer form and the ones carrying no handle; `TestTheGateSeesSddsMCPTools` holds the hook matcher; `TestTheSkillsAndDocsQuoteTheStagedBodyRefusal` holds the quoted refusal. Two guards no test can fail are named: the `staged` key in the ledger's known-key list (the marshaller writes it either way) and the ledger path error in `recordStaged` (masked by the save failing the same way).

**Proven live** in a headless Claude Code session on a scratch sdd project whose `draft_lint` flags a word, with the plugin loaded from the checkout and the installed build: a body staged holding the word and named by `bodyHandle` at capture start was refused with `body:2:1:Proof.Forbidden:FORBIDDEN found`; after a `patches` staging replaced the word, the same start passed the gate; a never-staged handle was refused once with the new wording and passed on the second call.

**Deviations.**
- Added: recorded text whose sha256 differs from the `sha256` in sdd's answer, or a patch sdd applied that the gate cannot replay, drops the record, so the next capture by that handle is refused once rather than linting stale text. An answer without `sha256` is trusted.
- Added: a report naming `bodyHandle` leaves the staged body as the capture's held body, so a later `bodyPatch` after the capture drops the handle edits it; before, the gate held no body after a `bodyHandle` report and refused that patch, which the gap also recorded. An unknown handle clears the held body, so that patch asks for the whole body.
- Re-staging a handle a capture is already bound to is linted only when a report names `bodyHandle` again.
- A staged body ending in a newline reaches the lint with one more, as a `body` does.

`agentic-helpers:agent-capture`, `agentic-helpers:agent-grounding` and `docs/grounding-gate/` changed in the same commit.
