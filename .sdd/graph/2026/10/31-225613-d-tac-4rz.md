Shell-guard asks about a script a command runs whenever an earlier command in the same call names that script's path as an argument, unless the earlier command only reads files. Today only a redirection (`>`, `>>`) or `tee` marks a script as written before it runs (`source/hooks/internal/shellwalk/scripts.go`), so `cp evil.sh x.sh && bash x.sh` or `sed -i 's/a/b/' x.sh && ./x.sh` is judged from the old file on disk while the new text runs unchecked. The done 20261031-220638-s-tac-7zg names this as left open; this extends the script-reading directive 20261031-211859-d-tac-59g to close it.

**Rule.** An earlier command naming the script's resolved path (an operand, an option value such as `-o x.sh`, or `of=x.sh`) makes the script unreadable with the existing reason `the command writes it before running it`, an ask. Exempt are commands that only read or change metadata: `cat`, `head`, `tail`, `less`, `more`, `wc`, `grep`, `rg`, `file`, `stat`, `ls`, `test` and `[`, `diff`, `cmp`, `shasum`, `md5`, `od`, `xxd`, `chmod`, `chown`, and an earlier run of the same script, which is itself judged. A redirection or `tee` writing a here-document keeps its current handling: judged from that text.

**Rejected.** A list of known writers (`cp`, `mv`, `install`, `ln`, `rsync` destinations, `sed`/`perl`/`ruby -i`, `curl -o`, `wget -O`, `dd of=`): any writer missing from the list still slips through, and the list needs upkeep for every tool. Accepting the gap and documenting it: the write-then-run bypass stays open for every writer except redirections and `tee`. The reader list is chosen because it fails safe: a command it does not know costs an ask, never a bypass.

**Accepted costs.** An extra ask when a harmless command missing from the reader list names the script first (`mytool x.sh && bash x.sh`). A command that changes the script without naming it (`git checkout other && ./x.sh`, an archive extraction) stays unjudged.

**Acceptance.**
- `cp new.sh x.sh && bash x.sh`, `sed -i s/a/b/ x.sh && ./x.sh`, `curl -o x.sh URL && sh x.sh` and an unknown command naming `x.sh` before `bash x.sh` ask `cannot read the script x.sh (the command writes it before running it)`.
- `chmod +x x.sh && ./x.sh` and `cat x.sh && bash x.sh` are judged from the file on disk.
- `cat > x.sh <<'EOF' ... EOF` before `bash x.sh` is still judged from the here-document.
- `docs/shell-guard/usage.md` and the agent-shell-guard skill state the rule and the reader list.
