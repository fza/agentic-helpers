title: Seat ids and store migration
summary: Seats are keyed by an immutable id and their names become changeable labels in a `seats.json` mapping. A single `format.json` holds the store's version, and the first call on an older store migrates it under the store lock, rewriting the log with ids and RFC 3339 UTC times. It refines the Unicode seat names decision (20261025-155114-d-tac-dgu) and builds on the filed-entries directive (20261025-014326-d-tac-mvn) and RFC 3339 stored times (20261025-152555-d-tac-86k).

A seat has an id, and its name is a label the seat's holder can change. Entries, events and seat files refer to the id; the name appears only in the mapping file and in what agentic-memory prints. The store carries its format version in one file, and a store of an earlier format is migrated under the store lock by the first call that meets it.

- **Seat id**: `s-` and 6 random characters from `0-9a-z` (`crypto/rand`), as in `s-4kq9td`, minted when a name is claimed for the first time and never changed. A fresh id is drawn again if the mapping already holds it.
- **Mapping file** `seats.json` in the store root (`~/.claude/agentic-memory/<project>/seats.json`): one object, seat id to `{"name": "<name>"}`. Each seat has exactly one entry holding its current name, and no two entries hold the same name. It is written under the store lock, through a temporary file renamed into place.
- **Format file** `format.json` in the store root: `{"format": 2}`, the one version of the whole store. Every call reads it first; absent means format 1. The manifest's `format` field is dropped, and the segment header's format number is checked only as a guard against a file that is not a segment, never as a version.
- **Everything keyed by id**: the `seat` field of every event in `log/tail.jsonl` and in the segments; `seats/<id>.json`, `seats/<id>.last.json`, `seats/<id>.slice`; the cache's `briefs/<id>.json`.
- **Names at the edges**: `claim`, `release`, `holder`, `--seat`, the MCP keys carrying a seat and `exempt_seats` in `.sdd/grounding.yaml` take a name, normalised as 20261025-155114-d-tac-dgu sets, and resolve it through `seats.json`. Entry lines, the brief, `sweep` and `holder` print the current name. `holder <seat>` keeps its output shape, so callers outside Claude Code see no change.
- **Rename**: `agentic-memory rename '<new name>'` and the MCP tool `rename` (key `name`) change the name of the seat the calling session holds, and only that seat. A name already in the mapping or failing the name rule is refused. The old name is free afterwards; claiming it mints a new seat.

**Migration**, run by the first agentic-memory call that reads a `format` below 2, holding the store lock from the first step to the last, so no other call reads or writes the store meanwhile:

1. Copy `log/` and `seats/` to `backup/format-1-<UTC stamp>/` in the store root.
2. Mint one id per seat name found in any event, seat file or slice, and write `seats.json`.
3. Write a new log beside the old one: every event with its seat name replaced by the id and its `time` as RFC 3339 UTC, segments resealed under their new content hashes, the manifest without `format`.
4. Rename `seats/<name>.*` to `seats/<id>.*`, swap the new log in for the old with one directory rename, and write `format.json` last: its presence is what marks the migration done.

A failure before `format.json` is written leaves the store readable as format 1: every renamed seat file is renamed back and the old log stays in place. The call then reports `agentic-memory: migrating the store failed: <cause>; the store is unchanged and the next call tries again` once per session on stderr, and runs on the format-1 store. A call meeting a `format` above the one it knows refuses: `agentic-memory: this store has format <n>; this release reads up to <m>`. The readers for the earlier time forms that 20261025-152555-d-tac-86k keeps stay for the seat files and `.ctx`; the log no longer needs them after migration.

Why: a name that events and files are keyed by can only change by rewriting the log, so a seat could never be renamed, and a name in a new language (20261025-155114-d-tac-dgu) would be fixed at whatever its first claim chose. An id that never changes lets the name change in one place, and a single mapping file holding one current name per seat is the whole of what a name resolves through. One format file answers "which shape is this store" for every part of it, where version numbers scattered over the manifest and the segments each answer for a part. The migration runs on its own so no store is out of action until someone runs a command, per project and per machine, and the lock keeps a second call from reading a half-migrated store.

Rejected: mapping events in the log (`seat` and `rename` kinds, keeping name history; the mapping is one file with one entry per seat); reading old rows' names through the mapping forever instead of rewriting them (two shapes of event in every reader for good); an explicit `agentic-memory migrate` (every store refuses until someone runs it, on every machine, for every project); keeping old names as aliases after a rename (a seat has one name; the old one is free again); the store version in the manifest (the manifest is the log's, and seat files and the mapping lie outside it).

Accepted costs: the first call on an unmigrated store, possibly a hook, pays a one-off delay for copying and rewriting the log, and every other call on that store waits on the lock meanwhile; the log, otherwise never rewritten, is rewritten once, with the backup as the way back; `seats.json` is one more file whose loss strands every entry's seat, guarded by the backup; a renamed seat's old name in a transcript or another tool's notes no longer resolves.

Acceptance criteria:

1. A claim of a new name writes an `s-` id of 6 characters from `0-9a-z` to `seats.json` and `seats/<id>.json`; every event filed under it carries the id.
2. `rename 'haupt'` by the holder changes the name in `seats.json` only; entries, files and ids stay; `claim haupt` then reaches the same seat and `claim main` mints a new one. A session not holding the seat, a name in use, and an invalid name are each refused.
3. A functional test builds a format-1 store in `t.TempDir()` from fixture files under `test/fixtures/` (tail rows and a segment carrying seat names and integer times, `seats/main.json`, `.last.json`, `.slice`), runs one command, and finds `format.json` at 2, `seats.json`, ids in every event, RFC 3339 times, `seats/<id>.*`, no manifest `format`, and the backup holding the original bytes.
4. The same test with a write fault injected before `format.json` is written leaves every original file byte-identical, prints the failure line once, and the next call migrates.
5. Two processes starting on one unmigrated store migrate it once, the second waiting on the lock and reading format 2; run under `-race`.
6. A store with `format.json` above the known format is refused with the line above, and nothing is written.
7. `holder main --json` prints the same shape before and after migration.
8. `README.md` and `agentic-helpers:agent-memory` name `format.json`, `seats.json`, seat ids, `rename` and the migration.
