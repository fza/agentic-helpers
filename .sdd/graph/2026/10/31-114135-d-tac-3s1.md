The chunk cap that agentic-memory and agentic-tools embed with is recorded in each vector store's manifest, quantised to 64 runes, and calibration only proposes the cap for the next fill, refining 20261031-113450-d-tac-bmm so the stored index and the queries ranked against it always agree on one cap.

- **The store holds the cap.** Each vector store (agentic-memory's per-fingerprint vector folder, the tool library's) records in its manifest the cap its rows were built with; that record is the only source of the cap in use. Readers, the query cut of prompt recall, `search --query` and `find --query`, take the cap from it and never probe or fall back to 2048 runes. A store with no recorded cap is filled first, as the search paths already fill before scoring; a hook that cannot fill within its deadline goes without semantic scores, silently, as it does when a fill times out, while a command refuses with a clear message.
- **Quantised.** The cap derived from calibration rounds down to a 64-rune step, so probe noise below one step leaves the cap, and with it every row hash, unchanged.
- **Calibration proposes.** Calibration is written atomically (a temporary file renamed into place) and only decides the cap for the next fill. A fill finding the calibrated cap different from its store's recorded one re-derives the rows under hash(content, cap) and records the new cap.
- The 2048-rune cap stays only on the write side, for a provider reporting no token count.

Why: a query cut to one cap ranked against rows cut to another compares unlike texts, and a reader that probes or falls back on its own can disagree with the store it reads; one recorded cap per store keeps fill and search consistent, and the quantum keeps a noisy probe from re-embedding a store for nothing. sdd, the decision-graph CLI whose embedding setup agentic-helpers shares, adopts the same three rules for its own index, so both tools derive the same cap for the same endpoint.

Rejected: readers falling back to 2048 runes when no cap is recorded, which ranks queries against rows built at another size; deriving the cap at read time from the calibration, which lets a recalibration change queries before the rows follow.

Accepted costs: a first search on a store without a recorded cap waits for its fill; one more field in each store's manifest.
