shell-guard withholds a credential that a tool call returns from outside the project before the agent sees it. A new hook, `agentic-shell-guard output` on `PostToolUse` for every tool, scans the call's output with the shared scanner (20261026-223236-d-tac-vr7) and replaces each line holding a finding with `[agentic-shell-guard: credential withheld (<rule ids>)]`, through `hookSpecificOutput.updatedToolOutput`; the rest of the output reaches the agent unchanged, and a note says how many lines were withheld and that the source is unchanged.

Why: an agent reading a file outside the project, such as `~/.config/sdd/config.yaml` with provider keys in its comments, takes every key into its context, where it can be quoted, filed or sent on. The shell-guard directive (20261025-235046-d-tac-n48) judges Bash calls before they run and cannot see what a glob, a script or a variable reads; the output is what reaches the agent, so the output is what gets scanned.

Where output counts as outside the project:

- Read, Grep and NotebookRead: by the path they name; a path inside the project shows as is.
- Bash: shown as is only when every command in it is a known file reader or filter (`cat`, `head`, `tail`, `grep`, `sed`, `awk`, `wc`, `sort`, `cut`, `jq` and the like) and every path it names is a literal inside the project, with no directory change and no nested code; any other call, a script or a test run included, is redacted.
- Every other tool (WebFetch, MCP tools, a subagent's answer): outside.

Options: `shell_guard_secret_output` takes `all` (default), `files` (Read, Grep, NotebookRead and Bash only) or `off`; `shell_guard_secret_output_skip` lists tool names or patterns whose output is never redacted (default empty).

A scan that cannot finish withholds every string of the output rather than pass it. The replacement keeps the tool's output shape: every string value of the response is scanned and replaced in place.

Rejected alternatives:

- Refusing a call before it reads: sees only files it can name from the command, not a glob, a script or a variable.
- Both refusing and redacting: two mechanisms to keep consistent, and a refusal where redaction lets the rest of the file through.
- Redacting only output of commands naming a literal outside path: `$HOME`, globs, `cd ~` and scripts would pass.
- Redacting every output, project files included: a credential in a project file the agent is asked to fix could not be shown at all.

Accepted costs:

- The call has run; only what it returns is withheld, and a command that sends a file elsewhere without printing it is not covered.
- A whole line is withheld, its other text with it.
- A scan of every tool call's output, cheap where no rule keyword occurs.
- A project script printing a project credential is redacted too.
- Two plugin options, a new hook entry point, and the marker wording in the hook's contract, quoted by agentic-helpers:agent-shell-guard.

Acceptance criteria:

1. A Read of a fixture file outside the project holding a credential returns its other lines unchanged and each credential line replaced by the marker; a Read of the same file inside the project returns it whole.
2. Bash: `cat <outside file>`, `cat "$HOME"/<file>`, `cd <dir> && cat <file>` and a script are redacted; `cat <project file>` and `grep x <project file>` are not.
3. WebFetch and an MCP tool's output are redacted under `all`, not under `files`; nothing is under `off`; a tool matching `shell_guard_secret_output_skip` is never redacted.
4. A scan that cannot finish withholds the output; the replaced output keeps the tool's shape.
5. `plugin/hooks/hooks.json` wires `PostToolUse` for every tool to `agentic-shell-guard output`; both options are declared in `plugin.json`, read by `pluginconfig` and listed in the README; agentic-helpers:agent-shell-guard and `docs/shell-guard/` name the hook, the options and the marker.
