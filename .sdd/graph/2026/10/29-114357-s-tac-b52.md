agentic-tools now prints each tool version once per context, a repeated `find` or `list` hit printing `<name> v<n> (seen)` without its usage lines, built in agentic-helpers commit 08a998b, which closes 20261029-110801-d-tac-myr.

What was built against the decision's acceptance:
- A second overlapping `find` prints the pointer for each version the first printed, in rank order, the rest in full; `list` does the same. A newer version prints in full.
- Over MCP and `--json` a seen tool is `{"name", "label", "version", "seen": true}`, declared in the output schema as a second accepted shape. The label (null for the own project) is kept beside the decision's name and version, since a bare name can reach another project's tool.
- `--again` (MCP `again: true`) on `find` and `list` prints in full.
- The per-prompt offer skips an own tool `find` or `list` printed, and names each tool once per context; after a compaction, `/clear` or resume it offers the tool again. A new SessionStart hook, `agentic-tools start`, empties the set on those three sources; `end` empties it too.
- `docs/tools/` and agentic-helpers:agent-tools describe the pointer, `again` and the offer's skipping, the skill telling a fresh subagent to pass `again`.

Two departures from the decision's text. The seen set lives in `~/.cache/agentic-tools/seen/<pid>-<start>.json`, keyed on the owning `claude` process (pid and start time) rather than in the per-session file: the MCP server keeps the `CLAUDE_CODE_SESSION_ID` it started with across a `/clear`, so a set keyed on the session id would outlive the context it describes. And the offer marks no version printed, since it prints only names: a `find` after an offer still prints the tool's summary and usage in full, the least risky reading of 'the offer printed a tool's line'.

Verified: functional tests for every acceptance item, each new guard broken alone and caught; and the installed build itself (`go install`, then `agentic-tools` through the plugin's launcher with `AGENTIC_HELPERS_BIN_DIR` set) in this repository: a repeated `find --term count` printed `citation-relink@format-d-fdbox v1 (seen)` and the like for every hit, `--again` printed the full line, and `list --json` answered `{"name", "label", "version", "seen": true}`. The `start` hook and the MCP answers are checked by tests only, since a running Claude Code process keeps the hooks and MCP server it loaded at start. Not yet released: other projects run v2.15.0 until the next release.
