The agent helpers keep one source, this repository, and reach every machine as a Claude Code plugin installed from it, rather than as copies inside each project or as entries an installer writes into the global settings file.

The repository is its own plugin marketplace. A user adds it once with `claude plugin marketplace add fza/agentic-helpers` and installs the plugin at user scope with `claude plugin install`, which enables it in every project on the machine. The plugin carries the hook wiring and the skills. The Go binaries are not part of the repository: each release publishes them, and the plugin fetches the release matching its own version. A project takes part, as before, by carrying the directory a hook works on.

Why: Claude Code installs, versions, updates and removes a plugin itself, so the helpers need no installer editing `~/.claude/settings.json`, a file that also holds credentials, and no symlinks into the global skills directory that dangle when a checkout or a versioned install directory moves. A machine needs neither a checkout nor Go to run the helpers.

Rejected:
- An installer wiring settings entries and symlinking skills from a checkout. Every machine needs the checkout and Go, and every move of the binaries rewrites the credential-holding settings file.
- A Homebrew cask carrying the binaries and skills, with the installer wiring them. A cask's files sit in a directory named after the version that `brew upgrade` deletes, so wiring and skill links break on every upgrade unless something rewrites them, and Homebrew adds a second update cycle beside Claude Code's.
- Skills compiled into the binaries and rewritten by a SessionStart hook. It moves the skills into the Go module and makes a hook write files on every session start.
- Per-project copies, for the drift and repeated edits they cause.

Accepted costs: skills are namespaced by the plugin, so `agent-capture` is invoked as `agentic-helpers:agent-capture`, and every instruction file naming a skill changes with it; plugin auto-update is off by default for a third-party marketplace, so a machine runs the version it last updated to; a change here still lands on every machine that updates, so a broken release breaks everywhere at once.

Violation is observable: a hook entry for these binaries in a settings file, a skill symlinked into `~/.claude/skills/`, or a hook script or skill body committed inside another project's tree.
