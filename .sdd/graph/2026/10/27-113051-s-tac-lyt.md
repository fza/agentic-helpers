shell-guard refuses an ask an agent can fix by rewriting twice per session before it prompts, and a command name that can split asks even with no arguments, in agentic-helpers commit 5f8c8f3, not yet released, completing 20261027-101534-d-tac-jlu. Commits 7fc9efa and bf0be43 keep a lone `[` (the `[ -f x ]` test command) from reading as a glob unless a `]` or a later expansion may close it in the same word, which the split-name rule would otherwise have refused.

Each criterion with its test in `internal/shellguard/`:

1. `$CMD`, `{rm,-rf,/}` and other splitting names alone get the outside-project verdict (asked, refused first as below), `"$tool"` alone runs: TestACommandNameThatIsNotFixedTextTakesTheOutsideVerdict, and TestOneKnownWordFindsWhatStaysOneWord in `internal/shellwalk/`.
2. Attempts one and two deny with the count and the third asks, for a not-fixed name, a launcher value, a splitting name and a credential: TestARewritableAskRefusesTwiceThenPrompts; the third follows the permission mode: TestTheThirdAttemptFollowsThePermissionMode; a new session starts at one and reasons count apart: TestEachSessionAndReasonCountsApart.
3. `rm ~/x` and `find / -delete` ask at once: TestAnAskNoRewritingFixesPromptsAtOnce.
4. Skill and docs: TestTheSkillQuotesEveryRefusal.

Choices the directive left open: a call with no session id or no state directory counts as attempt one every time, so it is refused, since the agent can always rewrite these; a credential scan cut short still prompts at once, since it names no credential to rewrite.

Noticed in the doing: the state file is written without a lock, so two calls of one session landing at once can lose one count.
