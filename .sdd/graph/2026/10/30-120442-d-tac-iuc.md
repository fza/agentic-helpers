Every boolean agentic-helpers option in `userConfig` declares a `default` equal to the option reader's built-in value, as the pickers already do, and the reader treats an answer from the agent's layers (Claude Code's `pluginConfigs` in user settings, and the hook environment's `CLAUDE_PLUGIN_OPTION_<KEY>`) that equals the built-in value as unset, so `config.yaml` still decides that key.

**Why.** On Claude Code 2.1.314, saving the `/plugin configure` dialog without touching anything stores an answer for every boolean and every picker in `pluginConfigs`: `false` for each boolean, since none declares a default, and the declared default for each picker. Text and number fields left empty are not stored. The reader ranks those answers above `config.yaml`, so one untouched save switched off memory, the tool library, scratch, the grounding gate, capture and shell-guard with every one of its guards, and pinned each picker to its built-in value over `config.yaml`. The released v2.16 carries the boolean half of this.

**Rule.**
- `plugin.json`: every `type: boolean` option declares `default` equal to `pluginconfig.Defaults()`; pickers keep theirs; text and number options declare none.
- `pluginconfig.Resolve`: in the user-settings and hook-environment layers, a key whose value resolves to the built-in value is skipped, so the layer below applies. Managed settings are unaffected: a machine lock to the built-in value still holds.

**Rejected.**
- Declared defaults alone: an untouched save then pins every boolean and picker to its built-in value, silently overriding `config.yaml` for that user.
- Dropping booleans and pickers from `userConfig`, `config.yaml` only: no dialog for them, the pickers just built undone, and `scratch_sweep` loses the per-agent override 20261029-084134-d-tac-b2t requires.

**Accepted costs.** The dialog or a hook's environment cannot set a key back to its built-in value over a different `config.yaml`; that takes editing `config.yaml`. `agentic-helpers config` names such a key's layer as `config.yaml` even though the user saved an answer.

**Acceptance.**
1. Every boolean and picker in `plugin.json` declares the reader's built-in default; no text or number option declares one; `claude plugin validate .` passes.
2. A test resolves every key with `config.yaml` set to a non-default value and the user-settings answer, then the environment value, set to the built-in one: `config.yaml` decides. With the answer set to another value, the answer decides; with managed settings at the built-in value, managed decides.
3. The `pluginConfigs` answers stored by an untouched save, kept as a fixture, resolve every key exactly as no answer does.
4. `docs/plugin/usage.md` and README `Options` state the rule and the cost.
