agentic-memory tells a running session to re-read an instruction file it loaded once that file changes, so an instruction written into `CLAUDE.md`, `CLAUDE.local.md` or a file they import reaches sessions already running. Claude Code reads its instruction files when a session starts, when a session first touches a folder holding nested ones, and after compaction; a session started before an edit keeps working on the old text until then, so an instruction placed there (20261031-192031-d-tac-e9f) misses every session already running.

**Which files.** Whatever Claude Code reports through its `InstructionsLoaded` hook event: each loaded file's path, of every memory type (`User`, `Project`, `Local`, `Managed`) and load reason (session start, nested traversal, path glob match, `@` include, compaction). A new subcommand `agentic-memory instructions` on that event records each file's path and content hash for the session. Nested files are watched only by sessions that loaded them. Where Claude Code fires no `InstructionsLoaded` (an older release), the session watches a fixed set instead: the checkout's root `CLAUDE.md` and `CLAUDE.local.md`, the files they import with `@`, and `~/.claude/CLAUDE.md`.

**When and what.** On every prompt and after every tool call, the session's recorded files are hashed again. A file whose hash changed yields one hidden line, `agentic-memory: <path> changed since loaded; re-read it`, and its recorded hash is updated, so each change is told once. A change the session made itself through Edit, Write or NotebookEdit on that path updates the hash and says nothing. The record is per session, so a session holding no agentic-memory seat (none claimed) gets the line too; subagents get it only where Claude Code fires the event inside them.

**Rejected.** A fixed list of files for every session: it walks the checkout for nested files and announces them to sessions that never loaded them. Checking on prompts only: a long autonomous turn would work on old instructions. Only seated sessions: the record needs no seat. Re-injecting the changed text: the file is the authority, and its full text would cost context on every change.

**Accepted costs.** A hash of each recorded file on every prompt and tool call. A change made by a Bash command in the same session is told to that session too. Subagents may never see the line.

**Acceptance.**
- `plugin/hooks/hooks.json` wires `InstructionsLoaded` to `agentic-memory instructions`, recording path and hash per session.
- A recorded file changed by another process yields the line once on the next prompt or tool call; the session's own Edit or Write yields none.
- A nested file loaded by one session is not announced to another that never loaded it.
- Without the event, the fixed set is watched, and a test covers both paths.
- `docs/memory/usage.md` and the agent-memory skill name the line and what to do: re-read the file.
