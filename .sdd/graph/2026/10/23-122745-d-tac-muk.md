summary: 'Release notes never pass through a shell: `@semantic-release/github` creates the GitHub release carrying semantic-release''s notes, and GoReleaser uploads the archives and `checksums.txt` into that existing release (`release.mode: keep-existing`). This refines the plugin release pipeline (20261023-115644-d-tac-4ni) by replacing the shell-interpolated `${nextRelease.notes}` hand-off to GoReleaser, which forged commit subjects could turn into arbitrary commands.'

The release notes never pass through a shell. `@semantic-release/github` creates the GitHub release carrying semantic-release's notes, and `@semantic-release/exec` then runs `goreleaser release --clean`, which uploads the archives and `checksums.txt` into that release and keeps its notes (`release.mode: keep-existing` in `.goreleaser.yaml`). Its success and fail comments and released labels are off, so the job needs `contents: write` alone.

- `.releaserc.yml` lists, in order: the commit analyzer and the notes generator (`conventionalcommits`), `@semantic-release/exec` writing the version into `.claude-plugin/plugin.json` (prepare), `@semantic-release/git` committing it, `@semantic-release/github`, and a second `@semantic-release/exec` running GoReleaser (publish).
- `release.yml` installs `@semantic-release/github` at an exact version beside the other packages.

Why: interpolating `${nextRelease.notes}` into a command puts commit subjects into a shell script running under a token that writes to the repository. A quoted heredoc stops expansion only until a subject carries the delimiter line, after which the rest runs as shell.

Rejected:
- `goreleaser release --release-notes <file>` with the notes written by a heredoc in `publishCmd`. The delimiter can be forged by a commit subject.
- A random delimiter per run, or refusing notes that contain it. It narrows the hole rather than removing it, and the notes still sit inside a shell script.
- Letting GoReleaser write its own changelog. It would differ from semantic-release's, which reads the same commits by the `conventionalcommits` rules that pick the version.

Accepted cost: one more pinned package in the release job, and GoReleaser depends on the release already existing when it runs.

Done when `.releaserc.yml` carries no `${nextRelease.notes}` in any command, `goreleaser check` passes with `release.mode: keep-existing`, and `README.md` describes the release as created by semantic-release with the archives added by GoReleaser.
