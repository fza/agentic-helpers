The grounding gate never refuses a `Write`, `Edit` or `AskUserQuestion` call. Where such a call finds the reads owed, the gate lets it through with exit 0 and a `hookSpecificOutput.additionalContext` note naming what is owed. Every other refusal stays one: `agentic-capture`, a plain `sdd new`, an `sdd` call discarding a stream, an `sdd show` short of its depth, and `mcp__sdd__start_procedure` with `canonical: capture`. A `UserPromptSubmit` whose prompt starts with `<task-notification>` continues the turn before it: the reads that turn credited stay credited.

- **The note** is the refusal's text under a new first line: `GROUNDING GATE: let through, reads owed.` in place of `GROUNDING GATE: refused.`, then what the turn carries and the reads to run, as the refusal words them now. A note on a draft edit adds that the draft is not grounded and its capture will owe the reads.
- **A draft written through a let-through call** is not grounded, so its capture runs the three reads first, as for a draft written through `Bash`.
- **The rest of the gate** (ledger, credited reads, the listing rule, `show_depth`, `exempt_seats`, `enabled`) is unchanged.

Why: Claude Code draws any refusal of a `Write`, `Edit` or `AskUserQuestion` call as a red `PreToolUse:<tool> hook error` line in its default view, whether the hook exits 2 or answers a JSON `deny`; a refused `Bash` call folds into "Ran 1 shell command" and shows only in the transcript view. A PreToolUse `additionalContext` note on an allowed call shows nothing in either view and reaches the agent, verified in a live session with a probe hook. A task notification reaches `UserPromptSubmit` as a prompt like any other, so each one started a new turn and discarded reads the agent had run moments before, which was the most common cause of a refused question or draft.

Rejected: a JSON `deny` in place of exit 2 (drawn just as red, only without the hook's path); shorter refusal texts (still red); a plugin render hook hiding the line (no documented render site for tool results); keeping every refusal and only counting task notifications into the turn (red still shows whenever an agent slips).

Accepted costs: a question asked without the reads is no longer stopped, only answered with a note after it is asked; a draft is checked only at capture, so an ungrounded one can sit in `drafts/` until then; the first line of the note changes wording the `agentic-helpers:agent-grounding` skill quotes, and the skill changes with it; a prompt a person types starting with `<task-notification>` keeps the turn's reads.

Acceptance criteria:

1. A `Write`, `Edit` and `AskUserQuestion` payload with reads owed each exit 0 with `additionalContext` opening `GROUNDING GATE: let through, reads owed.`; with the reads done, each exits 0 with no output.
2. `agentic-capture`, a plain `sdd new`, a discarded stream, a short `sdd show` and an MCP capture with reads owed still exit 2 with their refusal text.
3. A draft written through a let-through `Write` is not grounded: a capture of it in a later turn without reads is refused.
4. A turn crediting all three reads, then a `UserPromptSubmit` with a `<task-notification>` prompt, then an `AskUserQuestion`, produces no note; the same with a typed prompt produces one.
5. `README.md` and `agentic-helpers:agent-grounding` describe the let-through note, the calls that still refuse, and the task-notification rule, quoting the new first line.
