title: Early exit for Bash calls without memory
summary: Commits the `agentic-memory pre-tool` hook to exit 0 immediately on Bash calls whose command does not name `agentic-memory`, so memory no longer adds its ~19 ms delay to those calls. This answers the measured ~21 ms per-Bash-call cost (20261031-214728-s-tac-msb) under the least-risk-first token-cost criteria (20261029-021515-d-tac-00q), while leaving the subagent ladder checks (20261031-202547-d-tac-xmy) unchanged for commands that do name memory. `agentic-memory pre-tool` answers a Bash call whose command does not name `agentic-memory` before it sets up the store and seat lookup, so a Bash call without a memory call no longer waits on memory. Measured on the installed binary: the hook takes about 19 ms on `ls -la`, `agentic-shell-guard` about 8 ms. Claude Code runs a call's PreToolUse hooks side by side, so the slower one sets the delay, and memory's sets it today. Nearly all of that time goes to `mem.locate` in `source/hooks/internal/memory/memory.go`, which runs before `guardShell` in `source/hooks/internal/memory/subagentshell.go` returns for a command lacking `agentic-memory`. The done 20261031-214728-s-tac-msb names the cost; the token-cost criteria 20261029-021515-d-tac-00q weigh least risk first, and this changes no output.

**Rule.** For `tool_name` `Bash`, the hook reads the payload first and exits 0, writing nothing, when `tool_input.command` does not contain `agentic-memory`. Every other call, the `Agent`, `Task` and memory MCP tool calls included, runs as today. Subagent shelf notices come from the PostToolUse hook and are not affected.

**Rejected.** Folding the subagent memory check into `agentic-shell-guard`, which already parses every Bash command: it ties the always-on shell-guard to the memory piece, which can be switched off on its own. Accepting the cost: about 11 ms more delay than shell-guard alone on every Bash call, in every project on the machine.

**Accepted cost.** One more early path in the hook's startup.

**Acceptance.**
- `agentic-memory pre-tool` on a Bash payload for `ls -la` takes no longer than `agentic-shell-guard` on the same payload, measured over repeated runs.
- The checks `guardShell` makes on a command naming `agentic-memory` behave as before: a subagent's memory write below level `full` is refused, a `full` subagent's call gains `--agent <id>`, and the main thread typing `--agent` is refused (the subagent ladder 20261031-202547-d-tac-xmy).
- `docs/memory/architecture.md` names the early exit.
