Seven agentic-helpers options with a fixed value set are declared in `userConfig` as pickers, each with `options` and a `default` equal to the option reader's built-in default: `embedding_source` (`auto`), `writing_style` (`terse`), `scratch_sweep` (`release`), `shell_guard_outside_project` (`ask`), `shell_guard_find_delete` (`ask`), `shell_guard_secrets` (`ask`), and `shell_guard_secret_output` (`all`). This closes the picker gap (20261030-100707-s-tac-ny9): Claude Code refuses a picker without a `default` or `required: true`.

Why the default is safe. The no-declared-defaults rule of 20261028-212647-d-tac-cld rests on the premise that a declared default reaches hooks as an answer and hides `config.yaml`. A probe on Claude Code 2.1.314 measured otherwise. A plugin loaded with `--plugin-dir` declared one picker and one text option with defaults and a third option without one. Its SessionStart hook received no `CLAUDE_PLUGIN_OPTION_*` variable while nothing was answered. With only the third option answered in `pluginConfigs`, the hook received that one and still none for the two defaulted options. An unanswered picker therefore leaves `config.yaml` deciding, as cld requires. The exception covers pickers alone; every other option keeps declaring no default.

**`embedding_provider` stays a text field.** Unset, it means no own embedder, so `auto` falls back to sdd's. A picker would need an invented value for that state, which `auto` would read as a provider set.

**Minimum Claude Code.** `options` needs v2.1.271, as 20261030-083534-d-tac-ws7 accepted; README states it.

**Rejected.** `required: true`: forces every install to answer, and the answers hide `config.yaml`. Dropping pickers: a typo in a dialog answer stays possible and surfaces only as an error at the next hook.

**Accepted cost.** Unverified so far: whether the interactive `/plugin configure` dialog, saved without touching a picker, stores its default in `pluginConfigs`. If it does, `config.yaml` loses those keys for that user.

**Acceptance.**
1. The seven pickers declare `options` and the reader's built-in default; `claude plugin validate .` passes.
2. A test checks that each picker's values are all the reader accepts and that a value outside them is refused. It also checks that each declared default equals the reader's built-in default, and that no other option declares one.
3. README names Claude Code v2.1.271 as the minimum, and `docs/plugin/usage.md` states the picker exception.
4. Before release, a live `/plugin configure` saved without touching a picker is checked for what `pluginConfigs` holds.
