Eight directives built in releases up to v2.16.1 are verified criterion by criterion against the v2.16.1 release binaries, each run in a throwaway home: shell-guard's permission-mode asks (20261026-223555-d-tac-1ny), `agentic-capture` forwarding its pre-flight limit (20261029-202429-d-tac-cij), the agent-neutral `config.yaml` layering (20261028-212647-d-tac-cld) and its scope for deleting keys (20261029-084134-d-tac-b2t), the `agent-memory` skill split (20261029-021831-d-tac-93f), the machine-wide size limits (20261029-024444-d-tac-x9j), the binary data formats (20261029-024635-d-tac-i5f) and the memory log's `due` row with format 7 (20261029-220457-d-tac-pia).

**Built in:** 1ny in v2.9.0 (a8e09e5); x9j, 93f and `capture_remove_draft` in v2.14.0 (bfcd0f0, e24d7c9, 284179c); cld (bc74187), i5f (e41781e), cij (23a9e08) and pia (53c6c8a) in v2.16.0.

**What the proofs surfaced.** Several criteria held only once these were fixed (cld's listing of effective values, x9j's docs), so the fixes belong to this verification; each is its own commit on main, not yet released, with a guard broken and caught:
- `agentic-helpers config` listed `""` for `memory_language`, `temporary_seat_lifetime` and `orphan_store_grace` instead of the built-in `en`, `1d`, `30d` (5070795).
- A `config.yaml` YAML cannot parse was named across several lines with the parser's source excerpt; it is now one line, and `config set` words an unknown key as `config get` does (728ac04).
- An attachment refused for its size read as the limit itself (`1.0 MB, past the 1 MB`); the size now rounds up (ac240be).
- A pruned tool version refused as a duplicate suggested `take`, which copies the current version; the refusal now says so (627f370).
- A memory migration recorded its size ledger before writing `format.json`, leaving a stale checksum until the next write; the ledger test helper now compares checksums too (87d184e).
- `drop` counted `0 entrys` (c536cb1).
- `agentic-helpers dump` named a torn journal record's offset without the 8-byte header (d7abaae).
- The SessionStart passes never removed the `.space.json` size files the ledgers replace, which the docs promised; one still sat on this machine (2d43219).
- Docs: `tools_total_mb` names `add` and `update` as enforcing it (ded5827); a stock-sdd capture cut off at its bound says to check `git log` (f08617f); `docs/plugin/usage.md` lists the three `check` problem lines (728ac04).

**Deviations, accepted as built:**
- 93f: `SKILL.md` was 18,121 characters at v2.16.1 and is 16,905 on main, against about 11k. Later features regrew the core; 20261030-125759-d-tac-eh9 moves rare-path text out and sends new rare-path text beside the core. Every other criterion holds; two still-emitted strings are quoted shortened with `...`.
- cld: its no-declared-defaults rule was refined since by 20261030-083534-d-tac-ws7, 20261030-113044-d-tac-is5 and 20261030-120442-d-tac-iuc (pickers and booleans declare their built-in default, which reads as no answer). The managed-settings layer is covered by `TestEveryLayerResolvesInOrderManagedSettingsLast`, since its path is a system folder no throwaway home reaches.
- 1ny criterion 3: a countdown left to run out was seen deny a call in a live `auto` session that then went on; a person answering before the countdown ends was not observed.
- cij: `llm.timeout` and `llm.extract_timeout` are read with two `sdd config get` calls, not one; README carries no pre-flight text, the skill and `docs/capture/` do.
- x9j: no `attach` MCP tool exists (attach is CLI only); MCP descriptions name the keys, not their values; `view` takes its layout as `--layout`. Commit 29a51db decides pruning on sizes measured on disk once the recorded totals pass the limit, while every figure shown still comes from recorded sizes.
- pia: its criterion 3 was proven by `TestMergePolicyFoldsEventsPastTheHorizon`, since a release binary cannot fake the 14-day horizon; a merge folds the latest due time into the `new` row's payload instead of keeping a `due` row. The refusal reads `this store has format <n>; this release reads up to <m>`, and v2.15.0 is fenced off by the home's `writers.json` line before any format check.
