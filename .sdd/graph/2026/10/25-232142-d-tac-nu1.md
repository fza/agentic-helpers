`agentic-memory claim <seat> --session <id>` for a session that already holds a seat hands that session over: in one step under the store lock, its current seat is released and the named seat claimed for the same running process. A launcher moves a kept agent from one row's shelf to another's without ending the session or leaving it a moment without a seat.

Why: a launcher keeps some sessions alive and gives them to another row, keeping their context. A seat never changes shelf, so the session has to change seat, and only its holder could release one.

## What

- **A handover takes effect at once.** The new seat's claim carries the running session's process, start time and transcript from the claim it replaces, so the session's next memory call, a Bash command or an MCP tool, already acts as the new seat. No reservation is written and no hook has to take one over.
- **The released seat closes as on `release`**: if it was the last seat in use on its shelf, a temporary shelf's clock starts.
- **The session is told on its next hook**: `agentic-memory: seat moved from <old> to <new> (shelf <name>)`, followed by the new seat's brief, as `claim` prints it.
- **Refused, changing nothing**: the named seat held or reserved by another session; the named seat on another shelf than `--shelf` names; the session id naming no live session.
- `--lifetime` and `--shelf` apply to the new seat as on any claim. MCP: the `claim` tool with `session`, as for a reservation.

## Rejected

- **`release --session <id>`, then a reservation.** Two steps with a moment between in which the agent holds no seat and its filing is refused.
- **The agent moving itself** (`release`, then `claim <new> --shelf <name>`), which works without any change. Leaves the move to the agent following its brief; the launcher can only check afterwards.
- **A handover writing a reservation the session takes over on its next hook.** The session's memory calls between the handover and that hook would find no seat.

## Accepted costs

- Any process naming a running session's id can move it off its seat. A launcher names sessions it started; nothing else knows a session's id unless told.

## Acceptance criteria

- `claim B --session S` with S holding A: A is released, S holds B with A's process and start time, `holder --session S --json` exits 0 naming B, and S's next memory CLI and MCP calls act as B.
- S's next hook prints `agentic-memory: seat moved from A to B (shelf <name>)` and B's brief.
- A temporary shelf whose last seat in use was A starts its clock at the handover.
- A handover onto a seat held or reserved by another session, onto a seat on another shelf than `--shelf` names, or for a session id no live session carries is refused and changes nothing.
- `docs/memory/` and the `agent-memory` skill describe the handover in the same change.
- Every new guard is broken and watched failing on its own test, the file restored byte-identically.
