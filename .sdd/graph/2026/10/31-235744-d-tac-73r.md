A memory filing reply names only the closest similar entry above the similarity threshold, on one line with its supersede and link hint, and folds the rest into a count with the command that lists them. Measured over three days of transcripts, filing replies came to 407k characters over 1026 filings, 62% of it similar-entry hints (`similar:`, `replaces it`, `relates` lines). The agent acts on the closest match in nearly every case; the others are repetition of the same hint shape. This follows the token-cost criteria 20261029-021515-d-tac-00q: the cut removes repetition, never the hint an agent acts on.

**Rule.** `agentic-memory new` (CLI and MCP) prints `similar: <id> <title> (<score>)` with its supersede or link hint for the best match only, then `+<n> more similar: agentic-memory search --query '<title>'  (run before concluding none is the same finding)` where more passed the threshold. The fold line follows the fold rule the agent-memory skill already states.

**Rejected.** Dropping similar hints entirely: duplicate findings would pile up unseen. Raising the threshold instead: it hides close matches without telling the agent any exist.

**Accepted cost.** A second-best match that is the real duplicate needs the folded search to surface, so a supersede can be missed when the agent skips it.

**Acceptance.**
- A filing with three entries above the threshold prints one `similar:` line and `+2 more similar: ...`.
- A filing with one match prints it as today, with no fold line.
- `docs/memory/usage.md` and the agent-memory skill state the reply.
