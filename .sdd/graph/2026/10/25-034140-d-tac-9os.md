Every tool of the plugin's `memory` MCP server takes exactly the keys its own input schema lists under `properties`, spelled exactly. Before the arguments reach the command (`callTool`, `internal/memory/mcp.go`), any other key, a wrong-case spelling of a listed one, or a key another tool takes, refuses the call with an error result: `agentic-memory: <tool> takes no key "<key>"; it takes <keys>`, the keys the schema lists in its order, every offending key named. Each schema also carries `"additionalProperties": false`, so a client validating against it sees the rule before it calls.

Why: the arguments decode with `json.Unmarshal` into one `request` struct shared by every tool, which matches keys case-insensitively and drops unknown ones. `{"ALL_SEATS":true}` works like `all_seats`, a misspelled `limt` is ignored silently, and `force` passed to `show` is accepted and does nothing, so a caller's mistake reads as the tool doing something else. Every consumer then guards against it on its own, as fdbox's gate does.

Rejected: `DisallowUnknownFields` and an exact-case check on the shared struct. Refuses a key no tool knows, but accepts another tool's key and ignores it. Rejected: leaving decoding lenient. Mistakes keep passing silently.

Accepted costs: a caller sending a wrong-case or extra key, today accepted, is refused; a key a newer client sends before the server knows it is refused rather than ignored.

Acceptance:

- `show` with `{"ids":["m-abc123"],"Force":true}` is refused naming `Force` and listing `show`'s keys; `{"ALL_SEATS":true}` on `search` is refused; `force` on `show` is refused; the same calls with the exact keys answer as before.
- Every tool's served schema carries `"additionalProperties": false`.
- Every key a schema lists is one the command reads, so no listed key is refused.
- `README.md` and `agentic-helpers:agent-memory` state the rule.
- Each new guard is broken, its test watched failing, and the file restored byte-identically.
