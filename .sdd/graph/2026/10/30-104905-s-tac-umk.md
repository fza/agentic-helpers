The shared write walk `internal/safefs` is built in agentic-helpers commits 9dde814 and 0cf3025, not yet released, closing the directive (20261030-082001-d-tac-v8k).

The tool library's descriptor walk moved into `internal/safefs`. Every writer under the data home, the cache home, a checkout or a git common dir now takes its root and walks to the target one folder at a time: the memory log, seats, registries, shelves, slots, vector segments, the space ledger, the home and its migration, scratch, the grounding ledger, `capture.lock` and `internal/atomicfile`. Refusal texts are unchanged. `docs/plugin/architecture.md` gains a Writes section, which the other architecture pages point to. `renameat` from `golang.org/x/sys` renames between two folder descriptors, as `source/AGENTS.md` now states.

Writes still on plain `os`: git's global excludes file (outside every root), the folder of `config.yaml` under the config home, and Claude Code's `.claude/settings.local.json`. That last one lies inside the checkout, so a committed `.claude` link could still redirect that one write.

Proof: table-driven tests per writer plant a symlink at the file, a symlink one folder up and a hard link at the file, and see each refused. A renamed-in `seats` folder holding a hard-linked `.lock` refuses `claim`. A committed `.tmp` link gets no scratch write, a linked root keeps working, and the tool library's safe-store tests pass unchanged. Guard breaks showed paired checks masking each other: the folder link refusal and the held-folder check, and the file link and open-file checks. Each pair is caught when broken together. The check holding an opened folder to the one just checked, which catches a folder swapped in between, stays in the code but untested: the swap is a race between two system calls that a stress run never hit, and no test hook was added to force it. Live on the installed build, a claim in a checkout whose `.tmp` links outside wrote nothing through it, and writes to the real store kept working.
