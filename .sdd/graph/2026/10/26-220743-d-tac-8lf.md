An agentic-memory rule may be an action owed at a moment, and the tool tracks whether it was done. A rule, the user-only kind of the entry kinds directive (20261026-215042-d-tac-g5a), filed with `--on claim` or `--on compact` (repeatable; MCP `on`, a list) is printed as a numbered do-now list at that moment, marked done by a tool call that proves it or by the agent's `ack`, and Stop holds the turn, at most twice, while one is pending; what stays pending is reported as skipped in the next brief.

Why: a heavy seat's brief held "on claim, arm a monitor on the to-main channel" among fifteen standing entries, and the agent did not arm it until the user asked. A rule in a list is text; nothing told the agent it was owed now, and nothing noticed it was skipped.

At the trigger:

- At claim and at the brief after a compaction, before the brief's sections: `do now (<trigger>):` then one numbered line per rule on that trigger, `<n>. <id> <title>  proof: <trigger>` or `<n>. <id> <title>  ack when done`.
- Each item is pending for the session from that moment, in a per-session file beside the ladder file.
- `--on` on any kind but `rule` is refused. A rule stays filed `--from user` only.

Proof:

- `--proof <trigger>` (repeatable; MCP `proof`, a list) takes the trigger form of trap triggers (20261026-220335-d-tac-nu3): `path:<glob>`, `command:<regex>`, `tool:<name>`. Any one matching tool call after the trigger, in the same session, marks the item done. The memory PostToolUse hook does the match.
- `agentic-memory ack <id>... --done` or `ack <id>... --decline '<why>'` (MCP `ack`, keys `ids`, `done`, `decline`) settles items no tool call can prove. Several ids land all or nothing, as the lifecycle verbs do (20261025-183015-d-tac-j5j). An id not pending in this session is refused.
- Every settlement is an event on the rule, done by proof, done by ack, or declined with its reason, so `show` lists who did what and a decline keeps its reason.

Stop:

- While items are pending, Stop exits 2 with `agentic-memory: do-now items pending:` and the numbered list, at most twice per trigger per session, so it cannot hold a session forever. It runs before the filing backstop of the agentic-memory directive's nudge ladder (20261025-014326-d-tac-mvn).
- Items still pending past the cap or at session end are recorded as skipped, and the seat's next brief opens its do-now list with `skipped last session:` and their lines, where the user reading the claim sees them.

`show`, `search` and the JSON entry object carry `on` and `proof`; `brief --json` carries the do-now list as `do_now`.

Rejected alternatives:

- A checklist with no tracking: shorter and first, but still text the agent may skip, with nothing noticing.
- Denying every tool call but the proving one until each item is settled: blocks all work behind the list, and a wrong proof pattern locks the session out of its tools.
- `ack` as the only settlement: proves the agent read the list, not that it acted; a tool call is evidence the hook can check.
- A separate `do-on-claim` kind: an action rule is still a user's instruction, with a rule's provenance and lifetime; a trigger on the rule says the rest.
- A `before commit` trigger: needs a memory PreToolUse hook on Bash that does not exist; claim and compaction cover the case reported, and a commit-time check belongs to the project's own hooks.

Accepted costs:

- A new verb, `ack`, and a per-session pending file.
- A second Stop gate; two blocks per trigger at most.
- `ack --done` without proof can still be typed without the work; such items say `ack when done` so the user sees which ones rest on the agent's word.
- The do-now and Stop wording is part of the hook's contract, quoted by agentic-helpers:agent-memory.

Acceptance criteria:

1. `new --kind rule --on claim|compact --proof <trigger>` files; `--on` or `--proof` on another kind is refused; a malformed trigger is refused; MCP the same.
2. Claim and the post-compaction brief print the do-now list first, numbered, for that trigger only.
3. A matching tool call after the trigger marks the item done; one before it does not.
4. `ack --done` and `ack --decline '<why>'` settle pending items, all or nothing; an id not pending is refused.
5. Stop exits 2 while items are pending, at most twice per trigger per session, before the filing backstop.
6. Items left pending appear under `skipped last session:` in the next brief.
7. Skill and docs name `--on`, `--proof`, `ack`, and the wording, in the same change.
