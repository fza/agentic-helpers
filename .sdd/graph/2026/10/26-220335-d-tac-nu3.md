An agentic-memory trap reaches the agent when a tool call touches what it is about. The memory PostToolUse hook (`agentic-memory tool`, already wired on every tool) prints a trap, the kind the entry kinds directive (20261026-215042-d-tac-g5a) gives things that already cost time, once per session, the first time a call matches one of its triggers:

`agentic-memory: trap for <what matched>:` then the trap's short brief line.

Why: a trap is useful only at the moment the mistake is about to happen. The per-prompt recall of the agentic-memory directive (20261025-014326-d-tac-mvn) matches the prompt text, so a trap about one directory stays silent while the agent edits that directory several tool calls into a task. The traps a heavy seat named, editing `.autopilot/plan/parts/jobs/`, spawning a builder, running `pilot board upgrade`, are all moments of a tool call, and two of them touch no file at all.

Triggers:

- Every file anchor of the trap, the regular files its title and body name (`anchorsFor`, `anchors.go:91`), triggers without being declared.
- `agentic-memory new --kind trap --when <trigger>` (repeatable; MCP `when`, a list) adds explicit ones:
  - `path:<glob>`: a path the call names matches the glob, `**` crossing directories, relative to the work tree root, matched by `github.com/bmatcuk/doublestar/v4` (`doublestar.Match`); the standard library's `path.Match` has no `**`. A directory, which never anchors, is reached as `<dir>/**`. The same matcher serves rules' `--proof path:`.
  - `command:<regex>`: a Bash call's command matches the RE2 pattern, case-sensitive.
  - `tool:<name>`: the call's tool name equals `<name>`, such as `Agent` or `mcp__sdd__start_procedure`.
- `--when` on any kind but `trap` is refused. Notes anchor every path they mention, so triggering on them would fire on most calls.

What a call names: the `file_path`, `notebook_path` and `path` fields of its input, and for Bash the path tokens of its command, found as anchors are found. The match runs after the call, since Claude Code places a PreToolUse hook's context beside the tool result as PostToolUse's is. Claude Code's Edit refuses a file not read in the session, so for Edit the notice lands on the Read before it.

Once per session: a trap told in a session is marked in that session's seen marks, the marks shared entries are told through (20261025-162357-d-tac-427), and not told again until the next session or compaction. Traps on the seat's shelf and traps received through `--for` or a followed topic both trigger. `show`, `search` and the JSON entry object carry the declared triggers as `when`.

Rejected alternatives:

- A PreToolUse deny on the first touch, with the trap as the reason: reaches the agent before any call, Bash included, but every first touch of a trapped path costs a retried call, and a false match costs a turn.
- Per-prompt recall alone, with traps winning ties: stays silent through a tool run whose prompts never name the trap's subject.
- Triggering every kind on its anchors: notes anchor every path they mention, so most calls would print one.
- A hand-written `**` matcher on `path.Match` per segment: braces, character classes and case handling are the edge cases doublestar's releases fix, and a matcher of our own would carry and test them itself. doublestar has no dependencies and a stable v4 API.
- Explicit triggers only, with anchors not counting: a trap naming a file is almost always about that file, and requiring the filer to repeat it as `--when` is a step that gets skipped.

Accepted costs:

- A Bash edit or a Write of a new file gets the notice only after it ran.
- A path and pattern match on every tool call of a seated session holding traps.
- A new direct dependency, `github.com/bmatcuk/doublestar/v4`.
- The notice wording is part of the hook's contract, quoted by agentic-helpers:agent-memory.

Acceptance criteria:

1. `new --kind trap --when` takes `path:`, `command:` and `tool:`; a malformed trigger or an invalid RE2 pattern is refused; `--when` on another kind is refused; MCP the same.
2. A table-driven test of the match: anchors, each trigger form, input fields `file_path`, `notebook_path`, `path`, and Bash path tokens.
3. The notice prints once per session per trap and again after a compaction, checked by a test.
4. Received traps trigger as the seat's own do.
5. A seated session holding no traps prints nothing and reads no trap state on tool calls.
6. Skill and docs name `--when`, each trigger form and the notice wording, in the same change.
