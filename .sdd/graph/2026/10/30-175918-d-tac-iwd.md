The plugin's `embedding_provider` option becomes a picker with four values, `auto` (default), `openai`, `ollama` and `off`, and takes over the choice `embedding_source` made, which leaves the options dialog. One field now says where search by meaning gets its embedder.

- `auto`: no embedder of its own. sdd's embedding block applies where sdd sets one in a layer 20261030-092612-d-tac-c24 accepts, else search by meaning is off. This is what an unset provider does today under `embedding_source: auto`, so a machine with nothing set behaves as before.
- `openai`, `ollama`: the own `embedding_*` keys apply, as today.
- `off`: no embedder at all; sdd is never run for it. Search by meaning, prompt recall, the tool library's prompt offers, `find --query` and the near-duplicate description check on `add` stay off; keyword search, filing and the byte-identical duplicate check keep working.

An empty value reads as `auto`. The reader refuses any other value, as it refuses one outside every other picker, so a typo no longer passes the dialog.

**`embedding_source` stays read.** `plugin.json` no longer declares it, but every layer that sets it keeps working as 20261030-084308-d-tac-pz4 decided: `sdd` takes sdd's block whatever the provider says, `own` never runs sdd, `auto` changes nothing. `off` wins over it. `agentic-helpers check` names it at session start where a layer sets it, pointing at `embedding_provider`. A configuration that never set it sees no difference.

Why: 20261030-113044-d-tac-is5 kept the provider a text field because its unset state had no value a picker could offer, and two fields answered one question, the second visible only to someone who read its description. `auto` names the unset state, and `off` gives the dialog a way to turn embeddings off that before needed `embedding_source: own` with the provider left empty.

**Rejected.**
- A `none` value as default: names the absence of an own provider, not what happens, which is following sdd.
- Keeping `embedding_source` in the dialog beside the picker: two fields for one choice.
- Dropping `embedding_source` from the reader: a `config.yaml` or saved answer setting it would change behaviour silently.

**Accepted costs.** The reader carries an option the dialog no longer shows. A saved dialog answer naming `embedding_source` stays in effect until removed by hand.

**Acceptance.**
1. `plugin.json` declares `embedding_provider` with `options` `auto`, `openai`, `ollama`, `off` and `default` `auto`, and no `embedding_source`; `claude plugin validate .` passes; the options test admits a key read but not declared only for `embedding_source`.
2. Table-driven over provider value, a set `embedding_source` and an sdd embedding block present or not: the embedder resolves as listed above, `auto` exactly as an unset provider did.
3. `off` and `own` run no `sdd` process.
4. A provider outside the four values is refused; an empty one reads as `auto`.
5. The check line names a set `embedding_source`.
6. README `Options`, `docs/memory/usage.md`, `docs/plugin/usage.md` and `docs/tools/usage.md` describe the picker and what `off` stops, in the same change.
