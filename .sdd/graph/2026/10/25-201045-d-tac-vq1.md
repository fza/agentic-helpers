One list per project, `~/.claude/agentic-helpers/<project>/writers.json`, names the checkouts that may write the project's agentic-memory store and its agentic-tools library, so a repository declaring another project's `repo_id` can write neither.

agentic-memory keys its store by the declared `repo_id`, as agentic-tools does, and any checkout can declare any: a cloned repository naming a trusted project's `repo_id` could claim seats in that project's memory, file entries there, and send shared entries (`--for`) that arrive in its sessions. agentic-tools already lists its writers per library (20261025-194433-d-tac-8qe); one list per project now serves both.

- **`~/.claude/agentic-helpers/<project>/writers.json`**: a JSON array of the absolute git common directories allowed to write, with `.lock` beside it for changes to the list. The project key is the one both pieces use. A new package `source/hooks/internal/writers` reads, claims and extends it for both, reading as the tool library reads: no link, no pipe, no second name, at most 64 KiB.
- **The first call that writes claims an unlisted project** for the calling checkout. A list that cannot be read refuses every write and is never claimed over.
- **agentic-memory**: every subcommand, MCP tool and hook checks the list, except `help`, `who` and `holder`, which only read and answer anywhere. A checkout not listed is refused: `agentic-memory: this memory belongs to other checkouts: <checkouts>; run `agentic-memory trust <this checkout>` from one of them to let this one write`. Its hooks stay silent, and none of its calls migrates the store's format.
- **`agentic-memory trust <path>`**, also the memory MCP tool `trust` with the key `path`, and `agentic-tools trust <path>` both add the checkout at `<path>` to the one list; one trust covers both pieces.
- **agentic-tools reads the shared list** in place of its library's own `writers.json`. A library's own list moves on first use: its entries are written into the shared list where none exists yet, and the library's file is removed. A library list that cannot be read blocks that move, and the project's writes stay refused.

Why: a checkout trusted for a project is trusted for both pieces; two lists would ask for the same trust twice and let them drift apart.

Rejected:
- A list per store, `writers.json` in each of the memory store and the tool library: each stands alone and nothing released moves, but a second clone is trusted twice and the two lists can disagree.
- Gating only the memory calls that write: a read-only call from an untrusted checkout would still claim an unlisted store or migrate its format, so every call but the read-only listings checks the list.

Accepted costs: a released file moves, through code carried for the move; a new folder `~/.claude/agentic-helpers/` and a shared package both pieces depend on; a checkout not listed cannot read the project's memory either, since a seat claim is its first write; the first call after an upgrade claims each existing memory store for the checkout that makes it.

Acceptance criteria:
1. A memory call from a checkout with an unlisted project records its git common directory in the shared list; later calls from it, and from its worktrees, work.
2. Every memory subcommand, MCP tool and hook from a checkout not listed is refused or silent, the store byte-identical before and after; `help`, `who` and `holder` still answer.
3. `agentic-memory trust <path>` and `agentic-tools trust <path>` each add the path's checkout to the one list, after which both pieces accept it; from a checkout not listed both are refused.
4. A library's own `writers.json` moves into the shared list on first use and is removed; a damaged one keeps the project's writes refused.
5. An unreadable shared list refuses every write of both pieces and is never claimed over.
6. The memory MCP `trust` tool takes exactly `path`; `docs/memory/`, `docs/tools/`, `agentic-helpers:agent-memory` and `agentic-helpers:agent-tools` describe the list, the claim, the refusal and both trust verbs.
