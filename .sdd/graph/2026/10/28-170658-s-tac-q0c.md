`agentic-capture` decides whether a titled draft may reach `sdd new` by `sdd info --format json` wherever `sdd info --help` lists `--format`, and keeps the `.sdd/meta.json` read where it does not, closing 20261027-175308-d-tac-i9e. Commit c8ddcba carries the change with its tests and the `docs/capture/` pages, `docs/plugin/usage.md` and the `agentic-helpers:agent-capture` skill; it is not yet released.

Tests cover `capabilities.titles` false refused, true captured, null refused, a failed `sdd info` refused, and an `sdd` whose `info --help` lacks `--format` taking the `meta.json` path unchanged, each guard broken and watched failing. The probe's cache key carries a surface version, so an answer cached before `info_json` existed is probed again.

Proven live on a schema-1 graph built by fork release fza.32, whose `sdd info --format json` reports `capabilities.titles` true: the v2.12.2 release refused a titled draft with `the graph is on schema 1, which has no entry titles`, while the `agentic-capture` built from the commit wrote the entry with its `title` kept.
