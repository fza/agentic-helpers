The idle waiter `agentic-memory wait` stays as it is: a headless `claude -p` run holding a seat keeps waiting after its answer, as 20261030-181944-s-tac-ueg records, and agentic-helpers changes nothing for it.

Why: driving `claude -p` in a project with memory while the run holds a seat is niche usage. Interactive sessions, the waiter's purpose, are unaffected, and a headless run that releases its seat before it ends exits at once.

**Rejected.**
- Skipping the waiter where the session is headless: needs a reliable headless signal in the `Stop` payload or environment, plus tests, for a case almost nobody hits.
- A shorter waiter timeout: shortens every interactive session's wake window to spare a rare headless one.

**Accepted cost.** A script driving `claude -p` with a seat waits up to 31 minutes per run, unless it releases the seat in the run (`agentic-memory release`) or ends the `agentic-memory wait` process itself.
