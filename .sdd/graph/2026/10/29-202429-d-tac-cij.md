`agentic-capture` hands its pre-flight limit to sdd as `sdd new --preflight-timeout`, so raising `--preflight-limit` gives a slow model call more time instead of being cut off by sdd's own 2-minute default.

Why: the limit directive (20261019-203503-d-tac-72s) bounded only how long `agentic-capture` waits for `sdd new --dry-run` and kept sdd's own limits firing first. Under the claude-cli provider, a long draft's pre-flight runs 72 to 93 seconds and can pass sdd's 2m `llm.timeout`; the call is then killed inside sdd on every try, whatever `--preflight-limit` says, and the give-up line (`the draft did not cause it, so capture it again later`) sends the agent into the same wall again. An agent seeing the flag do nothing went looking for it in `sdd serve --help`.

What changes:

- The limit per try is `--preflight-limit`, else `CAPTURE_PREFLIGHT_LIMIT`, else the larger of 5m and a configured `llm.timeout` (read once with `sdd config get llm`), so an owner's higher setting is never cut down.
- Every `sdd new` that runs a pre-flight (the dry run, each `--preflight-route`, and stock sdd's single checking call) gets `--preflight-timeout <limit>`, where the help probe (20261026-204842-d-tac-288) lists the flag; stock and fork both carry it. It bounds every model call of that run but not the extraction fallback, which stays on `llm.extract_timeout` (1m unless configured).
- `agentic-capture`'s own cut-off per try becomes the limit plus the extraction timeout plus 30s, so sdd's bound still fires first and killing the try's whole process group (from 20261019-203503-d-tac-72s) stays the backstop for a hung `claude -p`.
- When the last fault was a timeout, the give-up line adds that a long draft may need more time and names `--preflight-limit`.
- `agentic-helpers:agent-capture` gains: an engine (MCP) capture failing with `claude -p timed out` has no flag; only `llm.timeout` reaches it, and raising it (`sdd config set --local llm.timeout <d>`) is the owner's call.

Rejected:

- A better message alone: `--preflight-limit` would stay a flag that cannot fix the one case agents reach for it in.
- Forwarding only an explicit limit: a default run would still die at 2m on a long draft.
- Dropping `--preflight-limit` for sdd's config: a breaking CLI change, and a per-call bound is what a caller wants for one long draft.
- Reading the effective timeout from `sdd info`: no such field yet.

Accepted costs: one `sdd config get llm` per capture; a hung model call now holds a try for up to the limit instead of 2m.

Acceptance criteria:

1. With fork and stock help fixtures, each pre-flight `sdd new` carries `--preflight-timeout` with the limit from flag, variable, configured `llm.timeout` or 5m, in that order; without the flag in the help, none is passed.
2. A configured `llm.timeout` above 5m wins over the default; below it, 5m.
3. The try's cut-off is the limit plus the extraction timeout plus 30s.
4. Giving up after timeouts names `--preflight-limit`; other faults keep today's line.
5. Skill, README and `docs/capture/*` describe the forwarding and the engine timeout line in the same change.
