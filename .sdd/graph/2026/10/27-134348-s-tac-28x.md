agentic-tools keeps tool vectors in `internal/vectorseg` segments under `~/.cache/agentic-tools/vectors/<fp>/`, implemented in commit db2d16f, not yet released. It closes the tool vector segments directive (20261027-132915-d-tac-cer).

- `index.json` is schema 2 and carries no vector and no fingerprint; a row's id and hash are the description's hash.
- `add`, `update` and `merge` file the tool's vector after the own index names it, and a rebuild files only what no row is held for, skipping a description holding a credential.
- Merges count a row while any store on the machine names its description, `AGENTIC_TOOLS_SCOPE` notwithstanding.
- `find --query`, the near-duplicate check and the prompt offer score through one snapshot; the offer embeds the prompt only where an own tool not yet shown has a row.
- A whole-file `<fp>.json` cache becomes one segment on first open and is removed, embedding nothing.

Tests in `internal/tools/vectors_test.go` cover each criterion: a write leaving earlier segments byte-identical, the index holding no vector, migration with no embed, a replaced description merged away, another store's row kept under project scope, and the offer embedding nothing without a vectored own tool; the existing find, offer and near-duplicate tests pass unchanged. Each guard was broken and watched failing. Two presence checks on scores in find and the near-duplicate check were dropped as unreachable: a valid floor lies in (0, 1], so a tool with no score never passes it. `docs/tools/architecture.md` gains a Vectors section.
