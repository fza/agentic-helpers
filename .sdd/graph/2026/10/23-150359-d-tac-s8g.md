agentic-helpers works only with sdd built from the fork github.com/fza/sdd, installed with `brew install fza/tap/sdd`. A build is the fork when `sdd --version` (`sdd version <v>`) carries `fza` anywhere in `<v>`; the number after it is never parsed.

- `agentic-capture` runs `sdd --version` before the lint and the pre-flight. Where it does not carry `fza`, or sdd cannot be run, it exits 1 with `agentic-capture needs sdd built from github.com/fza/sdd; \`sdd --version\` printed <output>. Install it with \`brew install fza/tap/sdd\``, and runs nothing else.
- The grounding gate checks once per session, at its SessionStart, and only in a project carrying a graph it would guard. Where sdd is not the fork, it prints once `agentic-helpers: the grounding gate is off for this session, since \`sdd --version\` printed <output> and the gate needs sdd built from github.com/fza/sdd; install it with \`brew install fza/tap/sdd\` and start a new session`, records that in the session's ledger directory, and lets every call through for the rest of the session. A session with no such record is gated as before.
- Each check bounds `sdd --version` at 5 seconds.
- The carry-forward and the scratch sweep run no sdd and check nothing.
- `README.md` opens with the install: the sdd fork first, then the plugin.

Why: agentic-capture's flags, its refusal texts and the gate's read rules follow the fork's `sdd`, and upstream networkteam builds lack what they rely on. A capture through the wrong sdd writes an entry it cannot vouch for, so it refuses. The gate only reads commands and never runs sdd, so an agent kept from every tool for an install it cannot perform itself gains nothing; one notice and a gate stepping aside leave the session usable while saying what to fix.

Rejected:
- The gate refusing every call it guards in a graph project. Every agent in every sdd project, unattended jobs included, would stop until the owner installs the fork.
- The gate refusing only graph work (`agentic-capture`, `sdd new`, `wip`, `summarize`). More command matching for a partial guard, while drafts and questions still lean on reads from an sdd the gate distrusts.
- Checking on every hook event. A subprocess on every tool call for an answer that does not change within a session.
- A dedicated `sdd version --fork` output. The substring holds for every fork build, release and local alike, and needs nothing new from sdd.

Accepted costs: a session started before the fork is installed keeps its gate off until it is restarted; a `fza` in an upstream version would pass, which upstream's version scheme does not produce; the version check adds one sdd start to each capture and to each session's start in a graph project.

Done when `go test -race ./...` in `source/hooks` covers a capture refused for an upstream version, a dev version and no sdd at all, with nothing else run, a capture running on a release and a local fork version, the gate's SessionStart writing its notice and record for a non-fork sdd and none for the fork, a recorded session letting a call through that the gate would otherwise refuse, and a project without a graph never running `sdd --version`; each guard broken and watched failing; the skills and `README.md` name the requirement, the refusal and the notice.
