The plugin writes the context reading agentic-memory's nudge ladder reads, so no status line has to.

**Surface.** `plugin/hooks/hooks.json` gains `"modules": ["./register.ts"]` beside its command hooks, which makes the plugin a Claude Code mod. `plugin/hooks/register.ts` hooks `session.measure`, which fires after each main-thread turn, and where `e.context.percent` is set and `~/.claude/agentic-memory` exists writes `~/.claude/agentic-memory/sessions/<session>.ctx` as `{"used_percentage": <e.context.percent>, "size": <e.context.window>, "at": <unix seconds>}`, the session from `$.session.id()`, the home from `$.env.get('HOME')`, the write through `$.fs.write`. It always passes the event on with `next(e)`. The file's path and format are unchanged, so the nudge's reader (`internal/memory/hooks.go`) stays as it is, falling back to transcript growth where no reading exists.

**Tests.** `plugin/hooks/register.test.ts` runs under `claude plugin test plugin`; the `test` workflow runs it beside `go test`, with Claude Code installed from npm at a pinned version.

Why: Claude Code hands the context percentage to the status line and to mods, never to a command hook, so the reading came from a status line each machine had to write by hand, and a machine without one ran the ladder on transcript growth alone. A plugin cannot set the main status line: of a plugin's `settings.json` only `agent` and `subagentStatusLine` take effect.

Rejected: an `agentic-memory statusline` subcommand fed the status line's JSON on stdin. All Go and covered by `go test`, but every machine still wires it into its own status line by hand. Rejected: documenting the status line snippet and keeping the sensor in the user's script. Nothing changes, and the sensor stays a hand-kept script per machine.

Accepted costs: the repository's first TypeScript, tested by Claude Code's own runner rather than `go test`, and a CI step that installs Claude Code; `$.fs.write` offers no rename, so the write is not atomic, and a reading caught mid-write fails to parse and the ladder falls back to transcript growth for that one prompt; a Claude Code too old to load mods gets no reading and the same fallback; the plugin now depends on the mods API's names (`session.measure`, `context.percent`, `context.window`).

Acceptance:

- `claude plugin validate .` passes and lists `./register.ts hooks: session.measure`.
- A `session.measure` with `context.percent` set writes the `.ctx` file in the format above; one without it, or on a machine without `~/.claude/agentic-memory`, writes nothing; every case calls `next(e)`.
- `claude plugin test plugin` passes locally and in the `test` workflow.
- A session with no status line writing the reading gets its `.ctx` file after its first turn.
- `README.md` and `agentic-helpers:agent-memory` name the plugin, not a status line, as the writer of the reading.
- Each new guard is broken, its test watched failing, and the file restored byte-identically.
