It builds on the output trimming directive (20261031-102607-d-tac-lsl) and satisfies the empty-context test (20261031-102822-d-tac-n3k), which a printed trigger passes and a skill-only rule does not.

Every line in agentic-memory and agentic-tools output that stands for data it does not print, a fold or a paging line, carries its own trigger saying when to run the command it names, and the skills and MCP tool descriptions state one rule for all of them, so agents fetch what a fold hides instead of reasoning from the part they see.

**In the output.** Each such line ends with a short trigger in parentheses after its command, for example `39 settled (37 done, 2 dropped): agentic-memory show m-sx73lz --all-items  (run before judging what was done)`, `127 more: --skip 2  (run before concluding none fits)`, `+29 from other seats: agentic-memory search --all-seats --status live  (run before starting work another seat may hold)`. The same holds for the brief's `+<n> more notes` and `+<n> more due`, the item-change fold, the tool library's other-projects and paging lines, and any fold added later. A seen pointer (`(seen)`, `<n> seen above, unchanged`) gets none: its text is already in the context.

**In the skills and tool descriptions.** `agentic-helpers:agent-memory` and `agentic-helpers:agent-tools` carry one rule: a fold line hides unread data; before acting on, answering about, or concluding the absence of what it folds, run its command. The MCP descriptions of memory's `search`, `show`, `brief` and the tools' `find` and `list` carry the same clause.

Why: agents ignore a bare `5 more` and conclude from the visible part, so a fold that saves tokens can cost a wrong answer. Skills load on demand and are gone after a compaction until something loads them again, so only a trigger printed beside the fold reaches an agent with an empty context; the skill rule and the description clause make the behaviour one rule rather than per-line hints that drift.

Rejected:
- Skill rules alone: they miss the agent that sees the fold before any skill is loaded.
- Triggers in the output alone: with no central rule, a new fold line can ship without one and wording drifts between the tools.

Accepted costs: about 5 to 10 tokens on each fold line printed; a few lines in each skill and description; every test asserting a fold line's text moves.
