`agentic-capture` follows the sdd release that gives every entry a title and gates every write on the graph's schema version.

- The draft header key `title` becomes `sdd new --title` with one value. sdd judges the value (one line, not empty), as it judges every other.
- Where sdd's output carries `refusing to write — graph incompatible with this binary`, from the pre-flight or from the capture step, stderr says `the graph needs \`sdd migrate\` before sdd writes to it; the draft did not cause this, so run \`sdd migrate\` and capture again`, then sdd's own lines, and the run exits 1. It is no provider fault: nothing is retried and no fallback route is tried.
- `plugin/skills/agent-capture/SKILL.md` and `README.md` name the key and the refusal. The change ships as a minor release ahead of the sdd install.

Why: sdd's write gate covers all of `sdd new`, `--dry-run` included, so on a graph still at schema 1 every capture fails at the pre-flight, and the generic `pre-flight refused the draft:` points an agent at a draft that is fine. A title an agent cannot set is one it cannot correct either, and without a mapped key the header refusal turns a `title:` line away.

Rejected:
- Leaving the refusal to sdd's own text under `pre-flight refused the draft:`. sdd names the fix, but the line above it names the wrong cause, and an agent edits the draft first.
- Leaving titles to sdd's generation alone. A generated title that misses its subject could then be replaced only by hand.
- Running `sdd migrate` from `agentic-capture`. A schema migration rewrites the whole graph and asks first; it belongs to whoever owns the graph, not to a capture.

Accepted costs: the refusal is recognised by sdd's wording, so a rewording in sdd needs the match changed with it; until the titled sdd is installed, a draft carrying `title` fails on the installed sdd's unknown flag.

Done when `go test -race ./...` in `source/hooks` covers a draft with `title` reaching the pre-flight and the capture as `--title`, the schema refusal at the pre-flight and at the capture step each exiting 1 with the `sdd migrate` line and sdd's text and nothing retried or routed, and each guard broken and watched failing; a release carries it before the titled sdd is installed.
