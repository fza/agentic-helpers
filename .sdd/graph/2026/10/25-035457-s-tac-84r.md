Done for 20261025-032243-d-tac-8c2: commits d13507d (retired bodies) and d845d9c (fold), released as v2.2.0 (release commit c51ef6a).

- `mergePolicy` (`internal/memory/state.go`) folds each entry's leading run of events at or before the 14-day horizon into its `new` row (title, topics and retention as the run left them), its latest `confirm`, and the `retire` and `supersede` rows still standing after the run's revives, by original row; the run ends at the entry's first event past the horizon, so an older stamp appended after a younger one stays behind it. Topic merges and every younger event are kept byte for byte, an entry filed inside the horizon included.
- `retired_body_days` (`internal/pluginconfig`, `userConfig` in `plugin/.claude-plugin/plugin.json`) reads 90 unset and never under 14; a merge strips the body of an entry retired longer ago; `show` prints `(body dropped <n> days after the retire)` and `revive` refuses with `<id> body dropped; file it again`.
- `internal/memory/state_internal_test.go` drives each fold case against the state the unfolded log rebuilds; `TestARetiredBodyDroppedByAMerge` drives `show` and `revive`; `internal/pluginconfig` tests the default and the floor. Every guard was broken and its own test went red. `README.md` and `agentic-helpers:agent-memory` describe both.
- Not driven by a test: a binary of an earlier release reading a folded log. The fold writes only existing kinds, which every fold case asserts by the kinds it expects.
