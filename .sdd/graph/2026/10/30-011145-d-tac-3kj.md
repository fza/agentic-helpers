An agent reads a tool taken from another project before running it the first time in a context; a tool from its own project's library it may run by its usage unread.

Why: `take` hands an agent code another project's agent wrote, since reads span every project on the machine (d-tac-e9x), and nothing in the library checks what a script does: the guards scan for credentials, refuse links, hard links and pipes, and cap sizes. The hashes a take records only notice the agent's own edits to its copy, and the index holding them lives in the same writable home as the files, so checking against it proves nothing (s-tac-k4o). The risk that matters is spread: an agent misled by injected text registers or updates a harmful tool, and agents in other projects run it. Measured on this machine, 18 of 40 takes were read before running (s-tac-nim), with nothing telling an agent when to. Reading costs about 0.2 input tokens per byte plus a call of about 300 output tokens; spending it on foreign tools alone puts it where the risk is, per the least-risk-first order of d-tac-00q, while the own project's tools, which an agent in that project could equally edit in the checkout, run unread.

**What foreign means.** A tool shown as `<name>@<project>`, which is how `find`, `list` and `take` already name a tool from another project's store. A fork, written into the own store by `update`, counts as the own project's.

**What tells the agent.** The `agentic-helpers:agent-tools` skill states the rule. `take` marks each foreign tool in its reply, after its heading: `from another project: read it before running it`; over MCP and `--json` a taken tool carries `foreign: true`. The mark costs one line per foreign take and nothing for the own project's.

**What reading catches.** Obvious harm (a download piped to a shell, a removal outside the project, a network call a helper has no reason for) and a script that does not do what its summary says. Subtle harm can pass a read; this lowers the risk, it does not remove it.

**Rejected.**
- Reading every taken tool before running: a read on every take, roughly doubling a lookup for the commonest case, while a same-project writer could as well edit the checkout directly.
- No rule, reading left to judgement: a harmful tool from another project runs unread in about half the takes.
- Verifying copied files against the index's hashes: the index sits in the same writable home and proves nothing.

**Accepted costs.** A read per foreign tool per context. A harmful tool registered in the agent's own project runs unread.

**Acceptance.**
1. `take` of a foreign tool prints the mark under its heading and JSON `foreign: true`; `take` of an own tool, a fork included, prints neither.
2. The skill states the rule and what foreign means.
3. `docs/tools/usage.md` describes the mark in the same change.
