The key-worded MCP tool descriptions are proven on binaries built from commit b36b6a8, though their done (20261027-225457-s-tac-rf6) was written before that proof, on unit tests and guard breaks alone. When the done was written, every session on the machine ran the release binaries under `~/.claude/plugins/data`, `AGENTIC_HELPERS_BIN_DIR` was unset, and no binary built from commit b36b6a8 had served a single call. Three of the directive's four rules between keys (`ack`, `search`, `view`) had no test.

The proof that holds it, run on binaries built from a clean checkout of b36b6a8:

- `tools/list` of the built `agentic-memory mcp` serves 32 tools and `agentic-tools mcp` 8, none with `--`, `<` or `CLI form` in its description and none with an undescribed input key; `ids` reads "entry ids, an array even for one", `id` "the entry's id, one string".
- Through the built server, against a throwaway store and repository, `supersede` with `ids`, `by` and `because` lands (`superseded <id> by <id>: the cache moved`) and `show` reads both back; `supersede` with `ids` alone is refused `supersede needs --by <id>, --because '<why>' or both`.
- `TestEveryRuleBetweenKeysIsStatedInItsToolDescription` (commit 7ed11ca) checks the `supersede`, `ack`, `search` and `view` wordings; each wording removed in turn fails its own subtest, the file restored byte-identically.

Still unshown: that agents send the right shapes once a release carries the change, since no session runs it yet.
