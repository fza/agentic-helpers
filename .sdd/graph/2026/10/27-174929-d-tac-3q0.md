No agentic-helpers piece fails because an external tool it calls is older than that tool's newest release: sdd, git, gh, an embedding endpoint, Claude Code itself. A piece uses a newer feature only where a probe of the installed tool finds it, and where the feature is missing it keeps the path the older release supports. Requiring an upgrade is never the fallback for something an older release can still do. This widens the stock-sdd rule of 20261026-204842-d-tac-288, which probes `sdd --help` for fork features and keeps a stock path for each, to every tool and every release.

Why: the tools install machine-wide and run in every session, so a feature that needs the newest release of a tool breaks every machine whose owner has not run `brew upgrade` yet, and the breakage lands in sessions working on something else.

Rejected:

- Requiring the newest release of a tool once agentic-helpers uses a feature of it: fails for anyone who skipped an upgrade.
- Detecting by version number: versions of a fork and its upstream do not order, and a version says nothing about which feature a build carries.

Accepted costs: every use of a newer tool feature carries an older-path fallback and its tests, kept for as long as an older release can be installed; a probe runs on each new binary.

A piece adopting a newer tool feature is done only when a test covers both the probe finding it and the older path where it is missing.
