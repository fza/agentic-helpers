Every shell-guard ask follows the hook input's `permission_mode`, for every guard that can ask: outside-project removals (`shell_guard_outside_project`) and `find -delete` (`shell_guard_find_delete`), both set by the shell-guard directive (20261025-235046-d-tac-n48), and secrets (`shell_guard_secrets`, 20261026-223236-d-tac-vr7). A missing `permission_mode` reads as `default`.

- `default`, `acceptEdits`, `plan`: ask, with no time limit; a person is at the prompt.
- `auto`, `bypassPermissions`: ask with a countdown. A new hook, `agentic-shell-guard permission` on `PermissionRequest` for Bash, judges the call again; for a call shell-guard asked about, it waits `shell_guard_ask_timeout` seconds (plugin option, default 120, `0` for no limit) and then answers `deny` with the message `agentic-shell-guard: nobody answered within <n>s; <the guard's reason>`. An answer given before the countdown ends decides the call. After three countdowns run out unanswered in a session, it denies at once until the next user prompt. Its `hooks.json` timeout exceeds the countdown.
- `dontAsk`: `deny` at once, with the guard's reason.

Why: a hook's ask forces a permission prompt even in `auto` mode, and Claude Code gives a hook's ask no time limit, so an unattended job launched in `auto` (an fdbox board job, interactive and in `auto` or `dontAsk`) stalls on it with nobody to answer. Claude Code gives its own prompt for critical-path removals a two-minute countdown in `auto` and `bypassPermissions`, denying when it runs out so an unattended session keeps working; shell-guard's asks take the same shape. In `dontAsk`, Claude Code turns a prompt into a denial without a reason the agent can act on; denying with the guard's reason gives it one. A `PermissionRequest` hook runs when the prompt is about to show and may answer it; whichever of the person and the hook answers first decides.

Rejected alternatives:

- Marking unattended sessions with an environment variable the launcher sets, or a seat flag in agentic-memory: each needs the launcher to remember it, and a seat flag ties shell-guard to memory's store and leaves seatless sessions unmarked; the permission mode is already in every hook input.
- Denying at once in `auto` and `bypassPermissions`: an attended session in those modes loses the chance to approve; the countdown keeps the prompt for a person who is there and ends it for a session nobody watches.
- A countdown in every mode: in `default`, `acceptEdits` and `plan` a person approves each call, and a deny while they read the prompt would be wrong.

Accepted costs:

- An unattended session in `default`, `acceptEdits` or `plan` mode still stalls on a shell-guard ask.
- A person in `auto` or `bypassPermissions` mode away for longer than the countdown comes back to a denied call, which the agent then reports or works around.
- A new hook entry point, `agentic-shell-guard permission`, and the plugin option `shell_guard_ask_timeout`.
- The deny wording is part of shell-guard's contract, quoted by agentic-helpers:agent-shell-guard.

Acceptance criteria:

1. For each guard set to `ask`: `dontAsk` answers `deny`; `default`, `acceptEdits`, `plan` or no field answer `ask`; `auto` and `bypassPermissions` answer `ask`.
2. The `PermissionRequest` hook answers `deny` after `shell_guard_ask_timeout` for a call shell-guard asked about (a fake clock in tests), at once after three unanswered countdowns until the next user prompt, never for a call shell-guard did not ask about, and never with `0`.
3. Verified live in an interactive session in `auto` mode: an answer before the countdown ends decides the call and the hook's later deny changes nothing; a countdown left to run out denies the call and the session goes on.
4. `plugin/hooks/hooks.json` wires `PermissionRequest` for Bash with a timeout above the countdown; `shell_guard_ask_timeout` is declared in `plugin/.claude-plugin/plugin.json`.
5. agentic-helpers:agent-shell-guard and `docs/shell-guard/` name the modes, the countdown and the wording, in the same change.
