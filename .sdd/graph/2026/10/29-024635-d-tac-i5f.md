Agentic-helpers data files that grow per session or per event move from JSON files to formats of its own, built on the Go standard library alone: one preallocated slot file per store for per-session state, binary typed journals on the AGMSEG record codec, a size ledger per component, and an `agentic-helpers dump` command decoding any of them to JSON lines. JSON stays for metadata.

Why: per-session state lives today in one small JSON file per session and purpose, so files pile up by the thousand under the cache root and seen lists reach megabytes, each rewritten whole. Journals in JSON lines carry no checksum, so a torn or planted line is only caught by a parse error.

**1. Per-session state slot file.** Seen and shown marks, the recall ladder, trap notices, brief marks, shell-guard countdowns and the tool library's session files move into one preallocated slot file per store:
- fixed-width slots, an A/B twin per session, each slot carrying a generation counter and a CRC32C, the newer valid twin winning on read;
- written with `pwrite`, read with `pread`, so a writer touches only its own slot;
- a slot is reclaimed by clearing its key; the file's size is the slot count in its header times the slot width.

**2. Journals.** `tail.jsonl` of the memory log and `history.jsonl` and `takes.jsonl` of each tool become binary journals: length-prefixed, CRC-checked, typed records (a kind byte plus a schema byte, a reader skipping kinds it does not know) on the AGMSEG record codec of the memory log (d-tac-mvn), in `source/hooks/internal/memorylog`. Records are appended under the store lock the writer already holds, and sealed into AGMSEG segments as the memory log's tail is today.

**3. Size ledger.** Each component keeps a manifest listing every data file with its length and CRC. It is the recorded metadata the space accounting of d-tac-x9j reads instead of walking directories.

**4. Seen lists as bitsets** over a per-store interned name table, only if a benchmark (`BenchmarkCaptureNotice`, over a fixture of about 2000 entries filed in a month) beats today's JSON. Otherwise seen lists stay in their slot as they are.

**5. `agentic-helpers dump <file>`** decodes any of these data files to JSON lines, so nothing stored becomes unreadable to a person or a script.

**The context sensor stays a file.** `register.ts` writes the `.ctx` file whole on every turn through `$.fs.write` of the Claude Code mod API, which documents no positional write, so one small file per running session stays. A session's `.ctx` is removed at its end, and the SessionStart pass sweeps those of crashed sessions. The backlog of per-session files left by earlier releases is removed.

All of it lives in the per-store layout of d-tac-6xf. No new module dependency: the standard library covers CRC32C (`hash/crc32`), positional I/O and binary encoding.

**Rejected.**
- SQLite through `modernc.org/sqlite` in every hook binary: it grows every binary and costs an open per hook call.
- Converting the journals only: the per-session files and megabyte seen lists, the larger cost, would stay.
- The MCP server as the sole writer: a server can be off, and hooks must still record.
- Extended attributes for per-file state: lost on copy and backup.
- Lock-free appends through `O_APPEND`: atomicity is guaranteed only for pipes, and breaks on network home directories and on a full disk (`ENOSPC`).

**Accepted costs.**
- Every changed file needs a format bump of its component's own `format.json` (d-tac-6xf) and a migration run under the store lock, writing `format.json` last so a failed run leaves the old files in place, and a release meeting a newer format refusing it.
- Data files can no longer be read with `cat` or `jq` directly; `agentic-helpers dump` stands in.
- A codec of its own to maintain and test, where JSON came for free.

**Acceptance.**
1. Two sessions writing their slots concurrently never corrupt each other's, under `-race`.
2. A torn slot write leaves the twin readable; a CRC mismatch is read as the older twin.
3. A reclaimed slot is reused, and the slot file never grows past its header's count times the width.
4. A journal record of an unknown kind is skipped; a record failing its CRC stops the read at that record, as a torn segment does today.
5. A component's manifest matches the lengths of its files after every write, purge and prune, checked against a fixture store.
6. Bitset seen lists ship only with a benchmark result beating JSON, recorded in the change.
7. `agentic-helpers dump` decodes every file kind above to JSON lines.
8. `go.mod` gains no dependency.
9. A migration turns a store holding the old JSON files into the new formats, and leaves no per-session file but running sessions' `.ctx`.
