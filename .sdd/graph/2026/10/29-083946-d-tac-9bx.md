The grounding gate's let-through note fires once per cause, where the cause is the set of missing reads under the current graph state; later gated calls with the same cause pass silently. This replaces the firing rule of 20261029-023134-d-tac-xv3 ("the note fires on every gated call while reads are owed") and brings the note under 20261027-222117-d-tac-yjy, which holds every hidden hook message to at most once per cause.

- **Scope.** The note on calls the gate lets through: `AskUserQuestion`, and `Write`, `Edit` and `NotebookEdit` on a draft (`letThrough` in `source/hooks/internal/grounding/grounding.go`).
- **Re-armed** when the graph changes, when a compaction clears the reads' credit, or when the set of missing reads changes. Then the next gated call carries the note again.
- **State** is per session, kept in the gate's session ledger.
- **Refusals unchanged.** A capture, a plain `sdd new`, an `sdd show` short of the owed depth and a discarded stream are refused on every call with their full text.
- **Wording unchanged.** The note keeps the text xv3 set, naming only the missing reads.
- **Contract.** `agentic-helpers:agent-grounding` and `docs/grounding-gate/` say the note fires once per cause, in the same change.

Why: yjy makes a hidden message that repeats without a new cause a defect, and the note fired about 15 times in one session and was skipped each time. The capture refusal still catches reads an agent skipped.

Rejected: firing on every gated call, as xv3 built it (an exception to yjy, 150 to 250 characters per question, and it teaches agents to skip the note).

Accepted cost: an agent that forgets the single note asks later questions ungrounded.

Acceptance (each guard broken once and watched failing):
- A second gated call with the same missing reads and an unchanged graph carries no note.
- A graph change re-arms the note.
- A different set of missing reads re-arms the note.
- A capture is still refused on every call.
- `agentic-helpers:agent-grounding` and `docs/grounding-gate/` state the rule.
