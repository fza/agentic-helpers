agentic-memory links reach entries of sdd's connected repos, as `<repo_id>:<entry-id>` or a bare id one connected repo holds, in agentic-helpers commit 31a4c1f with a missing test added in 0d6fdab, not yet released, completing 20261026-220938-d-tac-l8w.

Each criterion with its test in `internal/memory/`:

1. `--link`, `link` and text links take the qualified form and refuse an id no connected repo holds, with `not in the local graph or any connected repo (sdd repo list)`: TestAConnectedRepoEntryLinksQualified, TestALinkNoConnectedRepoHoldsIsRefused.
2. A bare id one connected repo holds is stored qualified; one several hold is refused naming them: the same two tests.
3. Link flags, `closed:` conditions and `retire?` read a foreign entry's status from a fake export carrying a non-local repo: TestAForeignLinkFlagsWhatTheExportSays, TestClosedReadsAConnectedRepo, TestRetireQuestionReadsAConnectedRepo.
4. The status cache refreshes when a connected repo's cache changes: TestGraphStatusIsCachedUntilAConnectedRepoChanges.
5. The docs and agentic-helpers:agent-memory name the qualified form and the refusal wordings.

Without `sdd export`, a qualified id is refused with `resolving another repository's entry needs sdd export, which this sdd lacks`, and local links still resolve (TestWithoutExportAQualifiedIDIsRefused). The several-repos refusal wording, `<id>: in several connected repos (<q1>, <q2>); link one of them`, is new, since the directive named none.
