agentic-memory's hook-written state draft names a turn Claude Code sent itself as the user's last prompt: on v2.12.2 the draft for seat main-2 (fork ddb0272b) read `last prompt: <task-notification> <summary>Stop hook feedback</summary> ...`.

Observed: Claude Code delivers some of its own turns through UserPromptSubmit, a background task's notification among them, and the prompt hook records every non-empty prompt the credential scan passes as `last_prompt` (`prompt()` in `source/hooks/internal/memory/hooks.go`). The project's transcripts show such turns open with a tag: `<task-notification>`, `<local-command-caveat>`, `<local-command-stdout>`, `<bash-stdout>`.

Expected: the draft's last prompt says what the user last asked, as the draft directive's own wording has it (20261028-000548-s-tac-mgh records the delivered draft as listing the session's last prompt); a notification that a hook or a background task finished is no ask, and naming it there misleads whoever reads the draft as a lead on what the seat was working on.

Candidate remedy, unsettled: skip a prompt whose text opens with one of those tags when recording `last_prompt`, while a prompt only mentioning a tag stays the user's.
