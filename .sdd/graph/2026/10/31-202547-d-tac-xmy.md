Each subagent gets agentic-helpers context and memory access by a level its spawner names in the Agent prompt, on a ladder `none < rules < silent < shared < full`, with no marker meaning `none` and a nested subagent never getting more than its spawner. It replaces the single block for every subagent (20261031-195921-d-tac-sgm): exploratory and divergent subagents, such as idea branches that must not be anchored, get no rules or memory guidance, and not every subagent should be told to use agentic-memory at all.

**The levels**, each adding to the one below:
- `none`: the scratch folder and the machine line (the command-dialect notice `agentic-helpers check` prints at session start). Neutral facts that save a refused command and anchor nothing. Every subagent without a marker, idea branches and lookups included, runs here.
- `rules`: plus the parent seat's live user rules (20261031-192031-d-tac-e9f places standing instructions there).
- `silent`: plus read-only memory: search, show and brief; every write refused.
- `shared`: plus a one-line notice at the subagent's next tool call whenever another seat on the parent's shelf files or changes an entry while the subagent runs, the same notices shelf mates already get.
- `full`: its own temporary seat on the parent's shelf: it files, its entries name that seat, its state slot is its own, and notices run both ways through the shelf.

**The marker.** One line `agentic-helpers: <level>` in the Agent call's prompt. The agent-memory skill states the ladder and when to pick each level in its core; the details sit in a reference file beside it.

**How it is enforced.**
- A `PreToolUse` hook on the Agent tool reads the marker from `tool_input.prompt`, caps it at the spawner's own level (the spawner's `agent_id` is on the payload; the main thread has none and no cap), and rewrites the prompt through `updatedInput`: the marker line is replaced by the level's block (scratch, machine line, rules where due, the memory line where due). The child carries its level in its own prompt, so nothing has to pair a `SubagentStart` with its Agent call: that hook carries no prompt, call id or parent id, and the only pairings found (event order, internal transcript files) are undocumented.
- The rewrite never sets `permissionDecision: allow`: it changes the prompt and leaves the permission decision where it was, since an allow sent with a rewrite skips the user's prompt.
- Memory calls from a subagent are judged in `PreToolUse` on Bash `agentic-memory` and the memory MCP tools, which carry `agent_id`: a write below `full` is refused; at `full` the call is routed to the subagent's seat. The level per `agent_id` is learnt from the Agent call's own `PostToolUse` for background spawns and from the child's first tool call for foreground ones, keyed on the prompt's level line, and kept per session. The MCP server, which never learns the calling agent, reads that record by the call id it receives in `_meta` (`claudecode/toolUseId`).
- A `full` subagent's temporary seat is released when `SubagentStop` fires for its `agent_id`.

**Rejected.** One block for every subagent (the superseded decision): anchors idea branches and tells lookups to use memory. Deciding by agent type: idea branches and builders share the type `general-purpose`. Subagents writing on the parent's seat with guarded verbs: one state slot and one author for every agent. Pairing `SubagentStart` with the Agent call by event order or by `subagents/agent-<id>.meta.json`: both undocumented, and the order breaks when two agents spawn at once.

**Accepted costs.** A spawner that forgets the marker leaves its builder at `none`. A level fixed at spawn does not change while the subagent runs. Routing and refusal depend on `agent_id` in hook payloads, documented by Claude Code; the MCP join on `_meta` is observed, not documented, so the CLI path is the fallback where it breaks.

**Acceptance.**
- No marker: the child's prompt gains the scratch and machine lines only.
- Each level's block matches the ladder; a nested spawn asking for more than its spawner gets the spawner's level.
- A memory write from a subagent below `full` is refused on Bash and MCP; at `full` it lands on the subagent's temporary seat, which `SubagentStop` releases.
- `shared` and `full` subagents receive shelf notices at their tool calls; `silent` ones do not.
- The prompt rewrite never answers the permission decision.
- The agent-memory skill, `docs/memory/usage.md`, `docs/scratch/usage.md`, `docs/plugin/usage.md` and the README describe it.
