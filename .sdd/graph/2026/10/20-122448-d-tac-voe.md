`agentic-capture` accepts a pre-flight its caller already ran on the draft, so a draft judged once is never judged again at capture.

- `--preflight-done <sha256>` names the sha256 of the draft file's bytes as read from disk, front matter included: what `sha256sum <draft.md>` prints. Upper and lower case hex both match. A value other than 64 hex digits, or the flag given with `--skip-preflight`, prints the usage line and exits 1.
- The hash is taken over the same read the draft is parsed from, so a file changed after the hash cannot reach `sdd`.
- On a match, the header check and the project's draft lint still run, then `sdd new --dry-run` is skipped and the capture runs with `--preflight-verified`, as after a clean pre-flight of its own. Stderr carries `pre-flight skipped: the caller ran it on these exact bytes`. No `AGENTIC_CAPTURE_ROUTE` line is printed, since no route answered.
- On a mismatch, the pre-flight runs as without the flag, after one stderr line: `--preflight-done names <given>, but the draft hashes to <actual>; running the pre-flight`.
- `--skip-preflight` keeps its meaning, an entry recorded as unchecked. `--preflight-done` never records an entry as unchecked.
- `--help` prints the usage line, which lists `[--preflight-done <sha256>]`, then one line per flag; the `--preflight-done` line states the bytes the hash covers. It writes to stdout and exits 0. Any other argument the parser refuses still prints the usage line to stderr and exits 1.

Why: a caller holding a board of drafts can run the pre-flight when a draft is registered, keyed by the draft's sha256, and record the result. With a reasoning model answering in minutes, `agentic-capture` running the same pre-flight again on the same bytes doubles the cost of every capture for no new judgement.

Rejected:
- Hashing the argument vector `sdd new` receives. It names exactly what was pre-flighted, but a caller has to rebuild the flag mapping and Go's JSON encoding byte for byte. A Python caller's `json.dumps` already writes `<`, `>` and `&` where Go escapes them, so the key misses and the second pre-flight runs anyway, and every later change to the mapping breaks it again.
- Hashing the trimmed body alone. An edit to `refs`, `closes`, `kind` or `summary` would pass as verified with nothing having checked it.
- Recording a matched entry as unchecked (`--skip-preflight`). The caller's pre-flight is the same `sdd new --dry-run` on the same bytes, and an unchecked mark would misreport it.
- Skipping the draft lint on a match. It is the project's rule, local and fast, and the caller's pre-flight does not vouch for it.

Accepted costs: a match trusts that the caller built `sdd`'s arguments from the file as `agentic-capture` does, and that it held back a high finding; any byte changed in the file, front matter whitespace included, costs a second pre-flight.

Done when `go test -race ./...` in `source/hooks` covers a match capturing with `--preflight-verified` and no `--dry-run`, an uppercase match, a mismatch running the pre-flight after the line naming both hashes, a malformed hash and the flag beside `--skip-preflight` refused with the usage, a match still blocked by the draft lint, and `--help` printing the bytes line on stdout with exit 0; `README.md` and `skills/agent-capture/SKILL.md` describe the flag.
