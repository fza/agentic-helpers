The grounding gate runs a project's `draft_lint` and its `listing_prefix` topic rule on captures through sdd's MCP server, refusing a report the way `agentic-capture` refuses a draft. Engine-first routing (20261026-200321-d-tac-bo5) sent captures to the MCP path, where neither check ran, and never weighed losing them: a project that bans terms through its lint or files every entry under a listing topic lost both on every capture.

What the gate does, on `mcp__sdd__start_procedure` with `canonical: capture` and on each `mcp__sdd__next` of that capture, where the resolved project's `.sdd/grounding.yaml` sets the key:

- `listing_prefix`: a report or start params carrying `topics` with none starting with the prefix are refused. A playback `confirm` is refused while no topic carrying the prefix was seen for the capture.
- `draft_lint`: every report or start params carrying `body` or `bodyPatch` has the resulting body linted, run as `agentic-capture` runs it (from the repository root, on a body file, findings by line). Findings refuse the call and name each one.
- The body a `bodyPatch` yields is rebuilt by the gate: it keeps the last whole body it saw per capture instance and applies the edits as sdd does (each old text found exactly once, all or nothing). Where an edit does not apply, sdd refuses the report itself, so the gate lets it pass unlinted. Where the gate holds no body for the instance (its record lost), it refuses once and asks for the whole body.
- Refusals open `GROUNDING GATE: refused.` like the gate's existing refusals, listed in `docs/grounding-gate/usage.md`; their wording is part of its contract, and `agentic-helpers:agent-capture` and `agentic-helpers:agent-grounding` quote them.

Out of scope: retrying a model provider failure inside the MCP capture. The gate sees only the call, and sdd runs the model calls itself.

Rejected:

- Requiring the whole body on every revision where `draft_lint` is set: exact, but costs the full text again per fix.
- Linting whole bodies only: an edit could bring in what the lint forbids, unchecked.
- Accepting the loss: sdd's writing guide and pre-flight know nothing of a project's own rules.

Accepted costs: the gate repeats sdd's edit rule and reads capture reports' `body`, `bodyPatch` and `topics` fields, so a change to sdd's report schema or edit rule needs a matching change here; one lint run per report carrying text.

Acceptance criteria:

1. With `listing_prefix` set, MCP reports and start params with topics lacking it are refused, and a confirm is refused while none was seen; without the key nothing changes.
2. With `draft_lint` set, a whole body with findings is refused naming them; a clean one passes.
3. A `bodyPatch` is applied to the last whole body and the result linted; a patch whose old text is missing or doubled passes unlinted; a patch with no recorded body is refused asking for the whole body.
4. Without either key, MCP captures pass as today.
5. Skills and `docs/grounding-gate/*` describe both checks and quote the refusals in the same change.
