Done for 20261025-020550-d-tac-ofh: commit a9626e5, released as v2.1.0 (release commit 8d04187).

- `source/hooks/internal/grounding/mcp.go` records `mcp__sdd__search` (`query` semantic, `terms` literal, blank terms none) and `mcp__sdd__view` (its `layout` through the same listing rule as `sdd view`); a failed MCP call fires `PostToolUseFailure`, so only a call that succeeded is recorded.
- `mcp__sdd__show` is refused short of the owed depth, an omitted `down` read as 1 and `up` as 2, with the refusal `refusals/downstream-mcp.txt`; a `prc`-layer rules entry and an exempt seat pass. `mcp__sdd__start_procedure` with `canonical: capture` owes the turn's three reads; every other procedure and MCP tool passes.
- `hookio.ToolInput` keeps the raw tool input for MCP arguments; `plugin/hooks/hooks.json` adds `mcp__sdd__show|mcp__sdd__start_procedure` to the gate's `PreToolUse` matcher and `mcp__sdd__search|mcp__sdd__view` to its `PostToolUse` record matcher.
- Deviation: the decision names `mcp__sdd__show` in the `PostToolUse` record matcher too; it is left out. The per-turn ledger holds searches, listings and grounded drafts only (`evidence.complete` in `internal/grounding/ledger.go`), and a Bash `sdd show` is gated on depth and never recorded either, so recording an MCP show would add nothing to the ledger and parity with Bash holds without it.
- Every acceptance criterion holds, each driven by `internal/grounding/mcp_test.go` or `TestTheGateSeesSddsMCPTools`; every new guard was broken and its own test went red. `README.md` and `agentic-helpers:agent-grounding` describe the MCP forms.
