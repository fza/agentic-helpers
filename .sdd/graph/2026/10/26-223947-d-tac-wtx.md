The grounding gate finds `sdd`, `sdd new`, `agentic-capture` and gather calls in a Bash command by walking the command's syntax tree from `mvdan.cc/sh/v3/syntax`, already a dependency of `source/hooks`, instead of its own lexer (`grounding/shell.go`, 272 lines, and `reads.go:115-223`). The walk that finds commands, launchers (`env`, `xargs`, `bash -c`), heredoc and pipe feeds moves into a package both the gate and shell-guard use, `internal/shellwalk`. The gather-call reading rules of 20260930-184805-d-tac-7yz (a command word outside every quoted span, flags as the shell splits them, nothing credited inside `bash -c`) are kept, now read from the tree.

Why: the hand-written lexer gets quoting wrong where a parser cannot: `quotedSpans` ignores `$'...'` and backslash escapes inside double quotes, and the heredoc pattern takes only `\w+` delimiters, so a call spelled one of those ways slips past or a quoted mention is taken for a call. shell-guard (20261025-235046-d-tac-n48) already parses every Bash command with mvdan and already walks launchers, `sh -c` code and fed code; the gate repeats that work by hand.

A command that does not parse: the gate treats it as calling sdd wherever its text contains `sdd` or `agentic-capture` as a word, so the reads stay owed. shell-guard denies such a command anyway, but shell-guard can be switched off and the gate must not lose a capture to a parse error.

Rejected alternatives:

- Keeping the lexer and fixing its gaps one by one: each fix is another case a parser handles by construction.
- Letting an unparseable command through: with shell-guard switched off, an `sdd new` spelled to fail parsing would escape the gate.
- Each hook keeping its own walk over the tree: the launcher and nesting rules would drift apart.

Accepted costs:

- About 0.2 MB more in `agentic-grounding-gate`, which now links the parser.
- A shared package, `internal/shellwalk`, which both hooks' tests exercise.

Acceptance criteria:

1. The gate's existing tests pass unchanged against the parser.
2. New cases: `$'sdd' new`, `"s\dd" new`, a heredoc delimited by `'EOF-1'`, `bash -c 'sdd new …'`, `env X=1 agentic-capture d.md`, and a quoted mention (`echo "sdd new"`) that is not a call.
3. An unparseable command naming `sdd` owes the reads; one not naming it passes.
4. shell-guard's tests pass unchanged after its walk moves into `internal/shellwalk`.
5. `docs/grounding-gate/architecture.md` names the parser, in the same change.
