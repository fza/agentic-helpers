The embedder input sizing of 20261031-113332-d-tac-l3a changes in two points, so agentic-helpers keeps matching sdd's final sizing rule.

- **No batch split.** A request's reported token count is the sum over its inputs, so it never shows which input was cut, and sizing every input to the measured chunk size already guarantees each fits. The rule splitting a batch whose count suggests a cut input is withdrawn; a batch total is never compared with a per-input limit. Calibration rests on the single-input probes alone.
- **The cap is part of each row's hash.** Every stored vector row (an entry's chunks in agentic-memory, a tool's text in agentic-tools) is keyed by a hash of its content and the chunk size it was cut to. A changed chunk size, from a new calibration, re-derives and re-embeds that store's rows on the next fill; the vector fingerprint stays provider, model, dimensions and template hash. Fill, search and rebuild compute the same hash, so no path ranks a row cut at an old size as current.

Why: a batch split tests a signal the provider never gives, and a row embedded at an old chunk size would otherwise stay under the new calibration with chunks the embedder may have truncated.

Rejected: putting the cap into the vector fingerprint, which would start a fresh vector folder per calibration and drop rows whose text did not change size; keeping the batch split as a heuristic, which would split batches on noise.

Accepted costs: a recalibration that changes the chunk size re-embeds that store once.
