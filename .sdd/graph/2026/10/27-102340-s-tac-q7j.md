shell-guard withholds credential lines from tool output read outside the project, through a new `agentic-shell-guard output` hook on `PostToolUse` for every tool, in agentic-helpers commits e59e0c0, 982aa53, 2db7aaf, e57f63c and 42d0a5b, not yet released, completing 20261027-091326-d-tac-we7.

Each criterion with its test in `internal/shellguard/`:

1. A Read outside the project returns every other line unchanged and each credential line as the marker; inside, whole: TestOutputFromOutsideTheProjectIsWithheldLineByLine, also over linked paths, NotebookRead and Grep.
2. `cat` outside, `cat "$HOME"/...`, `cd ... && cat` and a script are redacted, `cat` and `grep` of a project file are not: the same test and TestOnlyAReaderOfProjectFilesShowsTheProject.
3. Modes, skip names and patterns, and the piece switch: TestTheOptionsDecideWhichOutputIsScanned.
4. A scan that cannot finish withholds every string and keeps the shape: TestAScanThatCannotFinishWithholdsEveryString.
5. Wiring, options and quoted wording: TestShellGuardScansEveryToolsOutput, TestEveryDeclaredOptionIsRead, TestTheReadmeListsEveryOption, TestTheSkillQuotesEveryRefusal.

Deviations, each stricter than the directive: a Bash reader counts as inside only with options from a closed per-reader list, short groups read letter by letter and every file-naming value path-checked; `awk` is not a reader, since its program can read files and run commands; Edit, Write and NotebookEdit outputs are always scanned, since a path judged after a write can be steered by a link swapped in between; the scanner reports the last line a match spans, so a private key is withheld whole. A tool that has run cannot be blocked, so a failure of the hook itself passes the output through and says so.
