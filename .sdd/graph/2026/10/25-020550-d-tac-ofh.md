The grounding gate treats sdd's MCP tools as it treats the `sdd` command run through `Bash`.

**Reads count.** A `PostToolUse` hook on `mcp__sdd__search|mcp__sdd__view|mcp__sdd__show` records into the same per-turn ledger as a Bash read:

- `mcp__sdd__search` with `query` counts as the semantic read, with `terms` as the literal read, both where it carries both.
- `mcp__sdd__view` counts as a listing by its `layout`, under the same rule as `sdd view --layout`: the view of every topic, or with `listing_prefix` set, one topic carrying the prefix.
- A call that came back refused or erroring counts for nothing, as a failed Bash read does.

**A show owes the depth.** The `PreToolUse` gate also matches `mcp__sdd__show` and refuses one whose `down` or `up` falls short of the depth the project owes (`--down 2 --up 1` by default, `show_depth` in `.sdd/grounding.yaml`). An omitted `down` or `up` counts as the MCP server's own default, `down` 1 and `up` 2, so an `mcp__sdd__show` naming no depth is refused at the default `down 2`. The exemptions hold as for `sdd show`: a `prc`-layer rules entry, a seat in `show_depth.exempt_seats`.

**The MCP capture owes the reads.** The `PreToolUse` gate also matches `mcp__sdd__start_procedure` and holds one whose `canonical` is `capture` to the turn's three reads, as it holds `agentic-capture` and a plain `sdd new`. Every other procedure starts freely.

The refusal texts name the MCP form where the refused call was an MCP one, and `agent-grounding` and `README.md` describe both forms in the same change.

Why: an agent grounding through the MCP tools was refused at its next question as if it had read nothing, and an entry written through the MCP capture procedure skipped the reads the gate exists to demand. sdd's MCP server is loaded in this repository by `.mcp.json`, so both happen here.

Rejected: counting MCP reads alone. Fixes the false refusal, but an MCP capture still writes ungrounded. Rejected: leaving the gate Bash-only. Both failures stay.

Accepted costs: the gate depends on sdd's MCP tool names and parameter names (`query`, `terms`, `layout`, `down`, `up`, `canonical`), and a rename in sdd silently stops the counting; a write reached through another procedure (a move dispatching a capture as a sub-procedure) is gated only where it starts `capture` itself through `start_procedure`.

Acceptance:

- A turn whose reads all ran through `mcp__sdd__search` (`query`, then `terms`) and `mcp__sdd__view` passes `AskUserQuestion`; the same turn without the view is refused naming the listing.
- An erroring MCP search counts for nothing.
- `mcp__sdd__show` without `down` is refused at the default depth, with `down 2` passes; an exempt seat passes either way.
- `mcp__sdd__start_procedure` with `canonical: capture` is refused without the reads and passes with them; another canonical passes without.
- Each new guard is broken, its test watched failing, and the file restored byte-identically.
