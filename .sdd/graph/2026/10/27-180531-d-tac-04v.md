Every tool of the plugin's `memory` and `tools` MCP servers answers one JSON object: the object as `structuredContent`, the same object serialized as the result's text block, as MCP 2025-11-25 asks for backwards compatibility, and an `outputSchema` per tool in `tools/list`. This applies to MCP only: the `agentic-memory` and `agentic-tools` commands keep their text output and their `--json` flags unchanged, and hook lines stay text.

- **Reads** with a JSON form answer it: memory's `show`, `search`, `brief`, `who`, `topics`, `view` and `holder` (20261026-214732-d-tac-y5y), tools' `find` and `list` (20261025-185701-d-tac-e9x).
- **Every other tool** answers `message`, its CLI text word for word, plus typed fields for what the call produced: ids, paths, hints such as near topics and similar entries.
- **A refusal** answers with `isError` set and `{"error": "<the refusal text>"}`.
- **The `json` key** stays in the schemas that list it, accepted and without effect, since the servers refuse any key a schema does not list (20261025-034140-d-tac-9os).
- **JSON keys are only ever added**, as for the read shapes.

Why: a script or agent reading a result gets typed fields without asking for them or parsing text, and the spec's `structuredContent` lets a client validate a result against its schema.

Rejected:

- Text by default with JSON on request: every structured reader has to ask, and the writes have no JSON form at all.
- Typed fields only: the hints today's text carries and the wording skills quote would all need redesigning.
- `message` only: writes stay unstructured, so a new entry's id is still parsed out of text.
- sdd's envelope of pre-rendered text inside JSON fields: a wrapper with no structured data in it.

Accepted costs: more tokens per call (keys, escaped newlines); an `outputSchema` per tool kept true to every answer; the skills' MCP examples rewritten; a key with no effect in the schemas that list `json`.

Done when a test checks every tool's answer, success and refusal, against its `outputSchema`, `message` equals the CLI text, a call with `json: true` answers as one without, and `agentic-helpers:agent-memory`, `agentic-helpers:agent-tools` and `docs/memory/*`, `docs/tools/*` show the JSON.
