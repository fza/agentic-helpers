The grounding gate lints a capture body given by `bodyHandle` as it lints one given as `body`: it records each file staged through `mcp__sdd__stage_attachment` by the handle sdd returns, and a capture report naming that handle has the recorded text linted with the project's `draft_lint`. This closes the gap of 20261030-163356-s-tac-mre and extends the MCP capture checks of 20261029-203232-d-tac-def.

**Recording.** A new `PostToolUse` hook on `mcp__sdd__stage_attachment`, in projects whose `.sdd/grounding.yaml` sets `draft_lint`, reads the call's input and sdd's answer and records, per session, the handle with the staged text:
- `content` as given, or the file a `path` names, read as the credential scan already reads it;
- `patches` applied as sdd applies them to the file staged under that `name` (each old text found exactly once, all or nothing), so the record follows the file as sdd edits it in place.
The record sits in the gate's session ledger and goes with it at session end.

**Linting.** On `mcp__sdd__start_procedure` with `canonical: capture` and on each `mcp__sdd__next` of a capture, a report or start params naming `bodyHandle` have the recorded text, after an optional `---` header block as sdd reads it, linted from the repository root as a `body` is. Findings refuse the call and name each one, with the existing refusal wording.

**No record.** A `bodyHandle` the gate holds no text for (staged before the hook ran, or the ledger lost) is refused once, asking to stage the file again or report the body as `body`, as a `bodyPatch` with no recorded body is refused today.

Projects without `draft_lint` keep `bodyHandle` with nothing recorded. The credential scan of staged files stays as it is.

**Rejected.**
- Refusing `bodyHandle` wherever `draft_lint` is set: exact and small, but those projects lose the handle's token saving.
- Accepting the gap: any agent using the handle in a linted project bypasses the project's own rule.
- Reading sdd's own staging folder for the text: its location is sdd's internal layout, which `read_attachment` alone is meant to reach.

**Accepted costs.** A new hook entry in `plugin/hooks/hooks.json` and state in the gate's ledger. The gate repeats sdd's staging rules (patches by name, the optional header block), so a change to them in sdd needs a matching change here. One lint run per report naming a handle.

**Acceptance.**
1. With `draft_lint` set, a body staged with findings and captured by `bodyHandle` is refused naming them; a clean one passes.
2. A staged file edited by `patches` is linted as patched; a patch sdd would refuse leaves the record unchanged.
3. A body staged by `path` is linted from that file's text.
4. An optional `---` header block is not linted as body.
5. A handle with no record is refused asking to stage again or report `body`.
6. Without `draft_lint`, nothing is recorded and captures by handle pass as today.
7. `agentic-helpers:agent-capture`, `agentic-helpers:agent-grounding` and `docs/grounding-gate/*` describe the check and quote the refusal in the same change.
