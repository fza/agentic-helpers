A memory entry can link to a graph entry and to another memory entry. A link is read, never followed for bodies: each search, brief and recall line says what became of the entries it links to and how many entries link to it, and recall names the newer entries that cite a hit.

**What a link points at.** A full graph id, `20261025-162357-d-tac-427`, or a memory id, `m-` plus the 4 to 16 characters an id carries. A short graph id (`d-tac-427`) is never a link: the explicit forms refuse it, the text scan ignores it. Ids are per project; a link never crosses projects.

**How a link is made.**

- **From the text.** Every full id in an entry's title or body that resolves when `new` files it links the entry. An id that resolves to nothing stays plain text, and the reply names it: `not linked (no such entry): m-zzzz99`.
- **With `new --link <id>`**, repeatable, MCP key `link` (an array of ids). An id that resolves to nothing refuses the whole filing, exit 1, `agentic-memory: <id>: no such entry`. It is a usage error, the one case where `new` does not land.
- **With `agentic-memory link <id> <target>`** after filing, MCP tool `link` with keys `id` and `target`. It appends a `link` event (`Entry` the linking entry, `Target` the linked one, `Seat` the caller). A target that resolves to nothing is refused as above. Any seat may link any entry, as with `supersede` and `confirm`; the owner's next brief lists it under changes by other seats: `m-5a1mqz linked to m-x9q2k1 by main`.
- **`agentic-memory unlink <id> <target>`**, MCP tool `unlink` with keys `id` and `target`, appends an `unlink` event dropping a link made by `--link` or `link`. Any seat may unlink; the owner's brief lists it. A link taken from the text holds as long as the body does: `unlink` on it refuses, exit 1, `agentic-memory: <target> is named in <id>'s text; supersede the entry instead`.

A graph id resolves when `.sdd/graph/<yyyy>/<mm>/<dd>-<hhmmss>-<type>-<layer>-<suffix>.md` exists in the checkout; a memory id when the folded log holds the entry.

**What a line says.** Outbound flags join the line's other flags with `; ` and read `→ <target> <state>`. States: `closed by <id>`, `superseded by <id>`, `settled`, `retired`, `gone`. A target that is live, active or open carries no flag. `gone` is a graph target whose file the checkout lacks, such as on another branch. The count of entries linking to this one reads `← <n>`, absent at zero.

    m-x9q2k1 Waiter test flaky on CI  [idea, long, ...]  → 20261025-162357-d-tac-427 closed by 20261026-101500-s-tac-a1b; → m-5a1mqz superseded by m-0c2k9d; ← 2

**`show`** adds a `links:` section listing each outbound target with its state, and a `linked from:` section listing each entry linking in, every line carrying its own `← <n>`.

**Recall and the brief** add under each hit up to two entries that link to it and were filed after it, newest first, title line only: `← <id> <title> [<seat>, <date>]`. An entry already in the same recall set or brief is not repeated. No body, no outbound title, and no heat travels along a link.

**The similar-entry hint** in `new`'s reply names two fixes per similar entry: `replaces it → agentic-memory supersede <old> --by <new>` and `relates → agentic-memory link <new> <old>`.

**Graph status** comes from `sdd export`, run when a read carries graph links, reading `repos[].entries[].{id,status,status_by}` of the local repo. The result is cached in the store's cache as `graph-status.json`, keyed by the newest modification time and the count of `.sdd/graph/**/*.md`; a directory's own time does not move when a nested file changes. Where sdd is not the fork, the export fails, or its shape no longer carries those fields, flags fall back to existence alone and the read prints once `agentic-memory: graph status unavailable (sdd export: <why>)`.

**The fold** of the log keeps each entry's net explicit links: links made by `--link` or `link` and not unlinked fold into one `link` row each, keeping the seat that made it; a link unlinked folds away with its `unlink`.

Why: an agent reading a recalled entry needs to know whether it still holds. The rule that memory points at the graph id holding a decision has nothing checking the id: a lead naming a directive since closed reads as live. A newer entry citing an old one (a fix, a follow-up) is the strongest sign the old one changed, and a bare count would cost a `show` per hit to find out. Titles answer that in a line; bodies and neighbours would spend the context memory exists to save. Links from the text need no flag to remember, the precedent anchors set; `--link` and `link` cover a connection made later or by another seat.

Rejected:

- Graph ids only: a handover chain between notes stays unchecked text.
- Memory ids only: leaves the stale graph pointer unsolved, the strongest case.
- Typed relations (refines, blocks, see-also): a second ref system beside sdd's, drifting from it.
- Links from the text only: no way to connect an entry after filing.
- Accepting a target that does not resolve and flagging it gone: a typo stays flagged forever, another project's id flags on every search.
- Refusing `new` when its text names an unresolved id: an entry quoting another project's id could not be filed as written.
- `link` for the filer only: a receiving seat could not connect a received entry in place.
- `unlink` for text links too: the id would still read in the body as a link. No `unlink`: one bad link would cost a re-filed entry, its age and its heat.
- Backlinks only inside `show`, as `sdd show` keeps them: a backlink would be seen only by opening the entry. `show` with `--up`/`--down` depth: deep chains spend context.
- Recall without inbound titles: a `show` per hit. Outbound titles too: twice the lines, repeating the hit's own body. Heat flowing along links: warms entries nobody read, and a hub pins the brief.
- Parsing graph frontmatter here: re-derives sdd's status rules, which `settled` already escapes. A stable `sdd status` command first: blocks the flag on an sdd release.
- Flag words `link closed: <target>`: longer lines. Bare `closed: <target>` like `gone: <path>`: reads as the entry's own state, and `gone:` would mean a file or an entry.
- Linking similar entries automatically: links nobody chose, noise in backlinks and recall.

Accepted costs:

- Each read carrying graph links may run `sdd export`, about 70 ms on a cache miss, against a shape sdd marks experimental.
- Any seat may change what an entry links to; the owner hears through the brief.
- An example id or a typo that hits a real entry links for good when it sits in the text.
- `new` refuses a filing over an unresolved `--link`.
- Longer lines: up to two recall lines per hit, the `←` count, a flag per non-live target. Arrows are non-ASCII in output skills quote.
- Two event kinds, `link` and `unlink`, the fold must carry.

Acceptance criteria:

1. `new` whose body names `20261025-162357-d-tac-427` and an existing `m-…` id links both; a body naming `d-tac-427` or `m-zzzz99` links neither, and the reply names `m-zzzz99` under `not linked (no such entry):`.
2. `new --link m-zzzz99` exits 1 with `agentic-memory: m-zzzz99: no such entry` and files nothing; `--link d-tac-427` exits 1 likewise; MCP `new` with `link` behaves the same.
3. `link <id> <target>` by a seat other than the owner lands, and the owner's next brief lists `<id> linked to <target> by <seat>`; `unlink` on that link lands and is listed the same way.
4. `unlink` on a link taken from the text exits 1 with `agentic-memory: <target> is named in <id>'s text; supersede the entry instead`.
5. A line linking to a closed graph entry carries `→ <id> closed by <closer>`; to a superseded memory entry `→ <id> superseded by <successor>`; to a live or active target no flag; an entry linked from two others carries `← 2`.
6. `show` lists `links:` and `linked from:`, every `linked from:` line with its own `← <n>`.
7. A recalled entry cited by three newer entries shows the two newest as `← <id> <title> [<seat>, <date>]`; an older citing entry is not shown; one already in the recall set is not repeated.
8. `sdd export` runs once across two reads with the graph unchanged, and again after a graph file changes; with `sdd export` faked failing, the read prints `agentic-memory: graph status unavailable (sdd export: …)` once and flags only `gone`. The subprocess is faked in tests.
9. A merge past the fold horizon keeps a `link` row per net explicit link with its seat, drops a link and its `unlink`, and the folded log answers the same lines as before the merge.
10. `new`'s similar-entry hint names both `supersede <old> --by <new>` and `link <new> <old>`.
11. The MCP `link` and `unlink` tools take exactly `id` and `target`; `new` takes `link`; each refuses other keys.
12. `docs/memory/usage.md`, `docs/memory/architecture.md` and `agentic-helpers:agent-memory` describe links, the flags, `←`, recall's inbound lines, `link`, `unlink`, and the export fallback.
