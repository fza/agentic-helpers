agentic-helpers ships as a Claude Code plugin whose hooks run the Go binaries through a launcher that fetches the release matching the plugin's version. semantic-release cuts each release from the commit messages in a GitHub Actions workflow started by hand.

Plugin:
- `.claude-plugin/marketplace.json` makes the repository a marketplace holding one plugin with source `"."`. `.claude-plugin/plugin.json` names the plugin `agentic-helpers` and carries its `version`.
- `hooks/hooks.json` wires every event and matcher `agentic-install` wires today, each as `"${CLAUDE_PLUGIN_ROOT}/hooks/run" <binary> <mode>`.
- `skills/` keeps its layout; each skill is invoked as `agentic-helpers:<skill>`.
- `bin/agentic-capture` and `bin/agentic-carryforward` are shims that exec the binary the launcher resolves, so Claude Code's Bash tool finds both commands by those exact names and `--help` is answered by the real binary.
- `agentic-install` and `source/hooks/internal/install` are removed. `README.md` tells a machine wired by it to run `agentic-install --remove` before installing the plugin.
- `go install -C source/hooks ./cmd/...` stays the path for development and for scripts running outside Claude Code.

Launcher (`hooks/run`, POSIX sh), in order:
1. `AGENTIC_HELPERS_BIN_DIR` set: exec the binary from that directory, no version check, no download.
2. Read the version from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`. `${CLAUDE_PLUGIN_DATA}/<version>/<binary>` present: exec it.
3. On a SessionStart event only: download `agentic-helpers_<version>_<os>_<arch>.tar.gz` and `checksums.txt` from the GitHub release `v<version>`, check the archive's sha256 against its line in `checksums.txt`, unpack into a temporary sibling directory and rename it to `${CLAUDE_PLUGIN_DATA}/<version>/`, then exec.
4. Otherwise the newest version present under `${CLAUDE_PLUGIN_DATA}`: exec it.
5. No binary at all: the grounding gate exits 2 with a message naming the fix (start a session with network so the release can be fetched); every other hook prints one notice at SessionStart and exits 0.

Release:
- `.github/workflows/test.yml` runs `go vet ./...` and `go test -race ./...` in `source/hooks` on every push and pull request.
- `.github/workflows/release.yml` runs on `workflow_dispatch` only: the same tests, then semantic-release with the workflow's `GITHUB_TOKEN` (`contents: write`).
- `.releaserc.yml` uses the `conventionalcommits` preset. `fix:` cuts a patch, `feat:` a minor, a `!` after the type a major; every other type, `sdd:` included, cuts nothing. `@semantic-release/exec` writes the next version into `.claude-plugin/plugin.json` (prepare) and runs `goreleaser release --clean --release-notes <file>` (publish). `@semantic-release/git` commits `.claude-plugin/plugin.json` alone with the one-line message `chore(release): v<version> [skip ci]`, and the tag lands on that commit.
- `.goreleaser.yaml` builds every binary under `source/hooks/cmd/` for darwin and linux, arm64 and amd64, with `CGO_ENABLED=0`, one archive per platform named as the launcher expects, plus `checksums.txt`, attached to the GitHub release with the generated notes. No Homebrew tap or cask.

Why: the plugin's version and the binaries it runs move together only if the launcher fetches the release named in `plugin.json`, and that file names a release only if the release commits it. A sandboxed session that cannot write under `~/.claude/plugins` still has to run, so a version already present stands in for a missing one. The gate refuses rather than lets work run ungrounded when no binary exists at all, and the other hooks lose nothing a later session cannot recover. The checksum catches a corrupt or truncated download. A manual start keeps a release a deliberate act while the commit types decide its number.

Rejected:
- Hooks calling a bare binary name, or probing PATH, `$(brew --prefix)/bin` and `~/go/bin`. Claude Code's PATH differs by how it was launched, and the binary found need not match the plugin's wiring.
- The launcher fetching the latest release with no version in `plugin.json`. Wiring and binary come from different commits, and every push to `main` becomes a plugin update.
- Checksums committed into the plugin by CI. It needs a build, commit, tag, publish sequence and a larger bot commit, to guard against a tampered release that the same GitHub account would have to publish.
- Every hook skipping silently, or erroring on every event, when no binary exists. Both leave the grounding gate off.
- The launcher building a checkout's sources with `go build` on SessionStart. Every session start pays the compile and needs Go, and a broken build leaves no binary.
- A Homebrew cask. The plugin fetches its own binaries, and a cask adds a second copy on a second update cycle.
- Releasing on every push to `main`, the `angular` preset (it reads a breaking change only from a footer a one-line commit message cannot carry), a changelog file, and a separate tag-triggered release workflow (a tag pushed with `GITHUB_TOKEN` starts no other workflow).

Accepted costs: CI pushes one commit to `main` per release, so local work pulls before pushing; the first SessionStart after an update needs network, and a session without it runs the newest version present; a checksum from the same release does not catch a tampered release; scripts outside Claude Code need Go and a checkout; CI needs Node for semantic-release; a breaking change marked without `!` ships as a minor.

Done when:
- `claude plugin validate .` passes, and a plugin installed from a local-path marketplace runs every hook through `hooks/run`.
- Tests of `hooks/run` against a fake release server and a temporary `CLAUDE_PLUGIN_DATA` cover: the override, a present version, a SessionStart download with a matching checksum, a mismatching checksum refused with nothing unpacked, a non-SessionStart event with the version missing falling back to the newest present, and no binary at all (the gate exiting 2, another hook exiting 0 with one notice).
- The shims run `agentic-capture --help` and `agentic-carryforward` through the launcher.
- A manual run of `release.yml` with a releasable commit commits the bumped `plugin.json` with the one-line message, tags it, and publishes the darwin and linux arm64 and amd64 archives with `checksums.txt` and notes; a run with nothing releasable publishes nothing.
- A push and a pull request run `go vet` and `go test -race` in `source/hooks`.
- `agentic-install` and `internal/install` are gone; `README.md` describes the plugin install, the migration from `agentic-install`, `AGENTIC_HELPERS_BIN_DIR`, and how a release is cut; every skill names its siblings as `agentic-helpers:<skill>`.
