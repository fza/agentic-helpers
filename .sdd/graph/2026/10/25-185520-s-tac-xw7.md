Done for 20261025-180343-d-tac-p9f: commit 35f7177, released as v2.4.0 (release commit 2973181).

- Links: a full graph id or memory id in an entry's title or body links it when it resolves, and stays plain text otherwise; `new --link <id>` (MCP `link`) refuses a filing over a target resolving to nothing; `link <id> <target>` and `unlink <id> <target>` add and drop explicit links, any seat may, and `unlink` of a text link is refused with `<target> is named in <id>'s text; supersede the entry instead`. New log kinds `link` and `unlink`; a merge keeps the net explicit links, and text links go with a dropped body.
- Reads: every line carries `→ <target> closed by|superseded by|settled|retired|gone` for a target no longer live, and `← <n>` for inbound links; `show` lists `links:` and `linked from:`; recall and the brief's working set name up to two newer entries citing a hit (`← <id> <title> [<seat>, <date>]`). Graph states come from `sdd export --dependencies none`, cached in `graph-status.json` keyed on the graph's file count and newest mtime; without an export, flags fall back to whether the entry file exists, warned once. The similar-entry hint offers `supersede <old> --by <new>` and `link <new> <old>`.
- Tests: `links_test.go` (text links, explicit links resolving, any seat linking, line flags, brief and recall citing lines, an older entry linked later not named, graph status cached until the graph changes, the fallback without an export, the similar hint) and `TestAMergeKeepsNetExplicitLinks`. Every guard was broken and caught.
- Docs: `docs/memory/usage.md`, `docs/memory/architecture.md` and `agentic-helpers:agent-memory` in the same commit.
- Binaries before v2.4.0 cannot read `link` and `unlink` events.
