agentic-helpers is not submitted to Anthropic's plugin directory on claude.ai; it stays in its own marketplace, `fza/agentic-helpers`, and reaches users who fall behind through the update notice of 20261030-215026-d-tac-pih.

**Why.** A check against the directory's pre-submission checklist and its Software Directory Policy found two conflicts that no README fixes. Rule 1G says a plugin "must not query or extract data from Claude's memory, chat history, conversation summaries" nor persistently store conversation content, and agentic-memory replays transcript turns after a compaction and at a claim, keeps each session's transcript tail for the next claim, and caches recent prompts with their vectors: its core. And the directory asks for readable source inside the plugin folder, while every piece runs as Go binaries `plugin/hooks/run` downloads from the GitHub release at runtime, held for a reviewer and opaque to the security scan; the plugin being a subfolder of the repository adds a hold on `hooks/run` itself.

**Kept from the check.** Fixes that serve the own marketplace landed anyway: `plugin/README.md` says what the plugin runs, sends, writes and decides, and the manifest description names every piece. The full findings, icon and privacy-policy needs included, are on record should the question return.

**Rejected.**
- Submitting with the cheap fixes and letting review rule: a likely rejection on rule 1G, and a rejected first submission stays on the listing's record.
- Making transcript replay opt-in for a directory build: memory loses its post-compaction replay by default, its core feature.
- A separate slimmer plugin without agentic-memory for the directory: two plugins to keep in step, and directory users get no memory.

**Settled** because nothing follows from it: the own marketplace already serves every user, and the question returns only if the directory's policy or packaging rules change.
