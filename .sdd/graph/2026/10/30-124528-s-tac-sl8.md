A split-layout link now joins a checkout to its graph repository's store silently only where that store already admits the checkout (20261029-150126-d-tac-8af). The rule shipped in agentic-helpers v2.16.0 (commit 76a6290) and holds on the v2.16.1 release binaries, closing the gap that a cloned repository's committed `.sdd/config.yaml` joined another project's store unasked (20261029-131359-s-tac-5pp).

**Live proof** on `agentic-memory` v2.16.1 against a throwaway data home: a graph repository `app-sdd` with its own store, and a code checkout whose `.sdd/config.yaml` holds `project_dir: ../app-sdd`. In the code checkout, `agentic-memory search --term x` exited 1 with the question: `no store is bound to the checkout <code> yet: its .sdd/ names the graph repository <app-sdd>, whose store does not admit it. Ask the user which store it belongs to, then run agentic-memory bind <store> or agentic-memory bind --new from this checkout.`, listing the graph store. No `agentic-store` pointer was written. After `bind <graph store>`, the checkout's pointer named the graph store.

**Suites** cover the rest of the directive's acceptance items, stock sdd's `graph_dir` beside the fork's `project_dir` and the silent join of an admitted checkout: `TestASplitLayoutJoinsTheGraphRepositorysStoreOnceItAdmitsTheCheckout` and `TestASplitLayoutJoinsSilentlyWhereTheGraphStoreAdmitsTheCheckout`. `docs/plugin/architecture.md`, `docs/memory/usage.md` and the `agentic-helpers:agent-memory` skill describe the question.
