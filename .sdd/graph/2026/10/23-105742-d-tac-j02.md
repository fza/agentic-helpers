agentic-helpers releases through Homebrew. semantic-release picks each version from the commit messages and runs GoReleaser, in a GitHub Actions workflow started by hand.

- `.github/workflows/test.yml` runs `go vet ./...` and `go test -race ./...` in `source/hooks` on every push and pull request.
- `.github/workflows/release.yml` runs on `workflow_dispatch` only (`gh workflow run release.yml`). It runs the same tests, then semantic-release. A failing test releases nothing.
- `.releaserc.yml` at the repository root uses the `conventionalcommits` preset with `@semantic-release/commit-analyzer`, `@semantic-release/release-notes-generator` and `@semantic-release/exec`. `fix:` cuts a patch, `feat:` a minor, a `!` after the type a major. Every other type, `sdd:` included, cuts nothing. With nothing releasable since the last tag, the run ends without a release.
- semantic-release pushes the tag `v<major>.<minor>.<patch>`, then its `publishCmd` runs `goreleaser release --clean --release-notes <file>` with the generated notes.
- `.goreleaser.yaml` at the repository root builds every binary under `source/hooks/cmd/` for darwin and linux, arm64 and amd64, with `CGO_ENABLED=0`, packs each platform's binaries with `skills/`, `README.md` and `LICENSE` into one archive, and creates the GitHub release carrying them and the notes.
- GoReleaser writes a cask through `homebrew_casks` to the tap repository `fza/homebrew-tap`, under `Casks/agentic-helpers.rb`, with a repository secret `HOMEBREW_TAP_TOKEN` allowed to write that repository and nothing else. Users install with `brew install fza/tap/agentic-helpers`.
- No `CHANGELOG.md` and no `@semantic-release/git`: the release notes live on the GitHub release alone.
- `go install -C source/hooks ./cmd/...` from a checkout stays a supported install path.

Why: the commit subjects already follow Conventional Commits, so they carry the version bump, and deciding it by hand repeats what they say. A manual start keeps a release a deliberate act while the version stays derived. GoReleaser runs inside semantic-release's job because a tag pushed with the workflow's `GITHUB_TOKEN` starts no other workflow, so a tag-triggered release workflow would never run. The test workflow puts the suite in front of every change and every release.

Rejected:
- Releasing on every push to `main`. Every pushed fix would become a release and a tap update, with no way to hold changes back short of not pushing.
- A tag pushed by hand cutting the release, with the version chosen by hand. It repeats a judgment the commit types already record.
- The `angular` preset, semantic-release's default. It reads a breaking change only from a `BREAKING CHANGE:` footer, and a commit message here is one line, so no major could ever be cut.
- `@semantic-release/git` with a changelog file. It commits back to `main` with a message carrying a body, which a one-line commit message forbids, and the notes already sit on the release.
- A separate tag-triggered release workflow. A tag pushed with `GITHUB_TOKEN` does not start it; a personal token would, at the cost of one more long-lived credential.
- A formula built from source in the tap. Every install needs Go 1.27.
- A HEAD-only formula tracking main. A plain `brew upgrade` skips it, and no release can be pinned as known good.
- GoReleaser's `brews` section. GoReleaser deprecated it for `homebrew_casks`.
- Submitting to homebrew-core. Its notability bar and review cycle do not fit a tool with one maintainer's machines as its users.

Accepted costs: CI needs Node for semantic-release; a breaking change must be marked with `!` in the subject or it ships as a minor; a fix sits unreleased until somebody starts the workflow; the release needs `HOMEBREW_TAP_TOKEN` kept valid; the binaries are unsigned, so the cask strips the quarantine attribute on macOS after install; how `agentic-install` finds the skills and which binary path it wires under Homebrew is decided separately, and until then a Homebrew install wires nothing.

Done when a manual run of `release.yml` with a releasable commit since the last tag runs the tests, pushes the next `v*` tag, publishes a GitHub release with generated notes carrying the darwin and linux arm64 and amd64 archives each holding every binary and `skills/`, and commits `Casks/agentic-helpers.rb` to `fza/homebrew-tap`; a run with nothing releasable publishes nothing; a push and a pull request run `go vet` and `go test -race` in `source/hooks`; `README.md` describes the Homebrew install and how a release is cut.
