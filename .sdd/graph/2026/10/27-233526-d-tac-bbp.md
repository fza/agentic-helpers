An agentic-memory seat follows its session into the new process `claude --resume` or `claude --fork-session --resume` starts: the new process holds its parent session's seat without the agent claiming again, or, where the parent still runs, a seat of its own on the parent's shelf.

Why: a seat is bound to its holder's claude process and start time, and a resumed or forked session runs in a new process, so it starts seatless and the SessionStart notice asking it to claim is easy to skip. A forked session of 97 prompts that shipped two releases filed nothing and left its seat's state slot empty.

This replaces 20261027-222158-d-tac-uwb, which matched a fork by its parent's first message uuid alone: a fork of a session that has compacted never carries that uuid, so the directive missed long sessions, the case it exists for.

How a session finds its parent:

- **Resume** continues the same transcript under the same session id, so a claim whose `session_id` is the new process's session id is its parent's. No two of 7499 transcripts on the machine share a first message uuid, which a resume copying its transcript would produce.
- **Fork** writes a new transcript under its own session id, naming no parent, and copies the parent's records from its latest compaction boundary on with their uuids unchanged, or from the first message where the parent never compacted. A fork of a compacted session observed on the machine starts with its parent's boundary record, at record 4484 of the parent's 10705, and never carries the parent's first message.
- Every claim therefore records `fork_uuid`: the uuid a fork made now would start with. The hook that writes a transcript into a claim sets it to the transcript's first message uuid, and the first hook after a compaction replaces it with the uuid of the transcript's latest `compactMetadata` record.

At SessionStart a process holding no seat looks for a claim or last claim whose `session_id` is its own session id, or whose `fork_uuid` is the uuid of its transcript's first record carrying one.

- **Parent gone** (a resume, or a fork after the parent ended): the session takes the seat over, under the seats lock, as a reservation's takeover does (20261025-223640-d-tac-d2p): its process, start time, session id and transcript replace the old holder's, and the brief and replay come back as on a claim.
- **Parent alive** (a fork while the parent runs): the running holder keeps its seat (20261025-164209-d-tac-qj7). The fork gets a new seat on the parent's shelf, named as `claim --shelf` names one, so it reads and writes the parent's memory and files its state apart.
- **No match**: unchanged, the seatless notice.

A session's own claim keeps working as before; the takeover only acts for a process holding no seat. Takeover and child seat say one line, the hook's existing claim header, and nothing else.

Rejected:

- Recording only the first message uuid (`first_uuid`), since a fork of a compacted session never carries it.
- Searching every seated session's transcript for the fork's first uuid at SessionStart, since it reads several megabytes per seat on every seatless start and slows with the store.
- Claiming a seat for every session at SessionStart, named from branch or directory, since it picks seat names for the owner and multiplies seats.
- Matching a fork by transcript path, which a fork changes.

Accepted costs: one read of the new transcript's head at SessionStart for a seatless process in a project with a store; one full transcript read at the first hook after each compaction; a fork of a running session adds a seat to the shelf.

Acceptance criteria:

1. A resumed session whose parent process is gone holds the parent's seat after SessionStart, with the brief printed, checked by a test.
2. A fork of a running session gets a new seat on the parent's shelf, and the parent keeps its seat, checked by a test.
3. A fork of a compacted session finds its parent through the boundary uuid the claim recorded after the compaction, checked by a test.
4. A session matching no claim gets today's seatless notice.
5. Claims record `fork_uuid`; a claim from an earlier release without it matches only by session id.
6. Each guard is broken once and its test watched failing; `docs/memory/` and agentic-helpers:agent-memory describe the takeover in the same change.
