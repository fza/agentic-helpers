Done for 20261025-183015-d-tac-j5j: commit bb914a0, released as v2.4.0 (release commit 2973181).

- `supersede <id>...`, `confirm <id>...`, `retain <id>... <level>` and `retire <id>...` run through one batch: one load of the log, every id checked (exists, the seat may change it, its state allows it), a repeated id counted once, then one `appendEvents` call. Any failing id refuses the whole call, exit 1, `agentic-memory: nothing <verb>:` and one indented line per failing id. Replies name every id: `superseded m-a, m-b by m-d`, `m-a, m-b retained long`, `retired m-a, m-b`, one `confirmed` line per id.
- `new --absorbs <id>`, repeatable (MCP `absorbs`), appends the `new` event and a `supersede --by` the new entry for each absorbed id in one append; a failing absorbed id refuses the filing as `nothing filed:`. The absorbed ids are checked for state only, since the successor is not in the log yet.
- MCP: `supersede`, `confirm` and `retain` take `ids` and refuse `id`; every schema keeps `additionalProperties: false`.
- Tests: `batch_test.go` (one append per batch with `show` reflecting it, a failing id leaving the log byte-identical with every failing id named, absorbs in one append and refused over a superseded id, the MCP keys, a repeated id changing once). The all-or-nothing check, the owner check, the state check, deduplication, the absorb check and the absorb events were each broken and caught on their assertions; the missing-id check was caught by a nil dereference in the next step rather than by its own assertion.
- Docs: `docs/memory/usage.md`, `docs/memory/architecture.md` and `agentic-helpers:agent-memory` in the same commit.
