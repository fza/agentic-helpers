agentic-memory's shipped-work hold counts a commit any session makes in the checkout, a shelf mate's included: a seat whose state predates HEAD is held once at its next turn end, whoever moved HEAD.

Why: the state slot says where the seat's work stands, and a shelf mate's commit changes what that work stands on. Seats on one shelf share one memory and usually one line of work, so a commit by one leaves every other seat's state describing a tree that no longer exists. Holding for it is the hold doing its job, not a false alarm.

The shipped-work hold (20261027-222420-d-tac-ac7) compares the commit the seat's last state write stamps, or HEAD at its claim, with HEAD at Stop. HEAD belongs to the checkout, not to a session, so the comparison already counts every commit made there.

Rejected: counting only commits the holding session made itself, by recording each session's own commits at its tool calls, since it would let a seat's state go stale exactly when a shelf mate shipped the work that seat depends on, and it adds per-session commit tracking for no gain.

Settled: the code already behaves this way, so nothing follows; the hold fires at most once per quiet period, so the cost is one turn per seat per shipping period, as ac7 already accepted for commits made outside the session.
