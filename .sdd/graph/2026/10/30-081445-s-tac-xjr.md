A process that may write part of the agentic-helpers data home can make the owner's own agentic-helpers processes write files outside the home. The home being bookkeeping rather than a security boundary (20261028-204914-d-tac-6xf) covers what a writer can put into the stores; it does not cover the owner's unsandboxed processes being turned into writers elsewhere. 20261025-185324-s-tac-k4o weighed a sandboxed job writing the stores; this is the same job reaching past them.

fdbox runs autopilot jobs inside a macOS Seatbelt sandbox that may write only its own store's `memory` folder and its own session folder in the home. Seatbelt refuses creating a symlink or hard link there and refuses moving, removing or replacing an existing folder, but it never checks the paths inside a folder being renamed in. A job can therefore build a folder elsewhere holding a symlink, or a hard link to a file it may write, and rename it into `stores/<id>/memory/` or `sessions/<agent>/<session>/` under a name that does not exist yet (`log/` or `seats/` on a store that has none, a new attachment id). When the owner's agentic-helpers process later creates or opens a file below that name, it follows the planted link and writes wherever it points.

The tool library already guards against this: its store reads and writes walk from the store by descriptor, checking each component with lstat and refusing hard-linked files (`internal/tools/safefs.go`, `internal/tools/safewrite.go`), and `internal/slots/slots.go` opens with `O_NOFOLLOW`. Every other writer under the data and cache homes opens by path and follows links at any component. Among them: the memory log's lock and tail append (`internal/memorylog/memorylog.go:232`, `:272`), the seats lock (`internal/seat/seat.go:159`), seat and shelf registries (`internal/seat/`), attachments, caches and bindings (`internal/memory/`), the vector segments (`internal/vectorseg/`), the home's identity and binding files (`internal/home/`), the migration (`internal/migration/`), and `internal/atomicfile`, whose rename lands at a path whose parent may be a planted link.

The cost is a write outside a sandboxed caller's confinement, made with the owner's rights: any file the owner may write can be appended to or replaced through a store's memory folder.
