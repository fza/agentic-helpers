An agentic-memory entry can name tools of the agentic-tools library, and opening such an entry with `show` takes each named tool at once, printing its usage and where its files were copied, so an agent reading a trap or finding gets the tool without a `find` or a separate `take`.

Why: an entry about a problem a library tool solves (a trap about BSD `sed`, a finding about a doc move) today leaves the agent to find the tool again. One `agentic-tools find` answered 5.3 KB, about 1,400 input tokens, measured on this machine, and a `take` is one more call whose output tokens cost roughly five times input. The pointer is what saves tokens; the take on `show` removes the last call. Felix, the project owner, set token savings as the goal; the options weighed carry equal risk, so per d-tac-00q fewest tokens decides.

**Naming a tool.** `new --tool <name>[@<project>]`, repeatable, MCP key `tool` (an array); `agentic-memory link <id> --tool <name>[@<project>]` and `unlink <id> --tool <name>[@<project>]` after filing, MCP `link` and `unlink` taking `tool` in place of `target`. The name resolves as `find` resolves it, own project first, every store in reach; a name resolving to nothing refuses the call, as an unresolved `--link` does under d-tac-p9f. A tool name in an entry's text never links: names are plain words, and a text scan would link every sentence using one. The link names the tool, never a version: age pruning (d-tac-0y1) removes old versions, so the link follows the current one. The flag is `--tool`, not a `tool:` target prefix, because trap triggers already read `--when tool:<name>` as a Claude Code tool.

**What a line says.** Brief, recall, search and trap lines carry `→ tool <name>` for a live tool, about five tokens and no usage text. A tool removed (by the 2 KiB floor's prune of d-tac-fwc, or otherwise) reads `→ tool <name> gone`; a merged one `→ tool <name> merged into <survivor>`, and the link follows the survivor.

**What `show` does.** After the body, a section `tool (registered by other agents):` per named tool: `<name> v<n>  taken: .tmp/tools/<name>/v<n>/` and the tool's usage lines. The banner keeps a tool's text, written by another agent, from reading as the entry's own instruction. The take copies as `agentic-tools take` does, reusing a copy the session already holds, and records the session's holding so `update --from` works; it is not counted among the tool's takers, so a `show` nobody followed up does not lift the tool in `find`. Under the seen set of d-tac-myr, a repeated `show` in one context prints `<name> v<n> (seen)  taken: <path>` without usage.

**Rejected.**
- `show` prints the usage and takes nothing, leaving the take to the agent: one more call, about 100 to 200 tokens with its reply, on every use.
- Usage on every brief, recall and search line: 30 to 80 tokens each time the entry surfaces, used or not, the costliest across sessions.
- Taking on every surfacing (brief, recall, trap): copies on prompts that never use the tool and inflates the take counts `find` ranks by, for no token saved over taking on `show`.
- A version pinned in the link: breaks once age pruning removes the version.
- A `tool:` target prefix on `link`: collides with the trap trigger form `--when tool:<name>`.

**Accepted costs.** A `show` nobody acts on still copies files into `.tmp/tools/`. Every read carrying a tool link resolves it against the stores in reach. `show`'s text and JSON gain a section, a breaking change to its output with skills and docs following in the same change. Confidence is medium: the saving rests on the measured `find` size and an estimated take cost; the tool-creation token probe running beside this decision measures take and find reply sizes too, and a figure that changes the trade calls for a new decision.

**Acceptance.**
1. `new --tool x` files a link to tool `x`; `--tool nosuch` refuses the filing; `link <id> --tool x` and `unlink` land, and the next brief of the entry's filing seat lists them under changes by other seats, as d-tac-p9f lists other link changes.
2. Brief, recall and search lines carry `→ tool x`; with `x` removed, `→ tool x gone`; with `x` merged into `y`, `→ tool x merged into y`, and `show` takes `y`.
3. `show` of an entry naming `x` copies its current version into `.tmp/tools/x/v<n>/`, prints the banner, the path and the usage, and leaves `x`'s takers unchanged; a second `show` in the same context prints the `(seen)` pointer and the path.
4. JSON `show` carries the tool section as `tools: [{name, version, path, usage}]`, `seen: true` replacing `usage` on a repeat.
5. `docs/memory/usage.md`, `docs/memory/architecture.md`, the `agentic-helpers:agent-memory` skill and the `new`, `link`, `unlink` and `show` MCP descriptions describe `--tool`, the flags and the take on `show` in the same change.
