`agentic-memory retire` takes an optional `--because '<why>'`, and the `memory` MCP tool `retire` the key `because`, recording why an entry ended: what finished it ("released as v2.2.0, commit c51ef6a") or why it stopped mattering ("gtimeout installed"). One reason covers every id the call names. It travels in the `retire` event's payload, and:

- a search line and `show` print it after the stamp: `retired 2026-10-25 16:02 CET: released as v2.2.0, commit c51ef6a`;
- `show`'s event history and the brief's list of other seats' changes carry it the same way;
- `--term` matches it beside the title and the body, so `--term 'v2\.2\.0'` finds the entry the release finished.

A retire event without a payload, as every earlier release wrote it, reads as a retire without a reason. `retire` keeps its behaviour otherwise: out of the brief, in search flagged, body dropped after `retired_body_days`, undone by `revive`. `agentic-helpers:agent-memory` tells an agent to give the reason whenever one exists, and calls `retire` the way to record that work is done.

Why: an ended entry that says only `retired` leaves a later reader to guess whether the work finished or was dropped, and with what result; the reason answers both in the line the reader already sees. Finished and dropped share every behaviour, so a reason serves where a second end state would only add a label.

Rejected: a `done` subcommand with a required note beside `retire` (a new verb, MCP tool and event kind whose behaviour equals `retire`'s, plus a rule every agent has to apply at every ending to pick between two names for one thing); renaming `retire` to `done` (changes the wording every hook text and skill quotes and still records no reason); a required reason (a batch retire of stale scratch entries has none worth writing, and a refusal costs a full resend).

Accepted costs: search cannot filter to finished entries alone, beyond a `--term` on the reasons' wording; a reason is written once and never edited, since an entry's events are never rewritten.

Acceptance criteria:

1. `retire --because '<why>'` writes the reason into the `retire` event's payload for every id it names; the MCP tool takes `because` and refuses any other new key, under the exact-keys rule.
2. A search line, `show`, its event history and the brief's other-seat changes print `retired <stamp>: <why>`; a test asserts each, and that a retire without a reason prints `retired <stamp>` as before.
3. A test folds a log holding a payload-less retire event from an earlier release and reads it as retired without a reason.
4. `--term` matches a retire reason; a test finds an entry by a word appearing only in its reason.
5. `revive` after a retire with a reason restores the entry live, and its search line carries no reason.
6. `README.md` and `agentic-helpers:agent-memory` name `--because` on `retire` and state when to give it.
