`agentic-memory who` lists only this checkout's seats by default, folding other projects' behind `--all`, and names for each live holder the Claude Code session name another agent sends a message to. Measured over 36 hours, `who` over MCP averaged 9.5k characters per call, most of it other projects' seats. Agents running `who` to reach another session then looked the session up again by hand, with `ps` calls and guesses at its identifier, because `who` printed a seat, a pid and a session id but not the name `SendMessage` takes.

**Rule.** A live holder's row carries `message: <name>`, read from Claude Code's session record `~/.claude/sessions/<pid>.json` (`name`, for the holder's pid, where `sessionId` matches the claim's session). A record that is missing, unreadable or for another session prints no `message:` part; nothing else in the row depends on it. Without `--all`, other projects' seats fold into `+<n> seats in other projects: agentic-memory who --all  (run before concluding a seat is not held)`, and `--all` rows carry the same `message:` part. The default follows the token-cost criteria 20261029-021515-d-tac-00q: the fold removes what the caller rarely reads, and the added name saves the lookups an agent made instead.

**Rejected.** Pointing agents at Claude Code's `ListAgents` only: it lists sessions by name but not which holds which seat, so the agent still joins the two by hand. Matching by process table (`ps`): costs a spawn and gives no name.

**Accepted costs.** The session record is Claude Code's own file and may change shape; where it does, `who` stops naming holders and says nothing else wrong. An agent looking for another project's seat needs `--all`.

**Acceptance.**
- `who` in a checkout lists its seats with `message: <name>` for each live holder, and folds other projects' seats into a count line.
- `who --all` lists every project's seats with the same part.
- A holder whose session record is missing or names another session prints no `message:` part.
- Tests read session records from a fake home under `t.TempDir()`.
- `docs/memory/usage.md` and the agent-memory skill say how to message a seat's holder.
