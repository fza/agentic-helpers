A seat name may be written in any script, and an agent claims a seat from the user's words in any language by listing the seats first.

**Seat names.** Every seat name agentic-memory reads (`claim`, `release`, `holder`, `--seat`, the MCP keys carrying a seat, and `exempt_seats` in `.sdd/grounding.yaml`) is normalised to Unicode NFC with `golang.org/x/text/unicode/norm`, then lower-cased with `strings.ToLower`, before it is checked or compared. The rule becomes `^\p{L}[\p{L}\p{M}\p{N}-]{0,23}$`, counted in runes: a letter, then up to 23 letters, combining marks, digits or dashes. `haupt`, `главная`, `メイン`, `मुख्य` and `café` are valid names, and `café` typed precomposed or decomposed names one seat with one file, `seats/café.json`. Every ASCII name valid before stays valid and unchanged. `seat.ErrBadName` and the refusal name the new rule.

**Claiming from the user's words.** When the user asks for a seat in any language without its exact name ("Haupt-Session", "sesión principal", "main seat"), the agent runs `agentic-memory sweep` (MCP `sweep`) for the current seats, maps the words onto the seat whose name means the same, and claims it. Where no seat or more than one fits, the agent asks the user which, naming the seats; it never coins a new seat from a translation without asking. `agentic-helpers:agent-memory` states the rule, and its description names "the user asks for a seat, in any language" among its triggers. The SessionStart notice keeps its wording.

Why: a user working in German names the job in German, and a seat called `haupt` is the name that user reads; restricting names to ASCII leaves the job's own word unusable. Two encodings of one letter look identical and, on APFS, open the same file, so without normalisation two sessions could hold what reads as one seat through two claim records. The agent cannot know which seats exist from memory of the SessionStart notice once seats have changed, so it reads them before mapping.

Rejected: names without combining marks on the standard library alone (refuses Devanagari, Thai and Arabic vowel signs, and a decomposed `é` typed on some keyboards); ASCII names with the agent translating (the user's own word for the job cannot be the seat's name); seat aliases (a stored mapping kept up per language by hand, where the agent's reading of a listed name serves); the `UserPromptSubmit` hook claiming on a matching word (a stray word claims a seat nobody asked for); a new read-only `seats` subcommand (`sweep` already lists every seat, and its only change frees holders whose process is gone).

Accepted costs: `golang.org/x/text` becomes the module's second dependency (maintained by the Go team, v0.43.0 released 2026-10-09), and its normalisation tables grow every binary by a few hundred KB; `strings.ToLower` applies Unicode's simple lower-casing, so locale rules such as Turkish dotted `İ` fold the default way; the mapping from words to a seat rests on the agent's reading, bounded by asking when it is unclear.

Acceptance criteria:

1. `go.mod` requires `golang.org/x/text`; `seat.Valid` normalises to NFC and lower-cases before matching `^\p{L}[\p{L}\p{M}\p{N}-]{0,23}$`.
2. A table-driven test accepts `main`, `haupt`, `главная`, `メイン`, `मुख्य`, `café` precomposed and decomposed, and a 24-rune name; it refuses a 25-rune name, a leading digit or dash, a space and a slash.
3. A functional test claims `café` decomposed and finds it held under `café` precomposed, with one file under `seats/`.
4. `exempt_seats: [Café]` exempts a session holding `café`.
5. `agentic-helpers:agent-memory` states the list-map-ask rule with the examples above, and its description names the trigger; `README.md` states the name rule.
