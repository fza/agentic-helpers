`agentic-capture` removes its draft file once a capture succeeds, prints `draft removed: <path>`, and the agent-capture skill tells the agent so; a new plugin option `capture_remove_draft` (boolean, default true) switches it. The owner asked for it in these words: "I want agentic-capture to be able to automatically remove a draft file when the capturing succeeded. and the agent must know that".

- **Option.** `capture_remove_draft` sits beside `capture_enabled` (20261026-000502-d-tac-yrx) in `plugin/.claude-plugin/plugin.json` and resolves through the `config.yaml` layering of 20261028-212647-d-tac-cld as an overridable key: it deletes only the capture's own draft, never data a store shares between agents. Off: the draft stays and no line prints. No per-call flag.
- **Success** means `sdd new` exits 0; it writes and commits in one step, and nothing runs after it. Then the draft is deleted and the reply prints `draft removed: <path>`.
- **Any failure** (lint, pre-flight, `sdd new`, timeout) keeps the draft and prints no line: it is the copy to retry or repair from.
- **Kept with a line instead:** a draft tracked by git, `draft kept: <path> is tracked by git`, since the capture never leaves a git change nobody asked for; a draft outside both the work tree and `/tmp`, `draft kept: <path> is outside the work tree`. A draft inside the work tree or under `/tmp` is removed; those are the places shell-guard lets an agent remove files, and a file elsewhere may belong to something other than the capture.
- **Skill and docs.** `agentic-helpers:agent-capture` rewrites its "## After" section and the line "The draft stays. Delete it once the entry reads right.": success removes the draft with that line; option off, tracked or outside keeps it; summary drift is fixed with `sdd summarize --text`, which never needs the draft. `docs/capture/` usage and architecture change with it.

This extends `agentic-capture` as 20260925-153653-d-tac-piz built it, a draft file turned into one graph entry.

Why an option rather than always on: an owner may want drafts kept machine-wide.

Rejected: a per-call `--remove-draft` flag (the agent must remember it); always on with a `--keep-draft` flag; deleting tracked drafts anyway (an uncommitted deletion another commit can sweep in); `git rm` (touches the index outside the capture's own commit).

Accepted costs: one more plugin option; projects committing their drafts delete them by hand; a removed untracked draft cannot be recovered.

Acceptance (tests, each guard broken once and watched failing): success removes the draft and prints the line; a failure after the write keeps it; a tracked draft is kept with its line; a draft outside the work tree is kept with its line; option off keeps the draft silently.
