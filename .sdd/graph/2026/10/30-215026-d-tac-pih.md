When auto-update is off for the agentic-helpers marketplace and a newer release exists, a seat claim tells the user so, at most once a day per machine, offering two ways forward in prose: update by hand, or turn auto-update on with a settings snippet; an `update_notice` option turns the notice off.

**Why.** Claude Code leaves plugin auto-update off for every third-party marketplace, and `marketplace.json` has no field to change that (code.claude.com/docs/en/plugins/host-marketplace, "Turn on auto-update"). A user who added `fza/agentic-helpers` stays on the release first installed until updating by hand, and nothing tells them a newer one exists. `README.md` mentions the toggle once, inside the update bullet.

**The check.** At most once per 24 hours per machine, during a seat claim, `agentic-memory` asks GitHub for the latest release (`https://api.github.com/repos/fza/agentic-helpers/releases/latest`, 3-second timeout) and caches the answer and the time in the data home. A failed or slow request is silent and waits for the next day. A build that is no release (a `go install` build) is never compared.

**When the notice shows.** On a claim, never on a resume or a claim made for another session; only when `update_notice` is not `false`, the latest release is newer than the running one, the marketplace is not pinned to a ref, and auto-update is off: no `autoUpdate: true` on the `agentic-helpers` entry of `extraKnownMarketplaces` in the managed, user or project settings, nor on its `known_marketplaces.json` entry, the order Claude Code reads them (code.claude.com/docs/en/plugins/loading, "Which marketplaces and plugins auto-update"). It shows once per local day per machine, whatever seat or project claims.

**The notice.** Lines in the claim reply addressed to the agent, which relays them to the user in prose: the newer and the running version; update now with `claude plugin update agentic-helpers@agentic-helpers`, taking effect next session; or turn auto-update on by placing `{"extraKnownMarketplaces": {"agentic-helpers": {"source": {"source": "github", "repo": "fza/agentic-helpers"}, "autoUpdate": true}}}` in `~/.claude/settings.json`; and `update_notice: false` silences it. The `agentic-helpers:agent-memory` skill tells the agent to relay it.

**Alongside.** `README.md`'s install steps gain one turning auto-update on, and this machine's `~/.claude/settings.json` entry gets `"autoUpdate": true`.

**Surfaces.** The option `update_notice` (boolean, `true` unless set, in the plugin's dialog and `config.yaml`); a package `internal/updates` holding the check and the auto-update reading; the cache file `update-check.json` in the data home.

**Rejected.**
- The notice at SessionStart: it fires on a resume too.
- The plugin writing `autoUpdate` into the user's settings itself: a plugin editing user settings unasked, overriding a deliberate pin or opt-out.
- Asking git (`git ls-remote`) for the tags: needs git and is slower than one HTTPS request.
- Checking on every claim: a network call per claim for an answer that changes a few times a week.

**Accepted costs.** One HTTPS request per machine per day; a notice that reads Claude Code's own settings and `known_marketplaces.json`, whose layout Claude Code may change; a user seeing the notice daily until acting or silencing it.

**Acceptance.**
1. A claim with auto-update off, an older running release and a newer latest one shows the notice once per local day; a second claim the same day, a resume and a claim for another session show none.
2. Auto-update on in any of the listed places, a pinned marketplace, `update_notice: false`, a non-release build, an equal or newer running version, or a failed check each show none.
3. The check runs at most once per 24 hours, and no test reaches the network.
4. The notice names both versions, the update command and the snippet, and the skill tells the agent to relay it to the user.
5. `README.md` gains the install step, `docs/plugin/usage.md` lists `update_notice`, and this machine's settings entry carries `"autoUpdate": true`.
