A body captured through sdd's MCP server by `bodyHandle` never passes the project's `draft_lint`. sdd fork release v0.18.0-alpha.2.fza.37, installed on this machine, lets a capture report name `bodyHandle`, a handle from `mcp__sdd__stage_attachment`, instead of carrying `body`, and the grounding gate's body checks on MCP captures (20261029-203232-d-tac-def) read only a report's `body` and `bodyPatch` (`internal/grounding/enginecapture.go`, `engineCall.body`), so a body given by handle is never run through the project's `draft_lint`.

Where it bites: every project whose `.sdd/grounding.yaml` sets `draft_lint` (on this machine sdd-autopilot, sdd-autopilot-python and sddviz) can get an entry its own lint would refuse, through the engine's ordinary capture path.

What still holds:
- The credential scan covers it: the gate scans every `stage_attachment` call's content and the file a `path` names (`internal/grounding/credentials.go`, `staged`), so a staged body holding a credential is refused before it is staged.
- The `listing_prefix` topic rule reads `topics`, which sdd requires on the report beside the handle.

A second effect: after a `bodyHandle` report the gate holds no body for the capture, so a later `bodyPatch` is refused as editing a body the gate has no record of, and the agent has to send the whole body again.

sdd binds a handle to the staged bytes (`sha256` and `bound` in the `stage_attachment` answer) and refuses a confirm over a re-stage that playback did not serve, so the staged file is what gets captured.
