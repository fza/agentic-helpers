agentic-memory presents each entry to a session once per context: after a brief, recall, search, view or show has put an entry's line or body before the agent, a later read of the same entry prints a pointer, `<id> <title> (seen)`, in its place, until a compaction, `/clear` or resume starts the context afresh.

**What counts as presented.** Two levels per entry: its line (brief, per-prompt recall, search, a view's list) and its body (`show`, a view's `as-bodies`). A read asking for a level already presented prints the pointer; a read asking for more than was presented prints in full, so a `show` after a search hit still prints the body, and a second `show` prints the pointer. The pointer keeps the hit's place in rank order, and paging and counts stay as they are. Over MCP and `--json` a seen entry is `{"id", "title", "seen": true}`.

**Escape.** `--again` (MCP `again: true`) on `search`, `view`, `show` and `brief` prints every hit in full and marks it presented. A freshly spawned subagent shares its parent's session id, and the memory tools see no agent identity, so it would receive pointers to entries it never saw; agentic-helpers:agent-memory tells such an agent to pass `again` on its reads. A forked subagent inherits the parent's context and needs no flag.

**Reset.** The seen set is the session's own, kept in the per-session file under the cache where per-prompt recall already records the entries it showed so it never repeats one before a compaction, and is emptied at a compaction, `/clear` and a resumed session's SessionStart, the points where the agent's context no longer holds what it was shown. A CLI call no session owns keeps no seen set and prints everything in full.

**Unchanged.** Heat: a pointer hit warms as a full one does, since heat counts use, not presentation. Filtering, ranking and flags are computed as before; only the printed form changes.

**Why.** Several searches in one task overlap, and each repeated hit re-spends a full line (search prints the full line of 20261026-220057-d-tac-5no, often over 100 tokens) or a whole body on text already in the agent's context.

**Pointer shape.** Id plus title, chosen by least risk first, then fewest tokens (20261029-021515-d-tac-00q): the title lets the agent recognise the entry and judge its relevance without searching back through its context by id, so a relevant repeat is not skipped or confused with another, at about 15 tokens instead of about 5.

**Rejected.** A bare id: cheaper, but the agent must find the earlier output by id to know what the entry is, which risks skipping a relevant hit. Folding seen hits into one footer line: cheapest, but loses rank order and makes a page look emptier than the search was. Dedupe within one command only: leaves the overlap between searches, the case that costs. Keying the seen set per agent: the memory tools receive no agent identity over MCP or the CLI.

**Accepted costs.** About 15 tokens per repeated hit. A fresh subagent that omits `again` gets pointers and calls again. A breaking change to the output of `search`, `view`, `show`, `brief` and recall; the skill and docs follow in the same change. One small write to the seen set per read.

**Acceptance.**
- Two overlapping searches in one session: the second prints a pointer for each hit the first printed, in rank order, with the rest in full.
- A `show` after a search hit prints the body; a second `show` prints the pointer.
- A brief's entries come back as pointers in a later search; recall prints no entry a read already printed.
- `--again` and MCP `again: true` print in full.
- After a compaction, `/clear` or a resume, every read prints in full again.
- JSON carries `{"id", "title", "seen": true}` for a seen entry.
- A pointer hit warms as a full hit did.
- `docs/memory/` and agentic-helpers:agent-memory describe the pointer and `again`, the skill telling fresh subagents to pass it.
