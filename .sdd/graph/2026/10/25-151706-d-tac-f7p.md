An agentic-memory entry is written in the project's language, never in the language the conversation happens to run in. A domain term keeps the spelling the project uses for it and is never translated. The language resolves in order: the graph's `language` in `.sdd/config.yaml`, else the plugin option `memory_language`, else `en`. The brief names it, so every session learns it at claim and after every compaction.

- **Domain term**: a word naming a thing in the project's code, documents or business, such as `Lieferschein` or `Kostenstelle`. An entry in English writes "the Lieferschein export skips cancelled orders", never "the delivery note export". A gloss in the entry's language may follow it in parentheses; the term itself stays.
- **New plugin option `memory_language`**: a locale code as sdd's `language` takes it (`de`, `en`), declared in `plugin/.claude-plugin/plugin.json` `userConfig` and read from `pluginConfigs` in user and managed settings like every other option. Empty or absent means the next source in the order decides.
- **Brief header**: the first line of the brief ends in `, entries in <locale>`, as in `agentic-memory: seat main, 14 live, 6 retired, entries in de`.

Why: Claude Code talking German to its user says how the agent speaks, not what language the project thinks in. A store filled in whatever language each conversation ran in mixes languages, so `--term` misses across them and an entry reads differently from the graph it points at. Translating a domain term breaks it twice: `--term` no longer finds the word the code and the business use, and the entry stops naming what it is about. sdd already authors entries in the graph's configured language whatever the dialogue language, so memory beside a graph follows the same rule.

Rejected: the conversation's language (the mixed store described above); always English (memory beside a German graph would be English while every entry it points at is German); the graph's language alone (a project without a graph that is not English has no way to say so); a per-project settings file for memory (a new file and lookup where `.sdd/config.yaml` already carries the language for every project with a graph).

Accepted costs: `memory_language` applies machine-wide, so it cannot express one graphless project in German beside another in English; nothing checks an entry's language, so the rule holds only as far as the `agentic-helpers:agent-memory` skill is followed; the brief header's wording changes, and the skill quoting it changes with it.

Acceptance criteria:

1. `pluginconfig.Options` carries `MemoryLanguage`, read from the `memory_language` key, empty by default.
2. The entry language resolves to `.sdd/config.yaml` `language` when it is set and not empty, else to `memory_language` when it is not empty, else to `en`; a table-driven unit test covers each step and a graph with an empty `language`.
3. The brief's first line ends in `, entries in <locale>` with the resolved locale, at claim and after a compaction; a test asserts it for a graph-set and an option-set language.
4. `plugin/.claude-plugin/plugin.json` declares `memory_language` in `userConfig`, with a title and description; `claude plugin validate .` passes.
5. `agentic-helpers:agent-memory` states that entries are written in the language the brief names whatever the conversation's language, and that domain terms keep the project's spelling untranslated, with the `Lieferschein` example.
6. `README.md` names `memory_language` and the resolution order.
