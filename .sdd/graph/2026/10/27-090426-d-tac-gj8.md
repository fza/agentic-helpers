shell-guard judges a Bash call whose command name is not fixed text, and that passes at least one argument, under `shell_guard_outside_project`: `ask` by default, `deny` or nothing as that option says, reason `agentic-shell-guard: cannot judge: the command name <word> is not fixed text`. The ask follows the permission mode as every shell-guard ask does (20261026-223555-d-tac-1ny).

Why: shell-guard reads a removal by its command name, and a name the shell builds at run time is one it cannot read: `$'\162m' -rf /` (an octal escape spelling `rm`), `$CMD -rf /`, `"$tool" ...`. Today such a call runs unjudged, so a removal outside the project in that spelling passes every guard of the shell-guard directive (20261025-235046-d-tac-n48), which already sends a removal it cannot place to the same verdict with a `cannot place:` reason.

Rejected alternatives:

- Decoding every `$'...'` escape exactly as bash does: closes the octal spelling only, and `$CMD -rf /` stays unjudged.
- Keeping it as a documented limit, as the grounding gate keeps a glob that cuts a tool's name: shell-guard's one mistake it exists to stop is a removal outside the project, and an ask costs a confirmation, not a lost file.
- A guard of its own with its own option: one more option that sometimes does nothing, when the outside-project verdict already decides what an unplaceable removal gets.

Accepted costs:

- A command an agent runs through a variable or a quoted expansion as its name (`$CMD args`, `"$tool" build`) asks too, each ask costing a confirmation. A name with no arguments runs.
- The reason wording joins the hook's contract, quoted by agentic-helpers:agent-shell-guard.

Acceptance criteria:

1. `$'\162m' -rf /`, `$CMD -rf /` and `"$tool" build` get the `shell_guard_outside_project` verdict with the reason above, for each of `ask`, `deny` and `off`; `$CMD` alone and `rm -rf ./build` keep today's verdicts.
2. The ask follows the permission mode: `dontAsk` denies, `auto` runs the countdown.
3. agentic-helpers:agent-shell-guard and `docs/shell-guard/` name the reason, in the same change.
