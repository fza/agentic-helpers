An agentic-memory entry may declare what ends it, and the tool retires it when that happens. `agentic-memory new --until <condition>` (repeatable; MCP `until`, a list) names the conditions, any one of which ends the entry. Every kind but `rule` may carry them; a rule ends only when someone retires it. It settles what ends a `todo`, which the entry kinds directive (20261026-215042-d-tac-g5a) left to be decided apart.

Why: the agentic-memory directive (20261025-014326-d-tac-mvn) left retiring to the agent, and it depended on the agent remembering to. One heavy seat retired about 60 entries by hand in one pass, most of them done for hours, and an owner decision's `capture-owed` tag outlived its capture by a day. Most of those entries named a handle the tool can watch: a graph entry closing, a file changing, a branch merging.

Conditions:

- `closed:<graph id>`: the graph entry is closed or superseded, read from the cached `sdd export` the link flags of the linked-entries directive (20261025-180343-d-tac-p9f) already use (`links.go:145`). Where the installed sdd lacks `export` (stock releases, 20261026-204842-d-tac-288), statuses are unknown: `--until closed:` is refused at filing with `closed: needs sdd export, which this sdd lacks`, and an entry already carrying one ends by its other conditions only.
- `merged:<branch>`: the branch's tip is an ancestor of the default branch (the target of `refs/remotes/origin/HEAD`, else `main`); `merged:<branch>@<into>` names another target. One `git merge-base --is-ancestor` per such entry per check. A branch that no longer exists ends nothing: the entry goes under `retire?` instead, since a deleted branch was merged or abandoned and the tool cannot tell which.
- `changed:<path>`: the path's content hash differs from its hash at filing.
- `gone:<path>`: the path no longer exists.
- `claim`: the filing seat's next claim by another session.
- `at:<time>`: RFC 3339, or a date meaning its start in local time.
- `captured`: a link from the entry to a graph entry filed after it.

`captured` is for an owner decision waiting for capture, which has no graph id to watch when it is filed. Linking memory to the graph id once the graph holds the decision is already the rule in agentic-helpers:agent-memory; under `captured` that link ends the entry too, so no separate retire is owed. When a tool call adds graph entries while the session's seat holds open `captured` entries, the memory PostToolUse hook names them once: `agentic-memory: graph gained <id>...; open todos waiting for a capture: <id> <title>...; link the one it settles: agentic-memory link <todo> <graph id>`. It finds new graph entries by the graph directory's state through the graph resolver (`internal/graphconfig`), never by parsing a capture's output, so the sdd engine and `agentic-capture` both trigger it. The wording is part of the hook's contract.

When the check runs: whenever a brief is built (claim, compaction, `brief`), and on `link` for `captured`. A reached end appends an ordinary retire under the store lock, recorded with the seat whose brief or call ran the check and the reason `end reached: <condition>`, the retire reason of 20261025-153956-d-tac-zbb. Only entries on that seat's shelf are checked, since another shelf's entry is not this seat's to retire. `revive` undoes it as any retire.

What the brief shows:

- `ended since last brief (revive to undo):` lists each entry the check retired since the seat's previous brief, with its condition. Shown once.
- `retire?` lists live entries, other than rules, whose end the tool infers but nobody declared: every link target closed, superseded, retired or gone; every anchor gone; or a `merged:` branch that no longer exists. Nothing is retired from it; this is the claim-time staleness check.

`show`, `search` and the JSON entry object carry the declared conditions as `until`.

Rejected alternatives:

- Flag every reached end, retire nothing: leaves retiring with the agent, the failure this answers, with a hint added.
- Retire inferred ends too: a trap citing a decision that later closed, or anchored to a file that later went, would retire while it still holds, and traps are the kind that stays useful longest.
- `captured:<term>`, ending when a later graph entry contains a literal term: needs every body on every brief, ends early on a loose term and never on a reworded capture.
- `gone:<draft path>` for owed captures: engine captures need no draft file, so a draft would exist only as a handle, and deleting an abandoned draft would end the entry too.
- Making `--until` required on a todo: a todo nobody can name an end for still decays at the short rate, and forcing a made-up condition is the retention guess again.

Accepted costs:

- A retire no agent asked for. It is listed once and revivable for 14 days.
- One git call per `merged:` entry on every brief.
- One graph directory stat per tool call in a seated session of a graph project.

Acceptance criteria:

1. `new --until` takes each condition form; a malformed one is refused naming the forms; `--until` on a `rule` is refused; MCP the same.
2. A table-driven test of the end check: each condition met and unmet, `merged:` against a fake repository, a missing branch landing under `retire?`.
3. A brief over a met condition retires the entry with `end reached: <condition>`, lists it under `ended since last brief` once, and `revive` restores it.
4. Only entries on the checking seat's shelf are retired.
5. `retire?` lists inferred ends and retires nothing, checked by a test.
6. `link <todo> <graph id>` on a `captured` entry whose target was filed after it retires it.
7. The PostToolUse notice fires once when the graph gains entries and the seat holds open `captured` entries, and stays silent otherwise.
8. Skill and docs name `--until`, every condition, both brief sections and the notice wording, in the same change.
