The grounding gate's credit for the three reads (`--query`, `--term`, the listing) lasts until the graph changes or the session's context is compacted, no longer until the next prompt. A session that read the graph once works across prompts on an unchanged graph without reading it again; a capture by any session, or a compaction of this one, voids the credit.

**What voids credit.**

- **A graph change.** The ledger's evidence carries `graph`, the value of `graphState()` (entry-file count and newest entry name, the state grounded drafts already carry) when the reads were recorded. `record` compares it before crediting a read: a different state clears query, term and listings first, then credits the read under the new state. `gate` treats evidence whose `graph` differs from the current `graphState()` as holding no reads.
- **A compaction.** `agentic-grounding-gate start`, wired on `SessionStart`, reads the payload's `source`; on `compact` it clears this session's query, term and listings and keeps its grounded drafts, whose own graph state already guards them.

**What goes.** The `turn` mode stops clearing the ledger, and its `UserPromptSubmit` wiring (`agentic-grounding-gate turn` in `plugin/hooks/hooks.json`) is removed with the mode. The `<task-notification>` carve-out goes with it, since no prompt clears credit any more.

Grounded drafts, the let-through note for `Write`, `Edit` and `AskUserQuestion`, and every refusal keep their rules; only how long credit lasts changes.

Why: an agent in a long dialogue on one subject re-ran all three reads on every prompt to clear a note or pass a capture, on a graph nothing had touched. Each run prints several thousand tokens of summaries already in context. The graph's own state says when those reads went stale; the turn boundary only approximates it. A compaction drops the read output from context while the ledger would still credit it, so compaction voids credit too.

Rejected:

- Keeping credit per turn: re-reads every prompt on an unchanged graph, now that questions only draw a note.
- Voiding on a graph change only: after a compaction the agent holds credit for reads it no longer has in context.
- Carrying credit across prompts only when the call's text shares a term with a credited read: a fuzzy match an agent can game, and more code than either rule it blends.

Accepted costs:

- Credit is blind to subject: reads about one subject clear a question about another, as a single turn already allowed.
- Every `gate` and `record` call walks `.sdd/graph` for `graphState()`, as a capture's grounded-draft check already does.
- A hand edit of an entry file moves neither count nor newest name, so it voids nothing, the cost grounded drafts already accept.

Acceptance criteria:

1. After the three reads, a second prompt with the graph unchanged lets `AskUserQuestion` through with no note and lets `agentic-capture` through without a grounded draft.
2. A new entry file in `.sdd/graph` between two prompts makes the next `AskUserQuestion` carry the reads-owed note and refuses `agentic-capture` of an ungrounded draft.
3. A read recorded after the graph changed clears the older credit: a `--query` before the change and a `--term` and listing after it leave the query owed.
4. `start` with `source: compact` clears query, term and listings and keeps grounded drafts; with `source: startup`, `resume` or `clear` it changes nothing for the session.
5. `plugin/hooks/hooks.json` no longer runs `agentic-grounding-gate turn`; the binary no longer accepts the `turn` mode; `claude plugin validate .` passes.
6. `docs/grounding-gate/usage.md`, `docs/grounding-gate/architecture.md` and `agentic-helpers:agent-grounding` describe credit lasting until the graph changes or the context compacts, and the package comment in `source/hooks/internal/grounding/grounding.go` lists the modes as they are.
