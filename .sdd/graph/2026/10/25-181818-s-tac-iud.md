Done for 20261025-153034-d-tac-e7l: commit 63ac278, released as v2.3.0 (release commit e355cfc).

- `projectkey.Key` returns `ErrNoRepository` where git names no common directory; memory runs only where `git rev-parse --is-inside-work-tree` says `true`. Outside one every subcommand and MCP tool refuses with `<dir> is not inside a git work tree; memory works only in one`, the MCP server still starts, every hook stays silent, nothing is read or created; `help` and `who` answer anywhere.
- The grounding gate's `exempt_seats` lookup reads `ErrNoRepository` as no seat.
- Tests: `TestOutsideAGitWorkTreeMemoryRefusesAndCreatesNothing` (with another store present, so a collapsed key would show), `TestOutsideGitThereIsNoKey`, `TestOutsideGitNoSeatIsExempt`; every guard was broken and caught.
- Deviation, deliberate: `help` and `who` answer outside a work tree. `help` reads no store and only prints the usage, so refusing it would leave an agent outside git no way to learn the refusal's fix; `who` reads every project's store and none of the caller's, as 20261025-162939-d-tac-8jx decides. Every subcommand touching the caller's store refuses.
- Docs: `docs/memory/usage.md`, "Where it works", and `agentic-helpers:agent-memory` state the limit and the refusal.
