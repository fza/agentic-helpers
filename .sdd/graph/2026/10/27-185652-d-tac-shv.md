agentic-memory's `view` takes four more words from sdd's view layout language (20260717-110000-s-prc-vwg), each keeping sdd's meaning as the memory view directive (20261027-004736-d-tac-abm) requires.

- `topic(L)` at section start is sdd's macro: that topic's entries ranked by heat, later words overriding. Mid-section it stays the filter. Today it filters wherever it stands and lists newest first, breaking the shared-meaning rule.
- `rank(in-degree)`: most-linked entries first, counting the links `← n` counts (superseded entries aside), ties newest first.
- `group(by(kind|seat|shelf|from))` with render `as-grouped`: one block per value, each in the section's rank. `seat` (the filing seat) stands where sdd has `participant`, `from` groups by the source an entry was filed from (`user`, `agent`, `tool`); `layer`, `type` and `participant` are refused naming the accepted fields. `as-grouped` without `group`, or `group` with another render, is refused. `--json` answers `{"groups": {value: {"entries": [...]}}}` in the section.
- `expand(refs)`: under each entry its outgoing links, a memory target as its short line, a graph target as its id and status, as `show` reads them. In JSON, the linked memory entries arrive as `expanded` entry objects.

Why: an agent composing `sdd view` layouts composes memory's with the same words, and these four answer questions memory's view cannot today: one topic's hottest entries, the entries others cite most, who on a shared shelf filed what, and what an entry points at without a `show` per link.

Rejected:

- `expand(links)`: a memory-only spelling of sdd's word.
- A `done` macro: `status(retired):rank(by(date))` says the same.
- `coldness`, `mult`, `add`, `log`: memory heat already reflects use.
- `--all-repos`: ids are per project, and it raises a trust question.
- Graph-only words: `type`, `layer`, `intent`, `indexed`, `untagged`, focus, `stalled`, participants, `readiness`, `wip`.

Accepted costs: existing views opening with `topic(...)` change from newest-first to hottest-first; a new render word and JSON section shape; `expand` grows output.

Done when:

1. Each word parses and acts as stated, table-tested over a fixture store, CLI and MCP alike, with refusals naming token, position and nearest word.
2. `view --explain` spells the `topic(L)` macro out.
3. Grouped JSON fits view's `outputSchema`.
4. `docs/memory/usage.md` and `agentic-helpers:agent-memory` name the words.
