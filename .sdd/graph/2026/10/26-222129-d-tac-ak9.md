Only using an agentic-memory entry warms it. Showing an entry in per-prompt recall no longer adds heat; `link` to an entry and `ack` of a do-now rule (20261026-220743-d-tac-8lf) now do. `agentic-memory who` prints each seat's filed and used counts over 14 days.

Why: recall warmed every entry it showed by 0.25 (`hooks.go:763`), so an entry shown once ranked higher in the brief and in the next recall whether or not the agent ever opened it, and the brief's order fed itself. A seat that files far more than it uses has no way to see it; one heavy seat retired about 60 of 85 entries in one pass, most never read after filing.

Heat per event:

- `confirm` 1.0, `show` 0.5, a top-three `search` hit 0.25, unchanged from the search-warming directive (20261025-021923-d-tac-n7f).
- `link <id> <target>` warms the target by 0.5, a memory entry target only.
- `ack` of a rule warms it by 0.5.
- Recall display, the brief listing an entry, a trap notice and a `do now` line warm nothing.
- `--no-heat` (MCP `no_heat`, 20261025-034001-d-tac-bf0) lifts every warm as before.

Filed and used:

- Each heat record gains the time of its last use, set only by the events above; filing sets no use.
- `who` adds `filed <n> / used <m> (14d)` per seat: entries the seat filed in the last 14 days, and how many of the seat's entries were used in that time. `who --json` (20261026-214732-d-tac-y5y) carries `filed` and `used`.

Rejected alternatives:

- Dropping an entry unopened for N sessions from the brief: a second decay axis beside time, with new per-session state, and a seat claimed rarely would keep entries forever while a busy one lost them in a day.
- Keeping recall warming at a lower amount: any warm on display alone keeps the loop, only slower.
- Leaving heat as is: recall display keeps feeding its own ranking, and nothing tells a seat it files more than it uses.

Accepted costs:

- Heat orders shift for every seat at release, as recall-built heat decays without being renewed.
- An entry the agent reads only in recall, never opening it, cools.

Acceptance criteria:

1. A recall showing an entry leaves `heat.json` unchanged for it, checked by a test.
2. `link` warms a memory target and `ack` warms the rule, by 0.5 each; `--no-heat` lifts both.
3. `who` prints filed and used counts per seat over 14 days, and `who --json` carries them, from a fixture store with known use times.
4. Skill and docs name the heat events and the counts, in the same change.
