The process table is read through the kernel, hook state files are replaced whole, and the agentic-memory store lock waits out an interrupted flock, in agentic-helpers commits a4f11de, e7dd3c6 and 48269d5, not yet released, completing 20261026-223829-d-tac-ah6 and resolving the gaps 20261026-224242-s-tac-gce and 20261026-224411-s-tac-lae.

- **Process table** (a4f11de): `internal/process` reads darwin's table through `unix.SysctlKinfoProc` and Linux's through `process.Procfs` over `/proc`, so no `ps` runs; `seat.Owner` reads each ancestor once; `golang.org/x/sys` is a direct requirement, named in `source/AGENTS.md`. Criteria 2 to 4 hold with tests: the Procfs parser over fixtures including a name with spaces and parentheses, a claim in RFC 3339 and in C-locale `lstart` text read against the real kernel, and `docs/memory/architecture.md`. Criterion 1 holds on darwin, a `ps` that always fails first on PATH; on Linux only `go vet` ran, since no Linux machine was at hand, and the Linux tests run in CI.
- **Whole state files** (e7dd3c6): a new `internal/atomicfile.Write` creates a temporary file unique to each writer beside the target and renames it into place. Every write the gap names goes through it, and so do the seat claim files and `seats.json`, which used the same fixed `.tmp` name. It does not sync: a darwin sync flushes the whole drive inside a hook call, and these files were never synced. A writer killed mid-write leaves a `.*.tmp` file nothing removes. A migration test that blocked a fixed temporary name now blocks one step earlier, so no test reaches the rollback of the log swap and the registry save.
- **Lock retry** (48269d5): a new `internal/filelock.Exclusive` retries a blocking flock on EINTR; the store lock and `memorylog/lock_unix.go` use it. EINTR reaching the lock in production cannot be provoked, since Go installs its handlers with SA_RESTART, so the retry decision is tested directly.

Noticed in the doing: `capture/capture.go` takes the same blocking flock without the retry.

Each new check was disabled in turn and its test watched failing, except where named here: two read-error checks in the Linux parser are masked by the checks before them, and the write and close errors of `atomicfile.Write` cannot be provoked.
