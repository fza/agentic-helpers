Every agentic-helpers option whose value is one of a fixed set is declared in the plugin's `userConfig` as a string with `options`, which Claude Code shows as a picker, and every number with known bounds declares `min` and `max`, so the plugin dialog and `/config` offer only values the option reader (`internal/pluginconfig`, which resolves and validates every option from every layer) accepts.

Why: fixed-choice options were plain text fields whose choices lived only in the description, so a typo reached the option reader and fell back silently, and the bounds it clamps to were invisible in the dialog.

**Pickers.** `embedding_provider` (`openai`, `ollama`); `writing_style` (`terse`, `plain`); `shell_guard_outside_project`, `shell_guard_find_delete` and `shell_guard_secrets` (`ask`, `deny`, `off`); `shell_guard_secret_output` (`all`, `files`, `off`); `scratch_sweep` (`release`, `session`, `idle`, from 20261030-082426-d-tac-h68). An option added later with a fixed set of values is declared the same way.

**Bounds.** `entry_id_length` 6 to 16; `shell_guard_ask_timeout` 0 to 3600; `tools_query_floor` and `tools_duplicate_floor` 0 to 1; `embedding_dimensions` and `brief_note_limit` at least 0; `entry_max_words`, `state_stale_after_writes`, `attachment_max_mb` and `attachments_total_mb` at least 1. Where the option reader clamps differently today (`attachments_total_mb` is raised to `attachment_max_mb`), it keeps doing so; the manifest bound is the static floor.

**Unchanged.** `userConfig` keeps declaring no `default`, as 20261028-212647-d-tac-cld requires so an unanswered option never hides `config.yaml`; every description instead ends with the same phrase, `default <value>`, replacing the mix of `default on`, `empty means ask` and `0 keeps the model's own`. `shell_guard_secret_output_skip` stays a comma-separated string, since a `multiple` option does not appear as a `/config` row. The option reader keeps validating every value, since `config.yaml` and `CLAUDE_PLUGIN_OPTION_<KEY>` bypass the dialog.

**Minimum Claude Code.** `options` needs Claude Code v2.1.271 or later, and an older Claude Code refuses to load a manifest declaring it. This is an exception to 20261027-174929-d-tac-3q0: a plugin manifest cannot probe the installed Claude Code before it loads, so no older-path fallback exists for it. The exception covers manifest keys only; every other use of a newer Claude Code feature keeps the probe and fallback 3q0 requires. README states the minimum version.

**Rejected.** Text fields with a strict check naming a bad value at session start: every Claude Code keeps loading the plugin, but a typo stays possible and is only reported after the fact.

**Accepted costs.** A machine on a Claude Code older than v2.1.271 cannot load agentic-helpers until it updates. Pickers and bounds are a second copy of what the reader validates, kept in step by a test.

**Acceptance.**
- Every option listed above carries its `options` or its `min`/`max`, and `claude plugin validate .` passes.
- A test reads `plugin.json` and checks each picker's values and each bound against what `internal/pluginconfig` accepts.
- No option declares `default`; every description ends `default <value>`.
- With a picker left unanswered, a hook receives no value for it and `config.yaml` decides; checked against a live Claude Code session before release.
- README states that agentic-helpers needs Claude Code v2.1.271 or later.
