Every tool and key description of the `memory` and `tools` MCP servers has a size budget a test enforces, and no description is shortened now. Measured on the installed binaries, the memory server lists 19 tools in 12.6k characters (664 on average, the largest 2.7k) and the tools server 7 tools in 7.2k; Claude Code loads a schema only when an agent asks for it, so a further trim saves little and takes guidance from an agent calling a tool without its skill. Under the token-cost criteria 20261029-021515-d-tac-00q the least risky option is to hold the present size rather than cut, as skills regrew after their own cuts.

**Rule.** A test in `source/hooks` reads both servers' `tools/list` and fails where a tool description or a key description exceeds its budget, recorded beside the test with the reason for each figure. Key descriptions keep naming accepted values and shapes, since values are taken exactly (20261026-222355-d-tac-kbi). Raising a budget is a change of its own.

**Rejected.** Shortening descriptions to what the skill does not say: the figure that motivated it, about 1.5k characters per schema, predates the earlier cut of the memory server's `tools/list` from 52.2k to about 16.5k characters (dropped output schemas, trimmed input schemas, rare commands made CLI-only), and what remains is what a caller without the skill needs to form a valid call. Trimming only the largest descriptions: a small saving for less guidance on the tools carrying the most rules. No test: nothing stops schemas regrowing.

**Accepted cost.** The present descriptions stay at their size; no saving is taken now.

**Acceptance.**
- The description test passes on the tree and fails when a description is padded past its budget.
- `docs/memory/architecture.md` and `docs/tools/architecture.md` name the budgets and where they live.
