**`hooks/run --command` fetches a missing release, and the `memory` MCP server starts through it.** `plugin/.mcp.json` runs `${CLAUDE_PLUGIN_ROOT}/hooks/run --command agentic-memory mcp`. A command whose release is not yet under the data directory downloads it like a SessionStart hook does, waiting on the `.fetch-<version>` lock where a SessionStart hook holds it, and runs the binary; with none fetchable it exits 1 on stderr and prints nothing to stdout. A hook other than SessionStart still never downloads.

Why: Claude Code starts a plugin's MCP servers alongside the SessionStart hooks. On the first session after a plugin update the server launched before the SessionStart fetch had unpacked the new release, found only the previous version, which carries no `agentic-memory`, and exited, so `plugin:agentic-helpers:memory` failed to connect for the session. Stdout belongs to the MCP server's JSON-RPC, so the SessionStart notice can never be printed there.

**The `agentic-helpers:agent-memory` skill names the word limit in text**: `entry_max_words` in the plugin's settings, 500 unless set. Why: Claude Code substitutes `${user_config.KEY}` into skill content only for a value the user saved; an option left at its `userConfig` default reaches the skill as the literal placeholder. `new` still names the count against the limit it reads from the settings.

Rejected: starting the MCP server with `--session-start`, which would print the fetch notice into the JSON-RPC stream; leaving the server to Claude Code's reconnect, which retries a failed plugin server only after a cache window; writing a default `entry_max_words` into the user's settings to force the substitution, which edits a file holding credentials.

Accepted costs: a command run before any session fetched waits on the download, at most the launcher's two bounded curl calls; the skill no longer shows a limit the user changed, only `new`'s reply does.
