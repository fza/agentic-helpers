The JSON answers of agentic-memory and agentic-tools reads leave out every key whose value is empty, and every ranked search hit carries a score like sdd's, on MCP and under `--json` alike; every key holding a value stays.

Why: a memory search over MCP answers the full entry object per hit, empty keys included (`"for":[]`, `"until":[]`, `"when":[]`, `"on":[]`, `"proof":[]`, `"forbids":[]`, `"status_change":null`, `"anchors":[]`, `"links":[]`, `"linked_from":[]`, `"attachments":[]`, `"other_branch":false`). Three hits came to 1674 bytes against 513 for the same hits as text lines, and nothing told the agent how well a hit matched. Under the token-cost criteria of 20261029-021515-d-tac-00q, dropping only empty values is the least risky cut (no value an agent reads is lost), and among such cuts it saves the most.

**Empty means:** an empty list or map, `null`, an empty string, and `false`. Every other value stays, whatever it is, defaults included: `seat`, `shelf`, `from`, `filed` (full RFC 3339), `branch`, `commit`, `retention`, `status`. Nothing the agent could act on leaves the answer. The rule covers the entry object of 20261026-214732-d-tac-y5y wherever it appears (`show`, `search`, `brief`, `view`), the other read shapes (`who`, `topics`, `holder`), and the tool objects of `agentic-tools find` and `list`.

**Score.** Each hit of a ranked `agentic-memory search` (by `--term`, `--query` or both) and `agentic-tools find` carries `score`, an integer percent relative to the best hit of the result, which scores 100, as sdd prints `100%`, `72%`. A listing without a term or query (`search --status ...`) carries none. Text output prints it after the id: `m-wssi 92% macOS has no timeout command  [...]`.

**Contract.** This replaces the "keys are only ever added" rule of 20261026-214732-d-tac-y5y and 20261027-180531-d-tac-04v with: a key appears when it holds a value, a reader treats an absent key as empty, and keys are never renamed. Since a script reading `--json` may expect an empty key to be present, it ships as a breaking change, in a major release.

**Rejected.**
- MCP answering the text lines: smaller still, but the agent loses the typed fields 20261027-180531-d-tac-04v gave it.
- Dropping fields that hold default or redundant values (own seat, `from: agent`, commit, full time): saves more, but loses data an agent may act on; only empty values go.
- Compact JSON on MCP only, `--json` unchanged: two shapes to keep and test for one reader's gain.

**Accepted costs.** A major release for a change scripts may notice. Readers must treat an absent key as empty. The score adds a few bytes per hit.

**Acceptance.**
1. A test decodes every read answer, MCP and `--json`, and finds no key holding an empty value, and every key of a fixture entry with all fields set present.
2. The same fixture round-trips: decoding a compact answer into the full struct yields the full answer's values.
3. Ranked `search` hits and `find` hits carry `score`, the first 100 and none higher, non-increasing down the page; a `--status` listing carries none.
4. Text search lines print the score after the id.
5. A three-hit memory search over MCP answers in fewer bytes than before, measured in the change.
6. `docs/memory/usage.md`, `docs/tools/usage.md`, `agentic-helpers:agent-memory` and `agentic-helpers:agent-tools` state the absent-key rule and the score.
