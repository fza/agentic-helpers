Every output trim of the agentic-helpers trimming directive (20261031-102607-d-tac-lsl) must hold for an agent arriving with an empty context: after a compaction, a `/clear`, a resume or in a new session the agent knows nothing beyond what the output in front of it says. A trim may point at earlier output only inside one context, resetting on compaction, `/clear` and resume as the seen pointer already does; it may never rely on what the agent saw, did or was told before.

Four trims of that directive fail the test and are withdrawn; the rest stand.
- **Claim keeps the last-turns slice when the previous session is the claiming one.** A session that compacted since those turns holds only a summary of them, so skipping the slice drops the very turns the claim exists to bring back.
- **A usage error keeps the whole usage after naming the stray argument.** An agent that mis-called a command with nothing in context needs the usage to call it right on the retry; without it the next call guesses or spends a help call.
- **`agentic-tools list` keeps the `[taken <n>, last <date>]` suffix.** Neither value can be rebuilt by a reader, and an agent choosing between tools of one project may weigh how often and how recently each was taken.
- **A brief's citing line keeps its date and drops only the seat where it is the reader's own.** The seat is printed in the brief's first line; the date is not printed anywhere else.

Why: the surfaces exist so an agent that lost its context can pick the work up; a trim that saves tokens by assuming context breaks the token-cost criteria the directive applies, which rank keeping agents informed above fewest tokens.

Rejected: keeping the claim-slice skip guarded by a check for a compaction since the previous session's turns. A missed compaction signal, `/clear` and resume each need their own detection, and the case it saves is rare.

Accepted costs: about 80 tokens per usage error, a few per tool line and per citing line, and the claim slice in the rare same-session re-claim.

Done when the trimming directive's implementation leaves these four outputs as they are, with a test for each that fails if the trim is applied.
