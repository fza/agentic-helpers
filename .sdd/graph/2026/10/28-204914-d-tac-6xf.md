Every agentic-helpers component keeps its per-project data in one agent-neutral home, grouped into one store per project, so every agent started in the same project shares one memory and one tool library.

**Home.** Data lives under `$XDG_DATA_HOME/agentic-helpers` (default `~/.local/share/agentic-helpers`), regenerable caches under `$XDG_CACHE_HOME/agentic-helpers` (default `~/.cache/agentic-helpers`). `AGENTIC_HELPERS_HOME` overrides the data root. No agentic-* tree remains under `~/.claude` or loose under `~/.cache`. `<data>/format.json` versions the home layout: a release meeting a newer one refuses, as memory refuses a newer store today (`ErrNewerStore`). Each component keeps its own format beside it.

**Layout.** Both roots hold `stores/<id>/<component>/` (`memory`, `tools`, hook state). `<id>` is a UUID v7 plus a suffix fixed at creation: the last path part of the sdd `repo_id` or the origin URL, else a slug of the checkout directory. Sessions live at `<data>/sessions/<agent>/<session>`.

**Mapping.** `stores/<id>/identity.json` is the truth: the store's identifiers and its admitted checkouts, the writers list of d-tac-vq1 folded in. `<data>/index.json` is a cache rebuilt from every `identity.json`. Identifiers, in precedence order: the pointer; volume UUID plus inode of the git common dir; the checkout directory; the split-layout link; the sdd `repo_id`; the origin URL with credentials stripped. Other remotes are only a hint shown in a question. Only strong matches (pointer, inode, path, split link) teach a store new identifiers. One identifier belongs to one store.

**Pointer.** `<git common dir>/agentic-store` holds the store id. It is read first and confirmed against `identity.json`, so worktrees and moved checkouts keep their store.

**Unclaimed stores.** Old data whose checkout cannot be found lives in `<data>/unclaimed/<id>/`, its `identity.json` holding the legacy key (the sdd `repo_id`, or `local/` plus a hash of the git common dir), the checkouts it last knew, and when it became unclaimed. A checkout matching no store is looked up there by the legacy key it would have had: a match is promoted into `stores/` silently, since earlier releases shared data by exactly that key. An unclaimed store nobody promotes is deleted once `orphan_store_grace` has passed since the migration. A store with a living checkout is never deleted, however long unused.

**Binding.** A checkout matching neither a store nor an unclaimed store gets a new store, silently. Questions arise only where two checkouts compete: a second checkout of a known repository, a reused path whose identity contradicts its store, split-layout sides on different stores, a conflict over one identifier. A question is only ever about the checkout the session runs in: the migration asks nothing about any other project, whose open matters wait for a session there. There the hook tells the agent to ask the user; the agent then runs `agentic-memory bind <store>` or `agentic-memory bind --new` from the current checkout. This replaces the `trust` commands, which had to run from a listed checkout that may be gone. A unique weak match (`repo_id` or origin alone) asks once. A reused path whose `repo_id` or origin contradicts the store asks; the same or none binds silently and learns the inode. Binding an identifier another store holds moves it, and the question offers `agentic-memory merge <a> <b>`, joining entries, tools and checkouts with their ids kept.

**Split layout.** A code repository whose graph lives in another repository, named either by `project_dir` in `.sdd/config.yaml` (a key only the sdd fork at github.com/fza/sdd reads) or by a stock sdd `graph_dir` pointing outside the checkout, binds silently to the graph repository's store, with the pointer written into both git common dirs. Different stores on the two sides ask keep or merge. This holds under stock sdd, as d-tac-3q0 requires of every surface.

The memory store of d-tac-mvn and the tools store of d-tac-e9x move under `stores/`; the store key resolution of d-tac-g3w gives way to this mapping. As s-tac-k4o records, any process able to write the home can edit a store, so the pointer and `identity.json` are the hooks' own bookkeeping, not a security boundary.

**Rejected.** `~/.agentic-helpers`: caches would land in backups. `~/Library/Application Support`: a space in every path, and a second layout per platform. One global mapping file: one corrupt file loses every project's mapping, where a per-store `identity.json` keeps each store self-describing and the index rebuildable. `st_dev` as the volume id: it is not stable across mounts. Binding silently on a weak match: two independent clones of one origin would share memory unasked.

Asking before promoting an unclaimed store is rejected: it would cost one question per old project, the daily-use interruption the mapping exists to avoid.

**Accepted costs.** Two roots instead of one. Unclaimed data is gone for good once its grace has passed. A question to the user whenever the mapping is unclear. One file written into `.git`.

**Scope.** The layout now. Adapters for other agents (seat lookup through the owning process, transcript reading, hook and plugin wiring, scratch directory) come later. Migration, configuration and size limits are decisions of their own.

**Acceptance.**
- No agentic-* directory under `~/.claude` or loose under `~/.cache` once a release with this layout runs.
- A user with one checkout per repository never sees a store question, through the migration and after it.
- A migration run asks, if at all, only about the checkout its session runs in.
- A checkout whose legacy key matches an unclaimed store gets that store's data, without a question.
- Two agents in one checkout read one store.
- A worktree and its main checkout resolve to one store through the pointer; a moved checkout keeps its store.
- A fresh clone of a known origin asks once, then resolves silently.
- A split-layout code repository resolves to its graph repository's store, under stock sdd and under the github.com/fza/sdd fork.
- A newer `format.json` is refused.
- A deleted `index.json` is rebuilt with the same mapping.
- No credential from a remote URL lands in `identity.json`.
