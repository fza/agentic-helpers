agentic-memory links reach the graphs of sdd's connected repos. A link may name `<repo_id>:<entry-id>`, the form sdd's own cross-repo references use; a bare graph id resolves in the local graph first, then in the connected repos, and is stored qualified when another repo holds it. Link flags, `closed:` end conditions (20261026-215617-d-tac-45q) and `retire?` read those entries' status as they read local ones.

Why: a seat working across repositories links memory to entries in another project's graph, and today such a link of the linked-entries directive (20261025-180343-d-tac-p9f) is refused as `no such entry` (`resolves`, `links.go:52`), so no `closed by` flag ever arrives and no end condition on it could fire. sdd already declares which graphs a project depends on (`sdd repo add`, `sdd repo list`) and exports them with derived status (`sdd export --dependencies all`); memory reads that list rather than keeping one of its own.

Mechanics:

- Statuses come from `sdd export --dependencies all`, every repo in it, keyed by `<repo_id>:<entry-id>` for non-local repos and by the bare id for the local one (`exportStatuses`, `links.go:177`, today keeps only `local`). The local graph is still found through the graph resolver (20261026-195422-d-tac-g3w).
- The status cache key covers the local graph's entries, as now, and each connected repo's cache state, so a `sdd repo sync` refreshes the flags.
- A full id in an entry's text links in either form, as bare ids do today.
- A bare id the local graph lacks is looked up in the connected repos. Found in exactly one, it is stored qualified; found in several, it is refused naming them, and the filer qualifies it.
- Lines name a foreign target by the last path segment of its `repo_id`: `→ format-d-fdbox:20261024-...-d-tac-k2m closed by ...`. `show` and the JSON forms carry the full qualified id.
- The PostToolUse notice for new graph entries (`captured`) watches the local graph only; a capture in another repository is that repository's.
- A repo not connected through sdd stays unresolvable; the refusal says `not in the local graph or any connected repo (sdd repo list)`.
- Foreign entries resolve only where the installed sdd carries `export`, which agentic-memory probes for (20261026-204842-d-tac-288); stock releases lack it. Without it a qualified id is refused with `resolving another repository's entry needs sdd export, which this sdd lacks`, and local links keep their file-existence fallback.

Rejected alternatives:

- A list of sibling graphs kept by memory: a second declaration beside sdd's connected repos, which drifts from it.
- Qualified ids only: an agent pasting a bare id copied from another graph's search output is refused as today and has to know the `repo_id`.
- Bare ids searched everywhere with no qualified form: a line cannot say which graph a target lives in, and an id two graphs both hold would be ambiguous with no way to say which.

Accepted costs:

- A larger export: whole dependency graphs, not only the local one.
- A connected repo's cache must be synced for its statuses to move; memory runs no sync of its own.

Acceptance criteria:

1. `--link`, `link` and text links accept `<repo_id>:<entry-id>` for a connected repo's entry, and refuse one no connected repo holds.
2. A bare id found in exactly one connected repo is stored qualified; found in several, refused naming them.
3. Link flags, `closed:` conditions and `retire?` read a foreign entry's status, checked against a fake export carrying a non-local repo.
4. The status cache refreshes when a connected repo's cache changes.
5. Skill and docs name the qualified form and the refusal wording, in the same change.
