A seated session's scratch folder is `.tmp/claude/<seat name>/` instead of `.tmp/claude/<session-id>/`, because an agent always knows its seat and rarely its session id: in a checkout using the session-id layout, `.tmp/claude/` filled with loose probes nothing sweeps, beside a single session folder.

**Folder.** A seat claim creates `.tmp/claude/<seat>/` whenever the checkout has a `.tmp/` folder and `scratch_enabled` is not false, with a marker file `.agentic-scratch` naming the seat's id. `agentic-memory claim` and the post-compaction brief print one line, `scratch: .tmp/claude/<seat>/`. A session holding no seat keeps `.tmp/claude/<session-id>/` under the current rules. A folder already at that name without the seat's marker is somebody's keep: it is never marked and never swept, and the claim line ends `(a keep, never swept)`. `agentic-memory rename` and a launcher's seat move carry the folder and its marker to the new name.

**Sweep.** Only a folder whose marker names a seat of this checkout's store is ever removed, so the marker, not the name, is the sweep's safety. A new plugin option `scratch_sweep` chooses when: `release` (default) removes the folder when the seat is released with `agentic-memory release`; `session` removes it when the holding session ends; `idle` never removes it on an event. In every mode, session start reaps a marked folder whose newest file is 7 days old, the backstop for crashed sessions and seats nobody releases. `scratch_sweep` deletes only a seat's own throwaway, so under 20261029-084134-d-tac-b2t it is declared in the plugin's `userConfig` and overridable per agent. Off with `scratch_enabled: false` as today.

**Migration.** The first session start of the release maps each `.tmp/claude/<session-id>/` folder to a seat: first the store's seat files (current and last session id), then the session's Claude Code transcript, whose `agentic-memory: seat <name>` line names the seat. A mapped folder's contents move into that seat's folder, a clashing name going into a `<first 8 characters of the session id>/` subfolder, and the empty session folder goes. A folder no seat claims stays and keeps the 7-day reap of the session-id layout until it ages out. Loose files at the root of `.tmp/claude/` are never touched.

**Rejected.** Sweeping at session end by default: the seat's next session would lose probes a state write points at. Sweeping only when idle: a released seat's throwaway would linger a week. Matching folders by seat name alone: a keep named like a later seat would be removed on release. Leaving old session folders unmigrated: their contents would be lost to the reap while their seat still works on them.

**Accepted costs.** A seat's throwaway outlives its session until release or 7 idle days, so agents still delete their own. A transcript read per unmapped folder during the one-time migration. One more option.

**Acceptance.**
- A claimed seat gets `.tmp/claude/<seat>/` with its marker, and the claim prints its path.
- With `scratch_sweep` unset, `agentic-memory release` removes the folder and session end does not; `session` and `idle` behave as stated.
- A marked folder whose newest file is 7 days old is reaped at session start in every mode.
- A folder without the marker survives release, session end and any age.
- A session holding no seat behaves exactly as today.
- An old session-id folder whose seat a seat file or transcript names lands in that seat's folder, clashes in a subfolder; an unmappable one is reaped on the old rule.
- The agent-scratch skill and `docs/scratch/` describe the seat layout, the option and the migration.
