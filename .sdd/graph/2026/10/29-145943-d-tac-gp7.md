`config.yaml` may only tighten an agentic-helpers guard, never loosen or switch one off, and the embedder's endpoint and API-key variable are read from Claude Code's settings alone, so writing that agent-writable file can no longer lift a guard or send a secret to a host an agent picks.

Why: 20261029-120304-s-tac-wux found that one `agentic-helpers config set` or one write to `~/.config/agentic-helpers/config.yaml` switched shell-guard or the grounding gate off machine-wide, and that `embedding_endpoint` plus `embedding_api_key_env` there could send any named environment variable as a bearer token to any server. Before the layering of 20261028-212647-d-tac-cld those keys lived only in Claude Code's settings, behind its own permission prompts.

**Tighten-only keys.** For each guard key `config.yaml` may set only a value at least as strict as the value the layers below it give (the built-in default):
- booleans that switch a guard on (`shell_guard_enabled`, `grounding_gate_enabled`, `shell_guard_lone_removal`, `shell_guard_expansion`, `shell_guard_nested_code`, `shell_guard_mktemp`, `shell_guard_secret_output`, `shell_guard_alternatives`): only `true`;
- verdict modes (`shell_guard_outside_project`, `shell_guard_find_delete`, `shell_guard_secrets`): `off` < `ask` < `deny`, only stricter;
- `shell_guard_ask_timeout`: only shorter.
- `shell_guard_secret_output_skip`, which can only loosen, is not read from `config.yaml` at all.
A loosening value there is ignored, the next lower layer applies, and `agentic-helpers check` names it at session start: `agentic-helpers: config.yaml may only tighten <key>; <value> ignored`. `agentic-helpers config set` refuses it: `refused: config.yaml may only tighten <key>; loosen it in Claude Code's settings`.

**Embedder keys.** `embedding_endpoint` and `embedding_api_key_env` are not read from `config.yaml`; only the agent's own options (Claude Code `pluginConfigs`) and managed settings set them. `config set` refuses both, and a value in the file is named at session start as ignored.

Loosening a guard or pointing the embedder elsewhere stays possible through Claude Code's settings, which its permission prompts cover, and managed settings still lock any key.

**Rejected.**
- Every guard and embedder key out of `config.yaml`: simplest, but no other agent could set even a stricter guard agent-neutrally.
- Shell-guard asking on `config set` and on Edit or Write to the file: an ask on every change and a new Edit/Write hook, still bypassed by any other writer such as `python` or `cp`.
- Accepting it as documented: one Bash call lifts every guard machine-wide, and the embedder can carry a secret off the machine.

**Accepted costs.** An asymmetric rule per key to document and test. A guard switched off for a machine needs Claude Code's settings rather than the shared file.

**Acceptance.**
1. For every guard key a table-driven test sets a looser and a stricter value in `config.yaml`: the stricter applies, the looser is ignored with the lower layer applying, and the check line names it.
2. `config set` refuses every loosening value and both embedder keys with the lines above, writing nothing.
3. `embedding_endpoint` and `embedding_api_key_env` in `config.yaml` change nothing; set as Claude Code options they apply.
4. Managed settings still win over every layer for every key.
5. `docs/plugin/usage.md`, README `Options` and the skills quoting `config set` state the rule.
