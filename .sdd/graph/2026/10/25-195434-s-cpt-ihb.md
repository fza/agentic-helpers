agentic-helpers is a set of machine-wide Claude Code hooks and the commands `agentic-capture`, `agentic-memory` and `agentic-tools`, each paired with a skill that tells the agent what it is doing (`agentic-helpers:agent-<piece>`). It is built and tested with Claude Code only.

Each piece stays silent until there is something to work on. agentic-memory works once a session claims a seat, keeping entries per project under `~/.claude/agentic-memory/<project>/`, inside git work trees. agentic-tools, the tool library, works once a first `add` creates `~/.claude/agentic-tools/`: each project has its own library there, reads span every project on the machine, and only the checkouts listed in a library's `writers.json` write it. The scratch sweep works where a project carries `.tmp/`; the grounding gate and `agentic-capture` work where it carries `.sdd/`.

The gate and capture exist for sdd, the decision graph under `.sdd/`, with a project's listing prefix, read command and draft lint in `.sdd/grounding.yaml`. sdd is a project's long-term memory, decisions and why, reviewed in the repository; agentic-memory is its short-term memory, where one job's work stands, kept on the machine and fading by retention.

Everything ships as one Claude Code plugin from this repository, which is its own marketplace. `.claude-plugin/marketplace.json` names the plugin in `plugin/`, which holds the manifest, `.mcp.json` with the `memory` and `tools` MCP servers, `hooks/` (`hooks.json`, the launcher `run`, and `register.ts`), `bin/` with the command shims, and `skills/`. The hooks and commands are Go binaries from the module `source/hooks`, one per `cmd/` folder; each release publishes them, and `plugin/hooks/run` runs the release the plugin's version names. `README.md` says what the repository is and how to install it; `docs/` holds one folder per piece with `usage.md` and `architecture.md`.

It supersedes 20261023-122613-s-cpt-2tu, which still named the carry-forward hook and its `.memory/` opt-in, omitted agentic-memory and agentic-tools, placed the hooks and skills at the repository root, and called the README the full description of each piece.
