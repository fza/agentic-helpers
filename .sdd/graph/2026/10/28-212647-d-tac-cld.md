Every agentic-helpers option reads from one agent-neutral file, `$XDG_CONFIG_HOME/agentic-helpers/config.yaml` (default `~/.config/agentic-helpers/config.yaml`), which an agent's own plugin options may override, so every agent on the machine shares one configuration while Claude Code's `/config` keeps working.

**Layers**, lowest first: the built-in default; `config.yaml`; the agent's own options (for Claude Code the `CLAUDE_PLUGIN_OPTION_<KEY>` a hook receives, else `pluginConfigs` in user settings); Claude Code's managed settings, which stay last so a machine lock still wins, as d-tac-yrx and s-tac-xf9 set. Keys in `config.yaml` carry the names `userConfig` declares today. Every call reads `config.yaml` once, one small file; nothing caches it.

**Keys that delete live in `config.yaml` only.** `retired_body_days`, `temporary_seat_lifetime`, `orphan_store_grace` and the overall tools limit decide when stored data goes. Stores are shared by every agent in a project, so two agents with different values would leave the lowest one deciding for both, whichever process ran the cleanup. These keys leave `userConfig`. Keys that only refuse a write (attachment and tool size limits) or shape what an agent writes (`writing_style`, `memory_language`) stay overridable; `memory_language` keeps the resolution of d-tac-f7p, the graph's `language` first.

**No declared defaults.** Claude Code exports an option to hooks whenever `userConfig` declares a default, so a declared default would arrive as an answer and hide `config.yaml`. `userConfig` therefore declares no `default`; each description names the built-in default instead, and README's `Options` section keeps listing every key with its default, as d-tac-yrx requires. An option exported empty counts as unset.

**`agentic-helpers config`**: no argument lists every key with its effective value and the layer it comes from; `config get <key>` prints one; `config set <key> <value>` validates the value as the reader does, writes `config.yaml` through a temporary file renamed into place, keeps the file's other lines and comments, and names any agent option or managed setting that overrides the key. An unknown key is refused, naming the nearest one. An invalid value in `config.yaml` falls back to the next lower layer, and `agentic-helpers check` names it at session start.

**Migration.** The one-off migration of d-tac-di4 copies the user's answers for the keys leaving `userConfig` into `config.yaml`, so nothing set is lost. Answers for keys that stay remain in `settings.json` as the agent's layer: that file also holds credentials, and rewriting it is not this tool's to do.

The file sits beside the data home of d-tac-6xf, under the XDG root meant for configuration, so it lands in backups and dotfile repositories where caches and data do not.

**Rejected.** Options in Claude Code alone: another agent has no way to read or set them. `config.yaml` above the agent's options: a value changed through `/config` would silently do nothing. Each component reading every agent's configuration on every call: one lookup per agent per call, and a format to track per agent. Every key overridable: a deleting key set per agent races as above. Copying every answer into `config.yaml`: the copy would sit under the same answer in `settings.json`, and a later `config set` would appear to do nothing.

**Accepted costs.** An agent's option still shadows `config.yaml` for the overridable keys, so `config set` has to say so. Deleting keys can no longer be set through `/config`. `/config` shows no default for any option.

**Acceptance.**
- A table-driven test over every layer combination resolves each key as above, managed settings last.
- A deleting key set as a Claude Code option has no effect; set in `config.yaml`, it does.
- With no answer given, a hook receives no value for an option, and `config.yaml` decides; checked against a live Claude Code session before release.
- `config set` writes atomically, keeps comments, refuses an unknown key and an invalid value, and names an overriding layer.
- An invalid `config.yaml` value falls back and is named by `agentic-helpers check`.
- The migration writes the user's answers for the keys leaving `userConfig` into `config.yaml`, and touches no settings file.
- `plugin.json` declares no `default`; README `Options` lists every key with its built-in default; `claude plugin validate .` passes.
