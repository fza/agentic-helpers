`agentic-memory bind <store>` and `agentic-memory merge <a> <b>`, run from an agent, reach only the stores the open store question for the calling checkout offers; any other bind or merge needs an interactive terminal, which an agent's tool call never has.

Why: 20261029-131526-s-tac-sv3 found that both commands took any store id from any checkout, so an agent could attach to another project's memory and tools or join two unrelated stores, where the `trust` rule they replaced admitted a checkout only from one already listed.

- **`bind <store>`**: accepted when the open question for the calling checkout names the store; otherwise refused: `agentic-memory: <store> is not offered for this checkout; run the bind in a terminal`.
- **`bind --new`**: always accepted; it creates a store and reaches no data.
- **`merge <a> <b>`**: accepted when one side is the calling checkout's own store and the other is a store its open question offers; otherwise refused the same way.
- **Terminal**: a call whose standard input is a terminal (the user at a shell outside Claude Code) runs any bind or merge, since an agent's Bash tool and MCP calls never have one. `!` commands inside Claude Code count as the agent's.
- The MCP tools follow the same rule as the command line.

**Rejected.** A terminal for every bind to an existing store and every merge: strongest, but every store question the user answers would mean leaving the session to run the command. Keeping the commands as built: an agent reaches any project's data by id.

**Accepted cost.** A bind or merge no question offers needs the user at a real terminal.

**Acceptance.**
1. With a question offering stores A and B, an agent's `bind A` binds and `bind C` is refused with the line above, nothing written.
2. `bind --new` works with or without a question.
3. `merge` with the own store and an offered store joins them; any other pair is refused, nothing written.
4. The same calls with a terminal on standard input (faked behind an interface in tests) succeed.
5. MCP `bind` and `merge` refuse as the command line does.
6. `docs/memory/usage.md` and the `agent-memory` skill quote the refusal.
