agentic-memory takes every argument value exactly as sent. A value wrapped in an extra layer of quotes, such as `from` sent as `"\"user\""`, is refused like any other value outside its set, and the refusal names the accepted ones: `--from takes user, agent or tool, not "\"user\""` (`entries.go:46`).

Why: the MCP schema lists every enum value, so a client can check a value before sending it, and the refusal says what to send instead. Repairing input would give one value two accepted spellings, start a rule no other key follows, and tolerate exactly the malformed input the exact-keys directive (20261025-034140-d-tac-9os) refuses.

Rejected alternatives:

- Stripping one matching pair of quotes from enum values (`from`, `kind`, a `retain` level) before checking: the reasons above.

Accepted costs:

- A quoting slip costs one retried call.

Acceptance criteria:

1. A test sends `from` as `"\"user\""` through MCP and the CLI and checks the refusal names the accepted values.
