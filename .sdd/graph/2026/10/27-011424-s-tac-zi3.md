Agentic-memory entries carry attachments, files taken by path and stored once by content hash in a shared per-machine store, in agentic-helpers commits 2624947 and a2c0b3f, not yet released, completing 20261026-222724-d-tac-15x.

Each criterion with its test in `internal/memory/attachments_test.go`:

1. `new --attach` and `attach` store by path, CLI and MCP, no key taking content: TestAttachStoresAFileByPath.
2. A FIFO, a directory or a missing path is refused, a symlink to a file followed: TestAttachTakesRegularFilesOnly.
3. Both size options refuse with their wording: TestAttachHoldsToItsLimits.
4. One file across two projects is stored once, a duplicate name refused: TestAFileIsStoredOnceAcrossProjects and TestAttachStoresAFileByPath.
5. `read` pages text with the frame and offsets, refuses a binary naming `--to`, and `--to` writes byte-identical content: TestReadPagesATextAttachment.
6. An altered stored file is refused: TestAnAlteredAttachmentIsRefused.
7. No attachment bytes reach the brief, recall or the index: TestNoAttachmentReachesTheBriefRecallOrTheIndex.
8. The fold removes a file once no body names it, `revive` brings it back: TestAnAttachmentEndsWithItsBody.
9. A file stays while any project names it: TestAFileStaysWhileAnyProjectNamesIt, over two stores the test builds rather than fixture files.
10. Docs, the skill and the plugin options name `--attach`, `attach`, `read`, both options and the wording.

Beyond the directive (a2c0b3f), since any job can write the store: a stored file is never read past the size it was attached at, and a compressed one never inflates past it (TestAStoredFileIsNeverReadPastItsSize); `read --to` writes only inside the work tree or `/tmp`, resolved through symlinks, so a stored file is never restored as a missing `~/.ssh/authorized_keys` (TestReadToWritesOnlyInsideTheWorkTreeOrTmp). Attaching still reads from anywhere.
