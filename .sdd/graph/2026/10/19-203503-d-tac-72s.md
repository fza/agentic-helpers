title: Agentic-capture preflight limit
summary: '`agentic-capture` will bound each pre-flight try with a configurable time limit (`--preflight-limit`, default 5m) and retry provider faults — timeouts, rate limits, and 5xx-class errors — twice before giving up, while never retrying draft refusals and distinguishing them via exit code 2. ---

`agentic-capture` bounds each pre-flight try with a time limit and retries a try the model provider failed, so a capture no longer fails on a fault the draft did not cause.

- `--preflight-limit <duration>` cuts off one `sdd new --dry-run` try; `CAPTURE_PREFLIGHT_LIMIT` sets it for a caller, and the flag wins over the variable. Default `5m`: twice sdd's `llm.timeout` default of 2m plus its `llm.extract_timeout` of 1m, so sdd's own limits fire first. The limit is not forwarded to sdd.
- A try counts as a provider fault when it runs past the limit, or when sdd's output carries `no content or tool calls in response`, `RateLimitError` or status 429, `API error: status code` (or `API error [provider <p> status`) with 408, 409 or a 5xx, or `timed out`. A fault retries after 10s, then after 30s, and gives up after the third try with exit 1.
- A refusal of the draft never retries: a `[high]` finding or `validation failed` is checked before any fault pattern, so a finding quoting "timed out" stays a refusal. Statuses 400, 401, 403 and 404 and every other failure end the run at once.
- One stderr line per retry, with no name prefix, matching the tool's other output: `the pre-flight's provider answered nothing; trying again in 10s`, `the pre-flight gave no answer within 5m0s; trying again in 10s`. Giving up prints `... on all 3 tries; the draft did not cause it, so capture it again later`, then the last try's output where it printed any.
- The capture step, `sdd new --preflight-verified`, runs once and never retries. Its one model call is the summary, which sdd lets fail with a warning and runs before the file write and the commit; a failure in that step is a file or git one, after which the entry may be on disk.
- The runner starts every command as the leader of its own process group, and a cut-off kills the group, so a `claude -p` that sdd started dies with it instead of holding the output pipes open. `WaitDelay` (5s) stops reading pipes a child outside the group still holds. `agentic-capture` cancels the run on SIGINT and SIGTERM, since the group no longer receives the terminal's interrupt.
- Exit codes: 0 captured, 2 a high finding held the draft, 1 everything else. sdd exits non-zero on a high finding, so a failed dry-run carrying a `[high]` line is a held draft: exit 2, or a capture under `--force`.

Why: a provider that answers nothing, rate-limits or hangs made the whole capture fail with exit 1, the same as a refused draft, and the caller retried by hand; a hung provider held the capture as long as sdd's own limits allowed, and longer under the claude-cli provider, whose child kept the pipes open after sdd was killed. A refusal judged on the dry-run's exit code alone makes exit 2 and `--force` unreachable, since sdd exits non-zero on every high finding, and then a held draft and a provider that failed every try read the same to a caller.

Rejected:
- Naming the flag `--preflight-timeout`. sdd already has that flag for its own per-call limit, and its error "increase with --preflight-timeout" would point a reader at a setting that does not change sdd's limit. `--try-timeout` reads only once the retry is known; an `AGENTIC_` prefix on the variable breaks the `CARRYFORWARD_PROCESS_NAME` precedent.
- Retrying every 4xx. A bad key, a missing model or a malformed call fails the same way three times and costs 40 seconds of waiting.
- Retrying the capture step after checking whether the entry landed. sdd cannot fail that step on a provider fault, so the check would guard a path nothing reaches and judge sdd's file layout a second time.
- Killing sdd alone, or only bounding the wait on its pipes. Either leaves `claude -p` running, and three tries could hold three model calls at once, making a rate limit worse.
- Testing every case against a fake `sdd` script on PATH. The repository fakes a subprocess behind the `Runner` interface; one real-process test with fixtures under `source/hooks/test/fixtures/process/` covers the runner's group kill and `WaitDelay`.

Accepted costs: a retry layer on top of gollm's own retries of 408, 409, 429 and 5xx within sdd's limit; the runner is Unix-only, as the capture lock already was; the lint command runs in its own process group too.

Done when `go test -race ./...` in `source/hooks` covers each fault pattern retried once and on every try, a cut-off try, each refusal never retried, the limit's sources and their order, a capture step that fails after writing run once, and the runner killing a child and giving up on a stray one; `README.md` and `skills/agent-capture/SKILL.md` describe the limit, the retry rule and the exit codes.
