When the user gives an agent a standing instruction, the agent asks where it goes, every time, with three choices: a memory rule on this seat, `CLAUDE.local.md`, or `CLAUDE.md`. Nothing decided this before: the agent-memory skill filed every user instruction as a `rule`, a project's own instructions could send the same kind of instruction to `CLAUDE.local.md`, and the two drifted, as one checkout's memory rule limiting pushes to owner approval came to contradict its `CLAUDE.local.md` granting them.

**The question.** One question per standing instruction, before anything is written, naming each choice's reach: a memory rule reaches this seat's sessions only, at claim and after compaction, in any agent tool; `CLAUDE.local.md` reaches every Claude Code session in this checkout, subagents and seatless sessions included, and stays out of git; `CLAUDE.md` (or the file it imports, such as `AGENTS.md`) is committed and reaches every developer. The agent marks the choice it recommends. A rule filed for every seat is not offered.

**A file wins.** Where a memory rule contradicts `CLAUDE.local.md` or `CLAUDE.md`, the file holds: the agent supersedes the rule, naming the file, and says so in one line.

**Where it is stated.** The agent-memory skill (`plugin/skills/agent-memory/SKILL.md`) and `docs/memory/usage.md` state the question and the precedence; this repository's `AGENTS.md` memory section points at them instead of placing instructions itself.

**Rejected.** Memory by default with the file only where an instruction must reach seatless sessions: the reach test was hard to apply, as the same instruction fits either place. Filing memory rules for every seat: the same reach as `CLAUDE.local.md` with a second copy to drift. Instructions always in `CLAUDE.local.md`: Claude Code only, this checkout only, and an agent editing a file Claude Code loads at start without asking. Instructions always in memory: subagents and seatless sessions would never see them.

**Accepted costs.** One more question per standing instruction, and nothing written until it is answered. Rules already in memory keep their seat-only reach until the user moves them.

**Acceptance.**
- The agent-memory skill tells an agent to ask the three-way question for every new standing instruction and write nothing before the answer.
- It states that `CLAUDE.local.md` and `CLAUDE.md` win over a contradicting rule, which the agent supersedes.
- `docs/memory/usage.md` describes both; this repository's `AGENTS.md` defers to them.
