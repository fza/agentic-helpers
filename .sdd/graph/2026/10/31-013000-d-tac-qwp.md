agentic-memory's per-prompt recall tells the agent of a failed embedder once per outage, in a line saying recall failed and is retried each prompt: `agentic-memory: prompt recall failed, retried each prompt: <error>`. It replaces `agentic-memory: prompt recall is off this session: <error>`.

**Why.** Recall already runs again on every prompt and comes back by itself once the embedder answers, so the old line claims more than holds. The once-only flag (`Notified` in the shown slot, `source/hooks/internal/memory/hooks.go`) is set on the first failure and never cleared, so every later outage goes unmentioned. Under the hidden-message rule (20261027-222117-d-tac-yjy) an outage is the cause: one message each.

**Mechanism.** The first failed recall since the start, or since the last successful recall, prints the line and sets the flag; a successful recall clears it, writing the slot only when the flag was set.

**Rejected.**
- Rewording alone, still once per Claude Code session: every later outage stays silent.
- Leaving the line: it keeps claiming recall is off until the end.

**Accepted costs.** One more line per further outage; one slot write when recall recovers.

**Acceptance.**
1. A failed recall prints the new line once; further failures print nothing.
2. A successful recall after a failure re-arms it: the next failure prints the line again.
3. A successful recall with the flag clear writes nothing.
4. Tests cover each, and each new guard is broken once to watch its test fail.
