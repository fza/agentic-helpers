The grounding gate's reads-owed refusal and its let-through note name only the reads still missing, each with its exact command and why it is owed, and a let-through note no longer asks for the call again, in agentic-helpers commit 211af20 on main, not yet released, completing 20261029-023134-d-tac-xv3.

Each criterion with its test in `source/hooks/internal/grounding/`:

1. A note with only the listing missing names only the listing, one with all three missing names all three, a credited read is never asked for, and the search hint prints only with a search owed: TestANoteNamesOnlyTheReadsOwed.
2. A let-through note opens `GROUNDING GATE: let through, reads owed before the next question or draft.` and holds no "again": TestAGatedToolIsLetThroughWithANote.
3. A refusal keeps "then run this call again": TestARefusalAsksForTheCallAgain; a project with `gather_command` keeps the one-call line beside one read owed: TestTheGatherCallStaysBesideOneReadOwed.

The `agentic-helpers:agent-grounding` skill and `docs/grounding-gate/` change in the same commit, with the refusal fixtures under `source/hooks/test/fixtures/refusals/`.

One deviation in wording from the directive's example line: the note opens with the fixed line above, then lists each missing read on its own as `No <read> since the graph last changed.` followed by its command, rather than one line joining them after a semicolon. The refusal and the note print the same per-read lines (the `{owed}` slot of `refusals/reads.txt`), so only their opening line differs, and a draft's note adds its grounding sentence after that fixed line.

Live on the installed binary: a draft `Write` drew `GROUNDING GATE: let through, reads owed before the next question or draft. This draft is not grounded: its capture owes the reads.` followed by only the two missing reads (`--query` and the listing) with their commands, the credited `--term` read not listed, and no "ask again".
