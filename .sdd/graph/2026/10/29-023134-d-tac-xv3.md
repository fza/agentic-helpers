The grounding gate's reads-owed refusal and its let-through note name only the reads still missing, each with its exact command, and a let-through note no longer says "ask again" for a call that already went through. Today the text in `source/hooks/internal/grounding/refusals/reads.txt` prints all three read commands under "Run both + the listing, then ask again:" plus "Standing reads: <have>", even when one read is missing, and the let-through note of 20261025-161257-d-tac-ega (`letThrough` in `grounding.go`) carries the same "then ask again".

- **Only what is missing.** Refusal and note list each missing read with its exact command; reads already credited are neither listed nor requested again. Projects with `gather_command` keep the one-call line.
- **Let-through wording.** The reads are owed before the next question or draft, never "ask again". A refusal keeps the sense of "then run it again".
- **The search hint** "Empty search ≠ absence; a listing settles membership." prints only when a search is missing.
- **Firing.** The note fires on every gated call while reads are owed; no once-only suppression.
- **Contract.** The wording is part of the hook's contract: `agentic-helpers:agent-grounding` and `docs/grounding-gate/` change in the same commit.

Example let-through: `GROUNDING GATE: let through; owed before the next question or draft: sdd view --layout "active:as-counts" (no listing of every topic since the graph last changed)`. The reason in parentheses follows the credit rule of 20261025-182429-d-tac-fhx, where credit lasts until the graph changes.

The choice follows the token-cost criteria of 20261029-021515-d-tac-00q and the hidden-message rule of 20261027-222117-d-tac-yjy, which asks for one line naming the cause and the command that answers it.

Why: correct instructions (no re-running credited reads, no "ask again" for a call already made) avoid wasted reads and teach agents to trust the note. Over three days 204 notes came to 108k characters, about 530 each; a note naming one missing read is about 130.

Rejected: suppressing the note once per graph change (an agent can lose the owed read between questions); exempting questions unrelated to the graph (not reliably detectable); keeping the text as is (wrong instructions train agents to ignore the gate).

Accepted cost: the wording change needs skill, docs and tests updated together.

Acceptance (tests, each guard broken once and watched failing):
- A note with only the listing missing names only the listing.
- A let-through note holds no "ask again".
- A note with all three missing names all three.
