The update notice shipped in commit c0399cf on `main`: a seat claim tells the user once per local day that a newer agentic-helpers release is out while auto-update is off, with the update command, the auto-update snippet and the `update_notice` option that silences it.

**What landed.** Package `internal/updates` holds the check (`https://api.github.com/repos/fza/agentic-helpers/releases/latest`, 3-second timeout, User-Agent naming agentic-helpers) and the auto-update reading (managed, user, project and project-local settings, then `known_marketplaces.json`, ref and sha pins). The cache `update-check.json` lives in the data home; a lock `.update-check.lock` beside it, taken without waiting, keeps two simultaneous claims from both asking GitHub and both showing the notice. Only a direct claim adds the notice: the hook's claim for a resumed or forked session carries an unexported flag no CLI or MCP argument can set, and a claim for another session returns before the notice is reached. The option `update_notice` sits in `plugin.json`; the `agent-memory` skill tells the agent to relay the lines in prose. `README.md` gained the install step turning auto-update on; `docs/plugin/usage.md`, `docs/memory/usage.md` and `docs/memory/architecture.md` describe the option, the notice and the check; `plugin/README.md` lists the daily request under what the plugin sends. This machine's `~/.claude/settings.json` entry carries `"autoUpdate": true`.

**Proof.** `go vet ./...`, `go test -race ./...` and `claude plugin validate .` pass. Every guard was broken and its own test went red, the file restored byte-identically. End to end, `agentic-memory` built from `main` with its version stamped 2.17.0 claimed a seat in an isolated home and checkout: the first claim asked GitHub and printed the notice naming 2.18.0 and 2.17.0, the second claim the same day printed none. The `go install` build this checkout's sessions run is a dev build, which the check never compares, so no session here shows it until a release carries it.

**Deviations.** Project settings are read from the current checkout's top level, not the main checkout's, since Claude Code reads them there in a worktree. The `Accept` header on the request and the release client line in `cmd/agentic-memory/main.go` have no test; cmd packages carry none.
