Every message an agentic-helpers hook injects for the agent alone, never shown to the user as such (memory nudges, Stop holds, arrival and trap notices, do-now lists, gate refusals' hints), fires only when it changes what the agent does next, and at most once per cause. The owner set it as a standing rule: those hidden messages must be as scarce as possible, all of them.

What it binds:

- **One cause, one message.** A message fires for a cause it names and stays silent until that cause changes, as the replay nudge (20261025-192326-d-tac-303) fires once per newest entry and a trap notice (20261026-220335-d-tac-nu3) once per session. A message that would repeat on the next prompt, tool call or Stop without anything new is a defect.
- **No message where acting is free.** A hook that can do the work itself without a judgment call does it and says nothing, rather than asking the agent to.
- **Thresholds the owner can raise.** A message that fires on a count (writes, prompts, turns) reads its threshold from a plugin option, so the owner can make it rarer without a release.
- **Short.** One line naming the cause and the one command that answers it, never a recap.

Why: a hidden message costs context on every turn it fires, and an agent that sees one often learns to skip it, so a frequent message weakens every message beside it. Messages that fire rarely, and only when something is owed, are the ones agents act on.

Rejected: a per-session cap on hidden messages, since a cap silences the one message that matters once the budget is spent; leaving frequency to each hook's own judgment, which is how messages that repeat without a new cause come to exist.

Accepted cost: some upkeep an agent would have done after a reminder now waits for its cause to recur, or for the hook to do it itself.
