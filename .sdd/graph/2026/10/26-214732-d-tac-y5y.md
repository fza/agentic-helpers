Every agentic-memory read command takes `--json` and answers with one JSON object on stdout in place of its text: `show`, `search`, `brief`, `who` and `topics`. Each memory MCP tool of the same name takes the key `json` (boolean) for the same answer. `holder --json` keeps the shape it has.

Why: tools built on memory read its text today, and the text changes whenever a feature adds a line. fdbox's seat gate parses `show` and broke when the linked-entries work (20261025-180343-d-tac-p9f) added the `linked from:` block. A shape meant for programs ends that class of break for every consumer, and every read command of the agentic-memory directive (20261025-014326-d-tac-mvn) gets one so the next consumer does not parse text again.

Shapes:

- `show --json` → `{"entries": [entry...]}`, each entry carrying `body`.
- `search --json` → `{"entries": [entry...], "more": {"skip": n}}`, entries without `body`, `more` absent on the last page.
- `brief --json` → `{"seat", "shelf", "language", "live", "retired", "state": {"body", "at", "branch", "commit"}, "changed": [{"id", "change", "seat", "at"}], "rules": [entry...], "traps": [entry...], "todos": [entry...], "notes": [entry...], "news": [entry...], "topics": {name: count}}`, the sections following the entry kinds and the per-seat state slot.
- `who --json` → `{"seats": [{"name", "shelf", "state", "holder", "filed", "used"}]}`, `filed` and `used` counting the last 14 days, with `who --all --json` adding `project` per seat.
- `topics --json` → `{"topics": {name: {seat: count}}}`.
- The entry object, shared by all of them: `id`, `title`, `seat`, `shelf`, `for` (list), `topics`, `kind`, `until` (list of declared end conditions), `retention` (the decay level in force, the kind's or a `retain` override), `from`, `filed`, `branch`, `other_branch` (boolean: filed on a branch other than the checkout's), `commit`, `status`, `status_change` (`at`, `by`, `because`), `anchors` (`path`, `state`: `ok`, `drifted`, `gone`), `links` (`target`, `state`, `by`), `linked_from` (ids), `attachments` (`name`, `sha256`, `size`, `stored`).

Rules:

- Times are RFC 3339 UTC, as the store keeps them (20261025-152555-d-tac-86k).
- Keys are only ever added. Renaming or removing one is a breaking change and ships as one. No version field: agentic-tools `find --json` and `list --json` carry none and grow the same way.
- `brief --json` has no character budget and lists every live entry: the 9000-character budget exists because Claude Code swaps a longer hook output for a file path, and a program reading the command has no such limit.
- `brief --json` leaves the brief mark untouched, so a program reading it does not move the point the seat's next brief counts "changed by other seats" and "new from other seats" from.
- `--json` changes no heat rule: `search` and `show` warm as before, and `--no-heat` still lifts it.
- Text output is unchanged by this. A hook's output wording is part of its contract, since skills and agents quote it (`AGENTS.md`, Working agreements), and agentic-helpers:agent-memory quotes the text forms.
- A refusal stays text on stderr with the same exit code, so a consumer checks the exit status before decoding.

Rejected alternatives:

- `show` and `search` only: covers the break that happened, but the next tool needing the brief or the seat list parses text again, and the question returns.
- `show` only: the smallest fix, and search hits stay text for every lookup tool.
- A version field in every answer: no sibling command carries one, and an additive-only contract leaves nothing for it to signal.
- A Go package for consumers to import: the code lives under `internal/`, which another module cannot import, and fdbox is not written against this module.

Accepted costs:

- Five shapes to keep stable alongside the text.
- `brief`'s sections will gain keys as a working-set cap and claim-time checks land; each lands as added keys, never as a renamed section.

Acceptance criteria:

1. `show`, `search`, `brief`, `who` and `topics` accept `--json`, and their MCP tools accept `json`, each answering one JSON object with the keys named above.
2. A test decodes each answer and checks the keys, for the CLI and the MCP tool both.
3. Text output of every read command is unchanged by this change, checked by the existing text tests passing unchanged.
4. `brief --json` leaves the brief mark file unchanged, checked by a test.
5. A refused read under `--json` exits non-zero with its text refusal on stderr and nothing on stdout.
6. `docs/memory/usage.md` and agentic-helpers:agent-memory name the flag and the shapes.
