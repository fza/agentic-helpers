A headless `claude -p` run whose session holds an agentic-memory seat does not exit after its answer: the `Stop` hook `agentic-memory wait` (`asyncRewake`, timeout 1860 seconds in `plugin/hooks/hooks.json`) keeps waiting for an arrival to wake the session, and the run stays open up to 31 minutes. Observed on the installed build in a scratch project: a `claude -p 'Haupt-Session'` run claimed seat `main`, printed its answer, and kept running with `agentic-memory wait` as its child for over 10 minutes, until that process was killed, after which it exited at once and wrote its JSON result. A run that released its seat before ending exited normally.

Where it bites: any script, launcher or CI job driving `claude -p` in a project with memory, once the run claims a seat or inherits one; the caller waits up to half an hour per run or must kill it, and an outer bound cuts it off before the result is written.

The waiter of 20261025-163029-d-tac-32l exits once the seat is released, seized or its session ends, but a one-turn headless run neither releases nor ends while the waiter holds it, so nothing frees it. Likely, not yet checked: a headless run cannot be woken for a further turn at all, which would leave the waiter no receiver there.
