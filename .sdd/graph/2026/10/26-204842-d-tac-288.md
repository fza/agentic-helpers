agentic-helpers works with stock sdd (github.com/networkteam/sdd) and uses the fza fork's features wherever the installed `sdd` carries them, detected by what the binary offers, never by its version string. It replaces 20261023-150359-d-tac-s8g, which made the fork a hard requirement: `agentic-capture` exited 1 and the grounding gate switched itself off unless `sdd --version` carried `fza`.

**What changed.** Stock sdd now carries nearly every surface the tools use: `sdd new --dry-run` with the pre-flight's `[high]`/`[medium]` lines, `--skip-preflight`, `--index`, `--refs` as JSON, `--model`, `summarize --text`, `search --query/--term/--limit/--max-citations`, `view --layout`, `show --down/--up`, `sdd serve` with every MCP tool and parameter, `produced.entryId`, the `<id>.md` line `sdd new` prints. What only the fork carries: `sdd new --preflight-verified`, `--title`, `--actor-kind`; the root flag `--local-config`; the `sdd migrate` command; `init --project-dir` and the `project_dir` key; graph schema 2. `sdd export` is on stock's main branch but in no stock release.

**Detection.** A probe package replaces the fork check: it reads `sdd --help`, `sdd new --help` and `sdd init --help` (5 s each) and reports each surface by its flag or command name, urfave/cli listing every flag and command. The result is cached in the plugin's cache directory, keyed by the resolved `sdd` path, its modification time and size, so a new binary is probed again. Neither sdd has a capability command.

**agentic-capture**, per surface, never silently:

- Without `--preflight-verified`, the separate dry run is skipped and one plain `sdd new` runs: stock sdd checks and writes in one model call and writes nothing on a `[high]` finding. Its findings are read as a dry run's are (`[high]` exits 2, `[medium]` is shown), and a provider fault is retried as today, since a failed check wrote nothing. With the flag, the fork path runs as before.
- A draft header carrying `title` or `actor_kind` where `sdd new` lacks the flag is refused before anything runs, naming the fork as what carries it: an entry written without a field never gains it.
- `--preflight-route` without `--local-config`, and `--preflight-done` without `--preflight-verified`, are usage errors naming the fork.
- A graph whose `.sdd/meta.json` holds `graph_schema_version: 2` where sdd has no `migrate` command is refused saying the fork migrated the graph and only the fork writes it; with `migrate`, the refusal names `sdd migrate` as today.

**The grounding gate** never steps aside for stock sdd: its SessionStart version check, the session marker and the notice go. It only reads commands, and every command and MCP tool it matches exists in stock. The engine refusal of 20261026-200321-d-tac-bo5 gains one condition: where the governing `.sdd/` sets `project_dir` and sdd lacks `--project-dir`, it does not refuse, since such an sdd ignores the key and `sdd serve` would serve the code repository's own `.sdd/`. The resolver of 20261026-195422-d-tac-g3w keeps following `project_dir` as written.

**agentic-memory** runs `sdd export` only where the probe finds the command; elsewhere the existing fallback applies, a link flagged by whether its entry file exists.

**Install.** `README.md` leads with stock sdd (`brew install networkteam/tap/sdd`), then offers the fork with what it adds and the warning that a graph the fork migrated takes only the fork for writes.

Why: the tools serve sdd projects in general, and most of them run stock sdd; refusing every capture and silencing the gate there buys nothing, since what the tools need is present in stock. Where a fork feature is missing, the tool either has a stock path that keeps its guarantee or says plainly what it cannot do.

Rejected:

- Keeping the hard fork requirement: leaves every stock project without the gate or capture.
- A version floor or the `fza` substring: fork and stock versions do not order, and a substring says nothing about which feature a build carries.
- On stock, a dry run then a plain `sdd new`: two model calls, the second free to refuse what the first cleared.
- On stock, a dry run then `sdd new --skip-preflight`: stamps a checked entry `preflight: skipped`.
- Dropping `title` or `actor_kind` silently on stock: the entry would lack fields the draft asked for, for good.
- README leading with the fork: a prerelease-only personal fork as every user's default. Listing both side by side: hides that a migrated graph needs the fork.

Accepted costs:

- On stock, no pre-flight fallback routes and no `--preflight-done`, and a retried provider fault re-runs the whole call.
- A probe of three `--help` runs on each new binary; the cache keeps it off every other call.
- The probe reads help text, so a renamed flag in sdd stops its detection, falling back to the stock path.
- A team mixing stock and fork sdd on one graph breaks at the first `sdd migrate`.

Acceptance criteria:

1. With stock help fixtures, `agentic-capture` of a clean draft runs exactly one `sdd new` with no `--dry-run` and no `--preflight-verified`; a `[high]` in its output exits 2; a provider fault retries it.
2. With fork help fixtures, the dry run then `--preflight-verified` path runs as before.
3. On stock, a draft with `title` or `actor_kind`, a `--preflight-route` and a `--preflight-done` are each refused before any `sdd new` runs, naming the fork.
4. A schema-2 graph on stock is refused with the fork text; on the fork with the `sdd migrate` text.
5. No `sdd` on `PATH`: `agentic-capture` exits 1 naming it; the gate runs as without it.
6. The gate on stock refuses an ungrounded capture and lets a grounded one through, with no SessionStart notice and no session marker.
7. With `project_dir` in the code repository's `.sdd/config.yaml` and stock help fixtures, `agentic-capture` beside an sdd server in `.mcp.json` is not refused by the engine refusal; with fork fixtures it is.
8. agentic-memory on stock fixtures runs no `sdd export` and flags links by file.
9. A cached probe runs no `sdd`; a changed binary is probed again.
10. `README.md`, `docs/plugin/usage.md`, `docs/capture/*`, `docs/grounding-gate/*`, `docs/memory/architecture.md`, `agentic-helpers:agent-capture` and `agentic-helpers:agent-grounding` describe stock support and what needs the fork, and no longer the fork requirement or the gate's notice.
