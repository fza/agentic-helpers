`agentic-capture` takes fallback routes for its pre-flight, so a draft the caller's own provider cannot answer is checked by another provider instead of failing every try.

- `--preflight-route <model>=<layer>`, repeatable, names one route: the model sdd gets as `--model` and the configuration layer it gets as `--local-config`. A relative layer is resolved against the working directory. Routes are tried in the order given, after the caller's own configuration (the primary).
- The primary keeps its three tries and its 10s and 30s waits. Once it fails all three on a provider fault, each route gets one try with no wait. A provider fault is what the existing retry detects: an empty answer, a timeout or the `--preflight-limit` cut-off, a 429, a 408, 409 or 5xx.
- The first route answering without a provider fault decides the pre-flight, and its findings hold the draft back or let it through as the primary's would. A refusal never moves on: a high or medium finding, a shape error, any other 4xx.
- The capture step, `sdd new --preflight-verified`, stays on the caller's own configuration and runs once.
- With routes named, stdout opens with `AGENTIC_CAPTURE_ROUTE <model>` (or `primary`) for the route that answered, ahead of the capture's own output. Where every route failed, stderr carries `route <name>: <fault>: <last line of sdd's output>` per tried route, then `the pre-flight's provider failed on every route; the draft did not cause it, so capture it again later`, exit 1.
- A layer holds an API key. One that is missing, not a readable regular file, owned by another user, or readable by group or others is skipped untried with `route <model> skipped: <layer> <why>`. The layer is stat'ed and opened, never read, so its contents never reach output.
- A caller naming no route sees today's output unchanged. The usage line, which `--help` prints, lists the flag, so a caller detects support from it as it does `--preflight-limit`.

Why: a provider can answer nothing for one draft on every try while another provider answers the same draft at once. A caller with several providers already keeps one sdd layer per provider, and had no way to hand them to the capture, so a sound draft failed after half an hour of tries.

Rejected:
- Retrying each route with the primary's backoff. A route is already the fallback; waiting on it multiplies the worst case by the number of routes for a fault another route answers at once.
- Moving the capture step to the route that answered. Its one model call, the summary, fails soft, and the entry would record a configuration other than the project's.
- Printing the route line with no routes named. It would change stdout for every caller that parses the entry id from it.
- Reading or validating the layer's YAML. It holds credentials; sdd judges its contents, and a bad layer fails that route alone.
- A version number and release notes for the change. The binaries carry no version beyond the commit they were built from, and callers detect the flag from the usage line, so a version would be new process with nothing reading it.

Accepted costs: the worst-case run grows by one `--preflight-limit` per route, which a caller bounding the capture from outside has to allow for; the ownership check is Unix-only, as the capture lock already is.

Done when `go test -race ./...` in `source/hooks` covers the primary empty and the first route answering, the first route empty and the second answering, a high finding on the primary never sent on, a written entry never run twice, every route empty with each error printed, a missing, group-readable, foreign and unreadable layer skipped, and no route leaving the output as it was; `README.md` and `skills/agent-capture/SKILL.md` describe the flag.
