The compact JSON read answers and scores of 20261029-130234-d-tac-s4c ship in a minor release (a `feat:` commit, no breaking-change marker), not the major release s4c named; Felix, the project's owner, set the release level.

Why: the readers of these answers are agents and the plugin's own skills, which s4c updates in the same change, and a script reading `--json` that decodes into a struct reads an absent key as empty already. A major release would hold the token saving back for a contract change few readers notice. The same call was made for 20261029-083737-d-tac-kib.

Everything else in s4c stands: only empty keys leave, every key holding a value stays, ranked hits carry the score, and the absent-key rule replaces keys-only-added.

Rejected: the major release s4c named, for the reason above.

Accepted cost: a script that checks for the presence of an empty key breaks without a major version to warn it; the release notes name the change.

Settled: the release level is decided here, and s4c's own acceptance covers the work.
