Shell-guard keeps asking about a script the command creates before running it, such as `./configure && ./config.status` with `config.status` not yet on disk, and nothing changes for it. The done 20261031-220638-s-tac-7zg lists this as left open. At check time the text that will run does not exist, so no reading can judge it; the ask `cannot read the script config.status (no such file)` follows the script-reading directive 20261031-211859-d-tac-59g, under which what cannot be read is asked about and never refused.

**Rejected.** Letting a script missing at check time pass: any generator could create a file removing things outside the project and run it unjudged, reopening the write-then-run bypass. Rewording the reason to `not there yet; the command may create it`: the reason is quoted by skills, and the present wording already says what the agent needs.

**Accepted cost.** A build step that generates and runs a script costs one confirmation each time.

Settled: nothing follows from this decision, since it keeps the present behaviour.
