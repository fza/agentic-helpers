agentic-memory's prompt hook no longer records a turn Claude Code sends itself as the seat's last prompt, so a hook-written state draft keeps naming what the user last asked; commit 09afbf5 carries the change with its tests and the `docs/memory/` pages, and is not yet released.

A prompt whose text, leading whitespace aside, opens with `<task-notification>`, `<local-command-caveat>`, `<local-command-stdout>` or `<bash-stdout>` leaves `last_prompt` as it was; a prompt only mentioning one of those tags further in stays the user's. This is the remedy the gap named as its candidate, taken without change.

Proven live on binaries built from the commit and served through `AGENTIC_HELPERS_BIN_DIR`: in a seated session, a background task's notification turn passed the prompt hook and the session's recorded last prompt stayed the user's preceding message, where the v2.12.2 release records the notification.
