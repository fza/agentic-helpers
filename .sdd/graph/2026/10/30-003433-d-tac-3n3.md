A tool's usage moves out of `agentic-tools find` and `list` into `take`: each hit shrinks to one line, `<name>@<project>  v<n>  <summary>`, five hits a page instead of ten with usage, inputs and outputs under each, and `take` prints the usage of every tool it copies, under the path it copied to.

Why: usage is needed only for the tool an agent goes on to use, yet every hit carries it. One broad `find --term replace` answered 5,299 characters for 10 hits: name and summary 31%, first usage line 26%, further usage lines 39%. Measured over session transcripts on this machine, a typical `find` answers far less (median 492 characters over 44 calls), but the long tail is exactly the broad search (90th percentile 3,197, maximum 7,044) and `list` run alone (median 6,573 over 3 calls), and there the usage lines are most of the reply. A `take` answers a median of 370 characters, so moving usage there adds little to the one call that needs it. After a take, 51% of agents read the taken file before running it anyway (26 of 51 takes), so the usage under every hit mostly repeats what the agent reads later. The choice follows d-tac-00q: risk stays equal, since the one-line summary is what an agent picks by already, and fewer tokens decide; Felix, the project owner, left this choice to those criteria.

**find and list.** A hit is its line alone; paging stays, at five hits a page instead of ten, and the closing line names the page command. Over MCP and `--json` a hit carries `name`, `project`, `version`, `summary` and `score`, dropping `usage`, `inputs` and `outputs`. The seen pointer of d-tac-myr is unchanged.

**take.** After each `taken: <path>` line, the tool's usage lines, indented; inputs and outputs follow where the tool declares them. Over MCP and `--json` each taken tool carries `usage`, `inputs` and `outputs`. A copy already held is reused as today and its usage printed again, since the agent asked for it.

**Rejected.**
- Keeping the first usage line per hit: saves about 40% where summary-only saves about 66% at ten hits, for a run line the agent needs only after choosing.
- Ten hits a page: twice the lines for hits rarely read past the top few; `--page` still reaches them.
- Leaving find as it is: the broad searches and `list` keep costing several thousand characters each.
- Printing usage only on request (a `--usage` flag on take): one more call or flag for what every take is followed by.

**Accepted costs.** Choosing between near-identical tools rests on their summaries alone; a wrong pick costs one more take, about 370 characters. A breaking change to `find`, `list` and `take` text and JSON, with `docs/tools/`, the `agentic-helpers:agent-tools` skill and the MCP descriptions following in the same change.

**Acceptance.**
1. `find` and `list` print one line per hit, no usage, inputs or outputs, five a page, and their JSON hits carry exactly `name`, `project`, `version`, `summary`, `score` (or the seen pointer).
2. `take` prints each tool's usage under its path, and its JSON carries `usage`, `inputs`, `outputs` per tool; a reused copy prints its usage too.
3. A fixture library of ten tools with multi-line usage: `find` matching all of them answers at most a third of the characters it answered before the change.
4. `docs/tools/usage.md`, `docs/tools/architecture.md`, the skill and the `find`, `list` and `take` MCP descriptions describe the new output in the same change.
