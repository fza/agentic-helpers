title: Agentic-tools store writers
summary: agentic-tools restricts writes to a project's own library to checkouts listed in the store's writers.json, claimed by the first write and extendable via agentic-tools trust. It refines the agentic-tools directive (20261025-185701-d-tac-e9x), which left any checkout declaring a project's repo_id able to write its store. A process that can write ~/.claude can still edit writers.json, as it can every store (20261025-185324-s-tac-k4o).
---

agentic-tools records which checkouts may write a project's library, so a repository declaring another project's `repo_id` in its `.sdd/config.yaml` cannot put tools into that project's own library.

The store is keyed by the declared `repo_id` (`source/hooks/internal/projectkey/projectkey.go:29`), and any checkout can declare any. A tool in the own library is named in the per-prompt offer, preferred for a bare name and lifted in ranking, so an untrusted clone naming a trusted project's `repo_id` would have its sessions' tools offered inside the trusted project's sessions.

- **`~/.claude/agentic-tools/<project>/writers.json`**: a JSON array of the absolute git common directories allowed to write the store. Every worktree of a checkout shares its common directory, so all of them write.
- **The first write claims a store** with no `writers.json`: it records the caller's common directory. A library renamed into place, as fdbox's, is claimed by its project's first write.
- **A write from a checkout not listed is refused**, the store untouched: `refused: this library belongs to the checkouts <paths>; run `agentic-tools trust <this checkout>` from one of them to let this one write`. Writes are every verb that changes the store (`add`, `update`, `merge`, `reindex`), a take's take line, and the index a read rebuilds and writes back. A `take` from such a checkout still copies, recording nothing.
- **The hooks stay silent for a checkout not listed**: no offer, no notice, no nudge, no session file, since each writes the session's file into the store.
- **`agentic-tools trust <path>`**, also the MCP tool `trust` with the key `path`, adds the git common directory of the checkout at `<path>`; it is refused from a checkout not listed, and for a path that is no git checkout.
- **A `writers.json` that cannot be read** (a link, past 64 KiB, not a JSON array of absolute paths) refuses every write rather than being claimed over, so a damaged file never hands the store to the next writer.

Why: the store key is the project's identity across clones, which agentic-memory shares, so the key stays and the right to write it becomes a property of the checkout, which a cloned repository cannot declare for itself. Reads are unchanged: other projects' tools are untrusted by design and read as such.

Rejected:
- Keying the store by the checkout's git common directory: two clones of one project would no longer share an own library, each seeing the other as a foreign project, and fdbox's rename target would become a hash.
- Accepting the exposure and documenting it: an untrusted clone could still put tools into a trusted project's offer.
- Matching the `origin` remote against the `repo_id`: a repository's own git config names any remote it likes.

Accepted costs: a second clone or a CI checkout of a project must be trusted once from a listed one; a new verb, a new MCP tool and a new file in the store; a process that can write `~/.claude` can still edit `writers.json`, as it can every store (20261025-185324-s-tac-k4o). agentic-memory keys its store the same way and is not changed by this entry.

Acceptance criteria:
1. A write to a store with no `writers.json` records the caller's git common directory; a later write from that checkout, or from a worktree of it, lands.
2. Each write named above, from a checkout not listed, is refused with the line, and the store is byte-identical before and after; `take` copies and records nothing.
3. Every hook stays silent and writes nothing for a checkout not listed.
4. `trust <path>` from a listed checkout adds the path's common directory, after which that checkout writes; from a checkout not listed, or for a path outside git, it is refused.
5. An unreadable `writers.json` refuses every write and is never rewritten by a claim.
6. fdbox's renamed library is claimed by the first write from fdbox's checkout.
7. The MCP `trust` tool takes exactly `path`; `docs/tools/` and `agentic-helpers:agent-tools` describe `writers.json`, the claim, the refusal and `trust`.
