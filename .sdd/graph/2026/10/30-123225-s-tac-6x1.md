The plugin options dialog work is built in three commits, not yet released, and proven against a live Claude Code 2.1.314 session: number bounds (20261030-083534-d-tac-ws7) in 2272a9d, pickers with their built-in defaults (20261030-113044-d-tac-is5) in 2f90349, and declared boolean defaults with built-in answers read as unset (20261030-120442-d-tac-iuc) in c7bd8aa.

**Live proof.** A session started with `claude --plugin-dir plugin/` showed every switch on and every picker at its built-in value; the dialog, saved without a change, stored exactly the answers kept in `test/fixtures/pluginconfig/untouched-save.json`. With those answers in a user settings file beside a `config.yaml` setting `memory_enabled: false`, `writing_style: plain`, `shell_guard_secrets: deny` and `scratch_sweep: idle`, the installed `agentic-helpers config` printed output identical to the run without the settings file, every listed key from `config.yaml`. The probe of 20261030-113044-d-tac-is5 had already shown that an unanswered picker sends a hook no value.

**Suites** in `source/hooks`: `TestEveryNumberOptionIsBoundedAsTheReaderBoundsIt`, `TestOnlyABooleanOrPickerDeclaresADefaultAndAPickerOffersWhatTheReaderTakes`, `TestAnUntouchedDialogSaveResolvesAsNoAnswer`, and the built-in-value cases of `TestEveryLayerResolvesInOrderManagedSettingsLast`. `claude plugin validate .` passes. README states the Claude Code v2.1.271 minimum and the built-in-answer rule; `docs/plugin/usage.md` states which options declare a default and why.

**Departures from 20261030-083534-d-tac-ws7 as written**, each settled by a later directive: `embedding_provider` stays a text field and `embedding_source` is the picker (20261030-113044-d-tac-is5); `shell_guard_ask_timeout` takes a span instead of number bounds (20261030-084036-d-tac-e9g); pickers and switches declare a default (20261030-113044-d-tac-is5, 20261030-120442-d-tac-iuc).

**Side effect worth knowing:** a session started with `--plugin-dir plugin/` leaves `plugin/tsconfig.json` and `plugin/.claude-plugin/types/` behind, which `TestThePluginShipsOnlyItsOwnComponents` refuses; they are removed after each such session.
