A forked session takes its agentic-memory seat at the first memory hook that finds the fork's transcript written, the next tool call's PostToolUse or a later prompt's UserPromptSubmit, and a resumed session keeps taking its parent's seat at SessionStart.

Why this replaces 20261028-082845-d-tac-5f8: that directive matched a fork at its first UserPromptSubmit, on the belief that Claude Code writes a fork's transcript right after the SessionStart hooks return. A live check on v2.12.1 showed it writes the transcript only after the first prompt's UserPromptSubmit hooks return: the fork's prompt hook printed the seatless notice at 09:35:36.032Z and its transcript file was born at 09:35:36.194Z. The hook removed its fork marker, read no first record, matched nothing and printed the seatless notice; the prompt hook stays silent for a seatless session afterwards, so the fork never got a seat. The fork's first record, once written, carried the parent claim's `fork_uuid`, so the matching rule holds a second time and only the moment was wrong again. The directive's tests wrote the transcript before the prompt hook, which a real fork never does.

How a session finds its parent is unchanged: a resume matches a claim by its own session id at SessionStart; a fork matches a claim or last claim whose `fork_uuid` equals the uuid of its transcript's first record. A fork of an ended parent takes the seat over as a reservation does (20261025-223640-d-tac-d2p); a fork of a running parent gets a new seat on its shelf, because a running holder keeps its seat (20261025-164209-d-tac-qj7).

When a fork is matched:

- **SessionStart**, source `fork`, nothing matching and the transcript holding no record: the hook writes the marker `forks/<session id>` under the project's cache directory and prints nothing, as before.
- **Every later UserPromptSubmit and PostToolUse** of a seatless session carrying the marker reads the transcript's first record. No record yet: the marker stays and the hook prints nothing for it. A record: the hook matches, removes the marker either way, and prints the claim's output, brief included, as its context (the prompt hook's output, or PostToolUse `additionalContext`); no match prints the seatless notice there, once.
- **A session that claims a seat itself** while the marker stands keeps its seat; the next hook removes the marker without matching.
- **Stop and SessionEnd do nothing for a marker.** A marker no hook resolves is swept with the cache, as before.

Rejected:

- Taking the seat quietly at the first turn's Stop as well, with the brief at the next prompt: the agent would hold a seat it does not know about for a turn, and Stop gains a job for the one case of a first turn without a tool call.
- Holding the first turn's end once with the claim text when no tool call seated the fork: one more hidden turn per fork, against the rule that hidden hook messages fire only when they change what the agent does next (20261027-222117-d-tac-yjy).
- Matching from the owning `claude` process's arguments (`--resume <id> --fork-session`) at SessionStart: a fork made without an id on its command line (`--continue --fork-session`) names no parent there, so it could only add to the transcript match, never replace it.
- Waiting inside the prompt hook for the transcript: Claude Code writes it after that hook returns, so the hook would wait out its whole timeout.
- Matching any seatless session at every hook, a detached waiter, and the other alternatives 20261028-082845-d-tac-5f8 rejected, for the reasons it gave.

Accepted costs: a fork whose first turn makes no tool call stays seatless until its next prompt; a memory write sent as a fork's very first tool call is refused for want of a seat, and the seat lands in that same call's PostToolUse; one stat of the marker per prompt and tool call of a seatless session, plus one read of the transcript head while the marker stands.

Acceptance criteria:

1. A resumed session whose parent process is gone holds the parent's seat after SessionStart, with the brief printed, checked by a test.
2. A fork whose transcript is absent at SessionStart and at its first UserPromptSubmit prints nothing at either and keeps its marker; at the next PostToolUse, with the transcript written, it gets a new seat on a running parent's shelf, the brief as `additionalContext`, and the parent keeps its seat, checked by a test that writes the transcript only after the prompt hook.
3. The same fork with no tool call in its first turn is seated at its second UserPromptSubmit, the brief as that hook's output, checked by a test.
4. A fork of a parent that has ended takes the parent's seat at the first hook finding its transcript, checked by a test.
5. A fork of a compacted session finds its parent through the boundary uuid the claim recorded after the compaction, checked by a test.
6. A fork matching no claim gets the seatless notice once, at the first hook finding its transcript, and no marker remains; a startup session gets the seatless notice at SessionStart as before.
7. A fork that claims a seat itself while its marker stands keeps that seat, and the marker is removed.
8. Each guard is broken once and its test watched failing; `docs/memory/` and agentic-helpers:agent-memory say a fork is seated at its first tool call or prompt after its transcript exists, in the same change.
9. Proven live on a released build: `claude --resume <id> --fork-session` beside a running seated session holds a new seat on its shelf after its first turn with a tool call.
