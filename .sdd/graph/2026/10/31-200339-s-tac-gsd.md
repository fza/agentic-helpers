**Live proof**, run with a throwaway home and data home so no real store was touched:
- Scratch move: session start printed `Scratch: moved .tmp/claude/alpha/ to .tmp/seats/alpha/`, moved a session folder to `.tmp/seats/<session>/`, moved a stray file and folder older than 24 hours to `.tmp/keep/` (a name clash became `notes.txt-2`, the existing file untouched), left a minutes-old stray in place, and removed the empty `.tmp/claude/`; the claim printed `scratch: .tmp/seats/alpha/`.
- Path rewrite: with the marker removed, the next call mapped title, body, `--about`, `gone:` and `changed:` ends from `.tmp/claude/alpha/x` to `.tmp/seats/alpha/x`, mapped a stored dotless `tmp/claude/alpha/x` the same way, wrote a backup `memory/backup/scratch-paths-<stamp>/` holding the old log and the marker; a rerun left the log byte-identical and took no second backup.
- Backup lifetime: a plain call removed a 31-day-old `legacy-<stamp>` from the data home and kept a 5-day-old one; a session start removed a 31-day-old `format-<stamp>` store backup and kept the younger ones.
- Instruction re-read: a headless Claude Code session loading the plugin from the checkout recorded every loaded instruction file through `InstructionsLoaded`; after `CLAUDE.md` was edited from outside between two turns, the second prompt got `agentic-memory: CLAUDE.md changed since loaded; re-read it`.
