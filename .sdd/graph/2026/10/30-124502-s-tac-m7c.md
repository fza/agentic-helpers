Scoping an agent's `agentic-memory bind` and `merge` to the stores the open store question offers (20261029-150407-d-tac-trv) shipped in agentic-helpers v2.16.0 (commit f687266) and holds on the v2.16.1 release binaries, closing the gap that both reached any store by id (20261029-131526-s-tac-sv3).

**Live proof** on `agentic-memory` v2.16.1 against a throwaway data home, run through the Bash tool (no terminal on standard input), with two unrelated checkouts A and B each given a store by `bind --new`:
- From B, `bind <A's store>`, `merge <B's store> <A's store>` and `merge <A's store> <B's store>` were each refused with exit 1: `agentic-memory: <A's store> is not offered for this checkout; run the bind in a terminal` (`run the merge` for the merges).
- `bind --new` ran in every checkout.
- A split-layout code checkout whose open question offered only its graph repository's store was refused `bind <A's store>` the same way, and `bind <graph store>` bound it.

**Suites** cover the directive's remaining acceptance items (offered merges, the terminal path, MCP parity): `TestAnAgentBindsAndMergesOnlyOfferedStores` (offered binds and merges join, a terminal on standard input runs any of them, faked behind `memory.Terminal`), `TestWithNoQuestionAnAgentBindsOnlyANewStore` and `TestTheMCPServerRefusesAnUnofferedBindOrMerge`. `docs/memory/usage.md` and the `agentic-helpers:agent-memory` skill quote the refusal.
