agentic-memory kept a leading dot out of every path it stored for an entry, and commit f5a7dea on `main` fixes it. `relative()` in `source/hooks/internal/memory/anchors.go` trimmed sentence punctuation from both ends of a path token with one `strings.Trim`, and the dot of `.tmp`, `.sdd` or `.github` counted as punctuation. Anchors parsed from a body, `--about` paths, `--until changed:` and `gone:` ends and the paths of a tool call reaching a `path:` trigger all lost it, so `.tmp/x` was stored as `tmp/x`.

What it cost: an entry filed `--until gone:.tmp/x` was stored as `gone:tmp/x`, a path that never existed, so it ended the moment it was filed; `changed:` ends and anchors on dot paths never saw their file, so no `drifted:` or `gone:` flag appeared; a `path:.sdd/**` trigger missed relative paths in Bash commands. `./x` resolved to nothing, as stripping the dot left `/x`, outside the root.

The fix trims each end on its own and keeps a dot opening a path on the left, while a trailing period still goes. `./x` now resolves to `x`; `../x` stays refused. Entries already stored keep their dotless paths, except those under `tmp/claude/`, which the scratch path pass (20261031-180135-d-tac-bke) maps to their new dotted location.

Evidence: `TestRelativeKeepsADotStartingAPath` and `TestAFilingKeepsTheDotOfADotFolder` failed against the old code (stored `tmp/x`, `sdd/config.yaml`, and `end reached: gone:tmp/x` on filing) and pass now; each guard of the fix was broken, caught and restored byte-identically; `go test -race ./...` passes in `source/hooks`. Live on the installed build of 911665d, a filing with `--about` and `--until changed:` on a dot path kept the dot. Not yet released.
