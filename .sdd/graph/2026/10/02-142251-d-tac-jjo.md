The grounding gate stays on by default in every project carrying `.sdd/`, and `.sdd/grounding.yaml` gains two top-level keys to lift it:

    enabled: false
    exempt_seats: [reviewer]

`enabled` switches the gate for the whole project. Left out, or `true`, the gate runs as now. `false` makes every mode of `agentic-grounding-gate` (`record`, `turn`, `gate`, `start`, `end`) exit 0 without reading the payload or writing a ledger, as in a project carrying no graph. A value that is not a boolean is a config error, refused like any file that does not parse.

`exempt_seats` names carry-forward seats the gate never refuses. A session holding a seat named there passes every check of `gate` mode: `AskUserQuestion`, a draft `Write`, `Edit` or `NotebookEdit`, `agentic-capture`, a plain `sdd new`, an `sdd` call sending a stream to `/dev/null`, and an `sdd show` short of the depth owed. The seat is resolved exactly as for `show_depth.exempt_seats`: the hook payload's session id matched against the claims under `.memory/roles/`, a subagent reading as its session's seat. `show_depth.exempt_seats` keeps its meaning, the depth check alone.

A file that does not parse keeps the gate on and refusing with the config error, since whether the project opted out is part of what the file says.

Why: the presence of `.sdd/` says a project keeps a graph, not that every session working in it should be held to reads before asking. A key in the file the gate already reads puts the switch beside the rules it switches. Defaulting to on keeps every project that writes no file under the gate it has today. A seat is the only record tying a name to a live session, so a whole-gate exemption by seat cannot be asserted by a session naming itself.

Rejected: a key meaning the opposite (`disabled: true`, `opt_in: true`). The switch reads best as the state it sets, and an opt-in default would release every project writing no file. Rejected: listing Claude Code session ids. They change every session, so the file goes stale at once and commits throwaway values. Rejected: widening `show_depth.exempt_seats` to the whole gate. A project exempting a seat from the depth would silently lift every other refusal for it.

Accepted costs: a project without `.memory/` cannot exempt a seat, and a session owes every read until it claims its seat. Two keys named `exempt_seats` exist at different scopes, the nesting alone telling them apart. `agentic-capture` keeps its own header check, project lint and pre-flight in a project with the gate off: those guard the entry, not the turn.

Acceptance criteria:

- No `enabled` key, or `enabled: true`: every refusal holds as now.
- `enabled: false`: `AskUserQuestion`, a draft `Write`, `agentic-capture`, a plain `sdd new` and `sdd show <id> 2>/dev/null` pass without reads, and no ledger is written under `.sdd/tmp/grounding-gate/`.
- `enabled: maybe`: a gated call is refused with the config error.
- A session holding a seat named in top-level `exempt_seats`: the same calls pass without reads, and a shallow `sdd show <id>` passes.
- A session holding no seat, or a seat named only in `show_depth.exempt_seats`: `AskUserQuestion` without reads is refused.
- README and the `agent-grounding` skill name both keys.
