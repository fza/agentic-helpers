`agentic-memory claim <seat> --session <id> [--lifetime durable|temporary|<duration>]` claims a seat for a session that is not the caller, so a launcher can put a job on its seat before the job runs. The claim the agent makes itself, `claim <seat> [--lifetime ...]` from inside its own session, stays as it is. A launcher uses either; agentic-memory prescribes neither.

Why: a launcher such as a job board starts sessions it names up front (`claude --session-id <uuid>`) and wants each one seated, with its lifetime, from its first moment, without depending on the agent following its brief.

## What

- **A claim for another session is a reservation.** It writes the seat's claim with that `session_id`, the time it was made, and no process. `holder <seat> --json` reports it with `"reserved": true` and `"alive": false`, exit 1, so a reader taking exit 0 as held and the keys `seat`, `session_id` and `alive` reads it as not yet held.
- **The session takes it over on its first hook.** Any agentic-memory hook whose payload carries the reserved `session_id` (SessionStart first, else the first prompt or tool call) fills in the owning process, its start time and the transcript, exactly as a claim from inside the session would. From then on the seat is held like any other.
- **A reservation no session takes over within 10 minutes counts free.** `sweep`, `claim` and the SessionStart check free it as they free a dead holder. A launcher starts its job right after the claim; ten minutes covers a slow start without letting a crashed launcher keep a seat.
- **A reservation refuses like a held seat.** A held or reserved seat refuses `claim --session` as it refuses `claim`, and a session already holding a seat refuses a reservation for itself.
- **`--lifetime` on a reservation sets the seat's lifetime at once**, as on a claim. The close clock of a temporary seat does not run while it is reserved.
- MCP: key `session` on the `claim` tool.

## Rejected

- **An environment variable the job's SessionStart hook claims from** (`AGENTIC_MEMORY_SEAT`, `AGENTIC_MEMORY_LIFETIME`). The claim would land inside the job, where a refusal reaches only the job's own SessionStart notice and never the launcher that asked for it.
- **Only the agent claiming for itself.** Leaves the seat, and a temporary seat's lifetime, to the agent following its brief, and the session seatless until it does.
- **A reservation held until its session appears, however late.** A launcher that crashed between claim and start would hold the seat until someone released it by hand.

## Accepted costs

- Any process that can run `agentic-memory` can reserve a seat for any session id. A claim from inside a session could already take any free seat.
- A seat has a third state beside free and held, which `sweep`, `who` and `holder` show.

## Acceptance criteria

- `claim <seat> --session <id>` on a free seat writes a reservation; `holder <seat> --json` shows `"reserved": true`, `"alive": false`, exit 1.
- The first memory hook carrying that session id makes the session the holder: `holder --session <id> --json` exits 0 with `"alive": true`, and the session's Bash and MCP calls act as that seat.
- A reservation older than 10 minutes, untaken, is freed by `sweep`, `claim` and SessionStart.
- `claim --session` on a held or reserved seat is refused and changes nothing; so is a reservation for a session already holding a seat.
- `claim <seat> --session <id> --lifetime 2d` leaves the seat temporary with 2d; no close time is recorded while it is reserved.
- `docs/memory/` and the `agent-memory` skill describe `claim --session` in the same change.
