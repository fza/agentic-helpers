A resumed or forked session now takes its agentic-memory seat back at SessionStart, or a new seat on its parent's shelf where the parent still runs, closing 20261027-233526-d-tac-bbp. Commit c30e504, not yet released.

- Claims record `fork_uuid`, the latest compaction boundary's uuid, else the transcript's first record's; a compaction's SessionStart empties it and the next hook reads it afresh.
- A seatless SessionStart matches a claim or last claim by session id first, then by `fork_uuid`, the latest claimed among equals, so a resumed fork takes its own seat rather than its parent's.
- Tests in `internal/memory/inherit_test.go` and `internal/transcript/forkstart_test.go` cover every acceptance criterion; each of 11 guards was broken and its test watched failing, files restored byte-identically. The fork uuid match masks the session id match for a plain resume, whose transcript starts with the recorded uuid; the old-claim and resumed-fork tests catch it alone.
- Lifetime and SessionStart tests that sent a later SessionStart under an ended session's own id now use an id no claim names, since that payload is a resume.
- Proven on binaries built from the commit, against a throwaway home and repository: a resume with its parent's process gone took `main` back with the brief; a fork beside a running holder got `main-2` with the brief while the parent kept `main`; a compaction emptied `fork_uuid` and the next prompt recorded the boundary's uuid, through which a fork of the compacted session took `main`; a transcript matching no claim got the seatless notice.
- `docs/memory/usage.md`, `docs/memory/architecture.md` and agentic-helpers:agent-memory describe the takeover.
