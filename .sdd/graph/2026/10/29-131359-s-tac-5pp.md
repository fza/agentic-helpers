A cloned repository can make agentic-helpers hand an agent another local project's memory and tool library: the silent split-layout join of 20261028-204914-d-tac-6xf binds a checkout to the store of whatever repository its committed `.sdd/config.yaml` names, with no question.

**Observed.** An automated security review of the 6xf build (agentic-helpers commit 50c9e1c, unreleased) flagged it, confirmed by reading the code: when a checkout has no strong match of its own but its split-layout link (`project_dir` for the github.com/fza/sdd fork, or a stock sdd `graph_dir` outside the checkout) resolves to a checkout another store admits, `mapping.joinGraph` in `source/hooks/internal/home/resolve.go` joins that store and writes the `agentic-store` pointer into both git common dirs. The link comes from a file committed in the cloned repository, so a repository naming `../some-other-repo` that exists on the machine gives every agent working in the clone that repository's memory entries and tools, unasked.

**Expected.** A store's data reaches only checkouts its owner placed there, or that the owner confirmed once, as the binding rules of 6xf already require for a weak match (a `repo_id` or origin alone asks).

**Candidate remedies, unsettled:** ask once for a split join unless the graph store already admits the checkout (the switch point is `mapping.joinGraph`, which returns a `ReasonSplit` question naming the graph store instead of joining); require the graph repository to name the code repository back; trust only a link set in the machine-local `.sdd/config.local.yaml` rather than the committed config.
