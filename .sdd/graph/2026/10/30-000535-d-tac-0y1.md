The agentic-tools library also prunes a tool's non-current versions by age: a version is removed once it has not been its tool's current version for `tools_version_days` days, 90 unless set, whatever space is left.

Why: the size limit of d-tac-x9j prunes only when the library is full, so on a machine that never reaches `tools_total_mb` every replaced version stays forever. A replaced version is history nobody is offered and nobody finds; three months after its successor took over it has served its one use, a way back from a bad update.

**What ages out.** Only versions that are prunable under d-tac-x9j: not their tool's current version, and named by no fork as its origin. A tool's current version is never removed by age, so every tool stays findable however long nobody takes it.

**Age is counted from replacement**, the time the history recorded for the next version, not from the version's own write. Counted from the write, a version current for a year would go the moment an update replaced it, taking the way back with it.

**Where and how it runs.** In the SessionStart pass `tools.Prune` already runs over every store, beside the size pruning, through the same path: the version's file hashes appended to `<tool>/pruned.jnl` first, so the duplicate check of d-tac-e9x still refuses a byte-identical re-add, then `v<n>/` removed and the store's ledger refreshed. A version a session took keeps its copy in the checkout's `.tmp/tools/`. Vectors are untouched: only a tool's current description holds one.

**The key.** `tools_version_days` decides when shared stored data goes, so per d-tac-cld it lives in `config.yaml` only, like `retired_body_days`, and like that key it takes at least 14; a lower value resolves to 14.

**Rejected.**
- Removing whole tools nobody took or updated for 90 days, current version included: keeps find results lean, but a rarely needed tool (a yearly script) vanishes, and it breaks the rule of d-tac-x9j that a current version is never pruned.
- Both, versions at 90 days and unused whole tools at a longer window: two keys, two code paths and their tests, and the same broken rule for unused tools.
- Age counted from the version's own write: removes the way back right after an update.
- An overridable key: two agents with different values would leave the lowest deciding for both.

**Accepted costs.** Unused tools stay in find results indefinitely; only their history shrinks. A rollback older than the window is gone from the store.

**Acceptance.**
1. A fixture store with a version replaced 91 days ago and one replaced 89 days ago loses the first and keeps the second in the SessionStart pass, under the default.
2. A current version, and a fork's origin, older than the window are kept.
3. An aged-out version's files still refuse a byte-identical `add`.
4. `tools_version_days` set as an agent option has no effect; set in `config.yaml`, it does; a value below 14 resolves to 14.
5. README `Options`, `docs/tools/usage.md` and `docs/tools/architecture.md`, and the `agentic-helpers:agent-tools` skill name the key and the rule in the same change.
