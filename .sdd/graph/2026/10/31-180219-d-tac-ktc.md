agentic-helpers deletes each of its migration backups once it is 30 days old, a lifetime fixed in code with no option, so backups no longer pile up in every memory store on every machine. Today a store keeps every `memory/backup/format-<n>-<UTC stamp>/` a format migration wrote, and the data home keeps `backup/legacy-<UTC stamp>/` from the move out of `~/.claude`, for good: one machine already holds 23 store backups across 7 stores, and each release with a migration adds one per store.

**What goes.** Every backup folder a migration wrote: a store's `memory/backup/format-<n>-<stamp>/` and `memory/backup/scratch-paths-<stamp>/` (20261031-180135-d-tac-bke), and the data home's `backup/legacy-<stamp>/`. The age is the UTC stamp in the folder's name, so a copy or touch cannot keep one alive or age it early; a folder whose name carries no readable stamp, or any other file under `backup/`, is never removed.

**When.** A store's first memory call of a session removes that store's expired backups, under the store's lock; the machine-wide first call removes expired data-home backups. Removal goes through `internal/safefs`, never following a link. Backups already on disk fall under the same rule.

**Rejected.** An option `backup_lifetime` in `config.yaml`: a value nobody tunes, and a key to document, validate and test. Keeping only each store's newest backup: a store migrated twice in a short span loses the backup from before the first migration. 14 days: a fault in a rarely used project's store can surface after the backup is gone. 90 days: stores migrated every release hold several backups at once.

**Accepted costs.** A migration fault noticed after 30 days has no backup left. The lifetime changes only with a release.

**Acceptance.**
- A backup folder whose stamp is 30 days old or more is removed at the next first call; a younger one stays.
- A folder without a readable stamp, a loose file, and a link under `backup/` stay.
- Data-home `backup/legacy-<stamp>/` follows the same rule.
- `docs/memory/architecture.md` and `docs/plugin/usage.md` state the 30-day lifetime.
