`agentic-capture` refuses a draft whose header carries `title` where `.sdd/meta.json` holds `graph_schema_version: 1`, before the lint, the pre-flight or any `sdd new` runs: ``the graph is on schema 1, which has no entry titles; drop the draft's `title` key, or run `sdd migrate` to upgrade the graph``, exit 1. A graph whose `meta.json` names no schema is on the installed sdd's own, as sdd reads it, so the check leaves it to sdd. It adds one refusal to the checks before anything runs (20261026-204842-d-tac-288) and guards the `title` key mapped to `--title` (20261023-143402-d-tac-cbw).

Why: sdd built from the fza fork (github.com/fza/sdd), the only sdd carrying `--title`, writes to a schema-1 graph without migrating it and refuses an explicit `--title` there, `--dry-run` included. `agentic-capture` passes `title` wherever `sdd new` offers the flag, so on such a graph the run reaches the pre-flight and fails on sdd's raw error, after the lint ran.

Rejected:

- Leaving the refusal to sdd. Nothing is written, but the refusal comes late and without `agentic-capture`'s framing.
- Dropping the title silently. The entry would lack a field the draft asked for, for good.
- Running `sdd migrate` from `agentic-capture`. A migration rewrites the whole graph; it is the graph owner's call.

Accepted costs: `agentic-capture` mirrors sdd's rule that schema 1 holds no titles, so a change in sdd needs the check changed with it; sdd exposes no machine-readable schema outside its MCP `info` tool, so the check reads `meta.json` directly.

Done when `go test -race ./...` in `source/hooks` covers a titled draft on schema 1 refused with no `sdd new` run, an untitled draft on schema 1 captured, and a titled draft on a graph naming no schema captured, the guard broken and watched failing; `agentic-helpers:agent-capture` and `docs/capture/*` name the refusal.
