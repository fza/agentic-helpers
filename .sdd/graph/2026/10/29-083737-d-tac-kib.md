The `json` key leaves the input schemas of both plugin MCP servers, `memory` and `tools`, and a call still sending `json` to a tool whose CLI command takes `--json` is accepted silently on both; this replaces the v3.0.0 removal-with-refusal of 20261027-180803-d-tac-lko.

- **Schemas.** No tool of either server lists `json` in `tools/list`. The `memory` server dropped it under 20261029-022449-d-tac-ygu (commit 6ad7f0a); the `tools` server (`jsonKey` in `source/hooks/internal/tools/commands.go`) drops it now, in a minor release.
- **Let through.** A call sending `json` to a tool whose CLI command has a `--json` flag answers as one without it, on both servers. Any other tool refuses `json` as an unknown key, through the exact-keys check of 20261025-034140-d-tac-9os (`exactKeys` in `source/hooks/internal/memory/mcp.go` and `source/hooks/internal/tools/mcp.go`).
- **CLI unchanged.** The `--json` flags of `agentic-memory` and `agentic-tools` stay: text is the default on the command line, `--json` selects JSON.
- **Skills and docs** name no MCP `json` key.

Every MCP answer is JSON since 20261027-180531-d-tac-04v, so the key does nothing. ygu let it through on the memory server while the tools server kept listing it; this brings the tools server under the same rule and drops the plan to refuse the key at v3.0.0.

Why: no caller ever breaks, both listings shrink now, and both servers treat one key alike.

Rejected: refusing `json` at v3.0.0 as lko planned (a breaking change and a major release for a key that does nothing, and the tools server keeps listing it until then); letting it through on the memory server while the tools server waits for v3.0.0 (two servers treat one key differently).

Accepted cost: a dead key stays accepted, and a caller sending it never learns it is useless.

Acceptance (each guard broken once and watched failing):
- The `tools` server's `tools/list` lists no `json` key.
- A `tools` MCP call with `json` on a tool whose command takes `--json` answers as one without it.
- A `tools` MCP call with `json` on any other tool is refused naming the key.
- Skills and `docs/` name no MCP `json` key.
