The agentic-tools library gets no minimum tool size: the 2 KiB floor and its one-off prune of every smaller tool, decided in d-tac-fwc, are dropped, because measured costs show that writing a small tool again costs more tokens than finding and taking it.

Why: d-tac-fwc rested on an estimate that a 362-byte script costs about 100 output tokens to write fresh, against about 1,400 input tokens for one `find`. Measured from the Claude Code transcripts in which 49 of the 51 stored tools were written, both figures were wrong. The full method, per-tool table and lookup tables are in the attached [measurements](./30-004635-d-tac-oee/measurements.md); the figures that decide:

- **Writing.** The assistant message that writes a tool's file (Write, Edit, or a shell redirect into it) costs a median 1,307 output tokens, thinking included, about 1.09 output tokens per byte of the first version. This is a lower bound: thinking in earlier messages is not counted. Tools under 700 bytes cost between 513 and 3,062 output tokens to write; `splice-between-markers`, 315 bytes, cost 3,062. Agents also used 28 of the 49 tools before registering them (median 324 output tokens of such use; `replace-exact` ran 25 times for 20,173), and registering cost a median 650.
- **Looking up.** The assistant message issuing a `find` costs a median 477 output tokens (45 messages, 90th percentile 1,120), one issuing a `take` 292 (56, 90th percentile 1,057). Replies are small: `find` a median 492 characters over 44 calls (90th percentile 3,197), `take` 370 over 51. After 26 of 51 takes the agent read the copied file before running it.
- **Break-even.** At output tokens priced five times input, a lookup costs about 4,100 input-equivalents plus about 0.19 per byte for the file read; writing costs at least 5.4 per byte. They meet near 800 bytes. Tool by tool, writing cost more than a lookup for 40 of the 49 tools.

A floor at 2 KiB would have removed 38 tools, most of which cost more to write than to find. A floor at the 800-byte break-even fails too: size tracks writing cost poorly, so it would remove tools that were expensive to write and keep cheap ones above it.

**Settled, nothing follows.** No floor is built, no prune runs, and the `agentic-helpers:agent-tools` skill, the `add` and `update` MCP descriptions and `docs/tools/` keep the 1 MiB cap as the only size rule. The age pruning of old versions (d-tac-0y1) and the summary-only search output (d-tac-3n3) are unaffected. Tiny near-duplicates such as the four replace tools crowd broad searches; `merge` handles them case by case.

**Rejected.**
- Keeping the 2 KiB floor: it removes tools that cost more to rebuild than to find, against the token-saving goal it was made for (d-tac-00q).
- A floor at about 800 bytes: size predicts writing cost poorly.

**Accepted costs.** The figures come from one machine's transcripts, mostly one project (fdbox, 47 of the 49 tools); the 5x output price and the write-message lower bound are stated assumptions. Use before registering mixes test runs with real use, which the transcript cannot tell apart.
