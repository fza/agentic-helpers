Read across all of agentic-helpers' token work, the savings that held came from removing repetition and folding settled history behind a runnable pointer, never from shortening what an agent acts on; the attached `token-savings-report.md` carries the full account and its evidence.

The pattern, as the measured changes show it:
- The largest costs were text loaded whole into every context (the memory skill at 32.3k characters per load, MCP tool listings, filing replies echoing hints), not individual answers. Splitting a core from on-demand references and listing only what the model reads cut more than any per-answer trim.
- A cut is safe only if it passes the empty-context test: an agent after a compaction, `/clear` or in a new session knows only the output in front of it. Trims relying on what the same agent saw earlier were withdrawn for failing it, and a fold is only safe when its line names the command that brings the data back and when to run it, since agents ignore a bare count.
- Choosing by least risk first, then fewest tokens (20261029-021515-d-tac-00q), let agents cut without asking and stopped trims that hid what an agent acts on; the rejected approaches (an LLM session wrap-up, a minimum tool size, slimming JSON that programs read, dropping safety frames) each failed that order.
- Measuring before and after each release found the next cost every time, including regressions such as a skill core regrowing past its split size.

What changes ahead: every new surface or output line is held to the same tests before it ships, and sdd's engine, which shares the setting, applies the report's lessons to its procedures, searches and entry chains.

The report is a snapshot: entries recorded after it supersede what it says. `m-` ids in it name agentic-memory notes outside the graph; graph ids resolve with `sdd show` in this repository.
