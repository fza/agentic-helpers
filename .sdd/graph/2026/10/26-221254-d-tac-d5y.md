A user rule in agentic-memory may name what never belongs in memory, and `agentic-memory new` warns when an entry matches it. `new --kind rule --from user --forbids <regex>` (repeatable; MCP `forbids`, a list) stores RE2 patterns on the rule, the user-only kind of the entry kinds directive (20261026-215042-d-tac-g5a); every later `new` on a seat that receives the rule matches its title and body against them and, on a match, prints beside the similar-entry notes the agentic-memory directive (20261025-014326-d-tac-mvn) gave `new`:

`forbidden by <rule id> <rule title>` / `  matched: "<matched text>"` / `  → agentic-memory retire <new id> --because 'forbidden by <rule id>'`

The entry lands either way.

Why: a project can rule out whole classes of entry. One heavy seat's project rule was that a tool the project only uses never goes into memory, and about 10% of its entries were notes on that tool's versions. The agent knew the rule and filed them anyway; nothing at filing time pointed at it.

Mechanics:

- `--forbids` on any kind but `rule` is refused, as is an invalid RE2 pattern. Patterns are case-sensitive unless they say `(?i)`.
- The rules checked are the live rules the filing seat's brief would show: its shelf's own and those received through `--for` or a followed topic. A rule filed `--for all` covers every seat in the project.
- A match warns and the entry lands, as the similar-entry note does (`entries.go:216`). A refusal would block a real entry a loose pattern happens to match, with rewording the only way past it.
- `show`, `search` and the JSON entry object carry the patterns as `forbids`.

A filing-time check against the graph ("the graph may already hold this") is a separate decision, deferred in its own entry.

Rejected alternatives:

- A never-file list in a committed repository file: a new project-side config file and path for memory, and the rule's words kept in two places, the instruction file and the list.
- Refusing a matching entry: blocks a real entry on a loose pattern, as above.
- An embedded phrase list in place of patterns: needs an absolute similarity floor tuned per embedder, and the list then fails silently where no embedder answers.
- No list: the instruction file and the brief's rules section stay the only guard, which the reported seat passed over.

Accepted costs:

- A rule lives in this machine's memory store; another machine needs it filed again.
- A regex misses a reworded note.
- The warning wording is part of the command's contract, quoted by agentic-helpers:agent-memory.

Acceptance criteria:

1. `new --kind rule --from user --forbids <regex>` files; `--forbids` on another kind or with an invalid pattern is refused; MCP the same.
2. A later `new` matching a received rule's pattern lands and prints the warning with the rule, the matched text and the retire command, checked by a test.
3. A rule the seat does not receive does not warn.
4. Skill and docs name `--forbids` and the warning wording, in the same change.
