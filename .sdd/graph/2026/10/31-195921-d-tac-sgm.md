Every subagent a seated or seatless session spawns gets one block of agentic-helpers context at its start, through Claude Code's `SubagentStart` hook: the parent seat's user rules verbatim, the scratch folder, the machine notes, and one line naming the agentic-helpers skills to load. A subagent shares its parent's session and already runs under every tool-call hook (shell-guard, the grounding gate, memory's trap notices), but `SessionStart` never fires for it and no skill is preloaded, so it starts without the user's standing rules, without knowing where throwaway files go, and without the machine's command dialect. Builder subagents acting against rules they never saw is what this closes.

**What the block holds.**
- `rules (from the user): ...`: the parent seat's live `rule` entries, title and body as the brief's rules section prints them. No seat, no rules line. A standing instruction placed as a memory rule (20261031-192031-d-tac-e9f) thereby reaches the seat's subagents as well as its sessions.
- `scratch: <folder>`: the seat's scratch folder, or the session's where no seat is held, as `agentic-scratch` names it at session start.
- The machine line `agentic-helpers check` prints at session start, where it prints one.
- One line naming the agentic-helpers skills and when to load them (before filing memory, before writing a probe or helper script, when a hook refuses a call).

Each piece answers for its own line: `agentic-memory`, `agentic-scratch` and `agentic-helpers` each get a `SubagentStart` subcommand in `plugin/hooks/hooks.json`, silent where they have nothing to say, as at session start. Traps stay out: they already fire at the subagent's own tool calls. Memory writes from a subagent stay on the parent's seat.

**Rejected.** The full brief: up to 9,000 characters per subagent, and state and todos invite a subagent to act beyond its task. Injecting only for agent types that act: a list of read-only types to keep current, with an unknown type counting as acting anyway. A pointer line asking the subagent to read the rules itself: it relies on the subagent obeying and costs a tool call where it does.

**Accepted costs.** Every subagent, read-only lookups included, carries the rules block, a few hundred tokens. A rule filed after a subagent started does not reach it: the block is built once, at the subagent's start.

**Acceptance.**
- `plugin/hooks/hooks.json` wires `SubagentStart` to the three subcommands; a test checks the wiring.
- A subagent of a seated session receives the seat's live rules, the seat's scratch folder, the machine line where one applies, and the skills line; a seatless session's subagent receives the session scratch folder, the machine line and the skills line, no rules line.
- Each subcommand is silent in a project without its directory.
- `docs/memory/usage.md`, `docs/scratch/usage.md` and `docs/plugin/usage.md` describe what a subagent receives; the README names it.
