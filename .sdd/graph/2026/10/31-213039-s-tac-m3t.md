Shell-guard closes five paths by which a removal outside the project ran with no prompt, in agentic-helpers commit 208e16e on local `main`, not pushed or released, building on the launcher and nested-code coverage of 20261031-163018-s-tac-ptl. Each was shown allowed by a probe against the earlier code.

- **zsh code arrays**: the value of a `functions[<name>]=` or `aliases[<name>]=` assignment is walked as shell code, so `functions[f]='rm -rf ~/x'; f` is judged, and the grounding gate sees an `sdd` call hidden the same way.
- **Arithmetic**: `(( ))`, `$(( ))`, `let`, C-style `for` and `[[ -eq ]]`-style tests read the variables they name. Text a variable holds is walked as code; a value only known at run time (set by `$(...)`, `read`, `mapfile`, `printf -v`, or a loop over expanded words) gets an ask, `arithmetic on <name> reads a value shell-guard cannot see`. Numbers, `$((...))` results and plain counters pass.
- **Launchers**: `xcrun`, `sandbox-exec`, `launchctl submit`, `uv run`, `npx`, `pnpm exec` and `screen` hand on the command they launch, with their own options and values skipped; `npx -c`, `pnpm exec -c`, zsh `sched` and tmux's `new-session`, `new-window`, `split-window`, `respawn-pane`, `respawn-window`, `display-popup` and `run-shell` hand on code. `make` is not a launcher: its operands are targets, which a run of `make -C dir touch made` confirmed.
- **Code on standard input**: `at` and `batch` read their job from a pipe or here-document like a shell does.
- **Monitor**: the PreToolUse and PermissionRequest matchers in `plugin/hooks/hooks.json` cover `Bash|Monitor`, and a Monitor call carrying a command is judged as a Bash call; one without a command passes.

Evidence: every new walk and guard row failed against the earlier code and passes now; every new guard was broken one at a time, caught by its own test and restored byte-identically; `go test -race ./...` in `source/hooks` and `claude plugin validate .` pass. On the installed build, payloads for `functions[probefn]='rm -rf ~/x'; probefn`, `x='a[$(rm -rf ~/x)]'; (( x ))`, `xcrun rm -rf ~/x`, `uv run rm -rf ~/x`, `echo 'rm -rf ~/x' | at now` and `tmux new-session -d 'rm -rf ~/x'` were denied; `n=$(wc -l < f); (( n > 1 ))` was asked about; `(( count > 0 ))` and `make -C sub rm` passed; a Monitor call running `rm -rf ~/x` was judged.

Left open: typing into a running session (`tmux send-keys`, `screen -X stuff`), arithmetic inside `[ ]`/`test` and `${a[x]}` subscripts, and a here-document fed to a shell behind a launcher such as `sudo bash <<EOF`.
