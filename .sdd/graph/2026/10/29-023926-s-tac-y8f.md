agentic-memory's near-compaction nudges never fire in a session whose compaction window is set through Claude Code's settings rather than the environment, because the reading is rescaled to the compaction window only from `CLAUDE_CODE_AUTO_COMPACT_WINDOW`.

**Expected.** The nudge ladder of 20261025-014326-d-tac-mvn asks a seat to file before a compaction, so its first rung must fire at a share of the window Claude Code actually compacts at.

**Observed.** `source/hooks/cmd/agentic-memory/main.go` reads the window from the environment variable alone, and `contextPercent` in `source/hooks/internal/memory/hooks.go` rescales the reading only when that value is set. The reading itself, written by `plugin/hooks/register.ts` (20261025-031151-d-tac-klv), is the used share of the model's full window. This machine sets the window in `~/.claude/settings.json` as `modelSettings["claude-opus-5-5"].autoCompactWindow` = 400000, the key `/autocompact` writes since Claude Code v2.1.288, and leaves the variable unset. With a 1M-token model window the first rung (`contextPercentThreshold`, 65) fires at 650k tokens, while Claude Code compacts at 400k, so no near-compaction nudge ever fires in such a session.

**Where Claude Code takes the window from**, per its documentation: `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, then the `--autocompact` flag, then `modelSettings[<model>].autoCompactWindow`, then a top-level `autoCompactWindow`, across settings scopes, capped at the model's window.

Candidate remedies, not settled: resolve the window from the settings for the session's model, which the SessionStart payload names; or have `register.ts` write the compaction window beside the reading, if Claude Code's measurement exposes it.
