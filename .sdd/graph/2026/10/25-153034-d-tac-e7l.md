agentic-memory works only inside a git work tree: a directory where `git rev-parse --is-inside-work-tree` prints `true`, a fresh `git init` without commits included. Outside one, nothing is read and nothing is created:

- Every subcommand refuses with exit 1 and `agentic-memory: <dir> is not inside a git work tree; memory works only in one`. Every tool of the `memory` MCP server refuses with the same text; the server itself still starts, so Claude Code reports no failed MCP server for a session outside git.
- Every hook event stays silent: no seat notice at SessionStart, no recall, no nudge, no `Stop` backstop.
- `projectkey.Key` returns `ErrNoRepository` where git names no common directory, in place of `local/` and a hash of the directory itself. Inside git the key stays the declared `repo_id`, else `local/` and a hash of the git common directory. The grounding gate's `exempt_seats` lookup reads `ErrNoRepository` as holding no seat.
- A `.git` directory and a bare repository are not work trees and are refused.

Why: a store keyed on a plain directory's path is reached only from that exact path, moves with nothing, and outlives anything it was about; a session in `~` or `/tmp` builds one without anyone noticing. Inside git the store follows the repository across worktrees, and every entry gets the branch and commit stamps its drift flags rely on.

Rejected: requiring a commit (a new repository's identity does not change at its first commit, and memory before it is as useful as after); requiring a remote or a declared `repo_id` (a purely local repository would get no memory at all); a notice at SessionStart outside git (every session started in a plain directory would carry a line about a tool it never asked for).

Accepted costs: a throwaway `git init` is enough to get a store; git-ignored directories inside a repository, such as `node_modules/`, share the repository's store; every subcommand and hook pays one `git rev-parse` before it does anything, where the key lookup already ran git.

Acceptance criteria:

1. A functional test runs `claim`, `new` and `search` in a `t.TempDir()` holding no repository: each exits 1 with the refusal text, and no directory appears under the store root.
2. The same test with the directory turned into a work tree by a faked git lookup claims a seat and files an entry.
3. A hook event outside a work tree writes nothing to stdout or stderr and exits 0.
4. A `memory` MCP tool call outside a work tree answers with the refusal text as a tool error, and the server answers `initialize`.
5. `projectkey.Key` returns `ErrNoRepository` outside git, checked with `errors.Is`, and keeps both keys inside git.
6. `README.md` and `agentic-helpers:agent-memory` state that memory works only inside a git work tree.
