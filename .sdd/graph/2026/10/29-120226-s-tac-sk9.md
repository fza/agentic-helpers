agentic-helpers now has a `writing_style` option, `terse` unless set or `plain`, which the agentic-memory brief header names beside the entry language and which the memory and tool library writing commands and skills tell agents to follow, built in agentic-helpers commit 9757f5b. This closes 20261029-021652-d-tac-xzt.

What was built against the decision's acceptance:
- `writing_style` resolves through the `config.yaml` layering (commit ed08e24) like every overridable key, default `terse`; any other word is refused as `"<word>" is none of terse, plain`, and in `config.yaml` falls back to `terse` with the problem named.
- The brief header reads `agentic-memory: seat <seat>, <n> live, <n> retired, entries in <lang>, terse`, or `plain` under `plain`.
- The agentic-helpers:agent-memory skill states the terse rules for titles, bodies and the state; agentic-helpers:agent-tools states them for summary, usage, inputs, outputs and `--why`. The descriptions of memory `new` and `state` and tools `add` and `update`, which serve both their MCP tools and `--help`, name the style.
- agentic-helpers:agent-capture says graph entries stay plain prose whatever `writing_style` says. `plugin.json` declares the option without a default; README `Options` and `docs/memory/usage.md` list it.

Verified: table-driven tests of the reader and the brief header, each new guard broken once and caught; and the installed build (`go install`, then `~/go/bin/agentic-memory brief`) in this repository prints `agentic-memory: seat main, 37 live, 99 retired, entries in en, terse`. Not yet released.
