A split-layout link (`project_dir` in the github.com/fza/sdd fork, or a stock sdd `graph_dir` outside the checkout) joins a checkout to its graph repository's store silently only when that store already admits the checkout; otherwise the hook asks the user once, and the agent binds with `agentic-memory bind <store>` or `bind --new`.

Why: 20261029-131359-s-tac-5pp found that the link comes from config committed in the repository, so a cloned repository naming `../some-other-repo` gave every agent in the clone that project's memory and tools unasked, through `mapping.joinGraph` in `source/hooks/internal/home/resolve.go`. 20261028-204914-d-tac-6xf already asks for a weak match (`repo_id` or origin alone); a committed link is no stronger evidence of the owner's intent.

- **Admitted:** the graph store's `identity.json` lists the checkout (a pointer, the inode or the path), as after a bind or an earlier join: the join stays silent and the pointer is written into both git common dirs.
- **Not admitted:** `joinGraph` returns a `ReasonSplit` question naming the graph store instead of joining; the line follows the question format of 6xf: the checkout, the graph folder it names, the store id, and the two commands.
- A bind answers it for good: the store admits the checkout, and later calls join silently.

**Rejected.**
- Following only machine-local config (`.sdd/config.local.yaml`): stock sdd's committed `graph_dir` and the fork's committed `project_dir` would stop joining at all, so every split pair would need a local setting.
- Requiring the graph repository to name the code repository back: no sdd release writes such a back-reference, so stock split layouts would never join.
- Keeping the silent join: an untrusted clone reads another project's data unasked.

**Accepted cost.** One question per new split pair, including the first call after the fork's one-step `sdd init --project-dir`; none after the bind.

**Acceptance.**
1. A checkout whose committed link names a folder whose store does not admit it gets the question and no data from that store; no pointer is written.
2. After `bind <graph store>` the same checkout joins silently, under stock sdd (`graph_dir` outside) and the fork (`project_dir`).
3. A checkout the graph store already admits joins silently, as before.
4. The split-layout acceptance bullet of 6xf holds after the bind, and `docs/plugin/architecture.md` and the `agent-memory` skill describe the question.
