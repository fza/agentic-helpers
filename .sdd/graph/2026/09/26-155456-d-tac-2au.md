The grounding gate lets a project set the `sdd show` depth it owes, and lets named seats call `sdd show` without the depth check. Every other refusal holds for every seat: `AskUserQuestion`, a draft `Write`, `Edit` or `NotebookEdit`, `agentic-capture`, a plain `sdd new` without `--dry-run`, and an `sdd` call sending a stream to `/dev/null`.

Both settings live in one `show_depth` block of `.sdd/grounding.yaml`:

    show_depth:
      down: 2
      up: 1
      exempt_seats: [reviewer, scout]

`down` and `up` are the least depth a show owes in each direction. A key left out keeps its default, `down: 2` and `up: 1`; `0` owes nothing in that direction; a negative depth is a config error, refused like any file that does not parse. The refusal and the `agent-grounding` skill name the depth the project owes. A `prc`-layer rules entry stays exempt as before.

The gate learns a session's seat from the carry-forward claim: it matches the hook payload's session id against the claims under `.memory/roles/`. A new `internal/seat` package reads the claims for both the carry-forward and the gate, so neither hook encodes the other's file layout. A subagent carries its session's id, so it reads as the seat its session holds.

The opt-out lifts the depth check alone. An `sdd show` from an exempt seat that sends a stream to `/dev/null` is still refused, since a swallowed usage error reads as an entry with nothing around it whatever seat reads it.

Why: a claim is the only record tying a seat name to a live session; a seat named some other way is one any session can assert. One block keeps the seat list beside the rule it exempts from.

Rejected: an environment variable naming the seat (`AGENTIC_SEAT=reviewer claude`). Nothing ties it to a claim, so any session can name itself into the opt-out, and it goes stale when a session changes seat. Rejected: lifting every check on `sdd show` for an exempt seat. It trades the discarded-stream guard for nothing the seat needs. Rejected: flat keys (`show_down`, `show_up`, `shallow_show_seats`) matching `listing_prefix` and `draft_lint`. The tie between the seat list and the depth rule would live only in the key names.

Accepted costs: a project without `.memory/` cannot exempt a seat, and a session owes the depth until it claims its seat. The claim reading moves out of `internal/carryforward` into the shared package. `show_depth` is the file's first nested key.

Acceptance criteria:

- No `show_depth` block: a show short of `--down 2 --up 1` is refused, as now.
- `show_depth: {down: 3}`: `--down 2 --up 1` is refused, the refusal names `--down 3 --up 1`; `--down 3 --up 1` passes.
- `show_depth: {down: 0, up: 0}`: a plain `sdd show <id>` passes.
- A negative depth: every gated call is refused with the config error.
- A session holding a seat named in `exempt_seats`: a plain `sdd show <id>` passes; `sdd show <id> 2>/dev/null`, `AskUserQuestion`, a draft `Write` and a plain `sdd new` stay refused without the reads.
- A session holding no seat, or a seat not named: the depth is owed.
