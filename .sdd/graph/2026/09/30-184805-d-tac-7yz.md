The grounding gate lets a project name one command that runs every read a turn owes in a single call. An optional key in `.sdd/grounding.yaml`, beside `read_command` and `read_suffix`:

    gather_command: pilot graph gather

The call shape the gate reads is `<gather_command> <subject> --query '<phrase>' --term '<token>' [--term ...] [--area <name>]... --entry <subject>`. A successful Bash call through it is credited in the ledger the separate reads fill:

- a search, whatever flags it carries;
- a semantic query when it carries `--query`;
- a literal search when it carries `--term`;
- a listing for each `--area <name>` whose name carries `listing_prefix`, recorded under that name;
- naming no `--area`, one listing recorded as `areas of <subject>`, the subject taken from its `--entry` value, since the command then lists every area the subject carries. No `--area` and no `--entry` credits no listing.

A call lacking `--query` or `--term` credits only what it carries, and the gate keeps demanding the missing mode.

Settled shapes:

- `gather_command` is validated as `read_command` is: plain words, one line. A quote, a `$`, a shell operator or a line break is a config error naming `gather_command` (`ErrGatherCommand` in `internal/graphconfig`). Absent, the feature is off and nothing changes.
- A call counts where the shell reads a command word: opening the line, after a separator or a runner, in a subshell, its first word by any path, its words split by any whitespace. A mention inside a quoted argument or a heredoc body counts for nothing, and neither does a longer word (`gatherer`). A call inside `bash -c` is not credited, as no search or listing inside one is.
- The call's flags are read as the shell splits them, quotes removed, up to the first unquoted `;`, `&`, `|`, `)` or line break. `--flag value` and `--flag=value` both count, and a flag quoted inside a phrase (`--query 'why --term matters'`) is not a flag.
- The missing-reads refusal (`refusals/reads.txt`), with `gather_command` set, opens with `One call runs all three, then ask again:` and the call `<gather_command> <entry> --query '<subject>' --term '<literal>'<read_suffix>`, then `Or run both + the listing apart:` above the three separate reads. Without the key the refusal is byte-identical to its earlier text.
- Show-depth checks, the discarded-stream check, draft and capture rules, and every existing credit path are unchanged. A gather call discarding a stream is refused only where `read_command` already matches it.
- The README and the `agent-grounding` skill describe the key beside `read_command`.

Why: a project may give its agents one command that runs the semantic search, the literal search and the area listing and prints one deduplicated list. format-d-fdbox adds `pilot graph gather`. Its text matches neither the `search` nor the `view` pattern, so without this key the gate refuses every question, draft edit and capture in a turn grounded through it, and the agent reruns three reads the gather call already made.

Rejected:

- Recognising gather as a verb of `read_command` (`<read_command> gather`). A project's gather may be a different program from its read command, and a verb baked into a machine-wide tool is one project's name in a general tool, the reason `graph.py` was dropped.
- Crediting a gather call as all three reads regardless of its flags. A call without `--term` read no literal token, and a single search mode is what the gate exists to stop.
- Matching the gather call anywhere in the shell-read text, as the `search` and `view` checks do. A quoted `echo 'x; pilot graph gather ...'` would then count once its separator sits inside the quotes; anchoring to a command word outside every quoted span does not.
- Reading the call's output to decide what it listed. Every other read is credited from the command, and the output format is the other project's to change.
- Suggesting only the gather call in the refusal. The separate reads stay valid, and a project whose gather call fails still needs the form it can run apart.

Accepted costs: the gate trusts that a gather call naming no `--area` lists every area its subject carries; it cannot check. In a project naming no `listing_prefix`, every `--area` name and the no-`--area` form count as the listing, standing in for the view of every topic such a project otherwise owes. A flag after the first unquoted operator is not read. A `gather_command` needing quoting or a variable cannot be named. A binary predating the key ignores it rather than refusing the file, so a project adding the key before installing the new gate gets its gather calls credited nothing.

Acceptance criteria:

- `gather_command` set: a call carrying `--query`, `--term` and `--entry` grounds the turn on its own.
- A call without `--term` is refused for the literal mode only, and a separate `--term` search then grounds the turn; likewise for `--query`.
- `--area area-hooks` is credited as the listing `area-hooks` in a project whose prefix is `area-`; `--area hooks` is not, and the gate still owes the listing.
- No `--area` credits one listing, `areas of <subject>`, from `--entry`; no `--area` and no `--entry` credits none.
- A failed call credits nothing. A quoted mention, a heredoc body, a word before the parenthesis (`Bash(pilot graph gather`) and a longer command word credit nothing.
- `gather_command` absent: a gather-shaped call credits nothing, and every refusal text is byte-identical to its earlier text.
- `gather_command` set: the refusal offers the gather call before the three separate reads, each ending with `read_suffix`.
- A `gather_command` holding a quote or a shell operator, or spanning lines, is a config error naming `gather_command`.
