The grounding gate recognises a capture however the shell spells it, and holds a plain `sdd new` run through `Bash` to the turn's reads.

An `agentic-capture` call counts wherever an `sdd` read already counts: opening the line or following a separator, after a runner (`env`, `command`, `exec`, `nohup`, `time`, `sudo`, `xargs`, `stdbuf`, `caffeinate`), inside a subshell `( ... )`, inside the string a `bash -c` or `sh -c` runs, and under any path, quoted or not (`"$HOME/go/bin/agentic-capture"`). It is then gated as 20260925-192347-d-tac-sqt sets out: the turn's three reads, or a grounded draft. A bare mention stays free: `go test ./cmd/agentic-capture`, `ls cmd/agentic-capture/`, a `grep` for the word, a quoted string, a heredoc body.

An `sdd new` call, matched the same way and not carrying `--dry-run`, passes only when the turn carries an `sdd search --query`, an `sdd search --term` and the listing the project owes. It has no draft file, so no grounded draft stands in for the reads. A refused call gets the `reads.txt` refusal. `agentic-capture` runs `sdd new` as its own subprocess, which no hook sees, so it is unaffected.

Why: a capture the gate cannot see skips the reads it exists to demand. The spellings the gate misses are the ones a shell makes routine: a `bash -c` wrapper, a subshell, `xargs`, an absolute or quoted path. `sdd new` is the other way into the graph, and the `sdd` and `sdd-bootstrap` skills under `.claude/skills/` capture with it directly, so it owes the same reads as `agentic-capture` while staying usable.

Rejected: refusing a plain `sdd new` outright and pointing to `agentic-capture`. It would also close the backtick loss of `sdd new "$(cat body.md)"`, but break the capture step of the `sdd` skills, which `sdd init` generates, stamps with `sdd-version` and `sdd-content-hash`, and regenerates over any edit, so they cannot be moved to `agentic-capture` from this repository. Rejected: leaving `sdd new` alone. Every entry written that way skips the reads entirely.

Accepted cost: the confirm-then-capture turn of the `sdd` skills always re-runs the three reads, since an `sdd new` call has no draft to ground. `sdd new` by hand keeps its backtick hazard; the `agent-capture` skill still directs every capture to `agentic-capture`. A variable standing for the command name (`A=agentic-capture; $A d.md`) still goes unseen, as 20260925-153646-d-tac-064 accepts for `sdd`. A capture through the sdd MCP tools (`mcp__sdd__next`) never reaches `Bash` and is out of this decision's reach. `README.md` and `skills/agent-grounding` state that `sdd new` owes the reads in the same change.

Acceptance:

- A functional test refuses, with no reads in the turn, each of `bash -c 'agentic-capture d.md'`, `(agentic-capture d.md)`, `echo d.md | xargs agentic-capture`, `"$HOME/go/bin/agentic-capture" d.md` and `env agentic-capture d.md`, and passes each once the turn carries every read.
- It passes `go test ./cmd/agentic-capture`, `ls cmd/agentic-capture/`, `grep -rn agentic-capture skills`, `echo 'agentic-capture d.md'` and a heredoc body naming the command.
- It refuses `sdd new d tac 'body'`, `bash -c 'sdd new d tac body'` and `/opt/homebrew/bin/sdd new d tac body` with no reads in the turn, passes each once the turn carries every read, and passes `sdd new d tac body --dry-run` without reads.
- Each new guard is broken, its test watched failing, and the file restored byte-identically.
