The grounding gate lets a project name the command its graph reads run through. Two optional keys in `.sdd/grounding.yaml`, beside `listing_prefix`, `draft_lint` and `show_depth`:

    read_command: python3 scripts/graph.py
    read_suffix: --entry <entry>

Every read a refusal suggests is built as `<read_command> <verb> <args> <read_suffix>`: the `--term` search, the `--query` search and the listing in the missing-reads refusal, and the filtered search in the discarded-stream refusal, where the suffix goes before the pipe (`<read_command> search --term '<literal>' --limit 8 --entry <entry> | grep -E '^  [0-9]'`). With neither key every refusal is byte-identical to the text it prints today: bare `sdd`, no suffix.

Read recognition matches `sdd` or the configured `read_command`, in every check that recognises a read: the search modes, the listing, the show depth and the discarded stream. The configured command is matched as a command word the way `sdd` is: opening the line, after a separator or a runner, in a subshell or inside `bash -c`, its first word by any path, its words split by any whitespace. The hard-coded `graph.py` goes: a project that relied on it sets `read_command`.

Settled shapes:

- `read_command` is one string of plain words, split on whitespace. Each word holds only letters, digits and `_ . / : @ % + = , ~ -`. A quote, a `$`, a shell operator or a line break is a config error: the gate matches the command against the shell-read text of a call, with quoted spans emptied, so such a word could never match and the refusals would suggest a read the gate then fails to credit.
- `read_suffix` is one string on one line, printed verbatim and never matched. A read satisfies the gate with or without it: the wrapper enforces its own suffix, and the gate only records that a read ran. A line break is a config error.
- A value that is not a string (a list, a map) is a config error. A config error is refused like any file that does not parse, with the existing config refusal naming `.sdd/grounding.yaml`.
- The suffix appears on every suggested read. No refusal suggests a subject-less read such as `info`, so no read goes without it; one added later that takes no subject leaves the suffix off.
- A config that does not parse credits no read in the `record` mode, and the stream check falls back to bare `sdd`, so a broken file never refuses a command reading nothing.
- Reads only. `agentic-capture` keeps running `sdd new`, and a plain `sdd new` is recognised as bare `sdd` only: a wrapper may refuse `new`.
- The `agent-grounding` skill and the README say reads run through the project's `read_command` from `.sdd/grounding.yaml`, and end with its `read_suffix`, bare `sdd` where none is set.

Why: a project may run its reads through a wrapper that records what each read returned. format-d-fdbox's `scripts/graph.py` records a read against its subject when `--entry` names it, and a project hook there refuses bare `sdd` reads. An agent copying a hint from this gate is refused there and reruns the read. The premise of 20260925-153646-d-tac-064, that the wrapper records nothing, no longer holds. Baking one project's wrapper name into a machine-wide tool recognised it everywhere and helped nowhere else.

Rejected:

- `read_command` as a YAML list (`[python3, scripts/graph.py]`). The gate joins the words either way, and a string reads like the command an agent types; words carrying spaces are what a list would add, and those are refused anyway.
- One template key (`read_template: python3 scripts/graph.py {verb} {args} --entry <entry>`). It adds a placeholder language, and recognition would have to parse the prefix back out of it. The gate needs two different things: a prefix it matches and a tail it only prints. Two keys say so.
- An environment variable naming the read command. It lives outside the repository, every session has to set it, and it differs per project while the hooks are machine-wide; the gate already reads per-project settings from `.sdd/grounding.yaml`.
- Keeping `graph.py` recognised beside the new key. It is one project's name in a general tool, and the key covers it.
- Requiring the suffix for a read to count. The gate would duplicate the wrapper's own rule, and a bare `sdd` read would stop counting in a project that also accepts it.

Accepted costs: a project that relied on `graph.py` being recognised by name owes a `read_command` line, and until it adds one its wrapper reads neither open the gate nor trip the stream and depth checks. A `read_command` needing quoting or a variable cannot be named. A broken config file credits no reads until fixed.

Acceptance criteria:

- No `read_command` and no `read_suffix`: every refusal text is byte-identical to today's, and every read shape recognised today through `sdd` is still recognised.
- `read_command` set: the missing-reads and discarded-stream refusals print it in place of `sdd`, and a `--term` search, a `--query` search and the listing run through it satisfy the turn's reads; a show through it short of the depth is refused, and a read through it discarding a stream is refused.
- `read_suffix` set: every suggested read in both refusals ends with it, before any pipe.
- Without the config, `python3 scripts/graph.py` reads are not recognised: they credit nothing and a stream they discard is not refused.
- A `read_command` that is a list, holds a quote or a shell operator, or a `read_suffix` spanning lines, is a config error: the gate refuses a question with the config refusal.
