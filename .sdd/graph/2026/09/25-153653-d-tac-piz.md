`agentic-capture <draft.md>` turns a draft file into a captured graph entry, for any project carrying an sdd graph. It is a fourth binary in `source/hooks`, installed with the hooks, and replaces format-d-fdbox's `scripts/graph.py` and `scripts/graph-capture.py`.

- The draft opens with a YAML block (`type`, `layer`, `kind`, `topics`, `refs`, and the other `sdd new` fields), read with `github.com/goccy/go-yaml`, and its body follows. Each field becomes a `sdd new` flag, and the body reaches `sdd new` as one argument, never through a shell, so backticks in it stay text.
- Where `.sdd/grounding.yaml` names `listing_prefix`, the draft needs at least one topic carrying it.
- Where `.sdd/grounding.yaml` names `draft_lint`, any command (a script, `vale --output=line`, anything else), capture runs it from the repository root with the body written next to the draft as `.<draft>.body.md`, so the lint sees the path exclusions the draft itself has. Output blocks the capture, with line numbers shifted to the draft; a failure with no output blocks as "the lint did not run". No key, no lint.
- `sdd new --dry-run` runs next: high findings block, medium ones are shown, low ones are dropped. The capture then runs with `--preflight-verified` under a lock at `.sdd/tmp/capture.lock`, since two captures at once race for the git index.
- No outcome log is kept: nothing reads one.

format-d-fdbox's `.sdd/grounding.yaml` gains `draft_lint: vale --output=line`, and its `AGENTS.md` and `sdd-autopilot-capture` skill name `agentic-capture` in place of `scripts/graph.py capture`.

Why: nothing in the capture path is specific to fdbox except its linter and its topic prefix, and both become per-project settings; every other sdd project gets the backtick-safe body and the pre-flight in one call.

Rejected:
- Keeping the capture in fdbox and trimming only the pass-through in `graph.py`. Every other project would keep capturing by hand.
- Running Vale from capture itself. The lint belongs to the project.
- A project script at a fixed path. The project maintains a script and shifts line numbers itself.
- `go.yaml.in/yaml/v3` and a JSON header. The first was passed over for goccy/go-yaml; the second changes every draft and every tool writing one.

Accepted costs: the module's first dependency, an exception to the standard-library-first line in `source/AGENTS.md`; the file named for grounding also configures capture.
