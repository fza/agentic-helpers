The grounding gate's third read is a listing whose shape the project names. A project naming a topic prefix in `.sdd/grounding.yaml` (`listing_prefix: <prefix>`) owes a listing of one topic carrying it, `sdd view --layout "topic(<prefix><name>):as-list"`. Every other project owes the view of every topic, `sdd view --layout "active:as-counts"`. The refusal names whichever listing is owed, and the ledger records listings under `listings`.

format-d-fdbox carries `listing_prefix: area-`, because every entry there carries an `area-` topic and its capture wrapper refuses one without it, so an area listing is what settles membership there.

Why: the gate hard-coded `topic(area-...)`, a convention of one project. In a graph whose topics carry no such prefix, this one included, no read could ever open the gate.

Rejected:
- Holding the prefix only where a project keeps a `scripts/graph.py` wrapper. The wrapper is a capture path and says nothing about a project's topic scheme.
- A key in `.sdd/config.yaml`. sdd owns that file and may reject or rewrite what it does not know.
- Dropping the prefix and leaving fdbox's rule as text alone. Nothing would then hold an fdbox session to an area listing before a question.
- One listing per topic the graph holds. The gate would have to run sdd itself, and the reads grow with the graph.

Accepted costs: a file in `.sdd/` that sdd does not own, read on every gated call. The view of every topic shows labels and counts, not membership.

Settled: agentic-helpers commit 9d49612 and format-d-fdbox commit db490c14f carry it in full, with the gate's tests covering both listing modes; nothing further is owed.
