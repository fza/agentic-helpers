`install.py` wires the grounding gate's refusing mode for every project on the machine: a `PreToolUse` entry with matcher `AskUserQuestion|Write|Edit|NotebookEdit|Bash` runs `agentic-grounding-gate gate`. In a project carrying an sdd graph it refuses a question or a draft edit until the turn ran both searches and the listing, a Bash `sdd` read that discards a stream or reads short of `--down 2 --up 1`, and an `agentic-capture` of a gap draft. A project carrying no graph is untouched, as the gate exits silently there.

Why: only `turn` and `record` were wired, so the gate recorded reads and refused nothing, while the `agent-grounding` skill and the README describe its refusals as standing rules.

Rejected:
- Leaving `gate` to each project's own settings. The skill and README would describe refusals that happen nowhere until a project opts in.
- Dropping the refusing mode and keeping the gate as a reminder. A reminder is skippable, and nothing would hold an agent to the reads.

Accepted costs: every question in a project with a graph owes three reads first, this repository included, and each gated tool call pays one process start.

Durable artifact: commit 064845f in github.com/fza/agentic-helpers, changing `install.py` and `hooks/test_install.py`, the test asserting the entry and its matcher.

Settled because the wiring is complete in that commit: the installer is the only place the entry is written, and every later `install.py` run on any machine writes it. No further change is owed.
