The grounding gate refuses a `Bash` call running `agentic-capture <draft>` unless the reads that ground it still hold. Two ways pass:

- the same turn ran an `sdd search --query`, an `sdd search --term` and the listing the project owes (a `topic(<listing_prefix>...)` view, or `active:as-counts` without a prefix), the check `AskUserQuestion` and a draft edit already face;
- the draft is grounded: a `Write` or `Edit` saved it, byte for byte as it stands now, in a turn that ran all three reads, and the graph has gained or lost no entry since.

A grounded draft is recorded by `agentic-grounding-gate record`, which `agentic-install` now also wires as a `PostToolUse` entry matching `Write|Edit`. After a save to a path under a `draft/` or `drafts/` directory in a fully read turn, it appends `{draft: <sha256 of the file>, graph: <state>}` to a `grounded` list in the session ledger `.sdd/tmp/grounding-gate/<session>.json`. The graph state is the count of entry files under `.sdd/graph/` and the name of the newest. The `turn` mode clears the reads and keeps `grounded`. The check sits in `gate()` in `source/hooks/internal/grounding/grounding.go`, before the existing gap, stream and depth checks; the gap refusal for a capture stays as it is. A refused capture gets the `reads.txt` refusal.

Why: the write to the graph is the step the reads exist to protect, and it was the one step not holding them. A draft written in one turn and captured in a later one reached the graph with no reads, since each turn starts a fresh ledger, and a draft written through `Bash` (a heredoc, `cp`) never met the gate. Demanding the reads again in every capture turn closes both, but the capture turn is almost always the one where the user confirms the playback, and its reads would repeat the draft turn's against an unchanged graph. Carrying the draft turn's reads over, only while neither the draft nor the graph moved, spares that repeat and still demands reads exactly where they could have gone stale.

Rejected: demanding the three reads in every capture turn with no carry-over. It closes the same holes, and costs the confirmation turn a full re-read that tells the agent nothing new. Rejected: carrying over on the draft's hash alone, without the graph state. An entry captured in between can settle or contradict the draft, the stale grounding the gate exists to catch. Rejected: the check inside `agentic-capture`, reading the gate's ledger. It ties the command to Claude Code's session id and the gate's private files, and run by hand from a terminal it has no session, so it either always refuses or always passes.

Accepted cost: a new `PostToolUse` wiring, so `agentic-install` rewrites `~/.claude/settings.json`, and a `grounded` list in the ledger that lives as long as the session; the gate's `end` and `start` modes remove a session's ledger (20260925-192325-d-tac-pc2). The graph state misses an entry edited in place; sdd entries are immutable, so only a hand edit does that. A draft made through `Bash` never becomes grounded and owes the reads in its capture turn. `README.md`, `skills/agent-grounding` and `skills/agent-capture` state that a capture owes the turn's reads unless its draft is grounded, in the same change.

Acceptance:

- A functional test drives the gate with an `agentic-capture` call: refused with each of `--query`, `--term` and the listing missing and no grounded draft; passed with all three.
- A draft saved through `Write` in a fully read turn, then captured in the next turn with no reads, passes.
- The same capture is refused when the draft changed after the save, when the save's turn lacked a read, and when an entry file was added under `.sdd/graph/` since.
- `agentic-install --print` shows the `PostToolUse` `Write|Edit` entry for `agentic-grounding-gate record`.
- Each new guard is broken, its test watched failing, and the file restored byte-identically.
