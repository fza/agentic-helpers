Done for 20260926-161520-d-tac-kvr: a project names the command its graph reads run through as `read_command` in `.sdd/grounding.yaml`, and the tail every suggested read ends with as `read_suffix`.

`graphconfig.Load` reads both keys. It collapses the whitespace in `read_command` and refuses a word holding anything but plain word characters, or a line break, with `graphconfig.ErrReadCommand`; a `read_suffix` spanning lines with `graphconfig.ErrReadSuffix`; a value that is not a string fails to parse. A new `reads` type in `source/hooks/internal/grounding/reads.go` spells every read check from the config: the search modes, the listing, the show depth and the discarded stream match `sdd` or the configured command, the latter as a command word by any path, after a runner, in a subshell or inside `bash -c`. The hard-coded `graph.py` pattern is gone from `grounding.go` and `shell.go`. `refusals/reads.txt` and `refusals/stream.txt` print `{read}` and `{suffix}`, with the suffix before the stream hint's pipe. A config that does not parse credits no read, and the stream check falls back to bare `sdd`. `sdd new` and `agentic-capture` recognition is unchanged.

Every acceptance criterion holds, covered in `source/hooks/internal/grounding/readcommand_test.go` and `TestLoad` in `internal/graphconfig`: `TestRefusalsWithoutAReadCommandAreUnchanged` compares both refusals, without either key, to golden copies under `source/hooks/test/fixtures/refusals/`; `TestRefusalsSuggestTheReadCommand` covers the command, the suffix, and each alone; `TestReadsThroughTheReadCommand` covers reads, stream and depth through the command; `TestTheWrapperIsNoReadWithoutTheConfig` covers `graph.py` unrecognised without the key; `TestAMalformedReadCommandIsAConfigError` covers a list, a quote, an operator, a variable and line breaks. The existing suites read through bare `sdd` in place of the removed `graph.py` spelling.
