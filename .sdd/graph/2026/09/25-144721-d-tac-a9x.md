The three Claude Code hooks and their installer are Go, not Python: one module at `source/hooks` (its own `go.mod`, no `go.work`) building four binaries, installed with `go install` into `~/go/bin`. This refines how 20260925-144321-d-cpt-ua3 reaches each project: the global settings entries run the installed binaries instead of scripts inside this checkout, and this repository stays their one source.

- `cmd/agentic-carryforward` replaces `hooks/carryforward.py`, with the same subcommands (`session-start`, `session-log N`, `prompt`, `stop`, `holder`, `claim`, `take`, `release`, `sweep`, `refreshed`).
- `cmd/agentic-grounding-gate` replaces `hooks/grounding_gate.py` (`turn`, `record`).
- `cmd/agentic-scratch` replaces `hooks/scratch.py` (`start`, `end`).
- `cmd/agentic-install` replaces `install.py` (`--print`, `--remove`). It wires `settings.json` entries that call the binaries by their `~/go/bin` path and links the skills as before.
- Shared code lives under `source/hooks/internal/`, and fakes and fixtures under `source/hooks/test/`. Go rules for the tree are in `source/AGENTS.md`, imported by `source/CLAUDE.md`, following `format-d-fdbox`.

Why: the binaries sit on PATH, so neither the skills nor `settings.json` carry a path into this checkout. `skills/agent-carryforward/SKILL.md` currently hardcodes `$HOME/Codepot/sources/agentic-helpers/hooks/carryforward.py`.

Rejected:
- One binary with subcommands. The user prefers a binary per hook.
- `go run` from `settings.json`. Every call would pay compile and link time, six hooks fire in series at session start, and every hook breaks without a toolchain.
- A module per hook plus `source/shared/`, as in fdbox. That is five `go.mod` files for about 1700 lines, needs a public API for the shared code, and gives five test roots.
- Unprefixed names. `~/go/bin` precedes `/usr/bin` on PATH, so a binary named `install` would shadow `/usr/bin/install`, and `scratch` is generic enough to collide.

Accepted costs:
- An edit here no longer reaches every project at once. A `git pull` has no effect until `go install ./source/hooks/cmd/...` runs again.
- The binaries version together.
- The layout departs from fdbox's module-per-product shape.

Done when `hooks/`, `install.py` and `test.sh` are gone, `go test -race ./...` passes in `source/hooks`, and `agentic-install` wires the `~/go/bin` binaries into `settings.json`.
